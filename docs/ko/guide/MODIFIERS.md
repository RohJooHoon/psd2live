# 프리셋 (모디파이어 스택)

[문서 목록](../../README.md) · [中文](../../zh/guide/MODIFIERS.md) · [English](../../en/guide/MODIFIERS.md) · [MCP 사용법과 인터페이스](../agent/MCP_AUTHORING.md) · [모디파이어 스택 내부 구조](../spec/RIG_MODIFIER_STACK.md)

명시적 스택이 있는 프로젝트는 프리셋 패널을 표시하고, 레거시 프로젝트는 열 때 기존 프리셋 패널을 유지합니다. **수정자 스택으로 변환**으로 변환을 요청할 수 있습니다. 변환은 일반 메시 프로젝트, 기본 레거시 바인딩, 여러 신체 부위와 추가 모듈이 있는 모던 테스트 사례에서 검증되었습니다. 다른 프로젝트는 여전히 결과 비교에서 실패할 수 있습니다. 비활성화된 레거시 시뮬레이션은 변환 후에도 비활성 상태로 남습니다. 활성화된 시뮬레이션은 후보 입력과 일치하는 기존 베이크가 있어야 합니다. 소스 바인딩은 추가, 조정, 재정렬, 적용할 수 있습니다. 흔들림, 물리 그룹, 시뮬레이션, 생성 모션도 같은 추가 흐름을 공유하며 스택 안에서 조정할 수 있습니다. 시작 페이지 바로가기도 격리된 변환을 거쳐 명시적 모디파이어를 추가합니다. 이전 패널 버전은 여러 언어와 테마로 캡처했지만, 그 캡처가 새로 설계된 목록과 인스펙터를 검증하지는 않습니다.

## PSD 프로젝트 만들기

시작 페이지는 처음에 **추천 수정자**를 선택합니다. 첫 리비전에는 공통 구조와 몸, 얼굴, 눈, 눈썹, 입, 머리카락 바인딩이 들어 있습니다. **빈 수정자 스택**을 고르면 편집 가능한 소스 메시로 시작합니다. 최소, 기본, 전체, 사용자 지정 선택은 바인딩, 물리, 시뮬레이션, 모션을 격리된 가져오기 후보 안에서 생성합니다. 명시적 인스턴스를 평가한 뒤 초기 리비전 하나를 설치합니다. 항목은 각각 독립적으로 편집할 수 있으며, 그룹은 출처만 기록합니다. 실패하거나 취소하면 일부만 만들어진 프로젝트는 설치되지 않습니다.

## 추가와 전환

Legacy와 Modern은 같은 프로젝트 모델 안의 두 가지 모디파이어 그룹 프리셋이며, 프로젝트 형식 버전이 아닙니다. 새 프로젝트는 선택한 바인딩, 모듈, 동역학, 모션, 의상 시뮬레이션을 직접 인스턴스로 만듭니다. 스택이 이들을 평가하며, 중간 단계의 레거시 모델을 생성하거나 마이그레이션하지 않습니다.

메시를 선택한 뒤 **프리셋 추가**를 누르세요. 알고리즘은 신체 부위별로 묶여 있고, 레거시 방식과 피팅 방식이 함께 표시됩니다. 의상과 머리카락 시뮬레이션은 각 부위에 나타나며 원래의 자동 재질과 가중치 설정을 사용합니다. 범용 생성기는 **고급** 아래에 있습니다. 선택하면 의존성 목록을 미리 보여 주고, 비용이 큰 평가는 확인할 때 실행합니다. 쌓을 수 없는 항목이 선택한 모든 대상에 이미 있으면(비활성 인스턴스 포함) 숨겨집니다. 일부 대상에만 있으면 기존 개수를 표시하고 아직 없는 대상에만 추가합니다. 흔들림이나 모션처럼 쌓을 수 있는 항목은 계속 추가할 수 있습니다.

**프리셋 전환**은 일반 작성 내용을 유지하면서 프리셋 전체를 **구버전 (기존 알고리즘)**, **신버전 (피팅 알고리즘)**, **비우기** 중 하나로 교체합니다. 한 번에 커밋되며 실행 취소할 수 있습니다. 몸에 붙는 의상은 시뮬레이션이 필요 없으면 건너뜁니다. 자동 생성된 가중치는 개별로 추가한 시뮬레이션 인스턴스에 속하며, 같은 이름의 기존 작성 그룹이 우선합니다.

현재 전환은 편집 내용을 버리는 대신, 생성 콘텐츠 오버라이드나 적용된 프리셋 기능이 있으면 거부합니다. 전환하기 전에 그 내용을 먼저 처리하세요. 단계별 MCP 그룹은 호환을 위해 남아 있지만 더 이상 UI의 주요 선택지는 아닙니다.

**설정** 탭은 항목을 폴더로 정리하며, 기본적으로 용도별로 묶습니다. 폴더나 항목을 만들고, 이름을 바꾸고, 삭제하고, 드래그해도 실행 순서는 바뀌지 않고 모델도 다시 빌드하지 않습니다. **실행 순서** 탭은 평평한 목록을 보여 주며, 파라미터 목록과 같은 드래그 방식으로 실행 순서를 바꿉니다. 잘못된 의존성 순서는 거부됩니다. 폴더 배치는 프로젝트와 함께 저장되며 실행 취소와 다시 실행을 지원합니다. 의존성은 새 소비자보다 앞에 추가되며, 기존 항목을 몰래 재정렬하지 않습니다.

라이브러리에는 **신규 · 경량**, **신규 · 풍부한 움직임**, **기존 · 경량** 프리셋도 들어 있습니다. **프리셋 관리**에서 현재 구성을 저장하고, JSON을 가져오거나 내보내고, 선택한 라이브러리 프리셋을 삭제할 수 있습니다. 저장된 프리셋에는 모디파이어 설정과 폴더가 들어가며, 생성 콘텐츠 오버라이드와 베이크 캐시는 제외됩니다. 시뮬레이션은 적용할 때 다시 베이크합니다. 번들 프리셋과 사용자 프리셋 모두 애플리케이션 환경설정에 JSON으로 저장됩니다. 빠진 번들 항목은 함께 배포된 JSON에서 복원한 뒤 같은 경로로 읽습니다. 대상은 안정적인 참조나 고유한 이름과 타입으로 찾으며, 모호하거나 없는 대상은 범위를 넓히지 않고 실패합니다.

공통 구조 모디파이어는 원래의 특징 변위 계층을 켤 수 있습니다. 구조를 적용한 뒤에도 이후 얼굴 바인딩은 이를 계속 사용합니다.

새 구조는 버전 2를 사용하며, 메시마다 부모 체인 전체를 복제하는 대신 고정된 대상 그룹 안에서 부모를 공유합니다. 하류 바인딩은 공유 구조의 대상 범위 전체를 덮어야 합니다. 서로 다른 작성 부모 아래의 대상은 하나의 구조를 공유할 수 없습니다. 저장된 버전 1 스택은 원래 오브젝트 ID와 재생 동작을 유지하며, 기존 분기를 자동으로 병합하거나 업그레이드하지 않습니다.

## 조정과 위치 찾기

간결한 목록에서 행을 선택하면 목록 오른쪽에서 모든 값을 편집할 수 있습니다. 가운데 구분선을 드래그해 각각 따로 스크롤되는 목록과 인스펙터의 크기를 조절하세요. 조정 양식은 공통 인스펙터 레이아웃을 사용합니다. 물리는 선택한 입력, 출력, 세그먼트를 편집하고, 모션은 선택한 트랙과 키를 편집합니다.

**대상**과 생성 콘텐츠에서 오브젝트 위치와 실제 기여를 확인할 수 있습니다. 선택한 항목에서는 **여기까지 적용**을 계속 쓸 수 있습니다.

`face/legacy`와 `face/fitted`는 같은 대상에서 서로 배타적인 베이스입니다. 피팅 베이스는 기존 피팅 알고리즘을 재사용하며, 별도의 레거시 얼굴 항목을 끼워 넣지 않고도 하류에 필요한 머리 파라미터를 제공합니다. 저장된 `face.depth-turn` 항목은 계속 재생되며, 새로 추가할 때는 `face/fitted`를 사용합니다. 단일 항목 계획은 대상에 이미 있는 레거시 얼굴 제공자를 재사용하고, 제공자가 없으면 피팅 얼굴을 기본으로 씁니다. 레거시 얼굴이나 레거시 그룹을 명시적으로 고르면 레거시 알고리즘을 유지합니다. 기존 스택은 다시 쓰지 않습니다.

모디파이어 이름을 드래그하면 실제 평가 순서가 바뀝니다. 드래그 이미지와 밀려나는 형제 행은 파라미터 패널과 같은 구현을 공유합니다. 잘못된 의존성 순서는 거부되며 원래 스택이 그대로 남습니다. 슬라이더나 숫자를 연속으로 편집하면 끝났을 때 히스토리 노드 하나를 커밋합니다.

비활성화하면 평가가 멈춥니다. 의존하는 항목은 **종속 항목 누락** 상태로 계속 보입니다. 원래 인스턴스를 다시 켜면 오버라이드가 복원됩니다. 제거해도 휴면 오버라이드는 유지되며, 실행 취소하면 항목이 돌아옵니다. 새로 추가한 인스턴스는 제거된 인스턴스의 편집을 물려받지 않습니다.

생성된 메시, 파츠, 디포머는 일반 편집기에서 이름을 바꾸고, 지원되는 정적 외형을 조정하고, 계층을 바꿀 수 있습니다. 참조하는 오브젝트는 그 모디파이어의 평가 단계 시점에 존재해야 합니다. 생성된 파라미터의 이름, 범위, 기본값 편집은 그 제공자와 함께 저장됩니다. 하류 정의와 충돌하는 변경은 거부됩니다. 이 편집은 그것을 만든 모디파이어에 속하며, 다시 켜면 이어서 적용됩니다.

모디파이어가 생성한 오브젝트 트랙에서 키를 추가, 이동, 삭제할 수 있습니다. 명령이 여러 인스턴스가 소유한 트랙을 함께 편집하게 되는 경우에는 특정 트랙을 선택하세요. 파라미터 패널의 정지점은 그 파라미터를 생성한 인스턴스와 함께 저장됩니다.

실시간 시뮬레이션을 지원하는 형식으로 내보내면 활성화되고 베이크된 시뮬레이션 항목이 포함됩니다. 장면은 같은 평가에서 생성된 파라미터와 물리 그룹을 참조합니다.

## 여기까지 적용

**여기까지 적용**은 그 항목까지의 실제 결과를 일반 편집 가능한 내용으로 실체화하고, 앞부분 전체를 제거합니다. 비활성 항목은 내용을 생성하지 않고 제거됩니다. 이후 인스턴스와 오브젝트 참조는 유지되며, 적용 전후의 전체 결과가 일치해야 합니다.

물리는 일반 설정이 되고, 생성 모션은 파일 이름, 내보내기 그룹, 런타임 페이드 기본값을 가진 일반 클립이 되며, 시뮬레이션은 생성된 바인딩을 실체화합니다. 현재 재생 프레임이 결과가 되는 것은 아닙니다. 의존성 누락, 맞지 않는 오버라이드, 유효하지 않은 베이크가 있으면 적용이 막히며, 실패하면 일부 결과도 게시하지 않습니다. 실행 취소하면 원래 스택이 복원됩니다.

눈 모디파이어에는 크게 뜨기, 눈꺼풀 선 페이드, 하이라이트 시차가 있습니다. 크게 뜨기는 눈 뜸 정도를 명시적으로 2까지 늘리며 파라미터 변경을 보고합니다. 하이라이트 추가 계획에는 얼굴 바인딩 선행 조건이 포함됩니다. 새로 추가된 정지점은 기여 목록에 키 좌표를 표시합니다.

눈 비침과 눈썹 비침은 따로 추가하고 항목마다 불투명도를 설정하세요. 기여 목록에는 생성된 메시, 계층, 마스크 관계가 표시됩니다.

**토글 연출**은 고정된 토글 레이어와 전환 레이어에 파라미터와 불투명도 키를 추가합니다. 들어오는 변형이 먼저 나타난 뒤 나가는 변형이 사라집니다. 토글과 전환은 생성된 매달림 체인에도 입력되며, 기여 목록에 영향받는 물리 그룹이 표시됩니다.

**입 윤곽선**은 조건에 맞는 입 원화에 자체 텍스처를 가진 윗입술과 아랫입술 메시를 만듭니다. 모디파이어에서 선 두께와 RGB 색을 설정하거나, 원본 원화에서 색을 샘플링하세요. 적용하면 메시와 텍스처 모두 프로젝트에 저장됩니다.

## 네이티브 생성기

흔들림은 피벗, 오프셋, 축, 세그먼트, 모양, 선택 사항인 물리를 노출합니다. 물리 그룹은 파라미터 입력/출력, 세그먼트, 정규화를 노출합니다. 생성 모션은 기존 알고리즘을 사용하며 현재 파라미터가 지원하는 트랙만 포함합니다. 삽입하기 전에 프리셋을 고르세요. 스택 안의 컨트롤로 길이, 반복, 페이드, 트랙, 키를 편집합니다. 삽입한 뒤에는 프리셋 인스펙터에서 값을 편집하세요.

물리에는 사용 가능한 출력 파라미터와 그와 다른 입력이 필요합니다. 필요하면 바인딩 모디파이어나 일반 파라미터를 먼저 추가하세요. 출력 쓰기가 충돌하면 기존 그룹을 대체하지 않고 삽입을 막습니다. 시뮬레이션은 재생 프레임과 관계없이 실제 상류 스택을 백그라운드에서 베이크합니다. 컨트롤에는 재질, 입력, 모드, 키, 과장, 블렌드 셰이프 출력 방식, 정적 입력 축 추가와 제거가 있습니다. 고정, 강성, 모양, 질량, 감쇠, 바람은 대상의 이름 있는 정점 그룹을 선택할 수 있습니다. 기본값은 각 대상에서 해당 종류의 첫 번째 그룹을 읽습니다. 시뮬레이션 대상 밖의 메시에 충돌체를 추가하고, 정점 A/B, 양 끝 반지름, 마찰을 조정하거나 제거할 수 있습니다. 끝점이 같으면 원, 다르면 캡슐이 됩니다. 정점 인덱스는 0부터 시작합니다. 학습용으로 일반 클립이나 앞선 모션 모디파이어를 선택하고, 가중치를 조정하거나 제거하세요. 클립이 없으면 항목은 유지한 채 시뮬레이션 평가를 일시 중지합니다. 시뮬레이션을 모션 제공자보다 위로 옮기면 거부됩니다. 자동 베이크는 같은 편집 트랜잭션 안에서 오래된 결과를 새로 고치며, 그렇지 않으면 오래된 결과가 제출을 막습니다. 움직임이 충분하지 않은 입력은 거부되며, 작은 입력을 유지하려면 명시적으로 **유지**를 고르세요.

깜빡임 여진과 눈썹 스프링은 바인딩과 함께 진자를 추가합니다. 모디파이어 안의 **물리**를 펼치면 입력/출력, 세그먼트, 정규화를 편집할 수 있으며, 값은 그 인스턴스에 남습니다. 서로 다른 대상은 호환되는 표준 출력 그룹을 재사용할 수 있으며, 첫 소유자의 정체성과 이름을 유지합니다. 공유 값이 호환되지 않으면 편집을 거부합니다. 다른 사용자를 먼저 비활성화하고, 설정을 맞춘 뒤 다시 켜세요. 적용하면 편집한 값을 일반 물리로 유지합니다.

입 모디파이어에는 캡처 축, 혀, 턱, 내부 깊이, 스프링이 있습니다. 추가 계획에 선행 조건이 나열됩니다. 볼 홍조와 그늘은 입 움직임과 결합하는 색상 채널을 추가합니다. 색상 키 편집은 인스턴스에 속하며, 비활성 중에는 잠들어 있다가 원래 인스턴스와 함께 다시 적용됩니다.

물리 패널은 평가된 스택 그룹을 **프리셋** 배지와 함께 표시합니다. 생성된 그룹은 소유한 모디파이어에서 편집하세요. **프리셋 열기**를 누르면 그 패널로 돌아갑니다. 순서는 스택을 따릅니다. 적용한 뒤에는 일반 사용자 지정 설정이 되어 평소처럼 편집, 비활성화, 재정렬할 수 있습니다.

피부 클리핑은 볼 홍조, 피부 오버레이, 앞머리 그림자에 얼굴 마스크를 추가합니다. 목 따라가기는 목을 머리 기울기에 바인딩하고 목 그림자를 클리핑하며, 추가 계획에 고정된 얼굴 바인딩 선행 조건이 포함됩니다. 둘 다 기존 원화를 사용합니다. 기여에는 모디파이어 적용 전후의 마스크 소스와 반전 여부가 표시되며, 대상이나 소스를 클릭하면 위치를 찾아갑니다.

분절 머리카락 체인은 같은 대상에서 레거시 머리카락 베이스를 대신하는 선택지입니다. 치마, 리본과 장식, 귀, 꼬리와 날개, 가슴 따라가기, 팔 지연도 따로 추가할 수 있습니다. 추가 계획에 필요한 몸과 얼굴 바인딩이 나열됩니다. 흔들림, 머리카락 부드러움, 실제 물리 그룹은 해당 모디파이어 안에서 조정하세요. 다른 항목을 옮겨도 체인 참조는 그대로 유지됩니다.

피팅 얼굴 회전은 얼굴 베이스이며 레거시 얼굴 베이스와 서로 배타적입니다. 회전, 깊이, 스타일은 모디파이어 안에서 조정합니다. 새 스타일을 고르면 그 모디파이어의 다른 값은 기본값으로 돌아갑니다. 조건에 맞는 옆머리는 크게 돌렸을 때 얼굴 뒤로 이동합니다.

물리를 추가할 때는 앞머리 흔들림, 뒷머리 흔들림, 젤리 눈 중에서 고릅니다. 필요한 파라미터가 없으면 계획에 프리셋과 함께 추가할 베이스 바인딩이 나열됩니다. 모션을 추가할 때는 원래 방식이나 자연스러운 대기, 깜빡임, 끄덕임, 고개 젓기, 또는 자연스러운 말하기를 고릅니다. 자연스러운 모션을 고르면 빠진 베이스 바인딩을 계획에 넣습니다. 확인하기 전에 값을 편집해도 계획된 선행 조건은 유지됩니다. 생성된 규칙이나 트랙은 인스턴스 안에서 편집하세요.

## MCP와 공유

`modifier_catalog`는 알고리즘을 나열하고, `modifier_stack`은 고정된 상태와 실제 기여를 보고합니다. `modifier_plan`은 소스 바인딩과 선행 조건을 계획하며, 네이티브 흔들림, 물리, 시뮬레이션, 모션 설정도 받습니다. 반환된 `group`과 `entries`를 `workspace_preview_regeneration`으로 시험 실행한 뒤, 같은 `state`에 대해 `modifier_add_group`을 제출하면 GUI의 추가 흐름을 재현할 수 있습니다. [MCP 사용법과 인터페이스](../agent/MCP_AUTHORING.md)를 참고하세요.

깜빡임 모션 모디파이어는 EyeBlink 런타임 파라미터 역할도 기여합니다. 이 기여는 관계 아래에 나타나며, 모디파이어를 적용한 뒤에도 일반 모델 메타데이터로 남습니다.

모션 모디파이어를 적용하면 파일 이름과 정확한 곡선 제어점이 보존됩니다. 이후 파라미터 범위를 편집하면 일반 클립이 새 범위에 맞게 제한됩니다. 저장, 다시 열기, 다시 빌드만으로는 곡선이 바뀌지 않습니다.

모션 트랙을 펼치면 키 시간, 값, 보간, 들어오는/나가는 베지어 핸들을 편집할 수 있습니다. **이벤트** 섹션에서 이벤트를 추가, 시간 변경, 편집, 삭제할 수 있습니다. 모디파이어를 적용하면 편집 가능한 일반 모션 클립이 남습니다.

## PSD가 아닌 방식으로 만들기

빈 Layout 프로젝트와 가져온 Layout 매니페스트는 명시적인 빈 스택과 편집 가능한 메시로 시작합니다. 빈 스택에서 처음 생성할 때는 완전한 Modern 기준을 사용합니다. 이후 생성은 선택한 호환 그룹을 새 대상에 추가하며 기존 바인딩을 대체하지 않습니다. MCP `rig_generate.preset_group`으로 여섯 그룹 중 하나를 고르거나, 일반 메시만 원하면 `none`을 지정합니다. 소스 원화에서 만들 때는 추천 그룹을 사용합니다. 레거시 문서는 기존 생성 경로를 유지합니다.

새 CMO3 가져오기는 빈 프리셋 스택을 사용하며, 가져온 모델과 물리를 일반 작성 내용으로 유지합니다.
