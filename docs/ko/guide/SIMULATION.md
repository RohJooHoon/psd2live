# 시뮬레이션과 베이크

[문서 목록](../../README.md) · [中文](../../zh/guide/SIMULATION.md) · [English](../../en/guide/SIMULATION.md) · [물리](PHYSICS.md) · [흔들림 생성](SWING.md) · [캔버스 편집](CANVAS_EDITOR.md) · [MCP 사용법과 인터페이스](../agent/MCP_AUTHORING.md)

처음이라면 [그림으로 보는 시뮬레이션 튜토리얼](SIMULATION_TUTORIAL.md)부터 시작하세요. 프리셋, 고정 가중치, 다시 베이크하기, 결과 확인을 스크린숏과 함께 안내합니다.

시뮬레이션은 편집기 안에서 메시에 실제 2D 천 / 머리카락 시뮬레이션을 실행합니다. 정점은 고정(핀)으로 붙잡히고 중력과 관성으로 움직입니다. Cubism 런타임은 이런 시뮬레이션을 하지 않으므로 **시뮬레이션 자체는 내보내지지 않습니다**. 내보내려면 Cubism이 재생할 수 있는 내용으로 **베이크**해야 합니다. 즉 피팅된 진자로 구동되는 새 파라미터의 메시 키폼과, 몇몇 파라미터의 정확한 보정입니다. 베이크 결과는 프로젝트에 저장되며, 모델을 다시 빌드할 때는 결과만 다시 기록하고 시뮬레이션을 다시 하지 않습니다.

## 기본 작업 흐름

1. 캔버스에서 치마나 머리카락 메시를 선택한 다음, **시뮬레이션** 패널(모든 작업 공간에서 **물리** 탭 다음에 있으며, 편집 작업 공간에서는 기본으로 표시됨)에서 **새로 만들기**를 클릭하고 **천** 또는 **머리카락**을 고릅니다. 한 바디에 든 여러 메시는 함께 시뮬레이션됩니다.
2. 고정을 설정합니다. 다음 중 한 가지 또는 두 가지 모두를 사용합니다.
   - 패널의 **정점 그룹**에서 **고정** 행의 **페인트**를 클릭하거나, 캔버스를 **시뮬레이션** 모드로 전환한 뒤 가중치 브러시로 **고정** 그룹을 칠합니다.
   - 패널의 **글루**에서 허리와 이어지는 글루를 **고정**으로 설정합니다.
3. 도구 모음의 미리보기 스위치를 켜서 **참조 시뮬레이션**으로 두고, 미리보기에서 머리를 돌리고 몸을 흔들어 보면서 자연스러워질 때까지 재질을 조정합니다.
4. 선택한 바디의 **베이크** 섹션(편집기의 첫 번째 섹션)에서 **베이크**를 클릭하거나, 패널 상단 도구 모음에서 **모두 베이크**를 클릭합니다. 베이크는 몇 초 걸리며 백그라운드에서 실행됩니다. 그동안 다른 편집을 계속할 수 있으며, 베이크 결과는 그 시점의 최신 버전 위에 별도의 실행 취소 단계로 커밋됩니다. 도구 모음의 **자동 베이크** 스위치는 기본으로 꺼져 있습니다. 켜면 패널에서 바꾼 내용이 즉시 커밋된 뒤 백그라운드에서 다시 베이크됩니다. 베이크가 끝나면 물리 패널에 출처가 **시뮬레이션**인 진자 그룹이, 파라미터 패널에 `ParamSim…` 파라미터가 나타나며, 내보내기에 포함됩니다.
5. 미리보기 스위치를 끄면 **내보내기 결과**로 돌아갑니다. 이제 미리보기는 내보낸 모델의 움직임을 재생하므로 참조 시뮬레이션과 비교할 수 있습니다.

### 패널 구성

패널은 물리 패널과 같은 구성입니다.

- **도구 모음**: 한 줄에 **새로 만들기**(천 / 머리카락), **모두 베이크**, **자동 베이크** 스위치, 미리보기 스위치(끄면 **내보내기 결과**, 켜면 **참조 시뮬레이션**이며 레이블이 현재 상태를 표시)가 있고, 그 아래 줄에 베이크 상태가 표시됩니다. 오른쪽에는 모두 펼치기와 모두 접기(바디 목록과 편집기 섹션)가 있으며, 참조 시뮬레이션이 켜져 있으면 맨 오른쪽의 초기화 버튼으로 실시간 시뮬레이션을 정지 상태로 되돌립니다. **새로 만들기**는 선택한 메시로 바디를 만들며, 이름은 `sim`에 첫 번째 메시의 이름에서 `ArtMesh` 접두사를 뺀 것을 붙여 짓습니다(예: `ArtMeshBottomwear` → `simBottomwear`, 이름이 겹치면 번호가 붙음). **모두 베이크**는 베이크되지 않았거나 오래된 활성 바디를 하나씩 차례로 베이크하며, 뒤의 바디는 앞 바디의 베이크 결과 위에서 베이크됩니다. 모두 끝나면 하나의 실행 취소 단계로 커밋합니다. 모두 최신 상태일 때 다시 클릭하면 전부 다시 베이크합니다. 베이크가 진행되는 동안에도 편집을 계속하거나 다른 바디를 베이크할 수 있습니다(다음 차례를 기다림). 베이크 중에 바디의 설정이 바뀌면 그 결과는 이전 설정으로 커밋되지 않고 다시 베이크됩니다. 베이크 중에 삭제된 바디의 결과는 버려집니다. **자동 베이크**는 로컬 UI 환경 설정으로, 프로젝트에 저장되지 않으며 기본으로 꺼져 있습니다. 버튼 옆의 개수는 상태를 나타냅니다. 기다리는 것이 있으면 노란색으로 "1/2개 베이크 필요", 없으면 "2/2개 베이크됨"으로 표시됩니다. 베이크 중에는 버튼이 취소로 바뀌며(취소하면 아무것도 커밋되지 않음), 상태 표시에 현재 바디와 그 번호, 진행률이 나타납니다. 한 바디의 베이크가 실패하면 그 바디는 이전 베이크를 유지하고 목록 아래에 안내가 나타나며, 나머지는 평소대로 커밋됩니다.
- **목록**: 접을 수 있는 **바디** 폴더입니다. 각 행 왼쪽의 확인란으로 바디를 켜고 끕니다. 오른쪽에는 베이크 상태와 종류가 표시됩니다. 베이크된 바디는 초록색 점만 표시되며, 주의가 필요한 상태만 글자로 표시됩니다(노란색 **오래됨**은 내보내기가 아직 이전 결과를 사용한다는 뜻, 빨간색 **베이크 안 됨**은 내보내지지 않는다는 뜻, 회색 **끔**). 컨텍스트 메뉴에서 베이크, 베이크 지우기, 삭제를 할 수 있습니다.
- **편집기**: 제목 행에 이름과 종류가 있고(종류를 바꾸면 그 종류의 재질 프리셋이 적용됨), 그 뒤로 **베이크**, **재질**, **입력**, **출력**, **글루**, **정점 그룹**이 이어집니다. 베이크 섹션에는 먼저 학습하지 않은 모션에 대한 시각적 검사(흔들림 비율, 지연, 안정화, 떨림. 차이가 눈에 띄면 경고 색)가 표시되고, 이어서 R²와 오차(끝에 닿는 경우와 떨림이 늘어난 경우는 따로 경고), **베이크 / 다시 베이크**, **베이크 지우기**, 모드, 상하, 키 수, 과장이 있습니다. 모드 기록 방식, 학습에 쓰는 모션, 정확한 포즈, 모드별 흔들림은 **고급** 아래에 있습니다. **비교** 섹션(기본으로 접혀 있음)은 베이크 결과를 참조 시뮬레이션과 나란히 놓습니다. [내보내기와 참조 시뮬레이션](#내보내기와-참조-시뮬레이션)을 참고하세요. 재질 섹션 맨 위에는 이름 있는 프리셋이 있으며, 재질을 바꾸면 섹션 제목에 **이 종류의 프리셋으로 되돌리기** 버튼이 나타납니다. 입력 섹션에는 각 파라미터의 이름과 ID가 나열되며, 모델에 더 이상 없는 파라미터는 경고 색으로 **없음**이 표시됩니다. 베이크 후에는 각 입력 아래에 그 입력이 바디를 얼마나 움직이는지 표시되고, 제외된 입력은 경고 색으로 **제외됨**과 **유지** 확인란이 표시됩니다. 그 아래 줄은 학습 범위입니다. 입력이 기본값과 다르면 섹션 제목에 **기본 입력으로 초기화** 버튼이 나타나며, 입력이 하나도 없으면 베이크할 수 없다고 경고합니다. 베이크 후 출력 섹션에는 만들어진 모드 파라미터와 진자(이름과 ID)가 나열됩니다. 이름을 클릭하면 바꿀 수 있으며, 비우거나 기본 이름으로 되돌리면 바디 이름을 따르는 방식으로 돌아갑니다. 각 모드 파라미터 아래에서 ID, 범위, 게인을 지정할 수 있습니다.

## 정점 그룹

정점 그룹은 각 메시의 정점마다 0–1 가중치를 가집니다. 그룹은 이 애플리케이션 안에만 존재하며 `.moc3` / `.cmo3`에는 기록되지 않습니다. 메시마다 종류별로 그룹이 하나씩 있고 종류로 구분하므로 이름이 필요 없습니다. **시뮬레이션** 모드에서 가중치 브러시나 가중치 그라데이션으로 칠합니다([캔버스 편집](CANVAS_EDITOR.md) 참고). 왼쪽 도구 모음의 가중치 도구 아래에 종류가 나열되며(`1`–`5`로도 전환), 하나를 클릭하면 칠할 그룹이 바뀝니다. 가중치 브러시는 원, 선, 사각형 팁도 제공합니다. 토폴로지를 편집한 뒤에는 각 정점의 원래 위치에서 보간하여 가중치를 유지합니다.

| 종류 | 효과 |
| --- | --- |
| 고정 (`1`) | 리그에 붙잡히는 정점이며, 가중치는 얼마나 단단히 붙잡는지를 나타냄 |
| 강성 (`2`) | 정점별로 늘어남과 굽힘 강성을 조절해 단단한 뿌리와 부드러운 밑단을 만듦 |
| 형태 (`3`) | 정점별로 원래 그린 형태로 돌아가는 스프링을 조절 |
| 질량 (`4`) | 정점별로 질량을 조절 |
| 감쇠 (`5`) | 정점별로 감쇠를 조절 |

패널의 **정점 그룹**에는 대상 메시에 각 종류의 그룹이 칠해졌는지가 나열됩니다. 각 행의 **페인트**는 첫 번째 대상 메시를 선택하고 캔버스를 **시뮬레이션** 모드로 전환한 뒤 그 종류의 가중치 브러시를 엽니다. 바람과 그 밖의 힘 필드는 아직 구현되지 않았으므로 패널과 가중치 브러시에는 **바람** 그룹이 없습니다. MCP의 `vertex_group_update` / `vertex_group_paint`는 여전히 `wind`를 받지만, `simulation_simulate`에 `wind`를 지정할 때만 효과가 있습니다. MCP에서는 이름 있는 그룹도 사용할 수 있으며 바디의 `groups`에서 이름으로 고를 수 있습니다. 한 종류의 그룹이 여럿이면 이름을 지정하지 않는 한 첫 번째 그룹이 사용되며, UI가 칠하는 것도 이 그룹입니다.

## 글루

글루는 저절로 고정이 되지 않습니다. 시뮬레이션되는 메시에 이어진 각 글루의 역할은 패널에서 따로 고릅니다.

| 역할 | 효과 |
| --- | --- |
| 무시 (기본값) | 시뮬레이션은 이 글루를 건드리지 않으며, 런타임에서만 용접됨 |
| 고정 | 시뮬레이션되는 쪽의 글루된 정점이 다른 메시의 실제 변형을 따라감. 예: 치마와 허리 |
| 함께 유지 | 양쪽이 모두 시뮬레이션될 때 이음매가 떨어지지 않게 유지. 예: 따로 나뉜 앞판과 뒤판 |

## 재질

| 항목 | 의미 |
| --- | --- |
| 질량 | 상대 밀도. 각 정점의 질량은 메시 면적에서 차지하는 몫(주변 삼각형 면적의 3분의 1)으로 정해지므로, 메시를 세분화하거나 다시 삼각 분할해도 변형의 디테일만 늘어날 뿐 천이 무거워지거나 부드러워지지 않음 |
| 늘어남 | 길어지는 데 대한 저항. 천과 머리카락은 1에 가까워야 함 |
| 굽힘 | 얼마나 급하게 휠 수 있는지. 이웃한 삼각형 사이의 각도 차이로, 굽힘만 다루며 줄어드는 것은 다루지 않음 |
| 면적 | 각 삼각형이 면적을 얼마나 단단히 유지하는지. 정면에서 보면 천은 깊이 방향으로 접힐 때 짧아지고 뭉침. 낮은 값은 가벼운 천이 이렇게 줄어들게 하고, 높은 값은 무거운 부분의 형태를 유지함. 값과 관계없이 삼각형이 뒤집히거나 면적이 0으로 찌그러지지 않음 |
| 결 | 결을 따르는 방향보다 결을 가로지르는 방향으로 얼마나 더 부드러운지. 결의 방향은 자동으로 "고정에서 멀어지는 방향"(메시를 따라 잰 경로 길이가 늘어나는 방향)으로 정해지며, 고정이 없으면 바로 아래 방향. 값이 높으면 가닥이 길이 방향으로 늘어나지 않지만 옆으로 갈라지거나 길이 방향으로 접힐 수 있음 |
| 감쇠 | 움직임이 잦아드는 속도(초당) |
| 형태 | 원래 그린 형태로 돌아가는 스프링. 0이면 순수한 물리. 단위 질량당 값이므로 메시 밀도가 되돌아가는 속도를 바꾸지 않음 |
| 여유 | 세게 흔들렸을 때 정점과 고정 사이의 거리가 정지 경로보다 얼마나 더 늘어날 수 있는지 |

기본값: 천은 면적 0.3, 결 0.3, 머리카락은 면적 0.5, 결 0.7입니다. 소매, 바지, 레그웨어 프리셋은 면적 0.5, 넥웨어는 0.4를 사용합니다.

**프리셋** 드롭다운은 위 항목들을 이름 있는 재질의 값으로 채우며, 이후에도 계속 조정할 수 있습니다. 프로젝트에는 값만 저장되며, 드롭다운은 값이 프리셋과 일치하면 그 프리셋의 이름을, 그렇지 않으면 **사용자 지정**을 표시합니다.

| 종류 | 프리셋 | 특징 |
| --- | --- | --- |
| 천 | 면 (기본값) | 위 표의 기본값 |
| 천 | 실크 | 가볍고 부드러우며 잔주름이 짐. 오래 흔들리고 천천히 멈춤 |
| 천 | 시폰 | 가장 가볍고 부드러움. 실크보다 공기 감쇠로 더 빨리 멈춤 |
| 천 | 울 | 무겁고 부드러움. 늦게 흔들리기 시작하고 금방 멈춤 |
| 천 | 데님 | 무겁고 뻣뻣함. 넓은 주름이 형태를 유지함 |
| 천 | 가죽 | 가장 뻣뻣함. 통째로 흔들리고 거의 뭉치지 않으며 원래 그린 형태로 되돌아감 |
| 천 | 신축 소재 | 늘어났다가 되돌아감. 끈과 양말용 |

| 머리카락 | 굵은 머리카락 | 더 무거움. 통째로 흔들리고 형태를 유지함 |
| 머리카락 | 앞머리 | 아래로 늘어지지 않고 이마에 붙음. 되돌아가는 힘과 감쇠가 더 강하며, 끝이 살짝 늦게 따라오면서 머리와 함께 움직임. 앞머리 프리셋에서 사용 |

시뮬레이션을 시작하기 전에 원래 그린 형태가 정지 평형 상태가 되도록 보정하므로, 시뮬레이션을 켜도 정지한 모델이 처지지 않습니다.

솔버는 2D XPBD(프레임당 16 서브스텝)입니다. 리그가 어떤 부분을 늘이는 곳(예: 머리를 돌릴 때의 시차)에서는 리그의 형태와 싸우지 않고 정지 길이도 함께 늘어납니다. 리그가 어떤 부분을 줄이는 곳은 깊이 방향으로 도는 것으로 보고 부드러운 압축으로 흡수합니다.

## 베이크

**입력**은 바디를 흔드는 파라미터이며, 암묵적인 기본값 없이 나열된 그대로 사용됩니다. 새 바디(패널에서, `inputs` 없이 MCP에서, 또는 모델 프리셋에서 만든 것)는 기본 입력을 받습니다. 머리와 몸 각도(`ParamAngleX`, `ParamAngleZ`, `ParamBodyAngleX`, `ParamBodyAngleZ`, 모델에 있는 경우)와 끄덕임, 몸 상하, 기울기(`ParamAngleY`, `ParamBodyAngleY`, `ParamBodyLean`, 있는 경우)입니다. 천 종류에서 세로 입력은 `ParamBodyAngleY`뿐입니다. 옷은 몸에 걸려 있으므로 끄덕임으로는 움직이지 않습니다. 몸을 기울이면 옷은 대부분 다른 자세로 자리를 잡을 뿐인데, 이는 세로 진자로 표현할 수 없는 정적인 오프셋이어서 되돌아가는 힘이 거의 없는 진자로 피팅되고 거대한 출력 배율로 증폭됩니다. 의상 프리셋을 다시 적용하면 아직 예전의 범용 기본 입력을 쓰는 바디는 천 기본 입력으로 바뀝니다. 빈 목록은 입력이 없다는 뜻이며 베이크 시 오류가 보고됩니다. 입력을 기록하지 않은 이전 프로젝트의 바디(당시에는 기본값을 뜻함)는 위의 전체 기본 목록을 보여 주며 열리고, 모델에 없는 파라미터는 그 바디를 다음에 변경할 때 제거됩니다. 기본 입력과 이전의 "빈 목록"은 같은 것으로 취급하므로 이 때문에 기존 베이크가 오래됨 상태가 되지는 않습니다.

베이크는 먼저 리그에서 각 입력이 바디를 어떻게 움직이는지 읽습니다. 학습 범위 전체에서 어떤 정점도 1 px 이상 움직이지 않는 입력은 베이크에서 제외되고(패널에 **제외됨**으로 표시되며, **유지**를 체크하거나 MCP `force_inputs`로 강제로 포함할 수 있음), 바디를 옆보다 위아래로 더 많이 움직이는 입력은 세로 파라미터로 가며(아래 참고), 나머지는 옆 방향 모드로 갑니다. 그래서 기본 입력 중 그 부위와 관계없는 파라미터(예: 치마에 대한 머리 회전)는 더 이상 진자에 피팅되지 않고, 사용자가 그 파라미터를 움직여도 바디가 이유 없이 흔들리지 않습니다.

각 입력에는 학습 범위(파라미터 단위의 낮은 끝에서 높은 끝까지)를 지정할 수 있습니다. 베이크는 그 범위 안에서만 입력을 구동하며, 기본값은 파라미터의 전체 범위입니다. 범위는 항상 기본값을 포함하며, 파라미터 범위를 벗어나는 부분은 잘립니다. 모드 파라미터의 크기는 학습 중 가장 격한 움직임에 맞춰지므로(4단계 참고), 범위가 좁을수록 바디는 그 안에서 더 크게 흔들리고 범위를 넘으면 더 빨리 끝에 닿습니다. 예를 들어 `ParamBodyAngleX`가 보통 ±5 안에서만 움직인다면, 학습 범위를 ±5로 두면 평소 움직임이 모드 파라미터 전체를 사용합니다. 학습 범위를 바꾸면 베이크가 오래됨 상태가 되며, 입력을 제거하면 그 학습 범위와 유지 설정도 함께 제거됩니다.

**학습에 쓰는 모션**(**고급** 아래, MCP `training_clips`)은 설계된 자극 외에 모델의 자체 모션(사용자 모션이나 내장 Idle, Nod, Shake 등)도 베이크가 학습하게 하며, 각각 ×0.05–×1로 가중치를 줍니다. 얼굴 추적보다 몇 가지 고정된 모션으로 주로 구동되는 모델에 적합합니다. 각 모션은 그 모션이 가장 많이 움직이는 파라미터 그룹에만 반영됩니다. 이 모션을 편집한 뒤에는 다시 베이크하세요(모션 내용은 오래됨 검사 대상이 아닙니다).

**출력**은 베이크가 기록하는 모드 파라미터와 진자입니다. 이름은 기본적으로 바디를 따르며(파라미터는 "<이름>", "<이름> 2", "<이름> Y" 등, 진자는 바디와 같은 이름), 바꾼 이름은 바디에 저장되어 다시 빌드할 때 적용됩니다. 새로 베이크할 필요가 없고 ID도 바뀌지 않습니다. 각 모드 파라미터는 내보낼 ID, 범위, 게인을 따로 지정할 수도 있으며, 이 역시 새로 베이크할 필요가 없습니다. ID는 기본적으로 생성된 `ParamSim<id>_<k>`이며, 다른 ID로 바꾸면 그 ID용으로 만든 모션과 물리를 재사용할 수 있습니다. 단, 모델의 다른 파라미터나 이 바디의 입력과 겹칠 수는 없습니다. 범위는 ±1…±100(기본 ±30)이며, 키와 진자의 출력 배율이 함께 조정되므로 움직임은 그대로입니다. 게인은 ×0…×3(기본값은 과장 값)이며 0이면 움직이지 않습니다. 베이크 자체는 항상 생성된 ID와 ±30으로 저장되며, 이 설정들은 다시 빌드할 때 적용됩니다. 물리 패널에서 출처가 **시뮬레이션**인 진자의 이름을 바꾸면 여기에도 기록되며, 그 진자는 계속 베이크로 구동됩니다.

### 설정

| 항목 | 의미 |
| --- | --- |
| 모드 (1–3, 기본값 2) | 만들 파라미터 수. 각 파라미터는 피팅된 진자의 정점 하나로 구동됨. 첫 번째 모드는 전체적인 흔들림이고, 이후의 각 모드는 아래에 매단 한 마디 또는 별도의 진자로서, 위 모드들이 보여 줄 수 없는 것만 더함. 즉 바디가 늦게 따라오면서 휘고, 뭉치고, 압축되는 모습. 모드가 1개이면 형태가 흔들림 각도에 따라 통째로만 움직이고 천에 압축이 없으므로 기본값은 2. 긴 가닥과 리본은 3을 쓸 수 있음 |
| 상하 (자동 / 켬 / 끔) | 세로 입력을 `ParamSim<id>_Y`로 따로 베이크할지 여부(아래 참고). 자동은 세로 입력이 바디를 2 px 이상 움직일 때만 만들고, 켬은 항상 만들며, 끔은 세로 입력을 베이크에서 제외함. 세로 입력만 있으면 오류가 보고됨 |
| 키 수 (3 / 5 / 7 / 9) | 각 모드 파라미터와 정확한 포즈 파라미터의 키 개수로, 고르게 배치됨. 키가 많을수록 호를 더 가깝게 따라가며, 파라미터가 아닌 키폼이 늘어남 |
| 과장 (×1–×2, 기본값 ×1.3) | 모드가 시뮬레이션보다 얼마나 크게 흔들리는지. 키폼을 다시 기록할 때 적용되므로 새로 베이크하지 않아도 변경이 즉시 반영되며, 파라미터를 끝까지 밀어붙이지 않음. 애니메이션 스타일은 보통 실제보다 약간 크게 하는 편이 보기 좋음 |
| 정확한 포즈 | 자기 축에 정확한 보정으로 베이크되는 파라미터(최대 4개). 기본값은 없음 |
| 모드 기록 방식 | 자동(기본값), 블렌드 셰이프, 키폼 축. 둘 다 재생 결과는 같음. 키폼 축은 모든 Cubism 버전이 읽을 수 있지만 모드마다 메시의 키폼 수가 키 수만큼 곱해짐. 블렌드 셰이프(Cubism 4.2+)는 기존 키폼 위에 키폼을 더함. 자동은 어떤 대상 메시가 키폼 64개를 넘을 때만 블렌드 셰이프를 사용하며, 대상 버전에 블렌드 셰이프가 없으면 항상 키폼 축으로 기록함 |

블렌드 셰이프는 파라미터가 아니라 키폼을 줄여 줍니다. 예를 들어 키폼이 9개인 메시에 키가 5개인 모드 2개를 쓰면, 키폼 축으로는 9 × 5 × 5 = 225개의 키폼이 되고, 블렌드 셰이프로는 키폼 9개와 블렌드 셰이프 8개가 됩니다.

### 단계

1. **정확한 포즈**: 각 정확한 포즈 파라미터의 모든 키에서 리그를 포즈로 잡고, 바디가 자리를 잡게 한 다음, 리그와의 차이를 그 파라미터 축의 보정 키폼으로 기록합니다. 정확한 포즈 파라미터가 설정되지 않았으면 건너뜁니다.
2. **각 입력을 단독으로 구동**: 베이크에 포함된 모든 입력을 다른 입력은 기본값에 둔 채 하나씩 단독으로 구동합니다. 한 구간은 0.15초 안에 입력을 학습 범위의 위쪽 끝까지 돌리고, 바디가 자리를 잡을 때까지(최대 1.6초) 유지한 뒤 기본값으로 돌아가고, 아래쪽 끝까지 돌렸다가 되돌아옵니다. 다른 구간은 0.25 Hz에서 3 Hz까지의 로그 스윕이며, 3 Hz 근처에서 진폭이 줄어듭니다. 각 구간은 정지 상태에서 시작하며 바디의 복사본에서 병렬로 시뮬레이션됩니다. 옆 방향 그룹과 세로 그룹은 이 시뮬레이션을 공유합니다. 매 프레임 바디와 리그의 차이(정확한 포즈 보정 포함)를 기록하고 각 메시의 키폼 좌표로 변환합니다. 각 그룹에는 입력을 함께 끌고, 흔들고, 한가롭게 흔드는 모션도 하나씩 있으며, 이는 검사에만 사용됩니다. 구간마다 움직임의 양이 균형을 이루도록 가중치를 주므로(최대 100배), 바디를 조금만 움직이는 입력도 큰 흔들림에 묻히지 않고 올바르게 피팅됩니다.
   이전에는 모든 입력이 하나의 모션에서 무작위로 함께 움직였기 때문에 어떤 입력이 바디를 움직였는지 피팅이 구분할 수 없었습니다. `tml` 뒷머리에서 `ParamBodyAngleX`는 머리카락 뿌리를 약 70 px 움직이는데도 진자는 이 입력에 1%의 가중치만 주었고, 마우스 드래그를 따라갈 때 내보낸 흔들림은 시뮬레이션의 약 5분의 1에 불과했습니다. 하나씩 구동하면 각 입력은 바디가 실제로 움직이는 방식대로 움직이게 하는 가중치를 받습니다.
3. **진자**: 모드 수만큼의 마디를 가진 Cubism 진자 `PhysicsSim_<id>` 하나를 모드별로 피팅합니다. 먼저 첫 번째 모드의 마디만, 이어서 이후의 각 모드를 차례로 피팅하는데, 각 모드는 위 모드들이 읽어 낼 수 없는 나머지 움직임만, 그것도 (전체 움직임이 아니라) 그 나머지 움직임 자체의 주방향으로 피팅합니다. 마지막으로 모든 마디와 가중치를 한 차례 함께 다듬습니다. 읽어 낼 때는 항상 모드를 순서대로 하나씩 풉니다. 이후 모드의 후보는 두 종류입니다. 하나는 진자 아래에 마디를 하나 더 매다는 것(진자의 정점은 위쪽 정점의 영향만 받으므로 마디를 더해도 위 모드는 바뀌지 않음. 시작점 4개에서 탐색)이고, 다른 하나는 자체 입력, 길이, 반응 속도를 가진 별도의 단일 마디 진자 `PhysicsSim_<id>_<k>`입니다(압축은 흔들림보다 가속에 더 빠르고 강하게 반응할 수 있음). 검사용 모션에서 더 나은 쪽을 사용하며, 파라미터 수는 같습니다. 모두 한꺼번에 피팅하면 이웃한 정점들이 거의 같이 흔들리고, 두 모드의 형태가 커지면서 서로 상쇄되어 학습 범위 밖의 움직임이 왜곡됩니다. 점수는 오차만이 아니라 전체적인 효과를 봅니다. 시뮬레이션을 얼마나 가깝게 따라가는지, 입력이 멈춘 뒤 얼마나 튀어 나갔다가 되돌아 흔들리는지(따로 한 번 더 셈), 그리고 어떤 움직임 구간이 시뮬레이션보다 더 떨리는지입니다. 각 입력의 종류(X 이동 또는 각도)와 초기 가중치는 작은 움직임을 겹친 데이터에 최소 제곱법을 적용해 추정합니다(입력이 6개 이하이면 종류의 모든 조합을 비교해 잔차가 가장 작은 것을 고름). 그다음 Nelder–Mead로 마디의 길이, 반응 속도, 흔들림, 수렴 속도와 입력의 가중치를 함께 탐색합니다. 모든 후보는 내보내기와 같은 계산으로 모든 학습 모션을 실제 진폭으로 한 번씩 재생해 점수를 매깁니다. 후보 중 검사용 모션에서 점수가 가장 좋은 것이 선택됩니다.
4. **모드 파라미터**: 진자의 k번째 정점 각도를 -30…30 파라미터 `ParamSim<id>_<k>`에 기록합니다. 출력 배율은 모든 학습 모션과 검사용 모션에서 진자의 최대 각도에 10% 여유를 더해 정하므로, 파라미터가 ±30에 닿지 않습니다. 파라미터가 끝에 머물러 있는 동안 머리카락이 멈추면 끊기는 것처럼 보이기 때문입니다. 범위를 ±1이 아니라 ±30으로 두는 이유는 키폼 축이 키에서 0.001 이내의 값을 키에 스냅하기 때문입니다(Cubism 런타임도 마찬가지). ±1 범위에서는 큰 바디가 정지 위치를 지나 흔들릴 때마다 이 스냅에 걸려 덜컥거립니다.
5. **키폼**: 모드별로 최소 제곱법으로 풉니다. 각 모드의 키폼은 앞 모드들이 남긴 형태에 피팅되며, 각 프레임의 형태는 진자가 재생될 때 각 파라미터 값에서 보간한 키폼의 합입니다. 키폼은 이웃한 키에서 급하게 꺾이지 않는 매끄러운 곡선이 되도록, 그리고 정지 키를 곧게 지나가도록 제약됩니다. 그렇지 않으면 파라미터가 키를 지날 때 속도가 튀어 또 다른 덜컥거림이 생깁니다. 그다음 검사용 모션에서 두 가지 조정을 시도하고, 떨림이 늘지 않으면서 더 잘 따라갈 때만 유지합니다. 하나는 다른 모드를 뺀 상태에서 각 모드의 키폼을 다시 푸는 것(상쇄되지 않으면서 함께 푸는 것에 더 가까움)이고, 다른 하나는 이후 모드에 ×0.25, ×0.5, ×0.75의 게인을 시도해 작은 움직임에 노이즈를 더하지 않게 하는 것입니다. 거의 움직이지 않는 파라미터는 만들지 않습니다.

**세로 움직임을 따로 베이크**: Cubism 진자는 중력 방향으로 매달려 각도만 출력합니다. 뿌리가 똑바로 위아래로 움직이면 각도가 바뀌지 않으므로, 입력을 어떻게 골라도 세로 움직임을 표현할 수 없습니다. 이 방식은 아티스트가 만드는 `裙y`, `长发y` 물리 그룹과 같습니다. 바디를 옆보다 위아래로 더 많이 움직이는 입력(보통 끄덕임, 몸 상하, 기울기)을 나머지와 분리해 3–5단계를 따로 거칩니다. 단일 마디 진자 `PhysicsSim_<id>_y`를 피팅해 모드 파라미터 하나 `ParamSim<id>_Y`("<시뮬레이션 이름> Y")를 구동하며, 그 키폼은 바디의 세로 방향 지연과 튀어 오름입니다. 두 그룹의 키폼은 메시에서 더해집니다. 세로 움직임이 2 px 미만이면 이 파라미터는 만들어지지 않습니다(상하가 켬이면 항상 만들어지고, 끔이면 만들어지지 않으며 세로 입력은 베이크에서 제외됨). 세로 입력만 있으면 모든 모드가 이 방식으로 피팅됩니다. `tml` 치마의 경우 웅크렸다 일어서는 동작이 시뮬레이션에서 최대 47 px의 잔차를 남기는데, 이전 베이크는 정적인 기울기만 유지했습니다. 따로 베이크하면 검사용 모션의 R²가 0.37에서 0.61로 올라갑니다.

R²만으로 자연스러워 보이는지를 판단할 수는 없습니다. 흔들림이 약간 작거나 위상이 조금 어긋나면 최소 제곱법은 오차를 낮추기 위해 키폼을 전체적으로 줄이고, 그러면 내보낸 움직임이 생기 없어 보입니다. 그래서 베이크 후 패널에는 먼저 각 그룹의 검사용 모션에 대한 시각적 검사가 표시됩니다.

| 지표 | 의미 | 경고 |
| --- | --- | --- |
| 흔들림 | 시뮬레이션의 주방향을 따른 끝부분(가장 많이 움직이는 정점의 10분의 1)의 흔들림. 내보내기 대 시뮬레이션 비율 | ×0.75–×1.3 밖 |
| 지연 | 내보내기가 시뮬레이션보다 몇 밀리초 늦는지(상호 상관 최대점) | 80 ms 초과 |
| 안정화 | 입력이 멈춘 뒤 정지 상태로 돌아오는 시간. 내보내기 대 시뮬레이션 비율 | ×0.6–×1.6 밖 |
| 떨림 | 3차 차분 에너지 비율의 제곱근 | ×1.5 초과 |

방향이 반대여도 경고합니다. MCP는 방향 일치도, 되돌아 흔들리는 횟수의 차이, 끝에 닿거나 멈춘 프레임의 비율, 가닥이 얼마나 짧아지는지, 정지 시 오프셋도 반환합니다. 다음 줄은 R²와 프레임 95%에서 시뮬레이션과의 최대 편차입니다. 프레임이 끝에 닿거나 저크가 시뮬레이션의 1.5배를 넘으면 별도의 줄로 경고합니다. 각 모드 파라미터의 흔들림은 **고급** 아래에 있습니다. MCP `simulation_bake`는 모든 지표와 각 입력을 어떻게 읽었는지(`inputs`)를 반환합니다.

베이크된 진자 그룹은 일반적인 생성 그룹처럼 물리 패널에서 보고, 변경하고, 끌 수 있습니다. 물리 패널에서 바꾼 내용은 생성된 진자에 대한 재정의입니다. 다시 베이크하거나 출력의 ID나 범위를 바꾸면, 재정의는 3방향 병합으로 새 진자에 이어집니다. 직접 바꾼 필드만 유지되고(출력 배율은 원래 값에 대한 비율로 유지), 나머지는 새로 피팅된 값을 따르며, 출력은 파라미터 이름 변경을 따라가고, 결국 새 진자와 같아진 재정의는 제거됩니다. 베이크를 지우거나, 바디를 삭제하거나, 새 베이크가 어떤 진자를 더 이상 만들지 않으면, 그 진자의 재정의, 비활성 상태, 순서도 함께 제거됩니다.

### 결과와 소요 시간

모델 프리셋으로 만든 바디(모드 2, 키 5, 과장 ×1)를 대상으로, 베이크 중에 보지 않은 13–15개의 모션에서 참조 시뮬레이션과 내보낸 모델(Cubism 진자 + 키폼)을 프레임 단위로 비교했습니다. 모션은 얼굴 추적과 비슷한 마우스 추종, 머리와 몸을 옆으로 기울이기, 내장 Idle / Nod / Shake, 각 입력의 스텝, 머리 회전, 드래그, 흔들기입니다. 시뮬레이션에서 끝부분이 10 px 이상 움직이는 모션만 셌습니다(괄호 안은 구간 수). 나머지 모션은 제외된 입력으로만 구동되어 시뮬레이션에서 바디가 움직이기 시작할 때 약간 흔들릴 뿐이므로, 이를 세면 모든 지표가 0 쪽으로 끌려갑니다. "올바른 방향"은 흔들림 방향이 일치하는(코사인 ≥ 0.9) 모션 수입니다. 흔들림은 각 모션의 내보내기 대 시뮬레이션 비율이 1에서 얼마나 떨어져 있는지의 중앙값을 다시 배율로 환산한 것입니다. R²는 모션 평균(-1 미만은 -1로 계산)입니다. 정지 오프셋은 입력을 1초 이상 유지하는 동안 내보내기와 시뮬레이션 사이의 거리(95번째 백분위수)입니다. 앞의 값은 모션 라이브러리로 학습한 이전 결과이고, 뒤의 값은 각 입력을 단독으로 구동한 결과입니다.

- 머리카락이 가장 크게 개선되었으며, 특히 실제 사용에 가까운 모션에서 그렇습니다. tml 뒷머리가 마우스를 따라갈 때 흔들림은 시뮬레이션의 0.19배에서 1.04배로, R²는 -0.15에서 0.92로 올랐습니다. Shake 모션의 R²는 0.07에서 0.83으로, `ParamBodyAngleX` 스텝은 전혀 움직이지 않던 것에서 R² 0.86으로 올랐습니다.
- 각 입력을 단독으로 구동하면 천을 2–4배 빨리 베이크하지만, R²는 이전보다 낮습니다(치마와 상의는 약 0.3, 이전에는 0.35–0.5). 세로 파라미터는 여전히 약합니다(`ParamBodyAngleY` 스텝 R² 0.17–0.30, 흔들림 0.2–0.8배). 시뮬레이션에서는 몸이 위로 움직이든 아래로 움직이든 밑단이 같은 쪽으로 튀어 나가고 한쪽으로만 되돌아 흔들리는데, 진자의 출력은 입력의 부호에 대해 대칭이므로 피팅은 절충할 수밖에 없습니다.
- 몸을 옆으로 기울일 때(`ParamBodyAngleZ`, 약 1.3초) 뒷머리의 흔들림 주기는 머리 회전(약 0.9초)과 다르고 형태도 다릅니다. 모드 2개로는 이 움직임만의 모드가 생기지 않으며(ds 뒷머리의 내보내기는 거의 움직이지 않고, tml 뒷머리는 0.59배로 흔들리며 R²는 0.11), 모드 3개도 도움이 되지 않습니다.
- 머리 회전처럼 천을 거의 움직이지 않는 입력(시뮬레이션에서 약 2 px)은 제외되므로, 사용자가 머리를 돌려도 치마가 이유 없이 흔들리지 않습니다.

시간은 32스레드 데스크톱에서 측정했습니다. 시뮬레이션과 피팅은 코어 간에 병렬로 실행되므로 코어가 적으면 더 느립니다. 표는 개발 도구 `SimBakeSuite`로 만들었으며, 이 도구는 모든 시각 지표와 모션별 끝부분 궤적 그래프를 출력합니다. 사용법은 [개발 도구](DEVELOPMENT.md#개발-도구)를 참고하세요.

### 오래됨

베이크는 기준이 된 설정, 대상 메시, 가중치 그룹, 관련 글루, 솔버 버전을 기록합니다(솔버가 바뀐 뒤에는 이전 프로젝트의 베이크가 오래됨으로 표시됨). 이 중 하나라도 바뀌면 패널에 베이크가 오래되었다고 표시됩니다. 도구 모음의 자동 베이크가 켜져 있으면 패널의 변경 사항이 커밋된 뒤 백그라운드에서 다시 베이크되며(별도의 실행 취소 단계), 탐색은 마지막 진자에서 시작하므로 처음부터 베이크하는 것보다 빠릅니다. 모델 프리셋을 적용할 때도 마찬가지로 먼저 커밋한 다음, 만든 바디를 백그라운드에서 베이크합니다. MCP `simulation_put`은 바디 자체의 `auto_bake`(기본으로 켜짐)를 따릅니다. 다른 곳(메시, 가중치)에서 한 변경은 여전히 오래됨으로 표시됩니다. 오래된 베이크도 내보내집니다. 업데이트하려면 **다시 베이크**를 클릭하고, **베이크 지우기**는 그 파라미터, 키폼, 진자를 제거합니다. 자동 베이크가 실패하거나 취소되면 이전 베이크가 유지되고 이유가 표시됩니다. 대상 메시가 다시 만들어지면(정점 수가 바뀌면) 그 메시의 베이크 결과는 건너뛰며 패널에 안내가 표시됩니다.

### 내보내기와 참조 시뮬레이션

패널 상단과 캔버스 **시뮬레이션** 모드의 도구 모음은 미리보기에 무엇을 보여 줄지 전환합니다.

- **내보내기 결과**: 미리보기는 베이크 결과, 즉 피팅된 Cubism 진자로 구동되는 파라미터와 키폼을 재생하며, 내보낸 모델의 움직임과 일치합니다. 베이크되지 않은 바디는 여기서 움직이지 않으며, 캔버스 왼쪽 아래에 "베이크되지 않은 시뮬레이션"이 표시됩니다.
- **참조 시뮬레이션**: 캔버스는 편집기 자체의 물리 시뮬레이션을 보여 줍니다. 비교용일 뿐이며 내보내지지 않습니다. 캔버스 왼쪽 아래에 경고 색으로 "참조 시뮬레이션 · 내보내지 않음"이 표시되며, 그동안 바디 자체의 `ParamSim…` 파라미터는 움직이지 않으므로 두 번 적용되지 않습니다.

바디 편집기의 **비교** 섹션은 둘을 나란히 놓습니다.

- **표시**(참조 시뮬레이션이 켜져 있을 때 사용 가능): 첫 번째 미리보기 캔버스가 참조 시뮬레이션을 어떻게 보여 줄지 정합니다. **참조**(위와 같이 내보내기 대신 표시), **내보내기**(내보내기만 표시), **겹쳐 보기**(내보내기 위에 참조 시뮬레이션을 반투명하게 그리며, 시뮬레이션되는 레이어만 그림) 중에서 고릅니다. 캔버스마다 자기 설정을 기억하며 작업 공간과 함께 저장됩니다.
- **나란히 보기**: 참조 시뮬레이션을 켜고 미리보기 캔버스가 두 개 있도록 합니다. 첫 번째는 내보내기를, 두 번째는 참조를 보여 주며, 둘 다 같은 포즈를 따라 함께 재생됩니다.
- **재생**: 드롭다운에서 모션(내장 Idle, Nod, Shake, 뼈가 있으면 스켈레톤 모션, 사용자 모션)을 고르면, 참조 시뮬레이션과 내보낸 진자가 모두 정지 상태로 돌아간 뒤 재생하므로 구간별로 비교할 수 있습니다.
- **검사**: 고른 모션으로 참조 시뮬레이션과 내보낸 모델을 백그라운드에서 따로 구동하고(게인 ×1), 베이크 섹션과 같은 시각적 검사 결과를 보여 줍니다. MCP에 대응하는 것은 `simulation_compare`입니다.

## 모델 프리셋

**모델 프리셋** 패널(이전의 Model Settings)의 **물리 및 시뮬레이션** 그룹은 흔한 부위를 한 번에 시뮬레이션으로 바꾸고 베이크합니다. 결과는 일반적인 가중치 그룹과 바디이므로 이후에도 **시뮬레이션** 패널에서 조정할 수 있습니다. 패널의 세 그룹 **리깅 및 표정**, **모션**, **물리 및 시뮬레이션**은 파라미터 패널의 폴더와 같은 스타일의 접을 수 있는 행이며, 오른쪽에 요약이 표시됩니다. **모션** 그룹은 모델에 **기본 모션**과 **스켈레톤 모션** 두 그룹을 넣을지만 정하며, 개별 모션은 애니메이션 패널에서 켜고 조정합니다. **물리 및 시뮬레이션**에는 항목마다 행이 하나씩 있습니다. 앞머리와 뒷머리에는 각각 **시뮬레이션 / 기존 흔들림 / 끔**을 전환하는 드롭다운이 있고, 의상과 눈동자 젤리는 확인란으로, 체크하면 프리셋이 적용되고 해제하면 제거됩니다. 의상의 메시별 느슨함 목록은 의상 행 아래에 나타납니다. 각 컨트롤 옆의 회색 글씨는 현재 내용(시뮬레이션되는 의상 부위, 원화에 해당 부위가 없음 등. 마우스를 올리면 전체 텍스트 표시)을 설명하며, 베이크되지 않았거나 시뮬레이션 바디가 삭제된 경우 경고 색으로 표시됩니다. 상단 도구 모음의 **선택 항목만(n)** 옵션은 체크가 선택한 레이어에만 적용되게 하며(체크 해제는 항상 전체를 제거), 오른쪽에 **고정 가중치 자동 설정**이 있습니다. 베이크 진행 상황과 취소는 아래쪽 상태 표시줄에 있고, 실패 이유는 그룹 아래쪽에 나타납니다. 체크 하나가 실행 취소 단계 하나이며, MCP에 대응하는 것은 `model_apply_preset` 도구입니다.

같은 패널의 **부위와 모듈** 그룹은 생성된 리그의 모듈을 영역별(머리와 얼굴, 눈, 눈썹, 입과 아래 얼굴, 머리카락, 몸, 의상과 장신구, 표정, 모션)로 나열합니다. 카드 하나가 좌우 양쪽을 다룹니다. 각 모듈에는 스위치와 함께, 현재 원화에 대해 그 모듈이 더하는 것(파라미터, 키폼, 물리 그룹. 꺼져 있을 때는 추정치로 "≈" 표시)을 회색으로 보여 주는 행이 있으며, 켜져 있으면 조정 가능한 값 몇 가지도 표시됩니다. 원화에 해당하는 모듈만 나열됩니다. 위쪽의 프리셋(전체 / 표준 / 최소)은 중요도에 따라 모듈을 켜고 끄며, 파라미터 예산은 모듈이 더하는 파라미터 수가 예산 이하가 될 때까지 가장 덜 중요하고 비용이 큰 모듈부터 끕니다. 옆의 버튼은 초기화합니다. 새 프로젝트는 모든 모듈이 켜져 있습니다. 모듈 도입 이전에 저장한 프로젝트는 예전과 같이 생성되며, 그룹에서 업그레이드를 제안합니다. 모든 변경은 실행 취소 단계 하나입니다. MCP에서는 `module_catalog`가 모듈을 나열하고 `settings_update`의 `changes.rig`로 변경합니다([리그 프리셋 아키텍처](../spec/RIG_PRESETS.md) 참고).

**시작** 페이지(작업 공간 탭 표시줄 맨 왼쪽, 또는 **파일 → 시작 페이지**)의 **PSD에서 생성**은 같은 프리셋을 PSD를 가져오기 **전에** 모아 둡니다. 속성 패널 맨 위의 **최소 / 기본 / 전체**는 각각 리그만(모션, 물리, 시뮬레이션, 입 윤곽선 없음), 두 모션 그룹 + 기존 머리카락 흔들림 + 의상 시뮬레이션 + 눈동자 젤리, 그리고 기본에 시뮬레이션되는 앞머리와 뒷머리, 이목구비 오프셋을 더한 것을 뜻합니다. 각 항목은 아래에서 조정할 수 있으며, 선택은 기억됩니다. 그 뒤 PSD를 어떤 방식으로 가져오든(시작 페이지, **파일** 메뉴, 최근 파일, 끌어다 놓기) 생성 과정에서 바뀐 프리셋을 하나의 실행 취소 단계로 기록하고, 이어서 머리카락과 의상 시뮬레이션을 차례로 생성한 다음(각각 한 단계), 편집 작업 공간으로 전환합니다. 의상은 기본으로 켜져 있으며, 원화에서 의상이 인식되면 의상 시뮬레이션이 생성되고 베이크됩니다. PSD로 생성한 모델이 이미 열려 있으면 **생성** 버튼 메뉴의 **현재 모델에 적용**으로 같은 프리셋을 그 모델에 적용합니다. 메시별로 레이어 나누기는 더 이상 가져오기와 함께 뜨지 않습니다. 대신 **모델 → 메시별로 레이어 나누기…** 메뉴를 사용하세요. 모든 레이어를 검사하고 한꺼번에 확인합니다.

| 프리셋 | 하는 일 |
| --- | --- |
| 앞머리 / 뒷머리 | 그 머리카락의 모든 메시가 머리카락 바디 하나(`preset_front_hair` / `preset_back_hair`)가 됩니다. 각 가닥(메시에서 이어진 각 조각)은 자기 위쪽에서 고정되고 끝으로 갈수록 자유로워지며, 고정 그룹만 기록됩니다. 앞머리는 **앞머리** 재질을, 뒷머리는 기본 머리카락 재질을 사용합니다. 동시에 그 머리카락의 기존 흔들림(`ParamHairFront/Back` 파라미터, `DeformHair*Physics` 디포머, 진자)이 제거되고, 메시(나뉜 부분 포함)는 원화가 제자리에 있는 채로 추종 디포머 아래로 옮겨집니다. **기존 흔들림**이나 **끔**을 고르면 바디를 삭제하고 기존 흔들림을 복원합니다(**끔**은 흔들림을 비활성화하기도 함) |
| 의상 | 상의, 하의, 넥웨어, 손(소매), 레그웨어 레이어를 읽고, 원화가 느슨해 보이는 곳만 시뮬레이션합니다. 몸에 붙는 부분은 리그를 따릅니다. 하의는 먼저 치마인지 바지인지 판정합니다. 이름(裙, skirt, スカート / 裤, pants, ズボン 등)을 먼저 보고, 없으면 알파 실루엣으로 판정하는데, 가랑이에서 밑단까지 가운데 틈이 이어지면 바지입니다. 몸통과 하의는 실루엣을 몸과 행 단위로 비교합니다. 몸 실루엣은 어깨선(하의는 허리선)에서 시작해 아래로 갈수록 천천히만 넓어질 수 있으며, 그 밖으로 튀어나온 것은 느슨한 것으로 봅니다(프릴, 리본, 퍼지는 밑단, 열린 코트 앞자락). 허리선(하의의 허리선, 또는 상의 아래까지 올라온 레그웨어의 위쪽) 아래의 상의, 엉덩이보다 넓은 곳의 엉덩이 아래 치마, 매듭 아래의 넥웨어는 자유롭게 늘어진 것으로 보며, 일자 바지와 펜슬 스커트는 몸에 붙은 것으로 남습니다. 소매와 레그웨어는 팔다리와 함께 굽으므로 대신 형태학적 열림 연산을 사용합니다. 팔다리 너비의 절반인 원판보다 얇은 부분(소맷부리 / 양말의 프릴, 리본)만 느슨한 것으로 보며, 퍼프 소매와 접어 올린 소맷부리는 팔다리를 따릅니다. 피부색 영역은 항상 몸에 붙은 것으로 남으므로 벌린 손가락도 시뮬레이션되지 않습니다. 느슨함은 레이어 안에서 몸에 붙은 영역과의 거리에 따라 커지며, 이로부터 고정(1 − 느슨함), 질량, 바람(느슨할수록 커지며 팔다리에는 바람이 적음)을 만듭니다. 느슨한 정점이 충분하지 않은 메시는 바디를 받지 않으며, 속해 있던 의상 프리셋 바디에서 빠집니다. 바디는 부위별로 `preset_top`, `preset_skirt`, `preset_trousers`, `preset_neckwear`, `preset_sleeves`, `preset_legwear`로 나뉘며, 바지, 소매, 레그웨어는 더 뻣뻣합니다. 의상 행 아래에는 각 메시가 부위와 느슨함 막대와 함께 나열되고, 몸에 붙은 것은 한 행으로 합쳐집니다. 하의에 마우스를 올리면 어떻게 판정되었는지 볼 수 있습니다. 체크를 해제하면 모든 의상 프리셋 바디가 삭제됩니다 |
| 눈동자 젤리 | 눈의 젤리 진자를 켜고 끕니다 |
| **고정 가중치 자동 설정** (도구 모음) | 선택한 레이어 또는 시뮬레이션되는 모든 메시에 대해 위의 가중치 그룹을 부위 종류별로 다시 계산하고, 그 그룹을 사용하는 바디를 다시 베이크합니다. 바디는 만들지 않습니다 |

프리셋이 기록하는 그룹의 이름은 `preset_pin`, `preset_mass`, `preset_wind`입니다. 바디가 이미 `groups`에서 자체 그룹을 지정하고 있으면 그 그룹을 제자리에서 갱신합니다. 같은 프리셋을 다시 적용하면 바디를 새로 추가하지 않고 기존 바디를 업데이트합니다. 사용자가 만든 바디에 이미 들어 있는 메시는 거부됩니다. 바람 그룹은 현재 MCP `simulation_simulate`에 바람을 지정할 때만 효과가 있습니다(위 참고).

## MCP

시뮬레이션은 작업별로 여러 도구로 나뉩니다. 파라미터는 `{"request": {...}}`에 넣으며, 모든 도구는 `id`로 바디를 고르고 `project_id`, `state`, `request_id`를 함께 보냅니다. 도구는 백그라운드 작업 핸들을 반환하며, `job_wait` / `job_get`으로 결과를 가져옵니다.

- `simulation_put`: `id`로 바디를 만들거나 일부를 변경합니다. 필드는 `targets`, `material`, `material_preset`(위의 프리셋 이름: `cotton`, `silk`, `chiffon`, `wool`, `denim`, `leather`, `elastic`, `hair`, `fine_hair`, `thick_hair`, `bangs`. 함께 지정한 `material` 필드가 그 값을 덮어씀), `groups`, `glue_roles`, `inputs`, `modes`, `keys`, `exaggeration`, `static_inputs`, `blend_shapes`(`true` / `false` / 자동은 `null`), `auto_bake`, `output_names`(파라미터 또는 진자 ID별 이름, 통째로 교체), `input_ranges`(입력 파라미터별 `[min, max]` 학습 범위, 통째로 교체), `vertical`(`true` / `false` / 자동은 `null`), `outputs`(생성된 모드 파라미터 ID별 `{id, range, gain}`, 통째로 교체, 새로 베이크할 필요 없음), `force_inputs`(바디를 거의 움직이지 않아도 유지하는 입력), `training_clips`(학습할 모션, `{motion: 0.05–1}`, 통째로 교체)입니다. `inputs` 없이 만든 새 바디는 기본 입력을 받으며, 빈 배열은 입력이 없다는 뜻입니다. `auto_bake`가 켜져 있으면(기본값) 같은 단계에서 다시 베이크하고 `bake` 요약이나 `bake_error`를 반환합니다.
- `simulation_simulate`: 읽기 전용 시험 실행입니다(패널에 대응하는 버튼 없음). 각 입력을 `hold`초 동안 유지했다가 놓고 `release`초 동안 관찰하며, `wind`는 선택 사항입니다. 최대값, 정지 시 드리프트, 늘어남, 설정 힌트를 반환합니다.
- `simulation_bake`: 베이크하고(몇 초) 각 모드 파라미터와 그 흔들림, 키 수, 진자 ID와 마디 수, 별도 진자의 ID(`own_pendulums`, 있는 경우), 각 입력을 어떻게 읽었는지(`inputs`: 바디를 얼마나 움직이는지, 이동과 회전만 하는지, 속한 그룹 또는 제외 여부), 각 그룹의 검사용 모션에 대한 시각적 검사(`visual`), 베이크 방식(`method`), 그리고 검사용 모션에서의 `fit_r2`, `error_p95_px`, `parameter_peak`(모드 파라미터가 사용하는 범위의 최대 비율), `clipped_frames`(끝에 닿은 프레임의 비율), `jerk_ratio`(시뮬레이션 대비 저크)를 반환합니다.
- `simulation_compare`: 읽기 전용 백그라운드 작업으로, `motions`의 모션(사용자 모션 ID 또는 내장 이름, 최대 8개)으로 참조 시뮬레이션과 내보낸 모델을 따로 구동하고 모션별 시각적 검사를 반환합니다.
- `simulation_clear_bake`: 베이크를 지웁니다.
- `simulation_delete`: 바디를 삭제합니다.

참조 시뮬레이션 미리보기는 문서와 히스토리에 들어가지 않는 시청 세션입니다. `simulation_preview`는 `mode=start`와 `simulation_id`로 시작하고(`restart` / `stop`은 `session_id`를 받음), `simulation_preview_step`은 `dt`초(최대 0.1) 단계를 1–240번 진행하며, `simulation_preview_get`은 현재 프레임을 읽고 `simulation_preview_render`는 렌더링합니다.

`vertex_group_update`는 규칙(`fill`, `outline`, `gradient`, `glue`, `region`)으로 가중치 그룹을 만들고, `delete=true`는 그룹을 삭제하며, 정점별 배열은 전달하지 않습니다. `vertex_group_paint`는 캔버스와 같은 브러시, 그라데이션, 반전으로 가중치를 바꿉니다. `workspace_inspect`에 `scope=simulations`를 주면 바디, 글루 키, 베이크 요약(`bake_stale` 포함)을, `scope=vertex_groups`를 주면 가중치 그룹을 나열합니다.

## 현재 범위

- 구현됨: 천과 머리카락(XPBD 솔버, 면적 기반 질량, 삼각형 면적과 뒤집힘 방지, 회전 기반 굽힘, 자동 결과 이방성, 고정, 글루 역할, 장거리 제약), 정점 그룹, 참조 시뮬레이션 미리보기, 파라미터 + 키폼(블렌드 셰이프 또는 키폼 축, 자동 선택) + 진자로의 베이크와 내보내기, 자동 베이크, 과장. 모델 프리셋(기존 흔들림을 대체하는 머리카락 시뮬레이션, 느슨함에 따른 상의 / 치마 / 바지 / 넥웨어 / 소매 / 레그웨어 시뮬레이션, 고정 가중치 자동 설정).
- 테스트됨: 위 표의 tml 뒷머리 비교 데이터. tml에서의 모델 프리셋 베이크(검사용 모션 R² / 95% 오차, 이전 솔버에서 측정했으며 새 재질 모델에서 다시 측정 예정): 뒷머리 0.69 / 229 px로, 위 10%를 직접 고정한 것과 같음. 앞머리 0.25 / 185 px로, 고정 범위를 어떻게 잡아도 0.2–0.3. 앞머리의 문제는 고정 범위가 아니라 재질입니다. 이마를 가로지르는 앞머리는 뒷머리처럼 가닥 길이 방향으로 중력을 받지 않으며, 기본 머리카락 재질의 약한 복원력 때문에 약 0.75 Hz의 부드러운 스프링이 되어, 머리를 흔들 때(1.2 Hz, 뼈대는 33 px 움직임) 뼈대에서 74 px, 끄덕일 때 47 px 벗어납니다. **앞머리** 재질(새 재질 모델, tml / ds)에서는 머리를 흔들 때 41 / 30 px, 끄덕일 때 12 / 10 px, 머리 회전이 멈춘 뒤 남는 것이 10 / 6 px이며, 베이크 R²는 0.18 → 0.27 / 0.21 → 0.49, 95% 오차는 216 → 85 / 112 → 57 px입니다. 치마 데이터는 이후 제거된 충돌 기능으로 측정했으므로 다시 테스트해야 합니다. 머리카락에 질량 / 바람 그룹을 더하면 뒷머리의 R²가 0.69에서 0.56으로 떨어지므로, 머리카락 프리셋은 이 두 그룹을 기록하지 않습니다.
- 장애물: 바디는 장애물(`obstacles`)을 가질 수 있습니다. 다른 메시를 따라가는 원이나 캡슐로, 입자를 바깥에 머물게 합니다. 참조 시뮬레이션과 베이크에 참여하며, 실시간 시뮬레이션을 재생하는 런타임 대상(p2lrt, 웹)으로 내보내집니다. 지금은 MCP `simulation_put`으로만 작성할 수 있으며, 캔버스에서의 편집은 아직 없습니다. 이전의 메시 충돌체(여백 기반)는 테스트에서 신뢰할 수 없는 것으로 드러나 제거되었습니다. 이전 프로젝트에 있는 이런 충돌체와 충돌 가중치 그룹은 불러올 때 무시됩니다.
- 아직 구현되지 않음: 바람과 그 밖의 힘 필드 내보내기, 강체와 연체, 일반 키로 베이크(생성기 제거).
- 느슨함 히트맵 육안 확인(tml, ds, 2등신 세트 하나): tml에서는 치마의 아래쪽 절반만 느슨합니다. ds에서는 앞치마, 허리 뒤의 리본, 밑단이 느슨하고, 퍼프 소매, 소맷부리, 양말 윗부분은 몸에 붙어 있습니다. 2등신 세트에서는 열린 코트가 허리선 아래에서 느슨하고 일자 바지는 몸에 붙어 있습니다.
- 테스트 예정: 예제 모델의 치마와 머리카락을 내보낸 뒤 공식 런타임에서 어떻게 보이는지, 모델 프리셋이 만든 머리카락과 의상 시뮬레이션이 얼마나 자연스러운지.
