## 분류와 우선순위

이 페이지는 향후 방향만 기록하며 일정을 약속하지 않습니다. 코드에 진입점이 있는지, 전체 작업 흐름이 사용 가능한지, 결과가 검수를 통과했는지는 따로 판단합니다. 평가는 [STATUS.md](STATUS.md)에만 기록하며 완료 항목은 이 페이지에서 빼고 [변경 이력](CHANGELOG.md)으로 옮깁니다.

새 기능은 Cubism과의 관계에 따라 세 가지로 분류합니다.

| 분류 | 의미 |
| --- | --- |
| p2lrt | Cubism에서 전혀 지원하지 않고 베이크도 불가능. p2l 런타임, 웹, Godot와 래스터 내보내기에서만 적용 |
| 호환 | Cubism이 지원하지 않지만 키폼, 파라미터, 진자 또는 텍스처로 베이크 가능. 키 사이에서는 근사가 생길 수 있음 |
| p2ledior | Cubism이 완전히 지원하며 손실이 없거나 편집 과정에만 영향을 주는 도구 |

각 항목 앞의 우선순위:

- 【다음 단계】현재 단계에서 우선 구현하며 동시에 약 다섯 항목을 넘기지 않음
- 【후속】현재 단계 이후에 진행하거나 다른 항목에 의존
- 【장기】어렵지만 앞으로 구현하고 싶은 항목
- 【지속】기능 진행에 따라 개선하며 단일 완료 시점이 없는 항목
- 【미정】진행 여부를 아직 결정하지 않은 항목

문서 끝에는 “현재 계획 없음”도 있습니다. 항목 뒤 괄호는 분류와 작업 성격입니다. **확장**은 기존 시스템에 기능 추가, **최적화**는 같은 알고리즘이나 프리셋의 효과·성능 개선, **신규**는 새 시스템, **리팩터링**은 기존 시스템의 구조 변경입니다.

## 단계

후속 작업은 세 단계로 진행합니다. 먼저 모디파이어와 무관한 기능을 구현하고, 모디파이어 스택 리팩터링을 단계 목표로 삼은 뒤, 여기에 의존하는 기능을 구현합니다. 나중에 다시 옮기지 않도록 모디파이어 의존 기능을 기존 디포머에 먼저 구현하지 않습니다.

| 단계 | 내용 |
| --- | --- |
| 1단계 | 모디파이어와 무관한 편집·애니메이션·내보내기. 아래 주제별 【다음 단계】 항목 참고 |
| 단계 목표 | [모디파이어 스택 리팩터링](#모디파이어-스택-리팩터링): 시작 전 설계와 단계별 계획 작성 |
| 3단계 | 모디파이어 의존 기능: 조명·그림자, 내부 조형의 3D 투영 프리셋, 머리카락 볼륨 셸, 디포머 계열 기능, 2D 지오메트리 노드 등 |

## 모디파이어 스택 리팩터링

- [ ] 【다음 단계】**모디파이어 스택**(호환 · 리팩터링): 디포머를 비파괴 모디파이어 스택(Lattice, Bend, Twist, Wave 등)으로 바꾸고 키폼으로 베이크합니다. 작업 공간의 기준을 런타임으로 통합한 작업은 완료되었으며 선행 조건입니다. 시작 전에 최소한 다음을 답하는 설계와 단계별 계획을 작성합니다.
  - 문서 계층·생성기 의존 그래프에서의 위치, `RigEditOverlay` 재생 순서·생성 결과 오버라이드와의 관계
  - 기존 Warp / Rotation / 변형 경로 / 뼈대 스키닝 / 내부 조형을 모디파이어로 표현하는 법과 옛 프로젝트의 호환 재생
  - Cubism 내보내기 다운그레이드의 베이크 정밀도·손실 보고서, p2lrt가 모디파이어 원형을 유지할지 여부
  - 단계별로 처음 구현할 모디파이어와 3단계 기능이 열리는 시점
  - 자동 생성 파츠도 스택에 연결하고 “적용”해 일반 레이어로 전환. 예를 들어 윗입술·아랫입술 외곽선은 적용 후 입 모양 설정과의 연동을 끊고 직접 페인팅 가능([#54](https://github.com/tsunehimatoi/psd2live/issues/54), 현재 입술 선에 그리면 안내만 표시)
- [ ] 【후속】**2D 지오메트리 노드**(p2ledior / 호환 · 리팩터링, 어려움): 생성기를 리팩터링해 노드 그래프로 파츠를 절차적으로 생성합니다. 정적 생성은 무손실이며 절차적 애니메이션은 베이크가 필요합니다. 모디파이어 스택 직후에 진행합니다.
- [ ] 【장기】**디포머 계열 기능**(호환 · 리팩터링): 배열 / 인스턴스화, 거친 가장자리, 획 기반 파츠 생성, 변신. 모디파이어 스택과 같은 디포머 리팩터링에 속합니다.
- [ ] 【지속】리그 생성의 내부 단계를 독립 그래프 노드로 분리. 블렌드 셰이프 쓰기 반환에서 시뮬레이션 키폼 오버라이드 처리.
- [ ] 【지속】프리셋 구현의 등록·선택·확장 체계: 부위·기본 알고리즘·모듈·레시피 레지스트리, 파라미터 수에 따라 모듈을 켜는 프리셋·예산, 파츠 역할 추론·수정은 구축됨([리그 프리셋 아키텍처](spec/RIG_PRESETS.md)). 물리·흔들림·시뮬레이션·모션 레시피 라이브러리의 모듈 등록, 블렌드 셰이프 출력·다운그레이더, 모듈 버전과 “생성 결과 업데이트” 연결은 남아 있습니다.
- [x] **자동 생성의 수동 정밀 조정 수준 도달**(호환 · 확장): 눈(눈꺼풀 피팅, 웃는 눈, 크게 뜨기, 감정, 시선에 따른 눈꺼풀, 잔떨림, 하이라이트, 홍채 압축), 눈썹(피팅, 형태, 눈과의 연동, 깜빡임 추종), 입(단계별 벌리기, 중간 입 모양 키, 닫을 때 선 교체, 모음, 얼굴 추적 입 모양, 턱, 볼이 아래 눈꺼풀을 미는 동작, 입안 깊이, 반동), 입체 머리 회전·얼굴 레이어 클리핑, 머리카락 다발 체인, 치맛자락 / 리본 / 펜던트 체인·가슴 탄성, 홍조·어두운 표정·풍부한 기본 표정, 자연스러운 깜빡임·시선 이동, 모듈 리그용 VTube Studio 매핑, 캔버스 특징점 수정이 구현되었습니다. 소재 네 개의 검토를 통과했고 신구 레시피가 공존합니다([리그 프리셋 아키텍처](spec/RIG_PRESETS.md)).
- [ ] 【후속】자동 생성 잔여 항목: 눈썹 스프링·감정 팬아웃 파생량, 치열 분할·혀 내밀기·입안 명암, 목·몸의 기울기 분담·머리에 붙은 목 그림자를 목에 클리핑, 머리 회전 시 앞뒤 머리카락 그리기 순서 전환·깜빡임에 따른 앞머리 떨림·모발 재질 조절값의 진자 반영, 팔 수동 흔들림 체인·천에 붙는 단단한 장식·자동 Glue·동물 귀/꼬리/날개 조건 모듈, 스위치 구성(곱 게이팅·전환·충격)·만화 기호·의상 교체, 말하기 곡선·구동 계층화·VBridger 모음 매핑, 캔버스에서 구동 메시 오프셋 드래그·오버레이 매크로 조절, 사용자가 기본 키폼을 편집하면 절대형 블렌드 셰이프 기준도 재설정.

## 조명과 그림자

모디파이어 스택 뒤의 3단계이며 별도로 진행합니다. 정적 주광만 만들고 작가가 그린 그림자 레이어를 우선 지원하며 동적 조명은 런타임에만 둡니다. 볼륨 프록시는 머리 회전 각도 확대가 목표가 아니며 큰 각도에는 여러 시점의 소재가 필요합니다.

- [ ] 【후속】**작가의 그림자 / 하이라이트 레이어를 각도에 따라 이동**(호환 · 신규): 클리핑 + 곱하기 / 스크린 레이어를 인식하거나 SHADOW / HIGHLIGHT / RIM 태그를 추가해 각도에 따라 이동·페이드하도록 합니다. 윤곽 안 명암의 수축·확장에는 내부 조형을 재사용할 수 있습니다.
- [ ] 【후속】**정적 주광**(호환 · 신규): 명암 경계, 앞머리 투영 그림자, 엔젤 링 하이라이트, 먼 쪽 어둡게 하기, 레이어 간 접촉 그림자를 그림자 레이어 키폼과 디포머 색상 키폼으로 베이크합니다.
- [ ] 【후속】**런타임 동적 조명**(p2lrt · 신규): 노멀 맵 기반 픽셀별 조명. Cubism에서는 정적 조명으로 다운그레이드하고 손실 보고서에 기록합니다.
- [ ] 【후속】**머리카락 볼륨 셸**(호환 · 신규, 어려움): 고개를 숙이거나 들 때 앞머리가 이마에서 떨어지거나 붙는 동작을 각도 축에 베이크합니다.
- [ ] 【장기】**역조명 베이크**(호환 · 신규): 작가가 그린 명암에서 노멀을 역추정해 정적 주광에 사용합니다.

- [ ] 【지속】편집 커밋의 증분 재구축: 페인팅·이미지 교체 뒤 생성 검사에서 외형이 바뀌지 않은 편집을 먼저 변경 여부로 판별하고 `BoundBaseKey` 입력 집합을 재사용해 G′ 전체를 만든 뒤 버리지 않게 합니다. 생성 검사용 아틀라스 페이지 합성이 미리보기의 PNG 구간 재사용을 오염시키지 않게 하고, 명령 오브젝트는 런타임 수준 파이프라인 캐시(메시, `RigStageCache`, 생성 기하)를 공유해 첫 커밋 콜드 스타트를 피합니다.

## Cubism 대비 부족분

도움말은 [`manual/index.txt`](../../src/main/resources/manual/index.txt)에서 Cubism 매뉴얼 각 페이지를 동일·상이·고유·미구현(`missing`)으로 표시합니다. 미구현 페이지는 위 주제별로 분류했으며 아래 그룹은 당분간 넣지 않습니다.

- **스냅샷**: 기존 파라미터 스냅샷과 어니언 스킨으로 대체.
- **씬 패널·프로젝트 패널**: 다중 파일 관리가 작업 공간 탭과 겹칠 수 있어 미정.
- **씬과 재생 목록**(모델 가져와 배치, 오디오 씬, 배경·그룹 트랙, 씬 관리, 포즈 전환 모션, 재생 목록): 영상 제작 성격이 강하며 “현재 계획 없음”의 배경·씬과 같은 유형.
