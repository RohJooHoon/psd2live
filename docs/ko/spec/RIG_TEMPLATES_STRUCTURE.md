# 알고리즘 템플릿 목록: 구조와 표현

> 이 목록은 부위·모듈 아키텍처보다 먼저 작성되어 “슬롯 / 템플릿”이라는 표현을 유지합니다. 같은 슬롯에서 서로 배타적인 방법은 해당 부위의 **기본 알고리즘**으로, 함께 적용할 수 있는 기능은 **모듈**로 등록됩니다. `*/current`는 각 부위의 `legacy` 기본 알고리즘에 해당합니다. 구현 상태는 등록표(MCP `module_catalog`)를 기준으로 합니다. 이 페이지의 P0/P1/P2는 계획 우선순위일 뿐이며, “구현됨”은 등록표를 도입하기 전에 이미 존재했던 알고리즘을 뜻합니다. [리그 프리셋 아키텍처](RIG_PRESETS.md)를 참고하세요.

[문서 목록](../../README.md) · [프리셋 아키텍처](RIG_PRESETS.md) · 템플릿 목록: [얼굴](RIG_TEMPLATES_FACE.md) · [머리카락과 몸](RIG_TEMPLATES_HAIR_BODY.md) · [물리와 모션](RIG_TEMPLATES_PHYSICS_MOTION.md) · [구조와 표현](RIG_TEMPLATES_STRUCTURE.md)

이 페이지는 [리그 프리셋 아키텍처](RIG_PRESETS.md)의 템플릿 목록 중 하나입니다. 각 영역 슬롯에는 여러 알고리즘 템플릿을 등록할 수 있으며, 모델 프리셋은 슬롯별 템플릿 하나와 파라미터 값을 선택합니다. 같은 문제를 해결하는 서로 다른 방법은 같은 슬롯의 별도 템플릿으로 공존합니다. 일반적인 Live2D 제작 관행을 바탕으로 설계했으며, 수치는 모두 권장 기본값과 조절 범위입니다. 구현 후 출력 결과에 맞춰 조정합니다. 각 슬롯의 `*/current`는 기존 알고리즘이며 기본 템플릿으로 등록됩니다. 이를 선택하면 출력은 바뀌지 않습니다.

공통 기호: FW = 얼굴 너비, EH/EW = 눈 높이/눈 너비, H = 캐릭터 키(캔버스 안 인물의 높이), T = 스위치 파라미터이며 모두 `0..1`로 통일합니다(내보낼 때 0..30 등 호스트 관례에 맞게 매핑할 수 있음). “엔진 기능” 항목에는 다음 약어를 사용합니다.

- MK: 다중 키(축 하나에 키 3개 이상, 비균일 키와 인접 키 쌍 포함)
- BS: 블렌드 셰이프(가산 형태 파라미터, mesh/warp 수준 = Cubism 4.2, rotation 수준 = 5.0)
- BSC: 채널 블렌드 셰이프(불투명도 / 색 / 그리기 순서의 가산) — Cubism 5.0 Extended, umamo는 아직 모델링하지 않음
- DOP: 디포머 수준 불투명도 채널(하위 트리 전체를 페이드아웃)
- DOK: 그리기 순서 키폼
- RM: 반전 마스크(Cubism 4.0+)
- MM: 다중 마스크(메시 하나에 마스크 소스 여러 개)
- PG: 곱셈 게이트(여러 스위치 축의 키 격자에 불투명도만 채움)
- RPT: repeat 파라미터(Cubism 5.3, umamo는 플래그만 읽고 쓰며 모델링하지 않음)
- PHY: 물리 출력(연쇄, reflect 포함)
- HOST: 호스트 매핑 사이드카(VTS 파라미터 설정, 핫키, 표정 exp3)
- MOT: 모션 생성(톱니 / 램프 / 계단 곡선)
- CHK: 품질 검사 규칙(`core/quality`)

PSD2Live 현황(각 슬롯의 `*/current`와 “차이점”을 작성한 근거):

- 파라미터: `StandardParameters`의 파라미터 20개를 무조건 추가하며 기본값이 고정되어 있고(입 모양 0, 눈썹 0), `parameterTree`는 6개 그룹으로 고정됩니다. TOGGLE / SWITCH 차분 레이어는 0/1 불투명도 메시 파라미터를 생성합니다(`RigBuilder.buildChannels`). 파라미터 “역할” 외의 분류는 없고(눈 깜빡임/립싱크 역할만 존재), 파생 파라미터나 호스트 매핑 설정도 없습니다.
- 디포머 계층: 생성기는 모두 키폼 축을 사용합니다. 블렌드 셰이프의 선례는 세 곳뿐입니다. `SkeletonPoses` 프리셋 포즈(blend shape), 시뮬레이션 `SimGenerator.usesBlendShapes`(대상 축의 곱이 64칸을 넘으면 자동으로 블렌드 셰이프로 전환), 내부 조형 `NativeInteriorEffect`(네이티브 blend 필드)입니다. umamo는 mesh/warp/rotation 블렌드 셰이프와 가중치 제한 곡선(`BlendWeightLimit`)을 지원하지만 채널 블렌드 셰이프는 모델링하지 않았습니다.
- 메시: 태그 계수(얼굴/머리카락/상의 0.65, 눈/눈썹/입/치아/혀 0.45, 나머지 1) × 전역 간격(GUI 40 / CLI 64), 최소 간격 12. 밀도 표가 `RigBuilder.meshSettings`, `GenerationDefaults`, `ComponentSplitter` 세 곳에 중복되어 있습니다. 변형 복잡도는 읽지 않습니다.
- 그리기 순서: 정적이며 PSD 순서 × `drawOrderStep`이고 사용자가 덮어쓸 수 있습니다. 다중 키 편집에서 그리기 순서 키폼을 직접 작성할 수 있습니다. 생성기는 먼 쪽 귀에만 AngleX 불투명도(`earOpacity`)를 주며 순서 반전은 없습니다.
- 마스크: 홍채는 흰자에, 치아·혀는 입에 클리핑됩니다. `SeeThroughLayers`: 눈썹 복사본 + 앞머리의 눈 위치 반전 창. 투영 그림자와 명암 마스크는 없습니다.
- 스위치: TOGGLE/SWITCH는 0/1 불투명도뿐이며 전환, 배타 구조, 디포머 수준 게이트가 없습니다. `ModelSidecars.standard` 표정은 MouthForm/EyeOpen/BrowY 오프셋에 불과합니다.
- 이펙트, 명암: 생성기가 없습니다. 채널 키폼(불투명도, 곱하기 색, 스크린)은 직접 편집할 수 있습니다.

## 슬롯 param.system(파라미터 체계)

### param.system/current — 표준 파라미터 세트
- 목적: 기존 기본값. 표준 파라미터 20개 + 차분 파라미터. 범위와 기본값이 고정되며 물리와 모션이 같은 표준 파라미터에 씁니다.
- 차이점: 구동원별 계층이 없고, 섀도 파라미터·파생 신호 표·호스트 매핑이 없으며, 기본값이 원화를 따르지 않습니다.
- 우선순위: 기본값으로 유지(P0 등록).

### param.system/source-split — 구동원별로 분리한 섀도 파라미터(추적과 연출 분리)
- 목적: 같은 변형을 여러 구동원(대기, 연출, 물리, 추적, 포즈 라이브러리)이 각각 가산 파라미터 하나씩 써서 서로 덮어쓰지 않게 합니다.
- 적용 대상: 여러 출처가 동시에 구동해야 하는 모든 가동 단위(팔 회전, 머리카락 흔들림, 몸 기울기, 안구).
- 출력 구조:
  - 단위 u와 출처 s ∈ {idle, act, phys, track, pose}마다 BS 파라미터 `<Unit>_<Src>` 하나(예: `ArmR_Lift_Phys`), 범위 −1..1, 기본값 0.
  - 주 파라미터(표준 파라미터, 추적이 기록)는 키폼 축으로 유지합니다. 섀도 파라미터는 해당 단위의 블렌드 셰이프로 같은 객체에 붙입니다(회전은 각도 증분, warp/메시는 변위장).
  - 파라미터 트리는 출처별로 그룹화합니다: `Tracking` / `Idle` / `Performance` / `Physics` / `PoseLibrary`.
- 알고리즘:
  1. 단위의 “단위 변형” D_u를 정의합니다(회전: 각도 증분, warp: 변위장).
  2. 출처별 진폭 상한 A_s(단위 최대 진폭 기준): idle 0.2, act 1.0, phys 0.75, track 0.5, pose 1.0. BS 끝점 = D_u(±A_s).
  3. 변형이 비선형(큰 각도, 호를 그리는 움직임)이면 BS에 중간 키를 추가합니다(deformer.layering/arc-baked-keys 참고).
  4. 바인딩: PhysicsGenerator 출력 → `_Phys`, MotionGenerator 대기 → `_Idle`, 터치/연출 모션 → `_Act`, 시선/마우스 → `_Track`, `_Pose`는 모션이 호출할 프리셋 포즈입니다.
  5. 연출 중에는 `_Idle`을 전체적으로 낮출 수 있으며(BS 가중치 제한 곡선을 연출 게이트 파라미터로 제약), 물리는 고칠 필요가 없습니다.
  6. 하위 호환: 대상이 BS를 지원하지 않으면 모든 출처를 더해 파라미터 하나로 베이크하고 손실 보고서에 “출처를 독립적으로 구동할 수 없음”을 기록합니다.
- 조절 파라미터: `sources`(활성 출처 집합, 기본 idle/phys/track), `amp.<src>`(최대 진폭 대비, 위 참고, 범위 0.1–1), `idleDuck`(연출 중 대기 감쇠, 기본 0.3, 0–1).
- 실패 양상과 확인: 여러 출처가 동시에 최대 진폭이면 warp 변위 합산이 왜곡됩니다(큰 각도 단위는 회전을 우선). Σ출처 상한 ≤ 단위 허용 범위(CHK: 초과 시 warning). 같은 구동이 두 출처에 동시에 쓰면 두 배가 됩니다(CHK: 같은 물리 그룹/모션 트랙이 같은 단위의 두 출처에 씀 → error).
- 엔진 기능: BS(rotation BS = 5.0 포함), BS 가중치 제한, PHY, MOT, 파라미터 그룹화.
- 난이도: medium. 우선순위 P1(deformer.layering/pose-grid-plus-blend에 의존).

### param.system/derived-signals — 단일 신호를 분기하는 파생 파라미터 표
- 목적: 감정/추적 신호 하나가 임계값과 시정수에 따라 여러 부품을 단계적으로 켭니다(입이 먼저 움직이고, 웃음이 중간 정도일 때 눈이 휘고, 볼 홍조는 천천히 떠오르고, 크게 웃어야 꼬리가 올라감).
- 적용 대상: 호스트 추적(VTS 등)이 있는 모델, 해당 부품(웃는 눈, 볼 홍조, 꼬리/귀)이 있는 모델.
- 출력 구조: 프리셋의 “파생 파라미터 표” 행: `{target, source, window [a,b], outRange, curve, smoothing τ}`. 호스트 매핑으로 내보내며, 에디터 미리보기는 표에 따라 시뮬레이션합니다.
- 알고리즘:
  1. 기본 표: 입 모양 ← MouthSmile [0.1,1] τ0, 웃는 눈 ← MouthSmile [0.4,1] τ≈0.15 s, 볼 홍조 ← MouthSmile [0,1]→[0.5,1] τ≈0.7 s, 꼬리 들기 ← MouthSmile [0.7,0.9] τ≈1.5 s, 동물 귀 세우기 ← 눈썹 높이 [0.5,1], 몸 ← 머리 각도 ×0.3 τ≈0.3 s.
  2. 리그 내부에서는 물리 그룹으로 평활화를 근사할 수만 있고 임계값은 만들 수 없습니다. 임계값은 반드시 호스트 측에 있어야 합니다.
- 조절 파라미터: 행마다 window, outRange, τ. `bodyFromHead`(0.3, 0–0.5, body 물리와 택일).
- 실패 양상: 이득이 너무 크면 일찍 포화됩니다. 몸이 머리 매핑과 물리 “몸이 머리를 따름”에 동시에 구동되면 이중 계산됩니다(CHK).
- 엔진 기능: HOST(호스트 매핑 사이드카), 에디터 미리보기 시뮬레이션.
- 난이도: easy. 우선순위 P1.

### param.system/host-mapping — 호스트 매핑의 평활화와 이득 표
- 목적: VTS 등 호스트 설정을 내보낼 때 채널 주파수에 따라 평활화와 이득을 설정합니다.
- 출력: 호스트 파라미터 설정(입력 → 출력 범위, 평활화). derived-signals와 출력 채널을 공유합니다.
- 알고리즘: 평활화 표(0–100 눈금): 립싱크 0, 시선 10, 눈 개폐 10, 눈썹 10–15, 머리 X/Y 15, 머리 Z 30, 몸 20. 이득 = 파라미터 중립값 / 일반적인 추적 중립값. AngleY 감도는 1.5부터 시작합니다.
- 조절 파라미터: 평활화 표, 이득 표.
- 실패 양상: 이득이 너무 크면 포화됩니다. 기본값을 바꾼 뒤(art-default 참고) 바이어스를 보정해야 합니다.
- 엔진 기능: HOST. 난이도 easy. 우선순위 P1.

### param.system/art-default — 기본값을 원화 위치에 두기
- 목적: 파라미터 기본값 = 원화 상태로 하고, 범위 양쪽 여유는 기계적 대칭이 아니라 표현에 필요한 만큼 배분합니다.
- 적용 대상: 입 모양(원화가 미소), 눈썹 각도, 치아 벌림, 손가락, 손동작, 그리기 계층 파라미터.
- 출력: 파라미터 `[min, v0, max]`, v0의 키 = 원화. v0이 끝점에 있으면 해당 축은 단방향 키폼만 만듭니다.
- 알고리즘: 분류기나 규칙으로 원화가 해당 축의 어디에 있는지 판단합니다(입꼬리가 입 중심선보다 높음 → 미소 → MouthForm 기본 1, 범위 −1..1 전체를 “웃지 않음→입 삐죽”에 할당). 호스트 매핑을 내보낼 때 바이어스를 보정하여 표준 추적 중립이 여전히 v0에 오게 합니다.
- 조절 파라미터: `useArtDefault`(파라미터별 스위치, 기본 꺼짐, 표준 추적 파라미터는 신중하게).
- 실패 양상: 표준 파라미터 기본값이 어긋나 호스트 추적이 어긋납니다(CHK: 기본값 ≠ 표준 기본값이고 호스트 바이어스 없음 → warning).
- 엔진 기능: HOST 바이어스. 난이도 easy. 우선순위 P1.

### param.system/head-drives-body — 몸 파라미터가 없을 때 머리 각도로 전신을 계층별 구동
- 목적: 얼굴 추적만 있는 호스트에서 Body 파라미터 그룹을 만들지 않고 머리 각도를 비율에 따라 전신 루트 체인에 배분합니다. 고개 기울이기 = 전신의 가벼운 옆 기울기 + 머리가 더 기울어짐.
- 적용 대상: 전신 일러스트, 사용자가 “몸 파라미터 없음” 모드를 선택한 경우.
- 출력: 전신 루트 체인 AngleZ warp(6–8×6) → AngleY warp → AngleX warp → 아주 작은 AngleX 회전(±1°). 머리 회전 AngleZ는 파라미터 각도의 0.5배만 사용합니다. 다리마다 AngleZ warp 한 층을 두고, 그 다리 쪽으로 기울 때 중간 키를 하나 추가합니다(끝점의 약 0.4배, 체중을 받는 다리는 무릎을 살짝 굽히고 골반을 살짝 올림).
- 알고리즘: AngleZ 전신 기울기 분담 0.2(행 가중치 발 0 → 머리 1 이즈인). AngleX 전신 ≤0.03H 가로 이동, 몸통 warp로 가슴 회전, 머리 warp로 주 회전. AngleY 몸통 ≤0.01H 신축. 확인: AngleZ 끝점에서 발바닥 변위 <0.005H.
- 조절 파라미터: `headRollShare` 0.5(0.4–0.6), `bodyLeanShare` 0.2(0.15–0.3), `stanceKey` 0.4(0.35–0.5).
- 실패 양상: 나중에 Body 파라미터를 추가하면 이중 계산됩니다. 루트 warp가 너무 거칠면 치맛자락이 꺾입니다.
- 엔진 기능: MK(한쪽 중간 키). 난이도 medium. 우선순위 P2(body.turn과 충돌하므로 모드로 제공).

(참고: 파라미터 보간 관련 “호 베이크 고밀도 키”는 deformer.layering/arc-baked-keys에, 순환 파라미터는 effect/loop-cycle에 있습니다.)

## 슬롯 deformer.layering(디포머 계층)

### deformer.layering/current — 키폼 축의 곱셈 조합
- 현황: 생성되는 모든 2차 움직임(머리카락 흔들림, 안구 젤리, 몸 2차 움직임)은 일반 키폼 축으로 주 메시에 합쳐집니다. 시뮬레이션은 곱이 64칸을 넘으면 자동으로 블렌드 셰이프로 바뀝니다. 뼈대 포즈는 블렌드 셰이프를 사용합니다.
- 차이점: “주 포즈 격자 + 가산 2차 움직임”의 통일된 규칙이 없습니다.
- 우선순위: 기본값으로 유지(P0 등록).

### deformer.layering/pose-grid-plus-blend — 포즈 격자 + 가산 층(주 템플릿)
- 목적: 키폼은 조합 가능한 소수의 “포즈 축”에만 남기고, 모든 2차 움직임·표정 보정·완벽 동기화·물리 출력을 블렌드 셰이프로 만들어 키 수를 곱셈에서 덧셈으로 바꿉니다.
- 적용 대상: 모든 생성기의 아키텍처 규칙. 특히 머리카락, 옷, 장신구, 눈, 입.
- 출력 구조:
  - 포즈 축(키폼 격자, 객체당 ≤3축): 머리 AngleX×Y(3×3), 몸 X×Y, 눈 개폐×웃음(또는 개폐×웃음×감정 3×2×2).
  - 주 포즈 warp **아래**에 “가산 warp”(자체 키폼 축 없이 BS만 있음)를 삽입하고 2차 형태를 그 위에 작성합니다. 변위는 로컬 좌표에 있으므로 부모의 고개 돌림/원근을 자동으로 따릅니다.
  - 물리 출력 파라미터는 모두 BS 파라미터입니다. 가산 warp 하나에 쌓는 형태는 ≤4–5개입니다.
- 알고리즘:
  1. 파라미터 분류: 포즈 축 vs 가산 층(판단 기준: 해당 변형이 “어떤 주 포즈에서도 거의 같게 보이는가”).
  2. 가산 층 증분은 기본 포즈에서 계산하며 양 끝 ±1을 각각 계산하고 대칭을 강제하지 않습니다. 기본은 두 키 선형이며 필요하면 중간 키를 추가합니다.
  3. 조합 안전성: 포즈×가산 조합을 무작위로 샘플링하고 `GeometrySafetyEvaluator`로 뒤집힘과 자기 교차를 검사합니다. 불합격이면 보정 조합 키를 추가하거나 키폼으로 되돌립니다.
  4. 큰 변형(단일 형태 변위 > 객체 크기의 25–30%)은 가산으로 하지 않고 계층 분할(nested-segment-cascade)이나 키폼으로 바꿉니다.
  5. 하위 호환: 대상이 <4.2이면 각 BS 파라미터를 “추가 키폼 축” 또는 “해당 파라미터를 축으로 하는 하위 warp”로 낮추고(수학적으로 동등), 손실 보고서에 조합 수 증가를 기록합니다.
- 조절 파라미터: `maxPoseAxes` 3(2–3), `maxBlendPerTarget` 4(3–6), `maxBlendDisplacement` 0.25(0.15–0.3, 객체 길이 대비), `autoBlendCells` 64(기존 시뮬레이션의 자동 임계값, “자동” 단계로 사용).
- 실패 양상과 확인: 가산 형태끼리 서로 당깁니다(CHK: 같은 대상의 BS 수 초과 warning). 물리 파라미터가 머리/몸 각도와 같은 키폼 격자에 들어감(CHK: info, BS로 변경 권장).
- 엔진 기능: BS(mesh/warp 4.2, rotation 5.0), BS 하위 호환 변환기(기존 `MocBlendLowering`), 조합 샘플링 검사.
- 난이도: hard(아키텍처). 우선순위 **P0**(프리셋 재구성의 기본 규약).

### deformer.layering/cross-parent-modifier — 부모를 가로지르는 감쇠 보정 형태
- 목적: 직교 보정(웃는 눈, 비뚤어진 입)을 BS 파라미터 하나로, 서로 다른 부모에 속한 여러 객체(입, 볼, 코)에 동시에 적용하며 거리에 따라 감쇠합니다.
- 적용 대상: 보정 계열 파라미터. 주축 양 끝에서 보정 형태를 만들며, 차이 벡터 방향의 끼인각 <20°, 길이 비 0.7–1.3.
- 출력: BS 파라미터, 범위는 0..1로 통일. 대상: 보정 중심 반경 안의 모든 메시/warp.
- 알고리즘:
  1. 주축 대표 키에서 차이를 계산합니다(눈: 감음 0과 뜸 1, 입: OpenY=0). 양 끝 차이가 일치하지 않으면 주 키마다 하나씩 저장합니다(BS가 주축을 따라 보간, “키별 차이” 기능 필요).
  2. 영향 범위: 보정 중심(입꼬리, 눈꼬리)에서 smoothstep 감쇠, 반경 약 0.25 FW.
  3. 하위 호환: <4.2이면 주축 격자에 두 번째 축을 펼치고 차원 증가를 보고합니다.
- 조절 파라미터: `radius` 0.25 FW(0.15–0.35), `perKeyDelta` 판정 임계값(끼인각 20°).
- 실패 양상: 주축 극단에서는 차이를 더할 수 없습니다(완전히 감은 눈에서 “웃음”은 호 방향을 바꿔야 함) → 키별 차이가 반드시 필요합니다.
- 엔진 기능: BS, 키별 차이(BS와 키폼 축 조합). 난이도 medium. 우선순위 P1.

### deformer.layering/cross-hierarchy-shared-blend — 계층을 가로지르는 공유 2차 형태(팔에 걸친 긴 머리카락)
- 목적: 한 물체를 “지금 어느 부위 위에 눌려 있는가”에 따라 조각내어 각 조각을 해당 부위의 디포머에 붙이고, 같은 BS 세트를 공유해 머리에서 오는 흔들림을 더합니다. 지지하는 부위를 따라 움직이면서 머리 흔들림도 따릅니다.
- 적용 대상: 어깨선을 넘어 가슴/위팔/아래팔에 걸친 긴 머리카락, 숄, 스카프, 긴 리본.
- 출력: 머리카락 조각을 2–4구간으로 자르고 각각 가슴/몸통/위팔/아래팔의 하위 warp에 붙입니다. 머리카락 물리 한 세트(머리 roll이 주 입력, 출력 3개 = 인접 노드)를 BS로 모든 구간에 더합니다. 구간 사이는 Glue.
- 알고리즘:
  1. 정지 포즈에서 각 머리카락 정점은 아래에서 덮고 있는 몸 메시를 소속으로 삼고, 없으면 머리에 속합니다. 연결 영역을 평활화하며 최단 구간 ≥ 머리카락 너비의 2배.
  2. 변위장은 머리카락 전체의 호 길이 s를 따라 연속으로 정의하고 각 구간은 자기 s 구간을 잘라 씁니다 → 구간 사이가 연속.
  3. 진폭은 s를 따라 커지며 눌린 구간은 0.3–0.6을 곱합니다.
- 조절 파라미터: `pressFactor` 0.45(0.3–0.6), `segments` 3(2–4), `headRollWeight` 0.75(0.6–0.9).
- 실패 양상: 팔을 크게 들면 눌린 구간이 끌려가 머리 위쪽 구간과 벌어집니다(Glue에 여유를 두거나 팔 각도 보정 warp 추가). 소속 판정이 떨립니다.
- 엔진 기능: BS(서로 다른 부모 사이에서 같은 파라미터 공유), Glue, PHY.
- 난이도: hard(research 수준의 소속 분할). 우선순위 P2.

### deformer.layering/nested-segment-cascade — 중첩 구간 warp의 단계별 감소(채찍)
- 목적: 같은 영역에 n층 중첩 warp를 만들고 k번째 층은 끝부분 s>(k−1)/n만 굽히며 각각 물리의 k번째 출력을 받고 층마다 진폭이 줄어듭니다. 끝부분 위상이 지연되고 총 진폭이 가장 큽니다.
- 적용 대상: 머리카락 영역, 치마 앞뒤 자락, 소맷부리, 깃 장식 등 흔들리는 영역. 같은 영역의 머리카락 그림자, 포니테일 뿌리도 같은 층 세트에 붙입니다.
- 출력: n=3층 중첩 warp. 물리 n+1 질점, 출력 v_k → k번째 층, 스케일 `scale0·r^(k−1)`. 좌우 각 진자 하나, 세로 입력은 한쪽에서 reflect.
- 알고리즘: 질점 길이는 구간마다 약간 줄입니다(약 1 : 0.9 : 0.85). 질량과 감쇠는 높게(약 0.95), 가속도는 약간 낮게(약 0.9) 하여 부드럽되 끌리지 않게 합니다. 머리 위 물체는 AngleZ(각도형 입력)를 주로, AngleX / AngleY(변위형 입력)를 보조로 하며 가중치는 약 3.5 : 1 : 1. 몸 위 물체는 BodyZ를 주로, BodyX / BodyY는 그 절반 정도.
- 조절 파라미터: `layers` 3(2–4), `decay` 0.7(0.6–0.8), `zToXWeight` 3.5(2–4).
- 실패 양상: 층이 많으면 바깥층의 작은 각도가 안쪽 층에 의해 증폭되어 끝부분이 떨립니다. 얼굴 위 머리카락 그림자를 같은 체인에 붙일 때는 마스크가 반드시 얼굴이어야 합니다.
- 엔진 기능: PHY 다중 출력, 중첩 warp, reflect. 난이도 medium. 우선순위 P1(physics.cascade 그룹과 공유하며 여기서는 계층 규약을 등록).

### deformer.layering/inherit-not-reinput — 계층 상속과 물리 입력 분담
- 목적: 머리에 걸린 띠(끈, 헤어밴드, 귀걸이 고리)는 머리 움직임을 계층 상속으로 받고 물리는 몸 입력만 받아 중복 계산을 피합니다. 여기에 작고 비대칭인 AngleZ 보정 층을 추가합니다.
- 출력: 띠 물리 층 위에 AngleZ rotation/warp를 삽입합니다. 띠 물리 그룹은 BodyX/Y/Z 입력만 포함합니다.
- 알고리즘: AngleZ 양 끝에서 머리 윤곽 위 띠 뿌리점의 접선 변화를 구하고 각도 = −k·Δθ. 당겨진 쪽 k≈1, 느슨한 쪽 k≈0.4. 보정각 ≤10°. 양 끝이 모두 머리에 고정되었거나 매우 짧으면(<0.5 EH) 생략합니다.
- 조절 파라미터: `kTight` 0.9(0.8–1), `kSlack` 0.4(0.3–0.5), `maxComp` 10°.
- 실패 양상: 물리 그룹이 머리 입력과 계층 상속을 동시에 포함 → 두 배(CHK: 머리 하위 트리 아래에 붙은 물리 그룹에 머리 각도 입력 포함 → warning).
- 엔진 기능: PHY 입력 집합을 부착 위치에서 도출. 난이도 easy. 우선순위 P1.

### deformer.layering/arc-baked-keys — 호 베이크 고밀도 키(적응형 키 삽입)
- 목적: Live2D는 키 사이를 선형 보간하므로 한 점을 중심으로 도는 부품은 중간에서 현을 따라가며 짧아지고 납작해집니다. 생성기는 앵커 키만 “작성”하고 호를 따라 중간 키를 적응적으로 보충합니다.
- 적용 대상: 머리 각도, 물리 출력 파라미터, 머리카락 끝, 손가락, 관절을 중심으로 도는 모든 키폼. 표정 스위치에는 적용하지 않습니다.
- 알고리즘:
  1. 생성기 내부에서 회전 체인/3D 프록시로 임의 파라미터 값의 형태 S(p)를 구합니다. 또는 각 제어점에 대해 세 앵커 p₋,p₀,p₊로 외접원을 맞추고 원호를 따라 각도로 보간합니다(거의 공선이어서 편차 <객체 크기의 0.2%이면 선형 유지).
  2. 적응: 반구간 중점 S(mid)와 선형 보간의 편차가 ε(객체 크기의 0.5%)를 넘으면 키를 삽입하고 재귀하여 편차 < ε/4가 될 때까지 반복하며, 반구간당 최대 6구간. 2차원 축은 각각 적응하고 합집합 격자를 사용합니다.
  3. 정면 근처 고밀도화(비균일 키 x_k = sign(k)·R·(|k|/K)^1.4)를 선택적 분포로 제공합니다.
  4. 내보내기 전에 거의 공선인 키(편차 < ε/2)를 병합합니다.
- 조절 파라미터: `epsilon` 0.5%(0.3–1%), `maxSubdiv` 6(2–6), `maxKeysPerAxis` 13(머리카락) / 37(손가락), `centerDensityExp` 1.4(1–1.6).
- 실패 양상: 균일한 고밀도 키는 파일을 폭증시킵니다(반드시 적응형). 외접원이 거의 공선이면 반경이 폭발합니다(반드시 판정).
- 엔진 기능: MK. 생성기는 앵커뿐 아니라 임의 p의 형태를 구할 수 있어야 합니다. 난이도 medium. 우선순위 P1.

### deformer.layering/rigid-pin — 딱딱한 장식을 천에 고정
- 목적: 단추, 배지, 리벳 같은 하드웨어를 회전 디포머 아래에 두고, 천 warp는 그 원점만 옮기며 장식은 주름을 따라 전단되지 않습니다.
- 적용 대상: 소속 천 면적의 <1%, 윤곽이 분리되고 대비가 강한 작은 부품.
- 출력: 부품마다 rotation 하나(원점 = 장식 중심, 천의 가장 안쪽 warp에 붙임) → 3×3–5×5 warp(BodyAngleX: 돌아가는 쪽 가로 압축 5–15%). 메시 12–20 정점.
- 조절 파라미터: `followRotation` 0.25(0–0.5), `perspectiveSquash` 10%(5–15%).
- 엔진 기능: warp 아래 rotation. 난이도 easy. 우선순위 P1.

### deformer.layering/root-spaces — 루트 공간: 무대 카메라 / 캐릭터 카메라 / 장면 루트
- 목적: 루트에서 순수 강체 “공간” 층을 분리합니다. 무대 카메라(화면 전체), 캐릭터 카메라(캐릭터만), 장면 루트(책상·의자, 스탠드 마이크처럼 캐릭터를 따라 움직이지 않는 것).
- 출력: `StageCam` rotation(평행 이동 ±0.6 캔버스 너비, 스케일 파라미터 −1→≈0, 0→1, 3→4, 1과 4 사이에 중간 키를 보충해 줌인을 등속으로) → 배경 이펙트 분기 + `ActorCam` rotation(평행 이동 ±0.3 너비, 스케일 0→1 / 30→3, 회전 ±45°, 피벗은 지지점) → 캐릭터 루트. `SceneRoot` warp는 캐릭터 루트와 나란히 두며 스위치 불투명도 키만 있습니다. 레이어 주석 scene / held / worn이 부착 위치를 결정합니다.
- 확인: 두 카메라 층은 강체 변환만 허용하며 기본값은 엄격히 항등 변환입니다(CHK).
- 조절 파라미터: 평행 이동 범위 0.3–1.2 너비, 스케일 상한 3–4, 회전 ±30–45°.
- 엔진 기능: rotation 스케일, DOP. 난이도 easy. 우선순위 P2(연출 프리셋, 기본 꺼짐).

## 슬롯 mesh.density(메시 밀도와 토폴로지)

### mesh.density/current — 태그 계수 × 전역 간격
- 현황: 얼굴/머리카락/상의 0.65, 눈·눈썹·입·치아·혀 0.45, 나머지 1. 최소 간격 12. 입선을 켜면 입 바깥 여백 0, 최소 간격 6. 밀도 표 세 개가 중복되며 서로 일치하지 않습니다.
- 우선순위: 기본값으로 유지하고 P0에서 단일 표로 병합합니다.

### mesh.density/deformation-driven — 변형 복잡도에 따라 정점과 warp 해상도 배분(주 템플릿)
- 목적: 정점은 “그림 자체가 휘는 곳”에 두고, 부모 warp가 옮기기만 하거나 강체 회전하는 큰 부품은 성기게 합니다. warp 행·열은 영역의 가로세로 비와 변형 파장에 따라 배분합니다.
- 적용 대상: 모든 메시와 생성 warp.
- 알고리즘:
  1. 메시마다 목표 변 길이 L = min(부모 warp 셀 변 길이 × 0.5, 선화 디테일 척도, 자체 키폼 특징 척도 × 0.25)이며 [ℓ_min, ℓ_max]로 제한합니다.
     - 자체 키폼 강도 D = 자체 키폼 사이 정점 변위의 2차 차분 평균 / 바운딩 박스 짧은 변. L = ℓ_base / (1 + k·D). D=0(부모가 옮기기만 함)이면 L ≈ 부모 warp 셀의 0.5 또는 짧은 변 /4.
     - 처음 생성할 때는 아직 키폼이 없으므로 “해당 부품에 바인딩된 파라미터 수 × 예상 변위”로 추정합니다(템플릿이 선언한 출력 구조에서 제공).
  2. 범주별 기본 변 길이: 선 계열(입술선, 아이라인, 속눈썹) 0.06 EW, 이목구비 패치 0.05 EW, 머리카락 다발 0.01 머리 높이, 얼굴·몸통 패치 0.03 머리 높이, 강체 팔다리 0.05 H, 넓은 천 0.02–0.03 H, 이펙트 패치 = 사각형.
  3. 특징선을 따라 고밀도화: 선 방향 변 길이 ≤ 선 너비, 수직 방향 2–3열. 곡률이 큰 윤곽, 관절, 그림 교체 경계에서 국소 고밀도화.
  4. warp 행·열: rows : cols = 높이 : 너비 × 변형 복잡도 계수. cell ≈ 영역 변형 파장 / 4(얼굴 머리 높이의 2–3%, 몸 1–2% H). 평행 이동/전체 회전만 하는 warp는 2×2–5×5. 제어점 총합 ≤600.
  5. 최소 정점 수: 작은 부품 16, 일반 30.
  6. 전체 예산 30k–60k 정점. 초과하면 핵심이 아닌 범주부터 같은 비율로 밀도를 낮춥니다.
- 조절 파라미터: `kComplexity`(k, 기본 1), `edgeTable`(위 범주 표), `rigidWarpMax` 5, `warpPointBudget` 600, `vertexBudget` 45000(30k–60k).
- 실패 양상과 확인: 촘촘한 warp × 다중 키로 내보내기 용량과 런타임 비용이 늘어납니다(CHK: 단일 객체 제어점 × 키 수 초과 warning). IK로 무릎을 굽히는 다리는 강체 팔다리의 낮은 밀도를 쓰면 안 됩니다(템플릿이 “해당 부품에 내부 굽힘이 있음”을 선언해야 함).
- 엔진 기능: 메시 생성이 레이어별 목표 변 길이장을 받음. 템플릿이 선언한 예상 변형을 읽어야 함. 생성 후 2차 세분화 가능(RasterMeshJournal이 키폼 이전).
- 난이도: medium. 우선순위 **P0**(먼저 밀도 표를 병합하고 “강체 / 옮겨지기만 함 / 자체 키폼” 3단계 추가. 키폼 기반 2차 세분화는 P1).

### mesh.density/structure-aligned — 구조선을 따라 메시 배치(띠 / 극좌표 / 제약 변)
- 목적: 메시 변을 구조선(우산살, 띠 중심축, 옷 주름)을 따라 배치하여 변형 시 구조선이 곧거나 매끄럽게 유지되게 합니다.
- 적용 대상: 띠 모양 부품(리본, 유광 띠, 꼬리, 긴 머리카락 다발) → 중심축을 따라 사각형 띠 2–3행. 원반형 소품(우산, 꽃, 마법진) → 극좌표 메시(살마다 방사선 하나, 3–5바퀴). 뚜렷한 직선 구조가 있는 부품 → 제약 변.
- 조절 파라미터: `stripRows` 2(2–3), `polarRings` 4(3–5), 구조선 검출 임계값.
- 엔진 기능: 제약 삼각분할. 난이도 medium. 우선순위 P2.

### mesh.density/rigid-quad — 딱딱한 패치에 4점 메시
- 목적: 딱딱한 장식(얼음 결정, 금속 날개, 빛 조각, 파티클, 가구 패치)에 4정점 메시를 사용합니다. 비용이 거의 없으며 rotation/warp가 통째로 움직입니다.
- 적용 대상: rigid/effect로 표시된 레이어. 투명 가장자리가 텍스처 면적을 낭비하면 바운딩 박스를 잘라낼 수 있습니다.
- 엔진 기능: 특별한 것 없음. 난이도 easy. 우선순위 P1.

## 슬롯 mesh.glue(보충 슬롯: 글루)

### mesh.glue/same-topology-lock — 같은 토폴로지 복사 레이어를 전 정점 글루로 결합
- 목적: 같은 형태를 밑색/그림자/선화 등 같은 토폴로지의 여러 메시로 나눈 경우 전 정점 글루로 하나로 묶습니다. 생성기는 주 레이어에만 키폼을 계산합니다.
- 알고리즘: 토폴로지와 정지 위치가 일치하는(정점 거리 <0.5 px) 메시 쌍을 검출 → 전 정점 글루 강도 1, 밑색 또는 마스크 소스를 주 레이어로 삼습니다. 내보낼 때 보조 레이어 키폼으로 베이크할 수 있습니다(대상이 글루를 지원하면 유지). 보조 레이어에 자체 BS나 국소 움직임이 있으면 영역별로 가중치를 낮춥니다.
- 조절 파라미터: `matchTolerance` 0.5 px(0.5–1).
- 실패 양상: 보조 레이어의 국소 움직임이 끌려 돌아갑니다. SeeThrough 복사본은 글루를 복사하지 않도록 명시되어 있으므로(파트너가 두 번 당겨지는 것 방지) 제외해야 합니다.
- 엔진 기능: Glue, Glue 베이크. 난이도 easy. 우선순위 **P0**(투영 그림자 쌍둥이와 명암 복사본이 모두 의존).

### mesh.glue/seam-auto — 인접 블록 이음새 자동 Glue
- 목적: 인접 블록이 서로 다른 최하위 디포머에 붙어 있을 때 이음새 글루를 자동으로 추가하여 틈을 막습니다.
- 알고리즘: 두 메시가 서로 다른 최하위 디포머에 속하고 alpha 경계 2 px 이내에서 인접한 길이 ≥ 두 메시 둘레의 5% → GlueSeam으로 경계 정점을 일치시키고, 호 길이를 따라 메시 변 길이 1.5–2마다 한 쌍을 잡습니다. 가중치 0.5/0.5, 부착점을 고정하는 쪽은 0.7/0.3. 같은 부모이고 키폼이 같으면 추가하지 않습니다.
- 조절 파라미터: `adjacencyPx` 2, `minShare` 5%, `pairSpacing` 1.75 변 길이.
- 엔진 기능: Glue, GlueSeam. 난이도 medium. 우선순위 P1.

### mesh.glue/hierarchy-bridge — 머리와 몸을 가로지르는 연결 부품의 구간 분할 결합
- 목적: 머리와 몸을 가로지르는 물체(이어폰 줄, 스카프, 목걸이)를 목선에서 머리 구간과 몸 구간으로 잘라 각자 소속 계층에 붙이고, 이음새를 글루로 묶어 끊어지지 않고 늘어나게 합니다.
- 알고리즘: 픽셀이 머리/몸 두 영역에 걸쳐 있고 연결되어 있음 → 목선에서 자릅니다(메시 셀 1–2개 겹침). 이음새 가중치 0.5(선) 또는 한쪽으로 치우침. 이음새 정점 밀도 ≥ 선 길이 3%마다 하나. 포즈 전환 시 분리되는 부품은 전환 지점에서 글루 강도를 0으로 키잉합니다(Glue 키폼/BS = 5.0 필요).
- 엔진 기능: Glue, (Glue BS 5.0 선택). 난이도 medium. 우선순위 P1.

## 슬롯 draw-order(그리기 순서)

### draw-order/current — 정적 순서 + 사용자 덮어쓰기
- 현황: PSD 순서 × `drawOrderStep`, `drawOrderOverrides`. 다중 키 편집에서 직접 작성 가능. 먼 쪽 귀는 페이드아웃만 하고 순서를 뒤집지 않습니다.
- 우선순위: 기본값으로 유지(P0 등록). 전제 규약: 정적 순서는 희소 눈금(층 사이에 빈 간격)을 사용하여 아래 템플릿이 끼어들 틈을 남깁니다.

### draw-order/group-level — 그룹 깊이 슬라이더(연속 level 파라미터)
- 목적: 팔, 날개, 소품, 하위 캐릭터 등 그룹의 그리기 순서를 연속 파라미터 하나로 만들어 그룹 전체를 평행 이동하고 그룹 안 상대 오프셋은 유지합니다. 곡선 하나로 교차 시점을 표현하며 중간값은 몸 스택의 어떤 틈에도 끼워 넣을 수 있습니다.
- 적용 대상: 몸 앞/뒤로 움직일 수 있는 팔다리 그룹, 날개, 이동 가능한 소품.
- 출력: `<Group>_Level` 파라미터, 범위 = [스택에서 끼워 넣을 수 있는 가장 낮은 위치, 스택 최상단], 기본값 = 원화 위치(보통 끝점). 그룹 안 메시마다 키 level ∈ {min, max}, 순서 = level + δ_i. 잘림을 막기 위해 끝점을 |δ_i|만큼 바깥으로 확장합니다. 또한 모션 생성기와 MCP가 고를 수 있도록 “랜드마크 깊이 표”(뒷머리 뒤, 몸과 팔 사이, 몸 앞, 얼굴 앞, 최전면)를 출력합니다.
- 알고리즘:
  1. δ_i = 그룹 안 순위 × 작은 간격, 간격 < 인접 비그룹 메시 간격 / (그룹 안 레이어 수 + 1). |δ| ≤ 인접 랜드마크 간격의 1/3.
  2. 모션에서는 깊이 관계(손이 몸통 윤곽 안에 있는지, 아래팔 회전 구간)에 따라 level을 설정하고, 깊이 정보가 없으면 작성자가 수동으로 키를 찍습니다.
  3. 다른 순서 키폼(손가락이 손바닥 뒤로 굽음)과 조합할 때는 곱 키로 오프셋을 더합니다.
  4. 검증: level을 샘플링할 때 그룹 안 순서는 변하지 않고, 그룹과 비그룹의 상대 순서는 교차 지점에서 한 번만 바뀝니다. 그리기 순서가 같은 곳은 반드시 엇갈리게 합니다(CHK).
- 조절 파라미터: `levelStep` 스택 간격 대비 0.25–0.5, `innerStep` 0.01–0.05, `default` = 원화.
- 실패 양상: 마스크가 있는 그룹은 마스크 메시도 그룹과 함께 움직여야 합니다. 메시마다 level 축이 하나 늘어 키폼이 두 배가 됩니다. 대상이 파츠 수준 순서를 지원하면 파츠에 두는 것을 우선합니다.
- 엔진 기능: DOK(추가 키폼 축으로). 이상적으로는 파츠 수준 그리기 순서 또는 BSC(가산 채널).
- 난이도: easy–medium. 우선순위 P1.

### draw-order/additive-offset — 그리기 순서 가산 채널
- 목적: 앞뒤 전환을 가산 오프셋 파라미터(±Δ)로 만들어, 연출이 어떤 포즈에서도 따로 전환할 수 있고 포즈 키폼마다 순서를 가질 필요가 없게 합니다.
- 적용 대상: 손가락 vs 쥔 물체, 손/소매, 꼬리 vs 옷, 소품 패치.
- 알고리즘: offset = ±Δ, Δ = 두 그룹의 순서 차 + 1. 그리기 순서는 보간하지 않고 파라미터 중간점에서 바뀝니다. 모션은 가림이 가장 적은 프레임에서 전환합니다.
- 엔진 기능: BSC(그리기 순서 블렌드 셰이프, Cubism 5.0, umamo는 모델링하지 않음) — 키폼 축으로 하위 호환.
- 난이도: easy(엔진 측 medium). 우선순위 P2.

### draw-order/turn-flip — 머리/몸을 돌릴 때 가림에 따른 표시·숨김과 순서 반전
- 목적: 측면 요소(귀, 옆머리, 먼 쪽 눈꼬리, 고리형 장식의 두 반쪽)를 3D 프록시 깊이에 따라 각도별로 표시·숨김하고 순서를 뒤집습니다.
- 출력: 각도 축에 불투명도 키(v가 0/0.5/1을 지나는 곳)와 그리기 순서 키(깊이 반전 각 θ* ± δ)를 추가합니다.
- 알고리즘:
  1. 머리 타원체(또는 몸통 원기둥, 어깨 오프셋 위치의 팔 원기둥)의 투영 깊이 z = cos(φ + θ).
  2. 가까운 쪽 귀는 범위의 약 절반까지 돌린 뒤 순서가 머리카락 위로 올라갑니다. 먼 쪽은 페이드아웃(기존).
  3. 반전이 일어나는 쪽에만 적용합니다(비대칭).
  4. 중심선에서 정확히 전환해야 하는 부품은 인접 키 쌍(0과 −ε)으로 계단을 만듭니다.
  5. 그리기 순서는 정수로 보간되며 두 키 사이의 값이 무관한 층을 넘어가면 안 됩니다(CHK).
- 조절 파라미터: `flipThreshold` 0.5 범위, `delta` 0.05–0.1 범위, `epsilon` 범위의 0.01%.
- 엔진 기능: DOK, MK(인접 키 쌍). 난이도 medium. 우선순위 P1.

### draw-order/ring-split — 고리형 장식을 반으로 나누고 단계적으로 내리기
- 목적: 왕관, 머리띠, 후광, 두건을 머리 중심선에서 두 반쪽으로 자르고, 고개를 돌릴 때 먼 쪽 반쪽을 2–3단계에 걸쳐 차례로 앞머리, 옆머리, 얼굴 아래로 내립니다.
- 적용 대상: 의미상 고리형 머리 장식이거나 머리 좌우를 가로지르는 닫힌/반쯤 닫힌 띠 모양 레이어.
- 알고리즘: 방위각 φ → z = cos(φ + θ). AngleX 키(0, ±20, ±40, ±60 등)에서 z를 구해 머리 스택 삽입 위치(앞머리 > 옆머리 > 얼굴 > 뒷머리)로 매핑합니다. 동시에 AngleX로 기하 키를 찍어 타원체 원근 압축을 표현합니다. 두 반쪽의 추가 키는 좌우 미러링합니다.
- 조절 파라미터: `stages` 2(2–3).
- 실패 양상: 원화가 분리되어 있지 않으면 이미지를 잘라야 합니다(픽셀 위에서 임계값으로 자르면 안 되며, 절단선은 기하로 정하고 전체를 두 반쪽에 소속시킴).
- 엔진 기능: DOK, MK, 미러링. 난이도 medium. 우선순위 P1.

### draw-order/depth-slice — 깊이를 가로지르는 조각 분할과 노출 패치
- 목적: 팔짱 등의 포즈에서 같은 팔다리가 여러 그리기 깊이에 걸칩니다. 뒤쪽 조각을 몸통 부품에 넣고 몸통 체인에서 같은 파라미터로 팔다리 움직임을 재현합니다. 팔이 떠난 뒤 가려졌던 영역은 패치 레이어로 교체합니다.
- 알고리즘: 가림 관계에 따라 앞 조각/뒤 조각을 자름 → 뒤 조각은 몸통 변형 체인에 넣고 포즈 파라미터로 불투명도를 줌. 팔다리 체인이 받는 전역 파라미터마다 뒤 조각 앵커 변위를 샘플링해 뒤 조각 warp 키에 맞춤. 패치 = 기본 그림과 포즈 그림에서 몸통의 보이는 픽셀이 다른 영역. 이음새 <0.1% H 검증.
- 조절 파라미터: 이음새 임계값 0.05–0.1% H, 파라미터당 3점 샘플링.
- 엔진 기능: 체인 간 움직임 피팅(다른 체인의 변형 샘플링), Glue. 난이도 research. 우선순위 P2.

## 슬롯 mask(마스크, 머리카락 투과, 투영 그림자 쌍둥이, 머리카락 그림자)

### mask/current — 앞머리 투과와 이목구비 클리핑
- 현황: `SeeThroughLayers`: 눈썹 복사본은 앞머리를 마스크로 사용. 앞머리의 눈 위치 반전 창 + 앞머리 복사본. 홍채는 흰자에, 치아·혀는 입에 클리핑.
- 우선순위: 기본값으로 유지하고 `mask/see-through` 템플릿으로 등록(P0). 그 “복사본 + 기록표 + 완성 단계 제작” 프레임워크는 아래 투영 그림자 쌍둥이의 본보기입니다.

### mask/cast-shadow-twin — 투영 그림자 쌍둥이: 투사체를 따르고 수용체에서 잘림(주 템플릿)
- 목적: 그림자의 형태는 투사체가, 보이는 범위는 수용체가 결정합니다. 그림자 메시를 투사체의 가장 안쪽 변형에 두고(warp와 BS 공유) 수용체를 마스크로 삼아 곱하기로 합성합니다.
- 적용 대상: 머리카락 다발→얼굴, 모자 챙→머리카락/얼굴, 리본→옷 몸판, 치맛자락→허벅지, 외투→점프슈트, 가슴 장식→가슴. 출처는 둘 중 하나입니다. PSD에 이미 그림자 레이어가 있으면(이름에 影/阴影/shadow 포함 또는 곱하기 어두운 색) → 식별, 없으면 투사체에서 생성.
- 출력: 그림자 메시(투사체 토폴로지 사본 또는 독립적인 저밀도 메시). 블렌드 Multiply. 마스크 = 수용체. 부모 = 투사체의 부모. 선택적 추가 시차 warp(AngleX×Y).
- 알고리즘:
  1. 식별: 투사체 = 그림자 위에 있고 외곽 윤곽이 가장 비슷한(Chamfer 거리 최소) 레이어. 수용체 = 아래에서 겹치는 면적이 >20%인 레이어.
  2. 생성: 오프셋 d = L·k·(z_투사 − z_수용)(빛 방향 기본값은 왼쪽 위 약간 앞). 윤곽 수축/페더링. 색 = 그림자를 받는 면의 색 ×0.8(또는 그레이스케일 텍스처).
  3. 시차: 머리 회전 각도 지점에서 그림자에 추가 변위 Δ = −c·(z_투사 − z_수용)·sin(angle), c≈0.3.
  4. 여러 수용체가 서로 다른 분기에 속하거나 순서가 인접하지 않으면 → 그림자를 복사하여 각각 수용체 마스크 하나씩, 순서는 해당 수용체 바로 위에 둡니다.
  5. 스위치: 그림자는 투사체의 스위치 노드와 함께 페이드아웃합니다(같은 DOP 하위 트리에 붙임).
  6. 그림자를 수용체 아래에만 붙일 수 있다면(수용체 변형이 주도): 투사체 움직임 파라미터로 기하를 키잉하고 추종 계수 0.6–0.9.
- 조절 파라미터: `lightDir` 왼쪽 위 45°, `offset` 투사체 너비의 0.3–1.0(또는 0.5–2% H), `opacity` 0.35(0.2–0.5), `parallax` 0.3(0.2–0.5), `split` 자동.
- 실패 양상과 확인: 수용체 자체가 클리핑되어 있으면 마스크를 합쳐야 합니다. 마스크 수 상한. 투사체를 숨긴 뒤 그림자가 남음(CHK: 그림자가 투사체 스위치를 따르지 않음 → warning). 볼 홍조, 머리카락 그림자, 얼굴 그림자와 여러 층이 겹쳐 너무 어두워짐.
- 엔진 기능: MM, 곱하기, 복사본 프레임워크(SeeThrough와 동일: 기록표, 완성 단계 제작, 원본의 모든 편집 추종), DOP 상속.
- 난이도: medium. 우선순위 P1.

### mask/hair-shadow-window — 머리카락 그림자: 그림자 색 얼굴 사본 × 머리카락을 따르는 마스크
- 목적: 얼굴 위 앞머리 그림자가 머리카락과 함께 흔들리고, 얼굴 밖으로 나가지 않으며, 피부 톤을 유지하고, 텍스처 늘어짐으로 가장자리가 변형되지 않게 합니다.
- 출력: 머리카락 조각마다 그림자 마스크 메시 하나(머리카락 조각 윤곽을 빛 방향으로 얼굴 높이의 2–4% 오프셋, 부드러운 가장자리 가능)를 머리카락 조각의 디포머에 붙이고 그 BS를 복사합니다. 수용 레이어 = 얼굴 피부색 × 그림자 색(밝기 ×0.85, 붉은 기)인 얼굴 사본을 얼굴 위에 그리고 모든 그림자 마스크의 합집합을 마스크로 사용합니다. 눈썹 아래와 장식도 마찬가지입니다.
- 조절 파라미터: `offset` 얼굴 높이 3%(2–4%), `darken` 15%(10–20%), `soften`.
- 실패 양상: 마스크는 불투명도를 보지 않으므로 그림자 마스크 메시 자체를 숨겨야 합니다(정적 불투명도 0이지만 여전히 마스크로 동작).
- 엔진 기능: MM(마스크 합집합), 복사본(얼굴 사본, 같은 토폴로지 결합), 숨길 수 있는 마스크 메시.
- 난이도: medium. 우선순위 P1(cast-shadow-twin과 택일하는 같은 슬롯의 다른 해법).

### mask/chin-neck-shadow — 턱 아래 목 그림자: 머리 공간에 붙이고 목으로 클리핑
- 목적: 목 위의 턱 그림자는 머리가 드리우므로 머리 디포머 아래에 붙이고(턱, 입 벌림, 끄덕임을 따름) 목을 마스크로 삼습니다. 또는 얼굴/턱 사본을 반전 마스크로 삼아 절대 얼굴 위에 그려지지 않게 합니다.
- 출력: 띠 모양 Multiply 그림자(턱 윤곽 아래 가장자리를 따라 0.08 FW 오프셋, 부드러운 가장자리). 부모 = 머리 회전 warp(또는 입 벌림 warp). 마스크 = 목(정방향) 또는 턱 사본(반전). AngleY 키: 고개를 숙이면 넓고 길어지고(목 높이의 10–15% 더 덮음) 들면 좁아지며, 위로 드는 절반 지점에 중간 키를 추가해 비선형 수축을 표현합니다. AngleX에서는 고개를 돌리는 반대 방향으로 치우칩니다.
- 조절 파라미터: `offset` 0.08 FW(0.05–0.1), `opacity` 0.4(0.3–0.5), `midKey` 0.5(0.4–0.6).
- 엔진 기능: MM, RM(선택), MK. 난이도 easy. 우선순위 **P0**(저비용, 보편적, 목과 머리 체인이 이미 있음).

### mask/contour-cutter — 반전 마스크 절단 메시로 윤곽 조각
- 목적: 방향 전환에 따라 바뀌는 윤곽(아래턱, 턱, 덩어리 겹침 가장자리)을 텍스처를 늘이지 않고, 각도에 따라 정확히 움직이는 “지우개”로 보이는 경계를 잘라냅니다.
- 알고리즘: 3D 프록시(머리 타원체 + 아래턱 곡선)로 포즈별 목표 윤곽을 구합니다. 절단 메시 = 목표 윤곽 바깥쪽 띠 모양 다각형(너비 0.1–0.2 FW). 키 위치는 정면 근처를 고밀도화(x_k = sign(k)·30°·(|k|/K)^1.4, K=12) + AngleY 13키. 대상 레이어의 반전 마스크 = 절단 메시. 윤곽 선화는 잘리지 않는 외곽선 레이어를 따로 둡니다. 덩어리 겹침 버전은 잘리는 몸과 같은 물리 체인에 붙입니다.
- 실패 양상: <4.0에는 RM이 없음. 마스크 수 상한. 선화가 잘림.
- 엔진 기능: RM, MK(비균일), 3D 프록시. 난이도 research(용도는 추론). 우선순위 P2.

### mask/interleave-cutout — 반전 마스크로 교차 깊이 표현
- 목적: 긴 띠(꼬리, 리본, 엄지)가 가리는 물체와 일부는 앞, 일부는 뒤에 있을 때, 긴 띠 전체를 가리는 물체 뒤에 그리고 가리는 물체를 “앞에 있어야 할 구간들”로 반전 클리핑해 구멍을 냅니다.
- 알고리즘: 각 구간 중심에서 원화에서 무엇이 보이는지 판단 → 전부 앞/전부 뒤면 일반 순서, 그렇지 않으면 S를 O 뒤에 두고 O는 앞에 있어야 할 구간의 합집합을 반전 마스크로 사용. <4.0이면 O를 분할하거나 draw-order/additive-offset을 사용합니다.
- 조절 파라미터: 가리는 물체당 마스크 수 상한.
- 엔진 기능: RM, MM. 난이도 medium. 우선순위 P1.

### mask/pattern-slide — 윤곽 마스크 안 표면 무늬 슬라이드(유사 3D 회전)
- 목적: 꼬리, 소매 등 원기둥형 부품의 무늬가 윤곽 마스크 안에서 가로로 미끄러져 굴러가거나 비틀리는 것처럼 보이게 합니다.
- 알고리즘: 무늬와 윤곽을 분리합니다(아트에서 미리 나눠야 하며 픽셀에서 자르지 않음). 무늬 메시는 같은 구간의 디포머에 붙이고 윤곽 합집합으로 마스크합니다. 구간마다 회전 파라미터 하나, 키폼은 수직 중심선을 따라 구간 너비의 ±30–50% 평행 이동하고 가장자리 근처는 cos 압축. 두 번째 진자(delay ×0.8) 또는 각속도로 구동. 무늬 텍스처는 윤곽 밖에 여유를 둡니다.
- 조절 파라미터: `rollAmp` 40%(30–50%), `phaseDelay` 0.8.
- 엔진 기능: MM, PHY(두 번째 진자). 난이도 hard. 우선순위 P2.

## 슬롯 toggle(표정, 의상 교체, 변형 슬롯, 게이트, 크로스페이드, 전환 파라미터)

### toggle/current — 차분 0/1 불투명도
- 현황: TOGGLE/SWITCH 레이어가 각각 0/1 불투명도 파라미터를 생성합니다. 표준 표정은 얼굴 파라미터 오프셋입니다.
- 우선순위: 기본값으로 유지(P0 등록). 아래 템플릿은 “스위치”를 구조(누가 양보하는가) × 타이밍(어떻게 전환하는가) × 묶음(파라미터 몇 개인가) × 출력(표정/핫키)의 네 직교 차원으로 확장합니다.

#### 구조 계열

### toggle/product-gate — 곱셈 게이트(NOR): 기본 부품이 어떤 대체 부품에든 양보(주 템플릿)
- 목적: 기본 부품 불투명도 = Π(1 − T_i). 모든 스위치가 0일 때 보이고 하나라도 켜지면 숨깁니다. 배타 관계를 표정 파일의 덮어쓰기 순서에 의존하지 않고 리그 안에 작성합니다.
- 적용 대상: 기본 부품 D + 대체 부품 집합 {A_i, T_i}(눈 모양, 입 모양, 팔 포즈 차분, 헤어스타일, 의상).
- 출력: 게이트는 D의 부모 그룹 디포머(DOP)에 두며 축 T_1…T_n, 축마다 두 키 {0, t_off}. 불투명도만 채우고 기하는 모두 기본 형태를 복사합니다. n>6이면 그룹 중첩: 게이트 warp 두 층이 각각 한 그룹의 NOR를 만들고 층별 불투명도 곱으로 결합합니다. 대체 부품 A_i는 T_i만 축으로 둡니다.
- 조절 파라미터: `tOff` 0.5(morph-swap 2단계와 함께) 또는 1, `groupSize` 6.
- 실패 양상과 확인: 숨겨진 부품이 다른 부품의 마스크 소스라면 숨긴 뒤 상대의 클리핑도 사라집니다(CHK: 게이트 하위 트리에 마스크 소스 포함 → warning). 숨겨진 부품의 물리는 계속 실행됩니다(허용). 스위치가 동시에 켜지면 대체 부품이 겹칩니다(우선순위 또는 signed-slot 필요).
- 엔진 기능: PG, DOP(미지원 시 메시마다 내려보내 키 수가 곱해짐 → 손실 보고서).
- 난이도: easy. 우선순위 **P0**.

### toggle/slot-swap — 슬롯 교체: 그룹 디포머 불투명도로 그룹 전체 전환
- 목적: 선택 부품을 “슬롯”(머리 위 장식, 오른쪽 아래팔, 뒷머리, 손에 든 물체)별로 묶고, 선택지마다 불투명도 축만 가진 그룹 디포머 하나를 두어 스위치 하나로 “기존 부품 숨김 + 새 부품 표시”를 동시에 합니다. 대체 부품은 원래 부품과 같은 가장 안쪽 포즈 warp 아래에 붙어 전환 후에도 고개 돌림/물리를 그대로 따릅니다.
- 적용 대상: 레이어 주석에 슬롯과 선택지가 표시된 경우(명명 규칙 `slot@option`) 또는 PSD 차분 그룹.
- 출력: 선택지마다 게이트 디포머 G_i 하나(선택지 바운딩 박스를 덮고 변형 없음). 기본 선택지 G_0은 product-gate 사용. 대체 부품은 기본 부품과 같은 관절/포즈 체인에 붙이고(차분 주석으로 부착 관절 표시: 팔꿈치/손목) 물리를 상속합니다.
- 조절 파라미터: 크로스페이드 타이밍(타이밍 계열 템플릿 참조), 표정 페이드인 0.3–0.8 s.
- 실패 양상: DOP를 지원하지 않는 대상으로 내보낼 때는 메시마다 내려보내야 합니다. 대체된 부품도 여전히 물리와 마스크에 참여합니다.
- 엔진 기능: DOP, PG, HOST(표정). 난이도 easy. 우선순위 **P0**.

### toggle/signed-slot — 부호 있는 변형 슬롯: 파라미터 하나의 양 끝에 서로 배타적인 두 변형
- 목적: 의미상 배타적인 두 변형을 같은 파라미터의 −1과 +1에 두어 파라미터 수를 절반으로 줄이고 배타성을 구조로 보장합니다. 0을 지나는 기본 상태 전환이 있으며, 두 슬롯의 곱으로 기본 부품을 게이트합니다.
- 적용 대상: 눈 모양, 홍채 모양, 입 모양, 볼 홍조 단계, 만화 기호, 파티클 그룹 선택.
- 출력: 슬롯마다 p ∈ [−1, 1](변형이 많으면 [−2, 1] 3상태로 확장). 음수 끝 변형 불투명도 max(0, −p), 양수 끝 max(0, p). 기본 부품 Π_slots(1 − |p|)(슬롯마다 키 {−1, 0, 1}). 모든 변형은 같은 추적/원근 warp(시선, 개폐, 고개 돌림)에 붙입니다. 선택적으로 기본 부품만 페이드아웃하는 별도 `off` 파라미터. 선택적 “팝”: 그룹 warp가 0→±1에서 0.6에서 1로 스케일, ±0.7에서 1.1 오버슈트.
- 조절 파라미터: `crossfadeWidth`(반 구간 전체 선형, 또는 ±0.1로 더 딱딱하게), `popScale` 0.6→1.1.
- 실패 양상: 변형이 눈 깜빡임에 따라 닫히지 않음(개폐 warp 아래에 붙이거나 개폐 파라미터도 게이트해야 함). 슬롯이 2개를 넘으면 기본 부품의 키 차원이 3^n이 되므로 파츠 불투명도나 표정 파일로 바꿔야 합니다(CHK).
- 엔진 기능: PG, MK, DOP. 난이도 easy. 우선순위 P1.

### toggle/state-machine — 표정 상태 머신: one-hot 상태 파라미터 + 그룹 불투명도 진리표
- 목적: 표정마다 상태 파라미터 E_i ∈ [0,1] 하나, 표정 파일 = one-hot. 얼굴 변형(뜬 눈 그룹, 감은 눈 선 그룹, ^^ 눈, ○ 눈, >< 눈, 눈물, 입 모양 그룹)마다 그룹 디포머 하나, 불투명도 = 진리표 V(blink, E_1..E_n).
- 적용 대상: 얼굴 차분이 풍부하고 표정이 “그림 교체 + 변형”인 모델.
- 알고리즘:
  1. 변형에 적용 표정을 표시합니다: `eyeL: {open:[neutral,rage,…], happyClosed:[cheek], circle:[sp8,sp10], blinkLine:[*]}`.
  2. 각 변형에는 실제로 영향을 주는 축만 추가하고(≤6축) 축마다 키 {0, 전환점, 1}에 0/1을 채웁니다. 내부적으로 “어떤 E_i든 임계값을 넘으면 숨김”이라는 max 규칙을 쓸 수 있으며 내보낼 때 격자로 베이크합니다.
  3. 감은 눈 선 그룹은 눈 깜빡임과 표정 모두의 제어를 받아야 합니다(기호 눈 상태에서 깜빡일 때 일반 감은 눈 선이 드러나지 않게).
  4. exp3 생성: 표정마다 {E_i=1}, 중립 = 모두 0, 페이드인·아웃 0.5 s.
- 실패 양상: 두 표정이 동시에 1이면 진리표가 정의되지 않으므로 우선순위나 배타 관계를 명시해야 합니다.
- 엔진 기능: PG(진리표 → 키 격자), DOP, HOST. 난이도 medium. 우선순위 P1.

### toggle/variant-twin — 변형 쌍둥이 메시(색/텍스처 교체 버전)
- 목적: 같은 레이어의 변형 버전이 원래 메시 토폴로지를 복사하고 모든 부모 디포머/물리/글루를 공유하며 마지막 층에서만 불투명도로 페이드인합니다. 조합 변형은 곱 키를 사용합니다(헤어스타일 H × 색 변경 V).
- 출력: 쌍둥이 메시를 원본 바로 위에 둡니다. 불투명도 축 V. 원본은 페이드아웃하지 않습니다(위층이 덮으면 충분하며, 변형에 투명 영역이 있으면 staggered-crossfade로 원본을 페이드아웃). 쌍둥이 사이에 글루 쌍을 복사합니다.
- 엔진 기능: 복사본 프레임워크, PG, Glue 복사. 난이도 easy. 우선순위 P1.

### toggle/recolor — 색 변경: 채널 키폼 + 미리 그린 대역 크로스페이드, 종속 스위치 곱셈 게이트
- 목적: 부위 X의 곱하기/스크린 키폼으로 목표 색을 만들고, 그 위에 원래 색의 같은 형태 사본 X′를 겹쳐 전환 시 페이드아웃합니다. 원래 색일 때는 완전히 원화이고 색을 바꾸면 조정된 색이 됩니다. 종속 스위치(시스루 치마 색 변경은 시스루 치마가 켜졌을 때만 적용)는 T_parent × T_child 곱을 사용합니다.
- 알고리즘: X′와 X는 같은 부모·같은 키폼(또는 전체 결합). X는 T=1에서 multiply = 목표 색/원래 색의 근사 비, screen으로 어두운 부분을 올림. X′ 불투명도 T=0:1 → T=1:0–0.05. 곱하기로 밝게 만들 수 없으면 미리 그린 대역만 사용할 수 있습니다.
- 조절 파라미터: `residual` 0.05(0–0.1).
- 엔진 기능: 채널 키폼(multiply/screen, 4.2), PG, same-topology-lock. 난이도 easy. 우선순위 P1.

### toggle/outfit-blend — 전체 의상 교체: 블렌드 셰이프가 불투명도와 기하 차이를 함께 운반
- 목적: 두 의상의 대응 부위를 같은 부모 warp에 붙이고(물리, 몸 키폼은 한 번만), 의상 교체 파라미터를 “가산” 층으로 둡니다. 기존 의상 −1, 새 의상 +1 불투명도에 약간의 기하 보정을 더하며, 각도와 물리는 그대로 작동하고 키폼은 두 배가 되지 않습니다.
- 알고리즘: 의미 태그로 두 의상의 부위를 대응시킵니다. T ∈ [0,1] BS: 기존 의상 불투명도 −1, 새 의상 정적 0 + BS +1. 윤곽이 다른 곳은 공용 부모 warp에 T의 기하 BS를 추가합니다. 새 의상의 “밑색 층”은 T=0.5에서 이미 0.7–0.8에 도달하거나, 0.1–0.2 엇갈려 비침을 막습니다. 새 의상에 의존하는 장식은 곱셈 게이트를 사용합니다.
- 조절 파라미터: `stagger` 0.15(0–0.2), 기하 보정 폭.
- 실패 양상: 대상이 채널 BS를 지원하지 않으면 T축 키폼으로 베이크해야 합니다(키 수 ×2). 다른 배타 스위치와 공존할 때는 반드시 리그 안에서 곱셈 게이트를 사용해야 합니다.
- 엔진 기능: BSC(불투명도 BS, 5.0 Extended, umamo는 모델링하지 않음) → T축 키폼 + DOP로 하위 호환. 난이도 medium. 우선순위 P2(채널 BS 모델링 후 P1로 상향).

### toggle/staged-transition — 스위치 = 짧은 애니메이션: 단일 파라미터 안에서 전환 연출(주 템플릿)
- 목적: 호스트 표정은 목표값과 페이드인 시간만 설정할 수 있습니다. “파라미터 값”을 “시간”으로 삼아 변위, 순서, 반짝임을 연출하여 핫키 하나로 움직임이 있는 전환을 얻습니다.
- 적용 대상: 스위치 가능한 소품/변형/의상. 아래층의 가려진 영역은 완전히 그려져 있어야 합니다(커버리지 검사).
- 출력: 파라미터 T ∈ [0,1](호스트 측에서 0..30으로 매핑 가능), 기본값 0. Add 표정 T=1 + 핫키로 내보내며 페이드인 ≥0.5 s를 권장합니다. 전환은 의상 하위 트리 최상단의 전환 디포머(기하 + 불투명도)에 작성합니다.
- 알고리즘(범주에 따라 하위 템플릿 선택):
  - 등장(appear): 출처 방향에서 변위 d만큼 들어오며 동시에 페이드인. 머리 위 소품 d = −0.1 물체 높이, 소환물 d = 0.3–1 물체 높이, 안경 d ≈ 0.03 EH(5–10% 살짝 확대).
  - 착용(wear-in): 양말/장갑/토시는 팔다리 주축을 따라 먼 끝에서 가까운 끝으로 미끄러지고, 모자는 위에서 떨어집니다. d = 부속품 길이의 15–30%. 그림자/곱하기 층의 최종값은 원화를 따르고 같은 곡선으로 페이드인. 오프셋은 반드시 그 마스크 안에 있어야 합니다. 부속품에 물리가 있으면 스위치 키는 물리 warp 안에 둡니다.
  - 퇴장(exit / lift-off): 반대 방향 변위와 페이드아웃. 큰 부품은 “먼저 떠오른 뒤 나눠서 페이드아웃”: 키 {0, 0.25, 0.5, 1}, 부착점에서 방사 + 상승 d(T) = D·{0, 0.25, 0.6, 1}(D = 의상 높이의 0.8–1.2), 각 조각은 바깥으로 10–20° 회전. 불투명도는 T≤0.25에서 모두 1, 이후 조각 면적순으로 정렬하여 큰 조각은 느리게(0.5에서 0.6), 작은 조각은 빠르게(0.5에서 0.35), 딸린 끈은 선형.
  - 교체(replace): 기존 부품은 [0, 0.66]에서 페이드아웃, 새 부품은 같은 구간에서 페이드인하며 호를 따라 자리 잡음(중간 키의 호 높이는 변위의 약 0.2). 물리가 있는 2차 부품(리본, 체인)은 [0.66, 1]에서야 나타납니다(빠른 보간 중 마구 휘둘리는 것 방지). 반짝임은 [0.67, 1]에서 훑고 지나갑니다(effect/sweep-glint).
  - 접기(fold): toggle/fold-to-anchor 참고.
- 조절 파라미터: `phaseSplit` 0.66(0.5–0.8), `offsetDir`, `offsetLen`, `arcRatio` 0.2(0.1–0.3), `fadeOrder`(면적순).
- 실패 양상과 확인: 아래층이 완전히 그려지지 않으면 구멍이 드러납니다. 커버리지 검사: 가려진 영역에서 아래층 alpha ≥0.95인 비율이 ≥98%가 아니면 warning(픽셀에서 자동으로 보충하지 않음). 호스트에 페이드인 시간이 없으면 전환 연출은 사라지지만 최종 상태는 올바릅니다. T가 중간에 멈추면 반쯤 떠오른 중간 상태가 됩니다(표정은 0/1에만 머묾).
- 엔진 기능: MK, DOP, 하위 트리 최상단에 전환 디포머 삽입, HOST(Add 표정, 핫키, 페이드인 시간), CHK(커버리지 검사).
- 난이도: medium. 우선순위 **P0**(appear / exit / replace 세 하위 템플릿). lift-off 분할 페이드아웃은 P1.

### toggle/fold-to-anchor — 분리 가능한 모듈을 부착점으로 축소한 뒤 페이드아웃
- 목적: 분리 가능한 그룹(머리 번, 머리끝, 리본, 모자, 외투) 최상층에 rotation을 하나 삽입하고 원점 = 부착점으로 둡니다. 전환 시 부착점으로 축소한 뒤 페이드아웃하여 “집어넣는” 애니메이션을 만듭니다. 모듈 조합으로 여러 헤어스타일/차림을 만듭니다.
- 출력: `Toggle<Group>` 0..1: 0 → scale 1/opacity 1, 0.6 → scale 0.3/opacity 0.5, 1 → scale 0.001–0.05/opacity 0. 각도는 바뀌지 않습니다. 단일 항목 표정 + 자주 쓰는 조합(좌우 대칭 그룹, 핵심만 남기기)을 생성합니다.
- 조절 파라미터: `endScale` 0.02(0.001–0.05), `fadeStart` 0.6(0.4–0.7), 조합 표정 목록.
- 실패 양상: 축소 시 그룹을 가로지르는 강한 Glue가 본체 정점을 부착점 쪽으로 끌어당깁니다(CHK: 분리 가능한 그룹과 본체 사이에 Glue → warning, 또는 T>0에서 Glue 강도를 0으로 키잉). 숨겨진 그룹이 다른 부품의 마스크 소스인 경우.
- 엔진 기능: rotation 스케일, DOP, HOST. 난이도 easy. 우선순위 **P0**.

### toggle/staggered-crossfade — 엇갈린 크로스페이드
- 목적: 대칭 크로스페이드는 중간점에서 두 층이 각각 50%라 합성 불투명도가 75%뿐이어서 아래가 비칩니다. 위층의 새 부품을 먼저 가득 채우고 아래층의 기존 부품을 나중에 물러나게 하여 언제나 적어도 한 층은 100%가 되게 합니다.
- 알고리즘: 새 부품 순서가 기존 부품보다 높음 → 새 부품 [0, 0.5] 페이드인, 기존 부품 [0.5, 1] 페이드아웃, 반대면 서로 바꿈. 그리기 순서를 바꿔야 하면 중간점에서 딱 끊고 그 순간 두 부품 모두 100%. 새 부품과 겹치는 기존 부품은 (1−t)²로 더 빨리 페이드아웃할 수 있고(잔상 감소), 겹치지 않는 부품은 선형.
- 조절 파라미터: `overlap` 0(0–0.25), `fadeExponent` 1(1–3).
- 엔진 기능: MK, DOK. 난이도 easy. 우선순위 **P0**(모든 스위치의 기본 타이밍).

### toggle/morph-swap — 먼저 납작하게 누른 뒤 그림 교체(변형 브리지)
- 목적: 두 그림의 형태가 거의 같아지는(선 하나) 순간에 전환하여 전환이 보이지 않고, 전환이 연속 애니메이션으로 읽히게 합니다(“한 번 깜빡이며 >< 눈으로 변함”).
- 알고리즘: 브리지 형태 = 둘의 공통 퇴화 형태(눈 중심을 중점으로 하는 0.9 눈 너비의 가는 수평선, 두께 3–8% EH). A: 0 원래 형태 → t_s에서 브리지 형태로 눌림. B: t_s+ε 브리지 형태 → 1 원래 형태(0.75에서 5% 확대 팝). 불투명도 A는 [0, t_s]에서 1, t_s+ε에서 0, B는 반대. 그룹 전체에 그룹 디포머 불투명도 사용.
- 품질 확인: A, B 브리지 형태 중심 거리 <1% FW. ε ≤0.02. 표정은 0/1에만 머묾.
- 조절 파라미터: `tSwitch` 0.5(0.4–0.6), `epsilon` 0.01(0.005–0.02), `squash` 0.15(0.1–0.3).
- 엔진 기능: MK(인접 키 쌍), DOP. 난이도 easy–medium. 우선순위 P1.

### toggle/bridge-layer — 전환 브리지 그림
- 목적: 윤곽을 맞춰도 전환할 때 선 굵기, 그림자, 손 모양이 여전히 튑니다. 전환 순간에 두 원화 사이의 전환 그림을 불투명도 최대로 나타낸 뒤 선형으로 페이드아웃하여 최종 그림에 자리를 넘깁니다(최종 그림은 항상 아래에 깔림).
- 알고리즘: 차이 Δ가 임계값을 넘으면 생성합니다. 출처는 아트의 중간 그림을 우선하며, 자동 방안은 전환 포즈에서 두 그림의 메시 대응점을 평균하여 다시 래스터화하거나 가장 크게 튀는 국소 부분을 복사합니다. 최종 상태 분기에 붙이고 그리기 순서는 최종 상태 바로 위. 자체 불투명도 키 {s+ε:1, e:0}, 부모 분기는 s+ε 이전에 0.
- 조절 파라미터: `fadeEnd` 0.85(0.7–1), 전환마다 0–2장.
- 엔진 기능: MK, DOP 곱. 난이도 research(전환 그림 자동 생성). 우선순위 P2.

### toggle/gated-axis — 게이트 축: 스위치가 추적을 덮어쓰지 않고 수정
- 목적: 보정형 스위치(감정, 모드)는 연속 축 끝점의 형태만 바꿉니다. 화날 때 찡그림은 더 사납지만 눈썹 추적은 여전히 유효합니다. 상호작용형 스위치(클릭)는 0일 때 X/Y 평면 전체가 중립 형태와 같습니다(반응하지 않음).
- 알고리즘: 스위치가 작용하는 연속 축 집합을 선언합니다. Toggle[0,1] × Axis 키 격자를 생성하며, Toggle=1 행은 Axis 기본값에서 원래 형태와 같거나 작은 오프셋만 둡니다. 상호작용형은 Gate × X × Y. 같은 객체에 게이트 스위치가 여러 개면 곱셈 격자 대신 BS(가산)를 사용합니다.
- 조절 파라미터: 작용 축, 변형 강도.
- 엔진 기능: MK, PG, BS. 난이도 medium. 우선순위 P1.

### toggle/pose-macro — 표정 = 스위치 + Add 오프셋의 포즈 매크로
- 목적: 표정 파일이 스위치 집합과 연속 파라미터 Add 오프셋을 한 번에 설정하여 실시간 추적 위에 겹칩니다(“사진 찍기”: 펜 들기, 고개 갸웃, 아래 보기, 입을 반쯤 벌리고 웃기).
- 알고리즘: 감정 템플릿 = {이펙트 스위치: 1, 얼굴 오프셋: {BrowForm, MouthForm, EyeOpen, MouthOpenY, AngleY/Z…}}, 오프셋은 전체 범위의 10–60%(0.6을 넘으면 잘림). 눈 개폐 오프셋이 음수일 때 ≤0.2. 색 덮개층 최대 불투명도 0.6–0.8이며 얼굴 피부 + 귀를 마스크로 사용. 여러 Add 표정을 동시에 켜면 범위를 넘으므로 → 배타 그룹 또는 Overwrite.
- 엔진 기능: HOST(exp3 Add/Multiply). 난이도 easy. 우선순위 P1(`ModelSidecars.standard` 대체).

### toggle/storyboard-param — 단일 파라미터 단계 애니메이션(콘티 → 파라미터 단계)
- 목적: 짧은 연출(편지 열기, 물체가 몸 뒤로 날아감)의 여러 단계를 파라미터 범위 하나에 배치합니다. 단계 안은 일반 키폼, 단계 경계는 인접한 세 키 t_i−δ, t_i, t_i+δ로 불투명도/그리기 순서를 즉시 전환합니다. 모션은 곡선 하나만 있으면 됩니다.
- 조절 파라미터: `delta` 범위의 0.2%(0.1–0.5%).
- 엔진 기능: MK(인접 키), DOK, MOT. 난이도 medium. 우선순위 P2.

### toggle/handoff-twin — 소품 인계: 서로 다른 부모에 붙인 두 사본 + 크로스페이드
- 목적: 런타임에는 부모를 바꿀 수 없습니다. 소품이 한 공간(옷깃, 허리 옆)에서 손으로 옮겨갈 때 두 사본을 각각 올바른 부모에 붙이고 손이 가리는 순간에 크로스페이드하며, 부모 디포머 불투명도로 하위 트리 전체를 페이드아웃합니다.
- 알고리즘: P_A(부모 A), P_B(부모 B, 기하를 B의 로컬 공간으로 변환해 인계 시점에 정렬). swap 0..1, 전환 구간 20–30%. 모션은 손과 소품이 겹치는 프레임에 전환을 둡니다. 각 사본은 자체 물리/포즈 파라미터를 가집니다.
- 엔진 기능: DOP, 복사본, MOT. 난이도 medium. 우선순위 P2(prop 슬롯과 공유).

## 슬롯 effect(이펙트)

### effect/current — 없음
- 현황: 이펙트 생성기가 없습니다. 내부 조형(`NativeInteriorEffect`)이 유일한 “이펙트 레시피” 선례이며, 그 레시피 + 자체 파라미터 + 네이티브 blend 필드 + 무효화 전파 프레임워크를 재사용할 수 있습니다.

### effect/loop-cycle — 순환 위상 파라미터(생애 주기 파라미터)
- 목적: Live2D에는 시간이 없습니다. 0..1 위상 파라미터 하나는 양 끝 키폼이 완전히 같기만 하면 선형으로 진행할 때 이음새 없이 순환합니다. 여러 객체가 같은 파라미터에서 창을 엇갈리게 두면 = 위상이 다른 파티클 흐름이 됩니다.
- 적용 대상: 눈물방울, 땀, 반짝임, 불꽃, 별빛, 자전 장식(눈송이, 톱니바퀴, 마법진), 떠오르는 하트.
- 출력: 위상 파라미터 c ∈ [0,1](repeat 표시). 선택적 강도 파라미터 I와 c의 곱 격자(|I| ≥ θ_i이면 i번째 입자 활성, θ 증가 → 강도가 클수록 입자 수 증가). 상시 순환 모션(톱니 / 램프) 또는 호스트 순환 매핑.
- 알고리즘:
  1. 단일 객체: 창 [a, a+w](w 0.25–0.4) 안에서 처음 15% 동안 페이드인/스케일 s0에서 1로 성장, 경로를 따라 이동, 마지막 15% 동안 페이드아웃. 창 밖에서는 불투명도 0이며 기하는 시작점으로 돌아갑니다.
  2. 다중 객체: a_i = i/(n·c) + 지터(결정적 시드, 저불일치 수열 0, 0.4, 0.7, 0.2…), 순환마다 c번 나타나게 할 수 있습니다.
  3. 무작위감: 스프라이트마다 불규칙한 내부 키 4–9개를 결정적으로 배정합니다. 스프라이트가 많으면 비슷한 곡선끼리 파라미터 10–15개로 묶어 파라미터마다 여러 스프라이트를 구동합니다.
  4. 자전: rotation 키 0→0°, 1→±360°(같은 파라미터에 정·역 두 세트 → 하나는 순방향, 하나는 역방향). 모션에 0→n 선형 램프를 쓰면 = n배속.
  5. 순간 이동 순환(속도선): [t, t+0.3%] 안에서 끝점에서 시작점으로 점프하며 그룹마다 t를 엇갈리게 둡니다.
  6. 모션: 주기 T 톱니파(한 프레임에 0으로 복귀), 선형 구간(베지어는 순환점에서 속도가 급변). 이펙트 모션 주기와 캐릭터 대기 주기는 서로소 비율(예: 8:9)로 둡니다.
  7. 하위 호환: 대상이 repeat를 지원하지 않으면(<5.3) 0..1 선형 + 모션 순환점에서 하드 점프(양 끝 상태가 같아 보이지 않음).
- 조절 파라미터: `window` 0.3(0.25–0.4), `fadeFrac` 0.15(0.1–0.2), `period` T(땀 0.3–0.6 s, 별빛 10–20 s, 자전 4–12 s/바퀴), `count` 4–8, `paramGroups` 10–15.
- 실패 양상과 확인: 처음과 끝은 정점별로(불투명도, 색 포함) 반드시 일치해야 합니다(CHK: c=0과 c=1 평가 차이 > 0.5 px 또는 >0.01 불투명도 → error). 창의 합이 >1이면 두 입자가 같은 위치에 겹칩니다. 회전 원점은 반드시 스프라이트 중심이어야 합니다.
- 엔진 기능: RPT(umamo에서 실제로 모델링 필요: 평가 랩어라운드, 미리보기, 내보내기 플래그), MK, MOT(톱니/램프/위상 오프셋), PG(강도 × 위상).
- 난이도: easy–medium. 우선순위 P1(RPT 모델링 필요).

### effect/burst — 일회성 폭발: 진행도 파라미터가 파티클 그룹을 구동
- 목적: “모션 안의 곡선 수십 개”를 리그 안의 진행도 파라미터 p 0→1 하나로 압축합니다. 파티클이 작은 스케일에서 튀어나오고 세 단계 위상으로 엇갈려 무작위처럼 보입니다.
- 출력: 파티클마다 rotation 하나(원점 = 파티클 중심), 키 p ∈ {0, a_i, a_i+w/2, a_i+w, 1}. 위치 C → C+R·d_i(R = 0.2–0.4 H, ease-out). 스케일 a_i:0.15 → 중간점 1 → 끝 0.8. 불투명도 창. a_i는 세 단계 {0.15, 0.25, 0.35}를 순환, w = 0.5. 파티클 그룹은 signed-slot으로 선택. 회전형 파티클에는 loop-cycle을 추가합니다.
- 조절 파라미터: `phaseStep` 0.1, `window` 0.5(0.4–0.6), `startScale` 0.15(0.1–0.2), `radius` 0.3 H.
- 실패 양상: 파티클 부모 디포머는 고개 돌림을 따르면 안 됩니다(얼굴에 붙인 경우 제외).
- 엔진 기능: rotation 스케일, MK, MOT(0→1 사선). 난이도 medium. 우선순위 P2.

### effect/collapsed-rest — 붕괴된 정지 형태: 이펙트가 한 점에서 자라남
- 목적: 이펙트 메시의 정지 기하를 방출점으로 축소하여 불투명도 보간이 잘못되거나 파라미터가 꺼져도 절대 보이지 않게 합니다. “한 점에서 자라나는 것”이 곧 등장 애니메이션이며 기본 포즈가 깔끔합니다.
- 알고리즘: 방출점(눈물: 눈 안쪽 아래 모서리, 털 곤두섬: 헤어라인, 콧물 방울: 콧구멍, 땀: 관자놀이). 정지 기하의 모든 정점을 방출점 쪽으로 1–5%까지 축소(토폴로지 불변). 최대값 = 원화 기하, 70% 지점에서 1.05–1.15 오버슈트. 정지 불투명도도 0.
- 조절 파라미터: `collapse` 0.03(0.01–0.05), `overshoot` 1.1(1.05–1.15).
- 실패 양상: 붕괴된 메시는 에디터에서 선택하기 어렵고 메시 밀도 통계가 왜곡됩니다(CHK 통계에서 제외해야 함).
- 엔진 기능: 키폼 생성 시 “정지”를 원화가 아닌 기하로 설정 가능(기본 키 ≠ 원화). 난이도 easy. 우선순위 P1(모든 effect의 기본 등장 방식).

### effect/manga-symbol — 만화 기호 시스템(감정 패치)
- 목적: 핏대, 땀방울, 어두운 선, 홍조 사선, 생각 풍선, 음표, 털 곤두섬 등 절차적으로 생성하거나 PSD가 제공하는 감정 패치를 이목구비 앵커에 따라 배치하고, 얼굴 각도 warp에 붙여 고개 돌림을 따르게 하며, 불투명도와 움직임을 같은 축으로 두고 피부에 클리핑합니다.
- 알고리즘:
  1. 앵커(이목구비 기준): 핏대는 눈 바깥 모서리에서 바깥 위로 0.6 EW, 땀방울은 관자놀이 쪽, 어두운 선은 이마에서 눈까지 덮음, 홍조는 볼, 생각 풍선은 머리 위 옆쪽.
  2. 키폼: 등장 = 파라미터 0..0.3 안에서 스케일 0→1.1→1(collapsed-rest). 박동 = 짝지은 인접 키 또는 throb 파라미터로 스케일 ±10–15%(모션 2 Hz). 미끄러져 들어옴 = 어두운 선이 패치 높이의 10–20% 아래로 미끄러짐. 볼 홍조 5–10% 확대.
  3. 마스크: 얼굴 피부 + 귀 다중 마스크. 생각 풍선 내용은 풍선 몸체를 마스크로 삼고 내용 스크롤 파라미터를 둡니다.
  4. 반대 감정 쌍마다 signed-slot 파라미터 하나.
  5. 최대 불투명도 0.35–0.7(색 층 상한).
- 조절 파라미터: 크기(핏대 1 EW, 땀방울 0.5 EW), `maxOpacity` 0.6, `throb` 12%.
- 엔진 기능: MM, MK, signed-slot, 벡터 템플릿 텍스처(절차적 생성은 research). 난이도 medium. 우선순위 P1(PSD가 패치를 제공할 때의 배치와 키) / P2(텍스처 절차적 생성).

### effect/sweep-glint — 스윕 광택: 가산 그라데이션 띠를 금속 부품에 클리핑
- 목적: 금속, 보석, 유리 부품에 비스듬한 가산 그라데이션 띠를 생성하고 이 부품들을 마스크로 삼아, 스위치 전환이나 순환 파라미터에서 한 번 가로질러 훑게 하여 한눈에 “반짝였다”로 읽히게 합니다.
- 출력: 그라데이션 띠 메시(너비는 바운딩 박스 대각선의 약 0.3, 30–45° 기울기, 메시는 매우 거칠게). 가산 블렌드. 마스크 = 해당 물체의 모든 메시(물체별 그룹화). 키폼: 바운딩 박스 한쪽 바깥에서 시작해 다른 쪽 바깥에서 끝나며 불투명도 0→1→0. 스위치 T의 지정 구간(staged-transition의 [0.67,1]) 또는 loop-cycle에 붙입니다.
- 조절 파라미터: `bandWidth` 대각선의 0.3(0.2–0.4), `angle` 35°, `peakOpacity` 0.8(0.6–1).
- 실패 양상: 마스크 부품이 너무 많으면 비용이 늘어납니다. 스윕 방향은 물체 주축과 비스듬히 교차해야 합니다.
- 엔진 기능: MM, 가산 블렌드, MK. 난이도 easy. 우선순위 P1.

### effect/ambient-fx — 환경 이펙트 라이브러리(깜빡임, 표류, 흐르는 빛, 와이프, 날갯짓, 마스터 스위치)
- 목적: 매우 저비용의 환경 움직임: 사각형 파티클 깜빡임, 그룹 표류, 띠 흐르는 빛, 반전 마스크 와이프, 6점 나비 날갯짓, 이펙트 트리 루트의 전체 페이드아웃 파라미터.
- 하위 템플릿:
  - twinkle(quad): 불투명도 0..1 반 사인, 주기 ∈ {T, 2T, 4T}, 위상은 결정적 무작위.
  - drift(group): 그룹 warp 평행 이동 BS ±(0.3–1% H), 주기 2T.
  - streak(strip): 2×N 띠. 국소 파형 기저 K개(창 안 sin의 법선 방향 변위), 기저마다 13키. 모션은 위상을 엇갈린 사인.
  - wipe(strip): 반전 마스크 사각형이 띠 접선을 따라 이동, 톱니 0→1(4–5 s) + 1–2프레임 리셋 펄스로 마스크를 전체 덮음 위치까지 밀어 점프를 숨김.
  - flutter(6v): 두 날개가 중심선 기준 스케일 BS 2–6 Hz. 표류 약 1 s.
  - master: 이펙트 트리 루트 불투명도 파라미터 + 켜기/끄기 모션.
- 조절 파라미터: 주기 단계, 파티클 수, 표류 폭, 와이프 주기. 캐릭터 대기 주기와 서로소.
- 엔진 기능: RM, BS, DOP, MOT, RPT. 난이도 medium. 우선순위 P2.

### effect/audio-glow — 소리로 구동하는 가산색 글로우
- 목적: 마이크 등 소품이 말할 때 밝아집니다. 가산색 글로우 층은 음량 파라미터에 따라 이동/확장하는 형태를 마스크로 삼아 레벨 미터처럼 점점 채워집니다.
- 출력: 글로우 층(가산색) 불투명도가 음량 파라미터를 따름. 마스크 메시가 같은 파라미터로 이동. 호스트 매핑 VoiceVolume → 파라미터.
- 조절 파라미터: `maxOpacity` 0.8(0.6–1), `maskTravel` = 발광 영역 길이.
- 엔진 기능: 마스크 메시 자체 키폼, HOST. 난이도 easy. 우선순위 P2.

### effect/liquid-slosh — 용기 안 액면 출렁임
- 목적: 액체는 용기로 클리핑하고 X(가로 출렁임), Y(위로 솟음) 두 층 warp에 붙입니다. X층 중간 키에 완전한 사인 파형을 주어 중간값을 지날 때 물결이 일어난 뒤 기울어집니다.
- 알고리즘: ±1: 액면이 용기 중심을 축으로 10–15° 기울어짐(부피 보존). ±0.5: 완전한 사인파, 파고는 액면 너비의 3–5%, 기울기는 끝점의 절반. Y층 ±5–8% 용기 높이 + 가장자리 메니스커스. 물리 입력은 용기가 있는 부위(몸)의 움직임을 사용하며 2–3질점, 두 번째를 읽습니다.
- 조절 파라미터: `tilt` 12°(8–15°), `waveAmp` 4%(3–5%).
- 실패 양상: 액체 레이어 위쪽에 여유가 있어야 합니다. 용기가 작으면 warp 해상도를 높입니다.
- 엔진 기능: MK(중간 키가 있는 BS에 ExtendedBlendShapes가 필요할 때는 키폼 축으로 낮춤), PHY. 난이도 medium. 우선순위 P2.

## 슬롯 lighting(명암)

### lighting/current — 없음
- 현황: 각도/포즈에 따라 바뀌는 명암 생성이 전혀 없습니다. 채널 키폼(불투명도, 곱하기 색, 스크린)은 직접 편집할 수 있으며 채널 키폼은 이미 변경 감지에 참여합니다. 생성기가 처음 채널에 키를 넣을 때는 `journalOnly`가 채널 키에서 생성 축을 제거하지 않는다는 점에 주의해야 합니다(DOCUMENT_LAYER “후속”).

### lighting/sliding-mask-window — 고개 돌림 명암: 미끄러지는 명암 마스크 창(주 템플릿)
- 목적: 고개를 돌리면 얼굴의 빛 받는 면이 바뀝니다. 먼 쪽 볼은 그림자에 들어가고 가까운 쪽은 더 밝아지며 턱 아래 그림자가 따라 움직입니다. 부드러운 가장자리의 작은 마스크로 얼굴을 훑어 같은 토폴로지의 “명암판” 얼굴을 드러냅니다.
- 적용 대상: 얼굴(몸통, 뒷머리로 확장 가능).
- 출력:
  - 명암판 얼굴: 얼굴과 같은 토폴로지의 사본(밑색 × 그림자 색 합성, 또는 PSD에 표시). 얼굴에 전체 결합(same-topology-lock)하며 모든 키폼을 그대로 복사할 수 있습니다.
  - 마스크 메시: 부드러운 가장자리, 얼굴 너비의 약 1/3, 약 30정점. 머리 루트 warp 아래에 붙이고 AngleX × AngleY를 축으로 합니다. 정지 시에는 광원 반대쪽 얼굴 바깥에 둡니다.
  - 명암판은 마스크를 마스크로 사용합니다(곱하기 또는 일반).
- 알고리즘: AngleX ±끝점: 마스크가 먼 쪽 볼의 25–40% FW를 덮도록 평행 이동. AngleY: 숙이면 이마 어두운 부분, 들면 턱 아래 어두운 부분이 드러남. 최대 변위 0.5–0.7 FW.
- 조절 파라미터: `lightDir`, `shadeStrength` 0.3(0.1–0.5), `sweep` 0.6 FW(0.5–0.7), `maskWidth` 0.33 FW.
- 실패 양상: 마스크는 딱딱한 가장자리이므로 명암판 텍스처에 그라데이션이 있어야 합니다(명암판 생성 시 어두운 면 쪽에 그라데이션을 만들고 픽셀을 자르지 않음). 볼 홍조, 머리카락 그림자와 겹쳐 너무 어두워짐(CHK: 같은 픽셀의 곱하기 층 수 >3 → info).
- 엔진 기능: 복사본(같은 토폴로지 사본 + 결합), 마스크, MK, 텍스처 생성(명암판 합성).
- 난이도: hard. 우선순위 P1(명암판을 PSD가 제공하면 medium).

### lighting/shade-slide — 그림자 덮개층이 바탕 안에서 상대적으로 미끄러짐
- 목적: 광원은 고정되고 물체가 돌 때 명암 경계선이 물체 위를 미끄러집니다. 그림자/하이라이트 덮개층이 바탕 클리핑 범위 안에서 추가로 미끄러져 뒷머리와 얼굴이 더 이상 “종이 한 장이 도는 것”처럼 보이지 않습니다.
- 출력: 덮개층 부모 warp 아래에 AngleX×Y(또는 단일 축) warp 한 층을 추가합니다. 덮개층은 바탕을 마스크로 사용합니다. 덮개층과 바탕이 겹치는 윤곽 정점은 바탕에 Glue하여 내부 경계선만 미끄러지게 합니다.
- 알고리즘: 오프셋 Δ = k·(회전각/최대 회전각)·바탕 너비, 광원 반대 방향, k 0.03–0.12. 명암 경계 쪽은 살짝 늘림. 덮개층은 보이는 범위보다 10–15% 더 그립니다(또는 내부 경계선만 이동).
- 조절 파라미터: `k` 0.08(0.03–0.12), `axes` Y 또는 X×Y.
- 실패 양상: 한쪽으로 미끄러져 나가면 “그림자 없음” 빈 공간이 생깁니다. 바탕과 함께 부모 회전을 받으면 이중 적용됩니다(CHK).
- 엔진 기능: 마스크, Glue(일부 정점), MK. 난이도 medium. 우선순위 **P0**(그림자 레이어가 이미 있는 PSD에 바로 적용, 저비용).

### lighting/view-falloff — 시점에 따른 조명층 강도
- 목적: 얼굴의 부드러운 그림자/하이라이트 층은 정면에서 가장 뚜렷하고 측면으로 돌면 회전각에 따라 불투명도가 감쇠합니다. 오목한 영역(구강, 혀)은 끄덕임에 따라 스크린을 바꿉니다.
- 알고리즘: 조명층 식별(얼굴 하이라이트, 부드러운 그림자, 구강/혀). 불투명도: 정면 α0, AngleX 끝점 0.75 α0. 한쪽으로 치우친 층은 그쪽으로 돌면 ×1.2, 반대로 돌면 ×0.6. 오목면 스크린: AngleY 내려다보기 +8%, 올려다보기 −5%, AngleX 광원 쪽으로 밝게.
- 조절 파라미터: `sideFalloff` 0.75(0.6–0.85), `screenAmp` 5%(3–10%).
- 실패 양상: 변화가 너무 크면 깜빡입니다. 채널 키폼은 변경 감지에 들어가야 합니다(이미 반영됨).
- 엔진 기능: 각도 축에 채널 키폼(불투명도, 스크린) 생성. 난이도 easy. 우선순위 **P0**.

### lighting/orientation-shade — 방향에 따른 곱하기/스크린 생성(유사 법선 조명)
- 목적: 방향 파라미터(피치/요)가 있는 부품에 대해 프록시 형태의 법선과 주광 방향으로 색 키폼을 작성합니다. 팔다리를 접으면 가림 그림자가 짙어집니다.
- 알고리즘: 주광 L(왼쪽 위 앞). 프록시(평면/원기둥) 법선 n(p). multiply m = lerp(1, shadeColor, k·max(0, −n·L)). screen s = hiColor·max(0, n·L)^γ. 가림 그림자 층 불투명도 = o0 + k·굽힘각/90°. 표면 그림자 층(주머니, 주름)은 별도 warp로 깊이에 따른 추가 시차를 줍니다.
- 조절 파라미터: `strength` 0.2(0.1–0.3), `gamma` 2(1–3), `occlusionRange` ±0.25.
- 엔진 기능: 채널 키폼(multiply/screen 4.2), 3D 프록시, MK. 난이도 medium. 우선순위 P2.

### lighting/pose-highlight — 포즈에 따른 밝은 면 덮개층
- 목적: 팔, 다리 등 크게 움직이는 팔다리를 광원 쪽으로 들면 피부색이 밝아집니다. 팔다리마다 밝은 면 층 하나(원본을 10–20% 밝게, 팔다리에 클리핑), 불투명도 파라미터 기본값 0, 모션 생성 시 팔다리 각도의 “광원을 향한 정도”와 연동합니다.
- 엔진 기능: 마스크, MOT 연동(또는 팔다리 각도를 축으로 불투명도 키를 직접 작성하여 모션 불필요). 난이도 easy. 우선순위 P2.

### lighting/dynamic-gloss — 파라미터로 구동하는 동적 광택
- 목적: 금속/광택면 가산색 사본의 불투명도를 흔들림 각도의 함수로 만듭니다(광원을 향해 정지할 때 최대, 흔들려 벗어나면 감쇠, cos 로브). 호흡으로 스크린을 미세하게 맥동시킵니다.
- 알고리즘: 가산색 사본은 디포머와 BS를 공유합니다. 흔들림 파라미터에서 불투명도 최대 α0≈0.4, 양 끝 ≈0.6 α0. 선택적으로 영역 마스크로 발광 범위를 제한. 스크린은 호흡을 키로 하며 밝기 5–10%.
- 조절 파라미터: `peak` 0.4(0.3–0.5), `falloff` 0.6, `pulse` 7%.
- 엔진 기능: 복사본, 물리 파라미터 축의 채널 키폼(물리 파라미터가 BS 파라미터라면 BSC가 필요하거나 키폼 축으로 변경). 난이도 easy–medium. 우선순위 P2.

## 프리셋 아키텍처에 대한 요구 사항

아래는 이 템플릿 그룹이 공통으로 필요로 하는 엔진과 아키텍처 기능을 정리한 것으로, 프리셋 등록 메커니즘 설계에 사용합니다. 항목마다 혜택을 받는 템플릿을 표시합니다.

### 1. 템플릿 등록, 적용 조건과 조합

- 템플릿은 `slot/name`으로 등록하며 다음을 선언합니다. 적용 조건 선택자(의미 태그, 좌우, 표시점, `scene/held/worn`, `slot@option`, `rigid`, `metal` 같은 레이어 주석), 출력 구조, 조절 파라미터(`RigTuning`과 같은 기술 형식으로 단위, 기본값, 범위 포함), 필요한 엔진 기능, 생성기 의존성(`DocumentGenerators` 의존성 그래프에 등록).
- 같은 슬롯에서 “둘 중 하나”인 배타적 템플릿(`mask/cast-shadow-twin`과 `mask/hair-shadow-window`)도 허용하고 **직교 조합**도 허용합니다. `toggle` 슬롯은 적어도 구조(누가 양보하는가), 타이밍(어떻게 전환하는가), 묶음(파라미터 몇 개인가), 출력(표정/핫키)의 네 차원으로 나뉘며, 스위치 그룹 하나는 구조 템플릿 하나 + 타이밍 템플릿 하나를 고릅니다. 아키텍처에는 슬롯마다 하나만 고르는 방식이 아니라 “조합형 슬롯”이 필요합니다.
- 템플릿은 선언만 하며 `when (semantic.tag)`를 하드코딩하지 않습니다. 기존 알고리즘은 `*/current`로 기본 템플릿에 등록하고, 선택은 문서 설정에 저장되어 3방향 병합에 참여합니다.

### 2. 키폼 선언: 다중 키, 중간 키, 인접 키, 원화가 아닌 정지 형태

- 키 위치는 파라미터 비율로 선언하며(`[0, 0.25, 0.5, 1]`, 비균일 분포 `sign(k)·(|k|/K)^p`), 중간 키와 **인접 키 쌍**(`t, t+ε`, 즉시 전환·계단·박동용)을 지원합니다.
- 프레임워크는 “적응형 호 키 삽입” 서비스(`deformer.layering/arc-baked-keys`)를 제공합니다. 템플릿은 앵커 키와 “임의 파라미터 값에서의 형태 함수”만 제공하고, 프레임워크가 호·현 편차에 따라 키를 보충하고 거의 공선인 키를 병합합니다. 따라서 템플릿 인터페이스는 앵커 형태뿐 아니라 `S(p)`를 반환할 수 있어야 합니다.
- 기본 키 기하 ≠ 원화(`effect/collapsed-rest` 붕괴된 정지 형태)를 허용하고, 파라미터 기본값을 중간점이 아닌 원화 위치에 두는 것(`param.system/art-default`)을 허용합니다.
- 혜택: toggle의 모든 타이밍 템플릿, draw-order/turn-flip, mask/chin-neck-shadow, effect/*.

### 3. 블렌드 셰이프 출력

- 템플릿은 블렌드 셰이프(mesh / warp 4.2, rotation 5.0)를 출력할 수 있으며 다음을 포함합니다. 키별 차이(블렌드 셰이프가 주축을 따라 보간, `deformer.layering/cross-parent-modifier`), 가중치 제한 곡선(연출 중 대기 층 억제, `param.system/source-split`), 같은 블렌드 셰이프 파라미터를 서로 다른 여러 부모 사이에서 공유(`deformer.layering/cross-hierarchy-shared-blend`).
- 프레임워크는 “가산 warp” 삽입 지점을 제공합니다. 지정한 포즈 warp 아래에 블렌드 셰이프만 있고 키폼 축이 없는 warp를 삽입합니다(`deformer.layering/pose-grid-plus-blend`).
- 통일된 하위 호환 변환기: 블렌드 셰이프 → 추가 키폼 축, 또는 → 해당 파라미터를 축으로 하는 하위 warp. 손실 보고서(조합 수 증가, 출처를 독립적으로 구동할 수 없음)를 작성합니다. 기존 `SimGenerator.usesBlendShapes`의 “곱이 임계값을 넘을 때만 블렌드 셰이프로 전환”은 전역 정책의 한 단계가 됩니다.
- 채널 블렌드 셰이프(불투명도 / 색 / 그리기 순서의 가산)는 현재 모델링되지 않았습니다. `toggle/outfit-blend`, `draw-order/additive-offset`은 이것이 필요하거나 키폼 축으로 하위 호환해야 합니다.

### 4. 파라미터 역할, 그룹화, repeat와 호스트 매핑

- 파라미터 역할을 “눈 깜빡임 / 립싱크”에서 다음으로 확장합니다: `tracking`, `idle`, `performance`, `physics`, `pose`, `toggle`, `variant-slot`(부호 있는 슬롯), `state`(표정 상태), `level`(그리기 깊이), `phase`(순환 위상), `progress`(일회성 진행도), `camera`, `derived`. 역할은 파라미터 트리 그룹화, 섀도 파라미터 명명 `<Unit>_<Src>`, 모션 생성기가 어느 파라미터에 쓰는지, 호스트 매핑과 내보내기 동작을 결정합니다.
- `repeat` 플래그는 실제로 모델링해야 합니다: 평가 랩어라운드, 에디터 미리보기, 내보내기 플래그, 그리고 5.3 미만 대상의 하위 호환(선형 + 모션 하드 점프).
- 호스트 매핑 사이드카(입력 → 출력 범위, 평활화, 이득, 기본값 바이어스, 파생 신호 표, 핫키, 표정 Add/Overwrite, 페이드인 시간)는 파라미터 역할의 내보내기 산출물이며, 에디터는 같은 표로 미리보기를 시뮬레이션할 수 있습니다.

### 5. 물리 그룹 기여

- 템플릿은 물리 그룹을 선언할 수 있습니다. 입력 집합은 **부착 위치에서 도출**하고(머리 하위 트리 아래에 붙은 물체는 더 이상 머리 입력을 받지 않음, `deformer.layering/inherit-not-reinput`), 다중 출력은 층별로 스케일하며(`deformer.layering/nested-segment-cascade`), 좌우 세로 입력은 reflect, 출력은 블렌드 셰이프 파라미터에 씁니다.
- 같은 물리 출력을 여러 템플릿이 소비할 수 있으므로(머리카락 다발, 머리카락 그림자, 포니테일 뿌리, 그림자 쌍둥이가 같은 출력 세트를 공유) 물리 그룹과 그 소비자를 분리해 등록하여 “누가 파라미터를 소유하는가” 충돌을 피합니다.

### 6. 스위치 그룹 객체

- 스위치 그룹 = { 구조: 기본 부품, 대체 부품 집합, 슬롯, 곱셈 게이트, 부호 있는 슬롯, 상태 진리표; 타이밍: 전환 템플릿과 위상 구간; 의존: 부모·자식 스위치 곱; 출력: 단일 항목 표정, 조합 표정, 핫키 }.
- 게이트는 그룹 디포머 불투명도(하위 트리 전체)로 구현하며, 차원이 상한(예: 6축)을 넘으면 자동으로 그룹을 중첩해 곱합니다. 대상이 디포머 불투명도를 지원하지 않으면 메시로 내려보내고 키 수 증가를 보고합니다.
- 프레임워크가 담당하는 검사: 같은 그룹 배타성, 숨긴 하위 트리 안의 마스크 소스, 분리 가능한 그룹과 본체 사이의 글루, 가려진 영역의 아래층 커버리지(warning만 보고하고 픽셀을 보충하지 않음), 표정은 0/1에만 머묾.

### 7. 구조 삽입 지점(부착 슬롯)

- 템플릿에는 안정적인 부착 슬롯 이름이 필요합니다: 캐릭터 루트, 무대 루트, 장면 루트, 머리 루트, 얼굴 각도 warp, 눈 개폐 warp, 관절 체인 끝, 물리 구간 층, 하위 트리 최상단(전환 디포머), 포즈 warp 아래(가산 warp).
- 삽입된 디포머 ID는 결정적이며(템플릿 ID + 대상 ID에서 도출) 이후 일괄 멤버가 참조할 수 있습니다.

### 8. 범용 복사본 프레임워크

- 앞머리 투과(`SeeThroughLayers`)의 복사본 메커니즘을 범용 서비스로 확장합니다: 복사본 기록표, 완성 단계에서 제작, 원본의 모든 편집 추종, 복사본을 지정한 편집은 `generated_copy`를 반환.
- 사용처: 투영 그림자 쌍둥이, 명암판 얼굴, 변형 쌍둥이, 색 변경 대역, 인계 두 사본, 동적 광택 사본.
- 두 가지 글루 정책을 구분합니다: 복사본과 원본 사이의 **전 정점 고정**(`mesh.glue/same-topology-lock`, 그림자와 명암판에 필요)과 “원본의 글루 파트너 복사”(앞머리 투과에서는 금지, 파트너가 두 번 당겨지는 것 방지).

### 9. 마스크와 대상 기능 게이트

- 다중 마스크 합집합, 반전 마스크, 숨겼지만 여전히 마스크로 쓰이는 메시(마스크는 불투명도를 보지 않음), 마스크 참조 의존성 그래프(숨기거나 삭제할 때 검사), 메시당 마스크 수 상한.
- 런타임 대상별 게이트와 하위 호환: 반전 마스크 4.0, 블렌드 셰이프와 곱하기/스크린 4.2, 확장 블렌드 셰이프 5.0, repeat와 파츠 합성 5.3. 템플릿은 필요한 기능을 선언하고 프레임워크가 하위 호환 경로를 골라 손실 보고서를 작성합니다.

### 10. 그리기 순서

- 정적 순서는 희소 눈금을 사용하고 층 사이 간격을 남깁니다. 그룹 level 파라미터(그룹 안 오프셋 고정). 그리기 순서 키폼이 두 키 사이에서 무관한 층을 넘어가지 않는지 검사. 모션 생성기와 MCP가 쓸 “랜드마크 깊이 표” 출력. 대상이 파츠 수준 순서를 지원하면 파츠에 두는 것을 우선합니다.

### 11. 메시

- 템플릿이 부품의 예상 변형(범주: 선 / 이목구비 패치 / 머리카락 다발 / 강체 / 옮겨지기만 함 / 내부 굽힘, 바인딩된 파라미터 수, 부모 warp 셀)을 선언하면 메시 생성기가 이를 바탕으로 목표 변 길이장을 정합니다. 단일 밀도 표로 병합합니다. 키폼 생성 후 키폼에 따라 2차 세분화하고 `RasterMeshJournal`로 이전할 수 있습니다.
- 구조 메시 유형: 띠, 극좌표, 4점 패치, 제약 변.

### 12. 채널 키폼 생성

- 생성기가 불투명도, 곱하기 색, 스크린 키폼을 작성하는 것이 일반적인 일이 됩니다(명암, 스위치, 이펙트). 생성 결과 덮어쓰기와 `journalOnly`는 채널 키를 올바르게 처리해야 하며(생성 축 제거, 채널별 읽기), 채널 변경은 변경 감지에 참여합니다.

### 13. 공용 기하 서비스

- 3D 프록시: 머리 타원체, 몸통 원기둥, 팔다리 원기둥, 빛 방향. `draw-order/turn-flip`, `draw-order/ring-split`, `mask/contour-cutter`, `mask/cast-shadow-twin`, `lighting/orientation-shade`가 공용으로 사용합니다.
- 가림 분석: 정지 포즈에서 어떤 픽셀을 어느 레이어가 덮는지, 어느 것이 앞인지(투사체 / 수용체 식별, 긴 띠의 교차 구간 판정, 머리카락 소속).

### 14. 모션 곡선

- 모션 생성기는 톱니, 단조 램프, 계단, 위상 오프셋, 결정적 시드 기반 저불일치 위상 수열, 대기와 서로소인 주기를 지원합니다. 이펙트와 캐릭터 대기는 트랙을 분리합니다.

### 15. 품질 규칙

- 새 규칙 열거(각각 등급과 범주 확정): 순환 처음과 끝 불일치(error), 다중 출처 진폭 합 초과(warning), 물리 입력과 계층 상속 이중 계산(warning), 같은 구동이 두 출처에 씀(error), 게이트 하위 트리에 마스크 소스 포함(warning), 분리 가능한 그룹의 그룹 간 글루(warning), 아래층 커버리지 부족(warning), 그리기 순서가 같거나 무관한 층을 넘음(warning), 단일 대상 블렌드 셰이프 수 초과(warning), 카메라 층에 비강체 변형 포함(error), 곱하기 층 수 과다(info), 부호 있는 슬롯이 2개 초과(info).

### 16. 결정성과 재현

- 무작위 위상과 파티클 배정은 모두 결정적 시드를 사용합니다. 복사본과 삽입 객체 ID는 결정적입니다(`<원본 ID>_<역할>`). 모든 산출물은 생성기 의존성 그래프에 들어가 “모든 생성기 이후”의 덮어쓰기 병합에서 3방향 병합됩니다. 템플릿 설정이 바뀌면 관련 생성기만 다시 계산합니다.
