# Rig 프리셋 구조: 부위, 기본 알고리즘과 모듈

[문서 목록](../../README.md) · 모듈과 알고리즘 목록: [얼굴](RIG_TEMPLATES_FACE.md) · [머리카락과 몸](RIG_TEMPLATES_HAIR_BODY.md) · [물리와 동작](RIG_TEMPLATES_PHYSICS_MOTION.md) · [구조와 표현](RIG_TEMPLATES_STRUCTURE.md) · [디포머와 파라미터](DEFORMER_AND_PARAMETER_SPEC.md) · [문서 계층](DOCUMENT_LAYER.md)

이 문서는 자동 생성을 선택, 해제, 조절할 수 있는 부분으로 나누는 방법을 설명합니다.

- 각 부위에는 서로 배타적인 **기본 알고리즘** 하나 이상과 중첩할 수 있는 **모듈**이 있습니다.
- 프로젝트의 **레시피**에는 부위마다 사용하는 기본 알고리즘, 꺼진 모듈, 변경한 값이 기록됩니다.

각 알고리즘과 모듈의 설계(입력, 출력, 키폼 계산법, 보기 좋은 결과의 기준)는 네 개의 목록 문서에 있습니다. 여기서는 등록, 선택, 저장, 재생, 외부 노출 방식만 규정합니다.

## 목표

자동 생성 모델도 기본 상태부터 수작업으로 정밀 조정한 모델의 시각적 장점을 갖추어야 합니다.

- 눈, 눈썹, 입은 단순한 여닫기를 넘어 완전한 표정 공간을 가집니다.
- 눈 깜빡임과 말하기가 주변 부위의 연동과 잔진동을 일으킵니다.
- 고개 돌리기에 깊이감이 있습니다.
- 머리카락과 옷에 무게감과 위상 차이가 있습니다.

이 능력을 각각 모듈로 만듭니다.

- **기본으로 모두 켬**: 새 프로젝트는 적용 가능한 모듈을 모두 켭니다.
- **필요에 따라 끔**: 파라미터 수에 맞춰 하나씩 끄거나, 프리셋이나 파라미터 예산으로 한꺼번에 끕니다.
- **소수의 조절 항목**: 모듈마다 의미 있는 조절 항목 몇 개만 노출하며, 각 항목은 내부의 여러 하위 값을 함께 구동합니다. 이후에는 캔버스에서 특징점과 핸들을 드래그해 조절할 수 있습니다.

모듈의 완성 여부는 결과만으로 판단합니다.

1. 검토 도구(`RigReviewTool`)로 포즈 보드와 동작 클립을 만듭니다.
2. 해당 부위의 ‘보기 좋은 모습’과 ‘흔한 문제’를 항목별로 대조합니다.
3. 수치 검사는 참고용으로만 사용합니다.

## 용어

| 용어 | 의미 | 코드 |
| --- | --- | --- |
| 부위(area) | 카드 하나가 관리하는 범위: 머리와 얼굴, 눈, 눈썹, 입과 아래 얼굴, 머리카락, 몸, 의상과 장식, 표정, 동작. 한 카드가 좌우를 함께 관리 | `RigArea` |
| 기본 알고리즘(base) | 눈꺼풀 닫기에 기존 알고리즘 또는 템플릿 피팅을 쓰는 것처럼 부위 안에서 서로 배타적인 방식. ID는 `部位/名称`이며 버전과 조절값 포함 | `RigBase` |
| 모듈(module) | 웃는 눈, 시선을 따르는 눈꺼풀, 깜빡임 잔진동처럼 부위 안에서 중첩 가능한 기능. 각각 켜고 끄며 ID는 `部位.名称` | `RigModule` |
| 조절 항목(knob) | 기본 알고리즘이나 모듈의 조절값 하나. 단위, 범위, 기본값, 고급 항목으로 접을지 여부 포함 | `RecipeKnob` |
| 레시피(recipe) | 프로젝트에서 부위별로 선택한 기본 알고리즘, 꺼진 모듈, 변경한 값. 설정의 `rig`에 저장 | `RigRecipe` |
| 부품 역할(part role) | 해당 부위에서 레이어가 맡는 역할: 하이라이트, 동공, 아래 속눈썹, 쌍꺼풀선, 그림자, 홍조, 옆머리, 바보털, 포니테일, 땋은 머리, 동물 귀, 리본, 펜던트, 단단한 장식, 소매, 치마 | `PartRole` |
| 모델 프리셋 | 시작 페이지의 빠른 조합(최소 / 기본 / 전체)과 모델 프리셋 패널의 각 그룹 | `StartQuickPreset` |
| Rig 수치 | 파라미터 최댓값에서 기존 알고리즘이 사용하는 진폭. 각 부위의 기존 기본 알고리즘 파라미터이며 패널에서는 부위 카드의 ‘수치’에 배치 | `RigTuning` |

## 등록부

`core/recipe/RigModules.kt`가 유일한 등록부입니다. 부위는 패널에 카드가 표시되는 순서로 등록합니다.

**기본 알고리즘**

- 각 부위의 첫 기본 알고리즘은 `部位/legacy`이며, 등록부 도입 이전의 생성 방식입니다.
- 새 기본 알고리즘은 그 뒤에 등록하며 마지막 항목을 새 프로젝트의 기본값으로 사용합니다.

**모듈**

각 모듈은 다음 내용을 선언합니다.

| 필드 | 의미 |
| --- | --- |
| `tier` | 중요도: `CORE`(부위가 완전하게 보이는 데 필수), `MAJOR`(뚜렷한 시각적 품질), `MINOR`(추가적인 개선). 프리셋과 예산은 이를 기준으로 줄임 |
| `requires` | 의존 모듈. 의존 대상 모듈을 끄면 그것에 의존하는 모듈도 함께 꺼짐 |
| `applies` | 소재에 처리할 부품이 있는지 여부(부위, 좌우, 부품 역할로 판단). 적용 불가 모듈은 표시하지 않고 비용에 넣지 않으며 생성하지도 않음 |
| `parameters` | 이 소재에 새로 추가하는 파라미터 |
| `estimate` | 꺼진 상태에서의 비용 추정 |
| `physicsGroups` | 생성하는 물리 그룹 |
| `setting` | 기존 설정에서 대응하는 스위치(아래 참조) |

**ID와 버전**

- 프로젝트에 저장될 가능성이 생긴 ID는 이름을 바꾸지 않습니다.
- 알고리즘 변경으로 기존 프로젝트의 생성 결과가 바뀌면 버전을 올립니다. 레시피에는 값을 설정할 당시의 버전을 기록합니다.

**기존 스위치를 이어받는 모듈**

등록부 이전에 있던 몇 가지 스위치도 모듈로 등록합니다.

| 모듈 | 대응 설정 |
| --- | --- |
| `eye.see-through` | `seeThroughEyes` |
| `eye.jelly` | `physicsEyeJelly` |
| `brow.see-through` | `seeThroughBrows` |
| `mouth.outline` | `mouthOutlineEnabled` |

- 스위치는 기존 설정 자체이므로 이전 프로젝트에서도 유효합니다.
- 별도 조절 항목은 없습니다.

## 비용

비용은 다음 네 항목입니다.

- 추가 파라미터(ID를 하나씩 나열).
- 추가 키폼: 키에 해당 모듈 파라미터가 들어 있는 메시에서 늘어나는 격자 칸 수.
- 블렌드 셰이프의 형상 수.
- 물리 그룹 수.

비용의 출처는 다음과 같습니다.

- 모듈을 켰을 때는 생성한 Rig에서 실측합니다(`ModuleCost.measure`).
- 모듈을 껐을 때는 모듈 자체 추정값을 쓰며 패널에 ‘≈’로 표시합니다.

## 레시피: 선택, 저장과 업그레이드

**새 프로젝트와 이전 프로젝트**

- 새 프로젝트 설정에는 `rig` 키를 기록합니다. 빈 객체는 모두 기본값, 즉 부위별 기본 알고리즘과 적용 가능한 모든 모듈 활성화를 뜻합니다.
- 레시피 도입 전에 저장한 프로젝트에는 설정의 `rig` 키가 없으며 이전 레시피(`RigRecipe.Legacy`)로 읽습니다.
  - 각 부위에 `legacy` 기본 알고리즘을 사용합니다.
  - 기존 스위치를 이어받는 모듈 이외에는 켜지 않습니다.

  따라서 이전 프로젝트는 기존 방식으로 생성되고 설정 텍스트와 리비전 식별값도 바뀌지 않습니다.
- 업그레이드: `rig: {}`를 기록하며 실행 취소할 수 있습니다.
- 이전 레시피로 복귀: `rig: null`을 기록하면 설정에서 이 키가 사라집니다.

**수정(설정 패치 `changes.rig`)**

패널과 MCP가 같은 경로를 사용합니다.

| 내용 | 작성법 |
| --- | --- |
| 부위의 기본 알고리즘 | `bases: {部位: {base, values}}`; `null`이면 기본값으로 복귀 |
| 모듈 | `modules: {模块: {on, values}}`; `null`이면 ‘켜짐, 기본 수치’로 복귀 |

- 같은 기본 알고리즘 또는 모듈을 유지할 때 값은 기존 값과 병합합니다.
- 기존 스위치를 이어받는 모듈의 `on`은 해당 설정에 기록하며 `values`를 넣을 수 없습니다.
- 다음은 모두 거부합니다.
  - 알 수 없는 부위, 기본 알고리즘, 모듈, 수치.
  - 범위를 벗어난 값.
  - `bases`, `modules` 이외의 키.

**저장 형식**

- 기본값과 다른 항목만 씁니다. 모듈에는 `on: false`와 변경한 값만 기록합니다.
- 읽을 때 모르는 부위, 기본 알고리즘, 모듈, 수치는 건너뛰므로 새 버전으로 저장한 프로젝트도 열 수 있습니다. 값은 범위 안으로 제한합니다.

## 재구성과 재생

레시피는 생성 설정이며 다음 방식으로 재구성에 참여합니다.

- 단계 캐시가 읽을 수 있는 설정(`RigBuilder.stageConfig`)에 들어갑니다.
- `RigGenerationChange`는 이를 생성 규칙 변경으로 간주합니다. 레시피를 수정하면 새 기반 G′을 생성하고 이전 기반 G, 작성 상태 M과 3방향 병합한 뒤 로그 끝에 `rig_checkpoint`를 씁니다. 이전 기반에서 한 사용자 편집은 병합 규칙에 따라 보존합니다.
- 모듈이 추가하는 파라미터는 해당 모듈을 생성할 때만 모델에 넣습니다. 모듈을 끄면 참조되지 않는 파라미터는 병합 과정에서 제거합니다.

따라서 모듈을 켜고 끄거나 조절값을 바꾸는 일은 실행 취소 가능한 히스토리 커밋 하나이며, 저장하고 다시 열어도 정상적으로 재구성됩니다.

‘파라미터를 바꾸면 다시 계산하되 사용자 미세 조정을 보존’해야 하는 모듈은 로그 이후 생성기로 구현하고, 소유하는 키폼을 `DocumentGenerators`에 등록해야 합니다([문서 계층](DOCUMENT_LAYER.md) 참조).

## 부품 역할

부품 역할은 의미 태그를 세분화합니다.

- 같은 홍채 레이어라도 하이라이트, 동공, 홍채 본체가 각각 움직입니다.
- 같은 속눈썹 레이어라도 아래 속눈썹, 쌍꺼풀선, 눈꺼풀 그림자는 눈을 감을 때 서로 다르게 동작합니다.

**태그 단어로 사용**

- 각 역할은 태그 단어 하나입니다. `highlight`, `pupil`, `lower`, `lid`, `shadow`, `blush`, `side`, `ahoge`, `ponytail`, `braid`, `animal`, `ribbon`, `pendant`, `rigid`, `sleeve`, `skirt`, `upperlip`, `lowerlip`, `upperline`, `lowerline`.
- 역할 단어는 부위, 좌우 단어와 함께 레이어 태그(`LayerTags`)에 씁니다.
- 역할마다 세분화할 수 있는 부위가 정해져 있으며 다른 부위에 붙이면 효과가 없습니다.

**자동 판별**(`PartRoles`)은 다음 순서로 수행합니다.

1. 레이어 이름과 소속 폴더의 중국어, 일본어, 영어, 한국어 키워드.
2. 같은 부위의 레이어 사이 위치와 혼합 방식. 예를 들어:
   - 홍채 안의 작은 스크린 레이어나 밝은 레이어는 하이라이트, 작은 어두운 레이어는 동공입니다.
   - 눈 중심선 아래의 속눈썹 레이어는 아래 속눈썹, 위 속눈썹 위의 가는 선은 쌍꺼풀선입니다.
   - 곱하기로 합성하는 얼굴, 머리카락, 의상 레이어는 그림자입니다.
   - 얼굴 옆에서 얼굴 중간 아래까지 늘어진 앞머리는 옆머리입니다.
   - 좌우로 나뉘지 않은 하의 전체에서 밑단이 허리보다 좁지 않고 밑단 가운데가 끊어지지 않으면 치마입니다(바지는 두 다리 사이에서 끊깁니다).

**사용자 수정**

- 사용자가 태그에 쓴 역할이 우선합니다.
- 추론된 역할을 태그에서 제거하면 `PartRole.PLAIN`(역할 없음)으로 기록하고 분석 시 다시 추론하지 않습니다.
- MCP의 `layer_classify`는 `part` 필드로 역할 단어, `none`, `auto`를 설정합니다.
- 역할은 레이어 분류 재정의에 저장됩니다. 역할 없는 재정의는 이전 텍스트와 완전히 같습니다.

**역할을 읽는 주체**

- 모듈만 역할을 읽고 이전 레시피는 읽지 않으므로 역할이 이전 프로젝트의 생성 결과를 바꾸지 않습니다.

## 패널과 MCP

**패널**

모델 프리셋 패널의 ‘부위와 모듈’ 그룹:

- 상단:
  - 프리셋(전체 / 표준 / 간소 / 사용자 지정).
  - 파라미터 예산: ‘중요도 낮은 순, 파라미터 많은 순’으로 모듈을 꺼서 추가 파라미터가 예산 이하가 되게 합니다.
  - 재설정 버튼.
- 아래에는 부위별 카드가 있습니다. 카드 머리에는 켜진 모듈 수와 추가 파라미터 수가 표시되며 펼치면:
  - 기본 알고리즘이 여럿이면 알고리즘 드롭다운과 해당 조절 항목을 표시합니다.
  - 모듈마다 스위치와 비용을 한 줄에 표시하고, 켜면 조절 항목을 표시합니다.
  - 현재 소재에 적용 가능한 모듈만 표시합니다.
  - 마지막에는 해당 부위의 ‘수치’ 접기 항목이 있습니다. 이 부위의 Rig 수치(`RigTuning`; 머리와 얼굴에는 고개 돌리기, 코와 귀, 몸에는 몸 돌리기, 상하, 앞뒤 기울기, 크기 변화, 몸 Z와 호흡, 입체감과 원근감)를 자주 쓰는 소그룹으로 나열하고 나머지는 ‘고급’ 안에 접습니다. 이 값들만 재설정하는 버튼도 제공합니다.
- 현재 레시피에서 실제로 작용하는 Rig 수치만 표시합니다. 모듈이나 기본 알고리즘이 직접 생성하는 부분은 대응하는 기존 수치를 숨깁니다(`RigTuning.replacedBy`, `RigModules.tuningInEffect`). `face.depth-turn` 생성 시 얼굴, 이목구비, 앞뒤 머리의 AngleX / AngleY 3×3 고개 돌리기 수치는 표시하지 않습니다(스타일 고개 돌리기가 대체하며 기존 디포머는 회전 키에서 정지). 피팅 눈은 기존 감기 수치(깜빡임 깊이, 눈꼬리, 속눈썹 납작해짐), 피팅 눈썹은 눈썹 올리기, 피팅 입은 기존 입 모양 수치, 머리카락 체인은 앞뒤 머리 각각의 전체 흔들림과 말림을 대체합니다. 이전 프로젝트(레시피 미업그레이드)나 이 모듈들을 끈 경우에는 기존 수치를 표시하고 적용합니다. 프로젝트 파일과 MCP는 여전히 모든 필드를 받습니다.
- 이전 프로젝트에는 그룹 상단에 업그레이드 가능 안내를 표시하며 자동으로 업그레이드하지 않습니다.

**MCP**

- `module_catalog`(읽기 전용): 모든 부위, 기본 알고리즘, 모듈, 조절 항목을 나열합니다. 프로젝트가 열렸다면 다음도 반환합니다.
  - 새 레시피인지 여부와 부위별 현재 기본 알고리즘.
  - 모듈별 적용 가능 여부, 활성 여부, 비용.
- `settings_update`: `changes.rig`로 레시피를 수정합니다.
- `workspace_inspect scope=settings`: 저장 형태를 반환하며 그대로 다시 쓸 수 있습니다.

## 특징점 피팅(`core/fit`)

이목구비의 새 기본 알고리즘은 고정 수식에 의존하지 않습니다. 원화의 특징점을 읽고 표준 템플릿을 거기에 맞춥니다.

| 구성 요소 | 역할 |
| --- | --- |
| `EyeFitting` | 두 흰자 중심을 이은 선으로 머리의 수평 방향을 먼저 구합니다(눈이 하나면 Rig 수평 사용). 눈 좌표계도 함께 기울어져 고개가 기울거나 몸이 돌아간 캐릭터도 자기 얼굴을 기준으로 여닫습니다. 이 방향에서 흰자의 불투명 픽셀 양 끝을 안쪽·바깥쪽 눈꼬리로 삼고, 그 사이에서 ‘얼굴의 아래 방향’을 따라 위아래 눈꺼풀 가장자리를 읽습니다(각 17개 표본; 보통 흰자는 속눈썹 아래까지 완전하게 그려져 있습니다). 감은 눈 선에서는 중심선, 홍채에서는 외곽을 읽습니다. 안쪽 눈꼬리를 원점으로 하고 머리 수평 방향의 두 눈꼬리 간 거리를 단위로 삼습니다. 바깥쪽 눈꼬리는 안쪽보다 높거나 낮을 수 있습니다. 너비, 개폐 비율, 위아래 가장자리 순서, 눈꼬리 기울기를 검사하며 부적합한 눈은 기존 알고리즘으로 되돌리고 이유를 제공합니다. |
| `EyelidModel` | 유사 3D 눈꺼풀. 눈꺼풀은 눈꼬리 연결선을 중심으로 회전하는 평면이고 안구와의 교선이 눈꺼풀 가장자리입니다. 따라서 내려올 때 가장자리는 계속 안구를 덮는 호이며, 눈꼬리 선을 지날 때만 직선이 되고 이후 감은 눈의 아래로 휜 호가 됩니다. |
| `ThinPlateSpline` | 박판 스플라인. 템플릿 특징점을 검출 특징점에 정확히 대응시키며 같은 매핑을 모든 템플릿 포즈에 적용합니다. |
| `BiharmonicField` | 규칙 격자의 쌍조화 변위장. 제약 위치(눈꺼풀·입술 가장자리)에만 변위를 주고 나머지는 가장 매끄러운 해, 바깥 둘레는 0으로 둡니다. 눈꺼풀 피부와 그림자 등이 가장자리를 따라 여러 줄에 걸쳐 부드럽게 움직이게 합니다. |
| `EyeRig` / `EyeBand` | `eye/fitted`는 원화에서 주 획의 띠 몸체, 독립 속눈썹 다발, 옆 가장자리, 위아래 부품과 접합 영역을 관찰합니다. 띠 몸체는 연속 곡선과 가로 단면으로 닫힌 형태를 만들며 선 두께를 보존합니다. 일반 감기와 웃으며 감기를 따로 생성합니다. 식별된 뾰족한 다발은 국소적으로 모여 띠 반대쪽으로 넘어갈 수 있고 뿌리 영역은 매끄럽게 이어집니다. 옆 가장자리는 띠 근처로 모읍니다. 추가 눈 모양의 변위는 같은 눈 좌표에서 생성하고 전체 고개 돌리기는 기존 부모가 담당합니다. 중립 원화 키는 정확히 유지합니다. 믿을 만한 획 관찰이 없으면 기존 눈꺼풀 경로를 유지합니다. 흰자 클리핑과 획 기하는 각각 생성합니다. 두 눈이 합쳐진 레이어는 원본 위치에 따라 좌우 개폐에 독립적으로 바인딩합니다. |
| `BrowRig` | `brow/fitted` 기본 알고리즘과 눈썹 모듈. 눈썹도 머리 좌표계에서 읽습니다. 머리 수평 방향의 양 끝이 안팎 끝이며 얼굴 중심선에 가까운 쪽이 안쪽입니다. 중심선은 17개 표본으로 읽습니다. 상하 이동 폭은 아래 눈의 열린 높이 절반 정도(‘이동 진폭’ 조절 항목)이며 피팅 눈이 없으면 눈썹 길이 1/4입니다. 각도는 전단 변형 대신 눈썹 중점을 중심으로 호를 따라 회전하고 키 다섯 개를 사용합니다. 좌우 이동, 아치 변형, 깜빡임에 따른 내려감은 중첩 블렌드 셰이프입니다. |
| `HeadTurn` | `face.depth-turn` 모듈. 얼굴, 이목구비, 머리카락은 ‘고개 돌리기 스타일’(`TurnStyle`, 바이너리 `rig/head-turn-style.bin`에 저장)에 따라 변합니다. 스타일은 세 계층입니다. **기본 변형**은 이름이 있는 변위들의 집합으로, 모두 얼굴 너비를 단위로 하고 회전 방향에 따라 미러링합니다(+x 방향 회전을 양수로 사용). 얼굴 중앙의 미끄러짐; 턱에서 시작해 얼굴 윤곽의 호 길이를 24등분한 점 각각의 중앙 대비 변위; 각 눈(흰자와 속눈썹) 중심의 중앙 대비 앞섬과 상하 이동, 전체 2×2 선형 변화(폭 좁힘과 기울임을 함께 표현하며 먼 눈 바깥쪽이 더 모이는 현상은 회전이 아니라 선형 변화 자체의 결과), 흰자 바깥끝을 넘어선 속눈썹 꼬리의 추가 변위, 눈구멍 안 홍채의 상대 위치와 자체 너비, 같은 높이 윤곽까지 눈이 남기는 여유; 각 눈썹의 앞섬, 상하, 너비, 기울기, 아치; 입의 앞섬, 상하, 2×2 선형 변화, 입선 굽힘; 가까운 귀, 먼 귀, 머리 장식의 전체 변위; 머리카락 역할별(앞머리, 옆머리, 정수리, 늘어진 머리, 뒷머리, 뒷머리 아래 부분) 필드 파라미터 묶음입니다. 기본 변형마다 회전 몫 a와 피치 몫 p의 **체비쇼프 곡면**을 가집니다. f(a,p) = Σ c<sub>i0</sub> U<sub>i</sub>(a) + Σ c<sub>0j</sub> V<sub>j</sub>(p) + Σ c<sub>ij</sub> U<sub>i</sub>(a) V<sub>j</sub>(p), U<sub>i</sub>(a) = T<sub>i</sub>(2a−1) − T<sub>i</sub>(−1), V<sub>j</sub>(p) = T<sub>j</sub>(p) − T<sub>j</sub>(0)이며 각각 4차까지 사용합니다. 정지 시 0이고 첫 항은 좌우 회전, 둘째는 올려다보기·숙이기, 셋째는 대각 포즈 고유 변화를 맡습니다. 계수의 의미도 직접 읽을 수 있습니다. 회전 1차는 등속 부분, 2차는 선행·지연입니다(한 번의 회전에서 모든 부분이 동시에 축소되지 않습니다. 예를 들어 눈 간격과 먼 눈의 좁아짐은 후반에 두드러지고 가까운 눈은 초반 움직임이 느립니다). 피치의 홀수 차수는 들기와 숙이기의 차이, 짝수 차수는 공통 부분입니다. 각 참조의 모든 키폼으로 곡면을 피팅하고 고차 항은 차수별로 페널티를 주므로 키폼이 적은 참조는 낮은 차수의 매끄러운 형태를 유지하며 전체 평균 형상에 가까워집니다. 주축은 계수 위에 구성합니다. 저장 시 각 값에 필요한 항만 남깁니다(제거해도 어떤 곡면 묶음의 변화도 허용오차를 넘지 않는 항은 제거). 값별 스케일을 둔 8비트 또는 16비트 정수 계수를 압축하며 전체 스타일은 약 48 KB입니다. **사용자 제어**는 기본 스타일에 미술용 슬라이더를 더합니다. 각 슬라이더는 한 방향을 따라 여러 기본 변형을 바꾸며 100%는 해당 스타일 양의 전형적인 차이 하나입니다. 입체감(윤곽 대비 얼굴 중심선의 앞섬), 원근감(먼 쪽 모임: 먼 눈, 눈 간격, 입 너비), 시선 유지(눈 안에서 홍채를 유지), 볼 윤곽 흔들림(가까운 쪽·먼 쪽 볼 윤곽 차이), 대각 롤(대각으로 들고 숙일 때 눈선 기울기), 피치 깊이(들고 숙일 때 이목구비·앞머리 상하), 장식 추종(머리 장식과 앞머리)입니다. 머리카락에는 추종, 끝 선행, 뒷머리 시차 슬라이더 세 개가 대응 필드 파라미터를 비례 조절합니다. 회전 진폭은 곡면 회전 항, 피치 진폭은 피치 항, 두 값의 곱은 대각 항에 곱합니다(회전 조절값 45%가 스타일 자체). 여기에 전역 ‘회전 강도’를 곱합니다. 여러 완성된 회전 스타일에서 시작할 수도 있습니다(`style` 항목, 패널의 ‘고개 돌리기 스타일’ 드롭다운: 표준, 강한 입체감, 과장, 큰 동작, 끄덕임, 부드러움). 각각 스타일 주축 위의 전체 곡면 묶음(머리카락 포함)이며 선택하면 모듈의 나머지 값은 기본값으로 돌아가고 그 위에서 슬라이더를 조절합니다. 각도 수치는 파라미터 위치일 뿐입니다. AngleX 끝점 ±45가 스타일의 회전 끝점, AngleY 끝점 ±30이 들기·숙이기 끝점입니다. 이동하며 굽히거나 납작하게 하지 않고 원화 너비를 유지합니다(입꼬리를 넘는 전체 폭인지 일부만 차지하는지는 원화가 결정). `teeth`(기본 0)를 켰을 때만 최대 웃음에 따라 균일하게 넓힙니다. 윗니는 벌림 전반에 닫힌 상태 위치를 유지하여 커지는 개구부가 치아를 드러내게 하고 후반에 입을 따라 원화 위치로 이동합니다. 아랫니는 아래턱 소속으로 전 구간에서 아랫입술을 따릅니다. 윗니는 윗입술 중앙의 65%, 아랫니는 아랫입술 중앙의 88%를 따르며 둥근 입일수록 덜 따릅니다. 윗니는 윗입술 대비 원화보다 아래로 가지 않으므로 웃음에서 윗입술이 올라가면 치아도 올라가 위에 틈이 생기지 않습니다. 웃을 때 윗니 노출은 개구 높이 절반 이하로 제한하며 치아 메시가 입 중앙에서 입술 아래 얼마나 뻗는지를 보고 필요하면 줄 전체를 윗입술 뒤로 물립니다. 따라서 작은 웃음에서는 치아가 전혀 보이지 않기도 합니다. 치아는 구강의 개폐 명암에 참여하지 않고 항상 흰색입니다. 개구부보다 크게, 입술선 아래까지 그려 두고 노출량은 구강 클리핑만으로 정해야 합니다. 그러면 어떤 입 모양에서도 입술선과 붙어 틈이 없고, 작은 입·삐죽임·깔때기·O형에서는 입술 뒤에 숨습니다. 혀는 아래턱을 따라 아랫입술의 약 30%만큼 전체가 내려갑니다. 깊은 구강과 크게 그린 구강 바탕색은 입 모양을 따르지 않고 입의 가로 이동과 회전 시차만 따릅니다. `narrow`(기본 0)는 반쯤 벌렸을 때 먼저 좁아졌다 원화 폭으로 넓어지게 하여 처음 작은 원형으로 열리는 입을 표현합니다. 분리된 입(입 레이어에 `upperlip` / `lowerlip` / `upperline` / `lowerline` 역할, [PSD 레이어 규격](PSD_LAYER_SPEC.md#파츠-나누기) 참조)에서 입술선은 입술 가장자리를 따르는 획입니다. 선 레이어에서 측정한 두께를 유지하고 두께 방향도 가장자리와 회전하므로 둥근 입꼬리에서는 선이 수직으로 서며 가로로 튀어나오지 않습니다. 선 두께를 넘는 부분(둥근 입꼬리에서 선 수직 벽)은 닫을 때 함께 접힙니다. 닫을 때 윗선은 위로, 아랫선은 아래로 각각 반 선 두께만큼 이동해 한 선으로 합쳐집니다. 입꼬리에서 이미 한 획으로 그려진 두 선은 서로 마주 이동시키지 않아 두꺼워지지 않습니다. 입꼬리 근처(입 너비의 8% 이내)에서는 두 선 끝이 점차 함께 이동하고 입꼬리에서 각각 절반씩 따르므로 둥근 입에서도 두 끝이 하나의 입꼬리로 겹쳐 단차가 없습니다. 개구부도 같은 선 움직임을 따릅니다. 위아래 입술선이 있으면 입꼬리는 옆벽 중점이 아니라 두 선 접점으로 잡습니다. 입술 덩어리(입술과 주변 피부)는 가장 가까운 가장자리를 따라 전체 이동하며 멀수록 덜 움직입니다(바깥 가장자리 약 35%). 입술 그림은 굽히되 납작하게 하지 않습니다. 구강(역할 없는 입 레이어)은 두 입술선 사이에서 움직입니다. 선 띠 아래 부분은 해당 선을 따르고 중앙은 두 선 사이 위치로 보간하여 입꼬리를 포함한 어떤 입 모양에서도 구강 가장자리가 선 아래에 남습니다. 입술 덩어리가 있으면 `inside`(기본 50%)에 따라 일부만 접고 나머지는 입술 덩어리로 덮습니다. 없으면 전체를 입술선 아래로 접습니다. 구강은 다른 레이어를 자르는 개구부이므로 회전 시차를 더하지 않으며, 구강이 자르는 치아·혀·깊은 구강에만 시차가 있습니다. PSD에서 구강에 클리핑된 역할 없는 입 레이어는 구강 바탕색입니다. 모든 개구부보다 크게 그리며 입 모양 읽기에 참여하지 않고 구강으로 클리핑되며 치아·혀 뒤에 놓고 입 모양에 따라 움직이지 않습니다. 구강은 레이어 불투명도 0의 보이지 않는 형상이어도 클리핑 원본으로 사용할 수 있습니다. 분리된 입의 각 레이어는 원화를 따라 그린 메시를 유지하고 윤곽 입의 열 분할 메시로 바꾸지 않으므로 개구 메시가 원화를 완전히 덮습니다. 입의 하이라이트·그림자는 중심 위치에 따라 위·아랫입술을 따르거나 거의 움직이지 않는 깊은 구강으로 취급하여 구강으로 자릅니다. 치아·혀·깊은 구강을 자르는 것은 구강뿐이며 분리된 입에는 윤곽 띠를 생성하지 않습니다. |
| `EyeModules` | 눈 모듈의 메시와 채널. 개폐 축(`eye.wide`는 2까지 확장)과 웃는 눈 축(`eye.smile`)이 눈꺼풀 키폼 격자를 이룹니다. 시선 추종 눈꺼풀, 감정 눈 모양·가늘게 뜨기, 깜빡임 잔진동은 가산 블렌드 셰이프이며 개폐 정도로 가중치를 제한하고 감았을 때는 작용하지 않습니다. 웃는 눈에서는 원화 감은 눈 선이 위로 휜 호가 됩니다. 홍채는 감을 때 아래로 납작해지고 크게 뜰 때 조금 작아집니다. 하이라이트는 고개 회전 반대로 떠다니며 눈꺼풀선과 하이라이트는 닫히기 전에 사라집니다. 각 블렌드 셰이프는 메시 자체 그리기 순서와 불투명도를 기록하고 변위만 더합니다. |

확장된 눈 뜨기 구간(`Eye Open > 1`)은 `EyeOpeningModel`이 별도로 표현합니다. 위아래 눈꺼풀마다 가로·세로 4차 체비쇼프 변위 곡선이 있으며 `rig/eye-opening.bin`에 바이너리로 저장하고 Clenshaw 점화식으로 평가합니다. 변위에 `wideLift × (open − 1)`을 곱하므로 원화 값 1은 정확히 유지됩니다. 가로는 원래 눈 너비, 세로는 원래 열린 높이를 단위로 씁니다. 상수항은 전체 상승, 나머지 항은 양 끝 차이와 국소 곡률을 조절하여 중앙만 솟지 않게 합니다. 위아래 눈꺼풀은 눈꼬리에서 2D 변위를 공유하고 흰자와 속눈썹은 같은 개구를 사용합니다. 복합 눈선은 위아래 사이 위치에 따라 변위를 연속 분배하고 돌출 꼬리는 원화 오프셋을 보존하며 위 속눈썹은 같은 열의 두께를 유지합니다. 아래 눈꺼풀 근처 획은 원래 아래 가장자리의 최근접점을 따라 가파른 눈꼬리 아래 두꺼운 꼬리가 세로 열 전단으로 뒤집히지 않게 합니다. 쌍꺼풀선과 그림자의 쌍조화장은 가로·세로 제약을 함께 받습니다. 기본 상승은 원래 개구의 10%이고 0까지 조절할 수 있습니다. 기본은 온화하게 크게 뜨는 모습이며 명시적으로 저장한 진폭은 그대로 유지합니다. 기존 닫기 구간은 독립적으로 유지합니다. 크게 뜰 때 홍채는 원화 크기와 위치를 유지하고 동공 축소는 별도 감정 제어가 담당합니다.

개폐 관련 불투명도 트랙은 크게 뜬 끝점을 포함한 실제 파라미터 전 범위를 덮습니다. 닫힌 눈 선은 1 초과에서도 계속 숨기며 속눈썹·쌍꺼풀선·하이라이트는 열린 눈 상태의 가시성을 유지하여 트랙 밖에서 정적 불투명도로 돌아가지 않게 합니다.

`FitDetectionTool`은 원화 위에 검출 결과와 각 개방도의 가장자리를 겹쳐 피팅을 검사합니다. 피팅 눈의 속눈썹·흰자·닫힌 눈선 메시는 약 4배 촘촘하여 호로 휘었을 때 다각형 꺾임이 드러나지 않습니다.

## 구현 규칙

- `legacy` 기본 알고리즘의 코드 경로는 유지합니다.
  - 새 기본 알고리즘·모듈은 분기 지점에서 `config.recipe.base(部位)`와 `RigModules.builds(模块, config, 素材)`에 따라 구현을 선택합니다.
  - 구현은 순수 기하 입력만 의존하고 UI 상태를 읽지 않습니다.
- 모듈이 어느 파라미터의 키 위치를 바꾸면 그 파라미터를 공유하는 모든 메시가 같은 키 집합을 사용해야 합니다. 예를 들어 흰자는 홍채 마스크이므로 속눈썹과 키가 같아야 합니다.
- 2차 변화는 주 키폼 위에 블렌드 셰이프로 더하는 방식을 우선하여 차원마다 키폼 수가 곱해지는 일을 피합니다. 블렌드 셰이프를 지원하지 않는 내보내기 대상은 기능 저하 처리기가 베이크하거나 버리고 손실 보고서에 기록합니다.
- 생성 결과에는 Cubism이 표현할 수 있는 블렌드 셰이프만 포함합니다(`CubismBlendShapes`, 기본 Rig 조립 이후 실행). Cubism은 ‘블렌드 셰이프’ 타입 파라미터에서만 이를 중첩하며 이런 파라미터는 키폼 축으로 쓸 수 없습니다. 일반 파라미터에 연결된 셰이프는 moc3 / cmo3로 쓸 수 없고 Cubism 런타임에서도 잘못 그려집니다. 따라서:
  - 블렌드 셰이프만 사용하고 기본값이 0이며 각 셰이프 정지 키가 0인 파라미터(모음, 얼굴 추적, 눈썹 모양, 머리카락·천 체인 구간, 팔 흔들림, 가슴 등)는 블렌드 셰이프 파라미터로 변경합니다.
  - 키폼 축도 겸하는 파라미터(고개 각도, 눈·입 개폐, 시선, 눈썹 높이·각도, 입 모양)의 셰이프는 키폼으로 바꿉니다. 메시 자체 키폼 격자(기하와 각 채널 축의 합집합, 즉 moc3의 해당 메시 키폼 수)가 256개 이하이고 정점 값이 12만 이하라면 파라미터 키에 따라 메시로 접어 넣습니다. 결과는 정확합니다(셰이프 가중치는 키 사이에서, 제한은 점 사이에서 선형이므로 모든 키에서 평가한 격자가 완전히 재현). 넘으면 메시 자체 Warp에 맡깁니다. `<网格 ID>_Turn`은 회전, `<网格 ID>_Shape<n>`은 나머지 연동을 담고 각각 64키폼 이내입니다. 메시와 원래 부모 사이에 넣으며 8×8 격자를 메시 정점의 각 자체 키폼 변위에 최소제곱 피팅합니다. 이는 Live2D 수작업 모델에서 부품 Warp에 회전을 넣는 방식과 같습니다. 부모가 휠 때 Warp는 격자 근사만 가능하므로 오차는 약 1캔버스 픽셀입니다.
  - 셰이프가 바꾸는 불투명도·색은 메시 채널에 접어 넣습니다. 생성 셰이프는 그리기 순서를 바꾸지 않습니다(각 셰이프는 메시 최종 정지값의 그리기 순서를 사용).
- 생성 객체와 파라미터 ID는 결정적입니다.
  - 추가 파라미터는 Cubism 표준명을 우선하고 얼굴 추적 확장은 일반적인 커뮤니티 이름을 사용합니다.
  - 새 객체 ID는 모듈과 대상에서 파생하며 난수를 쓰지 않습니다.

## 세 계층 입 모양과 추적 내보내기

입 전체 소재에서 윤곽을 생성할 때 닫힌 입선은 입 모양 설정의 연속 곡선을 사용하며 개구 윤곽 중점은 닫힌 입선으로 남기지 않습니다. 독립적으로 분리된 입술선은 원화 구조를 유지합니다. 원화와 대상 윤곽의 표본 밀도가 다르면 샘플링 잔차를 닫으면서 거두어 위아래 입술 가장자리와 입술을 가로지르는 윤곽의 중첩 구간이 같은 선으로 모이게 하며, 가파른 입꼬리에 짧은 꼬리를 남기지 않습니다. 원화의 열린 입 포즈는 원래 윤곽을 유지합니다.

피팅 입은 정규화 윤곽, 변형 부분공간, 사용자 파라미터의 세 계층으로 평가합니다. 원화의 중립 열린 입은 제자리를 유지하고 닫을 때 위아래 가장자리가 만납니다. 셀 채색 입술선은 국소 접선·법선으로 두께를 유지하고 두껍게 채색한 입술 피부 바깥은 주 얼굴과 입 주변 변형을 공유합니다. 위아래 치아는 각각 위턱·아래턱을 따르며 입을 비틀면 치열 전체를 기울이고 눌리는 쪽을 모읍니다. 한쪽 입꼬리와 한쪽 부풀림·오므림은 독립 파라미터로 더합니다.

분리된 입의 치아·혀는 구강 마스크로 자르고 벌림에 따라 페이드인하지 않습니다. 불투명도 0인 구강도 마스크로 사용할 수 있습니다. 혀 내밀기는 결정적 ID의 동반 메시 `<舌网格 ID>_Out`을 생성합니다. 정지 시 투명하고 구강으로 자르지 않으며 아랫입술 위·윗입술 아래에 놓입니다. 모음 입 모양은 독립 구동할 수 있으며 개폐 파라미터가 커질수록 약해져 음성과 얼굴 추적을 중첩할 때 중복 개방을 피합니다.

`eye.gaze-lid`는 `ParamEyeBallLX/LY/RX/RY`를 추가하고 공유 시선 파라미터도 유지합니다. 독립 시선은 해당 홍채·눈꺼풀에 동시에 작용하며 2D 파라미터 미러링과 프로젝트 재구성에 호환됩니다.

VTube Studio 내보내기는 다음 선택지를 제공합니다. 출력 파라미터마다 한 번만 매핑하며 없는 모델 파라미터에는 매핑을 만들지 않습니다.

| 설정 | 선택값과 동작 |
| --- | --- |
| `vts_mouth` | `standard` 얼굴 추적; `voice` 음성 모음(모음 파라미터가 없으면 음량으로 개폐 구동); `voice_hybrid` 음성·얼굴 추적 혼합; `vbridger` 플러그인의 JawOpen, MouthPucker, MouthFunnel, MouthShrug, MouthPressLipOpen 입력 추가 |
| `vts_gaze` | `independent` 좌우 독립, 이전 모델은 공유 시선으로 복귀; `shared` 오른눈 시선 공유; `mouse` 마우스 위치 |
| `vts_brows` | `independent` 좌우 눈썹 높이; `shared` Brows 공유 |
| `vts_position` | 기본으로 꺼짐. 기존 `ParamFacePositionX/Y/Z` 매핑 |
| `vts_angry` | 기본으로 꺼짐. 실험적 FaceAngry 입력을 기존 눈 감정 파라미터에 매핑 |

공식 머리·시선·입·마우스·음성 입력 33개를 지원하고 배타적인 입력은 모드별로 선택합니다. 사용자 모델은 `Param<输入名>`으로 해당 공식 입력(예: `ParamVoiceSilence`)에 연결할 수 있으며 내보내기는 빈 파라미터를 생성하지 않습니다. VBridger 모드는 사용자가 플러그인을 실행하고 해당 입력을 제공해야 합니다.

입력명은 [VTS 공식 파라미터 표](https://github.com/DenchiSoft/VTubeStudio/wiki/VTS-Model-Settings#supported-input-parameters-face-tracking-etc), 플러그인 파라미터는 [VBridger 공식 문서](https://github.com/PiPuProductions/VBridger-Documentation/wiki)를 따릅니다.

현재 시각적 한계: 두껍게 채색한 입술 피부에서 최대 비틀기와 벌림을 중첩하면 입 주변 피부의 점별 변위 혼합으로 국소 메시가 뒤집힐 수 있습니다. 이 조합은 아직 시각 검수를 통과하지 못했으며 공유 피부장을 더 수정해야 합니다.

### 눈 구조 보정

`module_catalog.eye_structure`는 눈마다 원화 경로, 구성 요소 ID, 원본 요약, 위아래 소속, 기하 타입, 접합 영역, 분기 경로를 반환합니다. 관찰은 원래 생성 픽셀을 출처로 삼고 원본 레이어, UV, 그리기 순서, 명시적 마스크를 보존합니다. 숫자 접미사는 대체 이미지를 뜻하지 않습니다.

`settings.rig.eyeParts[layerId][componentId]`는 `side`, `region`, `primitive`, `contacts`, `path`를 재정의할 수 있으며 일치하는 `sourceStamp`를 반드시 함께 넣어야 합니다. 경로·접합 좌표는 해당 눈의 로컬 좌표(안쪽 눈꼬리를 원점, 눈 너비를 단위, 둘째 축을 얼굴 아래 방향)입니다. 원본과 맞지 않는 재정의도 저장하지만 변경된 원화에는 적용하지 않으며 원본을 복원하면 다시 유효해질 수 있습니다. 구성 요소, 레이어, 전체 `eyeParts`의 null 패치는 재설정에 사용합니다. 연속 설정 제스처에서도 재설정 순서를 보존합니다. 새 설정 노드는 schema 5를 쓰고 구조 보정이 없는 이전 프로젝트는 기존 노드 버전을 유지합니다.
