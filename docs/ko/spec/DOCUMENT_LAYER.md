# 문서 계층: 생성기, 재정의, 캐시

형식 설계는 프로젝트를 "의도 + 사용자 재정의"로 정의합니다. 생성기는 파라미터만 저장하고 생성 결과는 순수 함수로 계산하며, 생성 결과에 대한 사용자의 수정은 안정 ID 기준으로 기록하고, 생성기를 다시 실행할 때 3방향 병합을 합니다. 1단계에서는 흔들림 생성기를 본보기로 삼아 메커니즘을 검증했습니다. 이 페이지는 나머지 생성기로의 확장, 측정에 따른 생성 캐시 도입, 프로젝트 형식 v2의 구현 상태를 기록합니다.

## 구현 완료

| 부분 | 위치 | 내용 |
| --- | --- | --- |
| 내용 해시 | `format-compile` `document/ContentHash` | 각 부분의 정규 텍스트에 대한 SHA-256, 길이로 구분, IR 값을 바로 해시 가능 |
| 의존성 그래프 | `document/GeneratorGraph` | 생성기가 읽는 안정 ID와 소유하는 안정 ID를 선언. 위상 정렬, 순환 금지, 한 객체에 소유자는 하나뿐. 변경 후 다시 계산해야 하는 하위 생성기를 제시 |
| 생성 캐시 | `document/GenerationCache` | 입력 내용 해시로 생성 결과를 캐시(LRU). 미스 시 잠금 밖에서 계산하므로 느린 생성기가 다른 키를 막지 않음 |
| 3방향 병합 | `document/ThreeWayMerge` | 키 단위 병합: 사용자가 바꾸지 않은 것은 생성기를 따르고, 생성기가 바뀌지 않은 것은 사용자 값을 유지하며, 양쪽이 모두 다르게 바꾸면 사용자 값을 유지하고 충돌을 보고 |
| 문서 생성기 그래프 | 루트 프로젝트 `core/DocumentGenerators` | 프로젝트의 생성기를 의존성 그래프 노드로 등록. 재생은 그래프 순서대로 흔들림과 시뮬레이션을 실행. 재정의는 그래프로 키폼의 소유자를 찾음 |
| 생성 결과 재정의 | `core/GeneratedOverrides` | 흔들림 Warp 키폼과 베이크된 시뮬레이션 메시 키폼에 대한 캔버스 편집을 `generated_override`로 기록하고, 모든 생성기 뒤에 제어점 / 정점 단위로 3방향 병합해 재생 |
| 뼈대와 모션 캐시 | `core/SkeletonRig.generate`, `core/MotionPresets.tracks` | 뼈대 베이크와 생성 모션을 입력 내용 해시 기준으로 `GenerationCache`에 연결 |
| 재생 체크포인트 | `core/legacy/ReplayCheckpoints` | 체크포인트가 없는 저널에만 사용: 기반 리그 인스턴스와 저널 접두부 내용으로 재생 중간 모델을 캐시. 추가하면 새 항목만 재생하고, 실행 취소는 기존 체크포인트에 적중 |
| 생성기 재사용 | `core/DocumentGenerators`(`GeneratorReuse`) | 흔들림과 시뮬레이션이 객체 수준 읽기를 선언. 읽기가 바뀌지 않으면 지난 출력을 패치로 적용하고 다시 생성하지 않음 |
| 분할 실체화 | `core/ArtPrimitiveJournal`, `core/RigRegenerationCheckpoint`(`split`), `application/WorkspaceArtPrimitives` | 분할은 한 번의 재생성: 파츠가 원래 레이어를 대신해 생성에 참여하고, 원래 레이어에 대한 사용자 수정은 3방향 병합으로 파츠에 옮겨지며, `art_primitive` 레코드 뒤에 체크포인트를 씀. [분할 실체화](#분할-실체화-아트-프리미티브-레코드-art_primitive) 참고 |
| 작성 리그와 체크포인트 | `core/RigEditOverlay`(`replayAuthored`/`finish`), `core/RigCheckpoint`, `core/RigRegeneration`, `project/MaterializedRigStore` | 재생을 작성 단계와 마무리 단계로 나눔. 작성 리그는 리비전별로 저장해 빌드에 바로 사용. 저널 아래의 생성 결과가 바뀌면 3방향 병합하고 체크포인트를 씀. [체크포인트](#체크포인트)와 [실체화된 리그](MATERIALIZED_RIG.md) 참고 |
| 프로젝트 형식 v2 | `project/ProjectFormatV2` | 각 리비전을 내용 주소 방식의, 스키마 버전이 붙은 문서 노드로 분할. v1은 연 뒤 다음 저장 때 마이그레이션. [프로젝트 형식](PROJECT_FORMAT.md) 참고 |

`format-compile`의 네 가지 프레임워크 부분은 MIT이며 어떤 GPL 모듈에도 의존하지 않습니다.

## 프리셋 설정 초안

프리셋 컨트롤은 설정 패치만 투영하며, 현재 미리보기의 `RigEditOverlay`나 메시 기준선을 설정 편집으로 커밋하지 않습니다. `WorkspaceSettingsIntent.patchSettings`는 즉시 표시되는 연동 규칙을 제공합니다. `WorkspaceGenerationCommands.prepareSettingsDraft`는 캡처한 커밋된 문서에 같은 의도를 적용하고, 작성 포즈를 해제하고, 생성 결과를 다시 빌드하고 병합합니다. 미리보기와 커밋은 같은 순수 후보를 사용하며, 미리보기가 만든 체크포인트는 임시 모델에만 존재합니다.

슬라이더, 숫자 입력, 색상 팝업은 편집 세션 단위로 작업을 나눕니다. `WorkspaceSettingsDraft`는 연속된 수치 샘플을 최종 패치로 합치고, 포즈를 해제하는 토글 전환의 순서는 유지합니다. 세션이 끝나면 `WorkspaceDraftQueue`와 런타임 CAS를 거쳐 히스토리 노드 하나를 발행하며, 변화가 없으면 추가하지 않습니다. 시뮬레이션과 물리 편집은 계속 각자의 애플리케이션 계층 명령을 사용합니다. 저장은 먼저 컨트롤 세션을 끝내고 초안 커밋을 기다립니다. 이전 편집 기록과 히스토리 스냅샷은 그대로 유지됩니다.

## 생성기 의존성 그래프

`DocumentGenerators.graph`는 각 프로젝트에 대해 다음 노드를 구성합니다(객체 ID: `document:<부분>`은 문서 상태, `rig:<단계>`는 리그 전체 단계, `parameter:<ID>`는 생성된 파라미터, `keyform:<warp|mesh>:<대상>@<파라미터>`는 생성기가 해당 파라미터를 따라 대상에 추가한 키폼):

| 노드 | 읽기 | 소유 |
| --- | --- | --- |
| `rig.footprints`(메시 윤곽) | 원본 이미지, 설정, 레이어별 메시 설정 | `rig:footprints` |
| `rig.scaffold`(앵커, 얼굴, 프레임과 디포머) | `rig:footprints`, 레이어 분류, 설정, 뼈대 정의 | `rig:scaffold` |
| `mesh:<레이어>`(레이어별 메시와 키폼. 레이어 목록이 없으면 `rig.meshes`로 합침) | `rig:scaffold`, 해당 레이어의 픽셀, 분류와 메시 설정 | `rig:mesh:<레이어>` |
| `rig`(조립과 아틀라스 바인딩) | 각 레이어의 메시, `rig:scaffold`, 원본 이미지, 설정, 레이어 분류 | `rig:base` |
| `skeleton`(뼈대 베이크) | `rig:base`, 뼈대 정의 | `rig:skeleton` |
| `journal`(편집 재생) | `rig:skeleton`, 편집 저널 | `rig:authored` |
| `skeleton.skin`(저널이 배치한 메시의 본 스키닝. 저널이 본에 바인딩된 메시를 자기 디포머 아래에 걸었을 때만 존재) | `rig:authored`, 뼈대 정의 | 이 메시들이 자기 팔다리 본, 위쪽 몸 절반, 뼈대 포즈 파라미터에 대해 가지는 키폼 |
| `swing:<ID>`(베이크되지 않은 각 흔들림) | `rig:authored`, 해당 흔들림의 설정 | 그 파라미터, 그리고 그 파라미터가 각 대상 Warp에서 가지는 키폼 |
| `simulation:<ID>`(베이크되고 활성화된 각 시뮬레이션) | `rig:authored`, 해당 시뮬레이션의 설정과 베이크 | 그 모드 파라미터, 그리고 모드 파라미터가 베이크된 메시에서 가지는 키폼 |
| `overrides`(재정의 병합) | 생성된 모든 키폼, 재정의, 생성기 집합 | `rig:final` |
| `seeThrough`(앞머리 투과 복제본) | `rig:final`, 설정 | `rig:seeThrough` |
| `physics`(물리 그룹) | `rig:final`, `rig:seeThrough`, 생성된 파라미터, 물리와 뼈대 설정 | `physics` |
| `motions`(생성 모션) | `rig:final`, `rig:seeThrough`, `physics`, 모션 설정, 뼈대 정의 | `motions` |

- 재생(`RigEditOverlay.applyTo`)은 그래프의 위상 순서대로 저널 뒤의 노드를 실행합니다. 먼저 `skeleton.skin`, 그다음 흔들림과 시뮬레이션이며, 이는 이전의 "흔들림 전부, 그다음 시뮬레이션 전부" 순서와 같습니다. 동률은 선언 순서로 정합니다.
- 앞머리 투과 복제본(`SeeThroughLayers`, [디포머와 파라미터 참조](DEFORMER_AND_PARAMETER_SPEC.md#생성되는-변형) 참고): `rig` 노드는 후보(앞머리에 가려진 눈썹과 각 눈 레이어, 그리고 그 앞머리)만 기록합니다. `seeThrough` 노드는 재정의 병합, 레이어 표시 여부, 그리기 순서 재정의 뒤에(`AuthoredRig.finished` 끝, `withSeeThrough`) 설정에 따라 원본으로부터 복제본을 만들고, 눈을 위해 앞머리에 창을 뚫습니다(앞머리 역방향 클리핑, `BuiltRig.seeThroughWindows`). 마스크, 그리기 순서, 불투명도는 모두 그 시점의 원본과 앞머리에서 얻습니다. 창 뚫기로 바뀐 앞머리 마스크는 완성된 리그에만 있으며, 작성 단계와 저널의 앞머리에는 들어 있지 않습니다. 인스펙터는 `authoredMasksOf`를 통해 문서 자신의 마스크를 표시하고 편집하며, 레거시 소프트 삭제로 창을 뚫은 눈 레이어가 모두 삭제되면 창을 거둬들입니다(`withSeeThroughWindowsPruned`). 복제본은 작성 리그에 없고 어떤 `keyform:` 객체도 소유하지 않으며, 참조 필드(분할의 참조 필드와 `id`, `masked_by` 등)에서 복제본을 지목하는 모든 문서 작업(`WorkspaceDocumentEdits` 분배 지점과 저널 기록 지점)은 `WorkspaceGeneratedCopyEdit`(`generated_copy`)로 거부됩니다. 세 가지 설정은 재생만 일으키며 생성 설정으로 치지 않습니다. 복제본에는 자기 레이어 항목이 없으므로, 레이어 단위로 메시를 처리하는 곳(레거시 소프트 삭제가 원본과 함께 복제본을 삭제할 때, 아틀라스 압축과 재바인딩)은 `BuiltRig.layerOf`를 통해 원본의 레이어를 가져옵니다. 생성 마이그레이션이 리그 데이터로 읽는 빌드는 복제본을 만들지 않습니다(`SeeThroughLayers.withoutCopies`). 커밋되지 않은 미리보기(캔버스 각 도구의 `CanvasEditor.preview` 대입, 인스펙터 실시간 필드, Warp 제어 필드)는 모두 `SeeThroughLayers.refresh`를 통해 미리보기 안의 원본과 앞머리로 이어받은 복제본을 다시 만들며, 마스크, 순서, 외관은 커밋 때와 같습니다. 전체를 다시 빌드하는 미리보기(흔들림, 내부 조형 시험 재생)는 복제본이 이미 새 인스턴스이므로 같은 모델을 그대로 반환하며, 참조로 미리보기를 식별하는 곳은 영향을 받지 않습니다.
- 문서가 두 생성기에게 같은 파라미터를 선언하게 하면 먼저 선언한 쪽이 소유권을 유지하고 나중 선언은 버려집니다. 재빌드는 계속 진행할 수 있으며 충돌은 생성기 자신이 보고합니다.
- `DocumentGenerators.stale(before, after)`는 한 번의 문서 변경 뒤에 다시 실행해야 할 생성기를 제시합니다. 변경된 부분을 읽은 생성기와 그 하위 전체이며, 수정되거나 삭제된 생성기가 원래 소유하던 객체도 변경된 것으로 봅니다. 예를 들어 흔들림 하나를 조정하면 그 흔들림, 재정의 병합, 물리, 모션만 다시 실행하고 리그 생성, 뼈대, 다른 시뮬레이션은 다시 실행하지 않습니다.
- 리그 생성은 단계별로 노드에 등록됩니다(아래 [리그 생성 단계](#리그-생성-단계) 참고). `graph(overlay, layers)`에 레이어 목록을 주면 레이어마다 `mesh:<레이어>` 노드가 하나씩 생기며, 어떤 레이어의 픽셀이 바뀌면 그 레이어의 메시, 조립, 그리고 그 하위만 만료됩니다.

## 증분 재생

`RigEditOverlay.applyTo`는 순서대로 작성 단계(체크포인트가 있으면 마지막 체크포인트에서 시작해 그 뒤의 항목만 재생, [체크포인트](#체크포인트) 참고. 체크포인트가 없으면 레거시 정적 편집, 즉 파라미터 삭제/생성, 정적 Warp, 구조, 키폼 set/copy/delete와 `authoringJournal`의 모든 항목을 실행), 흔들림과 시뮬레이션, 재정의 병합, 지연된 패널 편집을 실행합니다. 생성된 문서는 처음 편집한 뒤부터 체크포인트가 있으므로 이후에는 최대 `CHECKPOINT_INTERVAL`개만 재생합니다. 아래의 재생 체크포인트는 체크포인트가 없는 저널(이전 버전이 쓰고 아직 편집하지 않은 리비전)에만 쓰입니다. 흔들림과 시뮬레이션은 `GeneratorReuse`가 읽기 집합 기준으로 재사용합니다.

**재생 체크포인트**(`core.legacy.ReplayCheckpoints`, 체크포인트가 없는 저널에만 사용)

- 재생 체크포인트는 "레거시 정적 편집 + 앞의 `i`개 저널 항목" 뒤의 모델입니다. 조회 조건: 기반 모델이 같은 인스턴스일 것, 레거시 부분이 같을 것(흔들림/시뮬레이션 파라미터 집합 포함. 이것이 구조 편집 중 무엇을 지연시킬지와 인터페이스 언어를 결정함), 앞의 `i`개 항목 각각이 체크포인트가 재생한 항목과 같을 것(먼저 참조를 비교하고, 다르면 내용을 비교).
- 무효화는 인덱스가 아니라 접두부 내용만 봅니다. 앞선 항목을 다시 쓰는 명령(드래그 병합, 생성 결과 재정의 캡처, 메시 정규화)은 그 항목과 그 뒤의 재생 체크포인트를 자연스럽게 불일치시키며, 가장 가까운 유효한 재생 체크포인트에서 재생합니다.
- 각 체인은 인덱스 0, 16개마다, 그리고 마지막 3개의 상태를 보관하며 모두 소프트 참조입니다(메모리가 부족하면 해제). 체인은 최대 4개(최근 사용 우선)까지 보관합니다. 분기할 때는 이전 체인을 유지해 다시 실행이나 전환에 쓸 수 있게 합니다.
- 항목 하나를 추가하면 그 항목만 재생하고, 바로 이전 상태로 실행 취소하면 재생 없이 바로 적중합니다. 완전한 재빌드(다시 열기, 타일 크기를 바꾸는 페인트와 이미지 교체)는 새 기반 리그 인스턴스를 만들어 처음부터 재생합니다. 타일 크기와 위치를 전혀 바꾸지 않는 페인트나 이미지 교체는 같은 기반 리그 인스턴스를 그대로 쓰므로(아래 「아틀라스와 페인트」 참고) 재생 체크포인트가 평소처럼 적중합니다.
- 뼈대는 기반 리그 안에서(저널 앞에서) 베이크되며, 저널 뒤에는 캔버스 스킨 반영만 있습니다. 뼈대 편집은 기반 리그의 내용을 바꾸어 그 이전의 모든 재생 체크포인트가 더 이상 성립하지 않으므로 처음부터 재생합니다. "처음 영향받는 항목 바로 앞에서 이어서 재생"은 뼈대에 적용되지 않습니다. 기반 리그를 내용으로 대조하지는 않습니다. 2배 tml(4096²)에서 기반 리그 전체의 IR 내용 해시는 약 160 ms인 반면, 저널 26개의 완전한 재생은 약 6 ms입니다. 내용이 같은 재빌드는 단계 캐시가 같은 인스턴스를 돌려주므로(「리그 생성 단계」 참고) 인스턴스 대조로 이미 충분합니다.
- `PuppetModel`과 그 객체는 불변 값으로 공유합니다. `-Dpsd2live.replayCheckpoints=false`는 재생 체크포인트와 생성기 재사용을 함께 끕니다. 코드에서는 둘이 별개의 스위치(`ReplayCheckpoints.enabled`, `GeneratorReuse.enabled`)이므로 따로 끌 수 있습니다.

**생성기 재사용**

- 흔들림 읽기: 각 대상 Warp와 그 모든 조상(측정이 이루어지는 부모 공간), 파라미터 목록과 파라미터 트리, 월드 원점(자동 피벗). 쓰기: 자기 파라미터, 파라미터 트리, 대상 Warp.
- 베이크된 시뮬레이션 읽기: 대상 메시와 베이크된 메시(기하, 블렌드 셰이프, 채널), 파라미터 목록과 파라미터 트리, 런타임 대상(블렌드 셰이프 사용 여부를 결정). 쓰기: 자기 파라미터, 파라미터 트리, 이 메시들.
- 생성기를 실행한 뒤 그 출력을 패치로 기록합니다. 새 파라미터 목록과 파라미터 트리, 그리고 교체된 객체입니다. 기록 전에 읽기 집합 안의 객체만 바뀌었고 나머지 필드의 참조는 그대로인지 검증하며, 그렇지 않으면 캐시하지 않습니다.
- 설정이 같고 읽기 집합이 항목별로 같으면(먼저 참조를 비교하고, 다르면 내용을 비교) 현재 입력에 패치를 바로 적용하며, 읽기 집합 밖의 객체는 현재 값을 유지합니다. 참조 비교는 비용이 거의 없습니다. 읽기 집합을 내용 해시하는 쪽이 오히려 생성기 자체보다 비쌉니다(아래 표 참고).
- 내용 비교는 놓칠 수만 있고(배열 필드는 참조로 비교) 오판하지는 않습니다. 놓쳐도 다시 생성할 뿐입니다.
- `DocumentGenerators.stale`은 여전히 문서 수준의 재실행 범위를 제시합니다. 재생할 때는 더 세밀한 객체 수준 읽기 비교를 기준으로 삼습니다. 예를 들어 관계없는 메시를 편집하면 흔들림과 시뮬레이션을 모두 재사용하고, 흔들림의 대상 Warp나 그 조상을 편집하면 그 흔들림만 다시 실행합니다.

**효과**(`CommitPerfTool.baseline`, 같은 기기에서의 전후 비교. "끔"은 재생 체크포인트와 생성기 재사용을 끈 것, "추가"는 마지막 항목을 뺀 저널을 먼저 재생한 뒤 전체 저널을 재생한 것):

| 시나리오 a(뼈대 + 흔들림 2개 + 베이크된 시뮬레이션) | 약 3.7 ms | 약 4.3 ms | 약 1.0 ms | 약 0.6 ms |

## 체크포인트

저널 재생의 전제는 항목이 기록될 때 마주한 생성 결과가 바뀌지 않는다는 것입니다. 생성 입력을 바꾸는 편집(머리카락 시뮬레이션 토글, 뼈대, 생성 설정과 분류, 분할 등)이 기반 리그를 바꾸면, 이전 항목을 새 결과 위에서 재생하지 않고 병합한 뒤 데이터로 저장합니다.

- **트리거**(`WorkspacePreviewBuilder.build`, `RigRegenerationCheckpoint.checkpointed`): 새 문서가 현재 문서를 이어 가고(`RigEditOverlay.continues`: 저널이 현재 저널로 시작함. 공통 시작 부분에 체크포인트가 없으면 레거시 정적 필드도 같아야 하며, 체크포인트가 있으면 더 이상 읽지 않음) 추가 경로를 탈 수 없는 경우입니다. 새 문서의 기반 리그를 생성하고, 이전 항목이 본 부분(`BuiltRig.resolvedPuppet(records)`: 경계 앞의 v2 분할 레코드의 파츠는 제자리에 두고, 그 뒤 레코드의 승객은 유지)을 현재 기반 리그의 `resolvedPuppet()`과 중립 IR로 비교합니다. 다르면 현재 기반을 G, 새 기반을 G′, 현재 작성 리그를 M으로 두고 병합하며(`RigRegeneration.merge`. G와 M은 먼저 새 아틀라스에 다시 바인딩), 현재 저널 끝, 이번 편집의 새 항목 앞에 `rig_checkpoint`를 삽입합니다. 같으면 평소처럼 재생합니다.
- **부모 재정의와 그리기 순서 재정의**: 둘 다 기반 생성의 입력이므로, 생성된 모델에서 이를 바꾸면 마찬가지로 재생성으로 병합하고 체크포인트를 씁니다(체크포인트만으로 빌드할 때는 기반 리그를 생성하지 않으므로, 병합하지 않으면 이 변경이 보이지 않음).
- **생성 설정과 분류**(`RigGenerationChange.changed`가 인정하는 변경: 얼굴 특징, 입 모양, 메시 전용, 머리-몸 강도, `rigTuning`, 레이어 분류): 생성된 모델은 편집을 준비할 때 바로 병합하고 체크포인트를 씁니다(`WorkspacePreviewBuilder.normalizeMeshEdits`). G′는 현재 원본 이미지로 생성하며(저장된 메시 입력은 그대로 사용하고, `generationSource`가 고정된 뒤에 추가된 레이어도 포함), 더 이상 `rig_generation_transition`, `rig_generation_frames`, 마이그레이션과 함께 만들어지던 메시 레코드를 쓰지 않습니다. 병합은 현재 저널 끝의 작성 리그에서 출발하므로 같은 편집은 그 뒤에 항목을 추가할 수만 있습니다. 앞선 항목을 동시에 다시 쓰는 편집은 거부되며("따로 커밋"), 더 이상 이전 항목을 새 생성 결과 위에서 조용히 재생하지 않습니다. 가져온 CMO3 모델은 병합할 생성 결과가 없으므로 여전히 마이그레이션 레코드를 씁니다([레거시 재생](#레거시-재생) 참고).
- **분할**(`RigRegenerationCheckpoint.split`): [분할 실체화](#분할-실체화-아트-프리미티브-레코드-art_primitive)를 참고하세요. 체크포인트는 분할 레코드 뒤에 쓰며, 레코드 자체는 재생하지 않습니다.
- **레코드**(`RigCheckpoint`): 작성 리그의 인덱스(객체는 `RigObjects`에 있으며 문서와 함께 영속화), 그 기반이 된 생성 스냅샷, 병합 문제입니다. 모델 프리셋이 머리카락 시뮬레이션을 켜면 프리셋 내부에서도 마찬가지로 병합하고 체크포인트를 쓴 뒤, 병합된 리그로 가중치를 계산합니다.
- **직접 편집**: 생성된 모델에서 저널을 이어 가며 항목을 추가하는 편집은, 저널에 체크포인트가 없거나 마지막 체크포인트 뒤에 이미 `RigEditOverlay.CHECKPOINT_INTERVAL`(32)개가 있을 때, 먼저 원래 저널 끝, 새 항목 앞에 현재 작성 리그의 체크포인트를 씁니다(`RigEditOverlay.checkpointsBeforeEntries`, `WorkspacePreviewBuilder`). 생성 스냅샷은 이전 체크포인트에 저장된 것을 이어받으며, 없으면 현재 기반 리그를 씁니다. 따라서 처음 편집한 뒤에는 어떤 빌드도 최대 32개와 이번 편집의 항목만 재생합니다. 추가된 항목은 현재 작성 리그에 작용하며, 앞선 항목을 다시 쓰는 편집(드래그 병합, 실행 취소, 다시 실행)은 체크포인트에서 그 뒤의 항목을 재생하거나 저장된 리비전을 가져오고(`PSD2LivePipeline.updateRigEdits`, `RigPreviewModel.authoredWithoutBase`), 어느 쪽도 기반 리그를 생성하지 않습니다. tml 샘플에서 첫 편집은 약 0.2 s, 이후의 체크포인트 작성은 약 50 ms, 콜드 빌드는 약 0.2 s입니다. 가져온 CMO3 모델도 이 두 가지 체크포인트를 쓰며(생성 스냅샷 없이, 바인딩 키는 `cmo3-import`), 가져오기 기준선 위에서 체크포인트부터 재생합니다.
- **재생**: `replayAuthored`는 마지막 체크포인트에서 시작합니다. 그 리그를 `reboundTo`로 기반 리그의 아틀라스에 바인딩한 뒤 그 뒤의 항목을 하나씩 재생합니다(재생 체크포인트를 거치지 않음. 재생 체크포인트 `core.legacy.ReplayCheckpoints`는 체크포인트가 없는 저널에만 쓰임). `authoredRig`의 메시 매핑은 체크포인트 헤더에서 가져옵니다. 그 뒤에 `art_primitive` 레코드가 없으면 빌드는 체크포인트에서 바로 진행되며(`RigEditOverlay.authoredFromCheckpoint`, `materializedPreview(rebind = true)`) 기반 리그를 생성하지 않습니다.
- **생성 기준선**: `rig_generation_baseline`이 고정한 생성 설정과 분류는 그 뒤에 체크포인트가 없을 때만 기반 생성을 제약합니다(`RigGenerationBaseline.restore`). 그 뒤의 항목은 모두 체크포인트에서 재생을 시작하며, 기반 생성은 문서의 현재 설정을 따릅니다.
- **커밋**: 런타임은 재빌드가 삽입한 체크포인트를 커밋되는 문서에 합칩니다(`WorkspaceRuntime.adopted`). 일괄 처리의 구성원은 이전 후보로부터 빌드하며(`rebuildFrom`), 병합의 M은 이전 후보의 작성 리그입니다.
- **마무리 단계**는 평소처럼 저널 전체를 훑습니다. 생성 결과 재정의와 지연된 패널 편집은 체크포인트의 영향을 받지 않습니다.
- **보고**: 마지막 체크포인트의 문제는 `RegenerationQuality`를 거쳐 `workspace_inspect`의 `quality.regeneration`에 들어갑니다. 커밋 전에 `workspace_preview_regeneration`으로 시험 실행할 수 있습니다. 커밋과 똑같이 후보를 준비하고 다시 빌드하며, 쓰게 될 체크포인트(`regeneration`은 병합 문제 포함, `materialized`는 새 항목 앞의 작성 리그)와 추가·삭제되는 객체를 보고하되 아무것도 발행하지 않습니다(`WorkspaceDocumentCommands.previewRegeneration`).
- **시뮬레이션 베이크**는 작성 리그가 마무리 단계를 거친 결과를 읽으며(`SimAuthoring.AuthoredRigs`, `RigPreviewModel.authoredPuppet`), 기반 리그를 생성하지 않습니다.
- 생성된 모델은 뼈대를 켠 뒤 더 이상 저널에서 정점 그룹을 다시 샘플링하지 않습니다(병합이 이를 마이그레이션함). 가져온 CMO3 모델은 병합할 생성 결과가 없으므로 기존 방식대로 처리합니다.

## 생성 결과 재정의

- 키폼의 소유자는 그래프가 결정합니다. 편집한 키에서 어떤 파라미터가 기본값을 벗어나 있고, 그래프에 `keyform:<종류>:<대상>@<그 파라미터>`를 소유한 생성기가 있으면 그 격자점은 생성된 격자점입니다.
- **흔들림**: 자기 파라미터 축이 대상 Warp에 추가한 키폼을 소유합니다. 재정의는 생성기, 대상 `warp:<ID>`, 전체 키, 당시 생성된 격자(`base`)와 사용자 격자(`points`)를 기록하며 제어점 단위로 병합합니다.
- **베이크된 시뮬레이션**: 모드 파라미터가 베이크된 메시에 가지는 키폼을 소유합니다(키폼 축으로 반영하는 시뮬레이션. 블렌드 셰이프로 반영할 때는 메시 격자에 그 축이 없으므로 편집이 재정의로 인식되지 않음). 재정의는 대상 `mesh:<ID>`, 당시 생성된 정점 오프셋(`base`)과 사용자 편집 후의 오프셋(`points`, 현재 모델에 그 캔버스 편집을 적용해 얻음)을 기록하며 정점 단위로 병합합니다. 다시 베이크하거나 게인을 바꾼 뒤, 사용자가 건드리지 않은 정점은 새 베이크를 따르고, 사용자가 건드렸지만 베이크가 바꾸지 않은 정점은 유지되며, 양쪽이 모두 바꾼 정점은 사용자 값을 유지하고 충돌을 보고합니다.
- **채널**: 생성기가 자기 축에 키를 넣은 불투명도, 그리기 순서, 곱하기 색, 스크린 색 키폼도 그 생성기의 소유입니다. 어떤 채널의 트랙이 저널 뒤에서야 생성기의 축을 가지고(작성 리그의 같은 트랙에는 이 축이 없음), 편집한 키에서 그 파라미터가 기본값을 벗어나 있으면 그 격자점은 생성된 것입니다. 키폼 `set`이 그곳에 쓸 때, 그러한 채널마다 `channel`(`opacity` / `draw_order` / `multiply_color` / `screen_color`)이 붙은 재정의 하나로 씁니다. `base`는 당시 생성된 값, `points`는 사용자 값(스칼라는 숫자 하나, 색은 성분 셋)이며, 재생할 때 성분별로 3방향 병합하고 충돌과 고아는 평소처럼 보고합니다(`GeneratedOverrideIssue.channel`, 품질 보고서의 `evidence.channel`). 같은 `set` 안에서 생성기가 키를 넣지 않은 채널, 그리고 저널이 그 축에 스스로 만든 트랙은 여전히 일반 저널 편집입니다. 생성된 채널 격자점으로/로부터의 복사, 채널에서 생성기의 키 삭제도 마찬가지로 기록할 때 거부합니다. 작성 리그가 없는 호출자(`ownedWrites`에 `authored`를 넘기지 않음)는 채널 재정의를 인식하지 않으며 동작은 이전과 같습니다. 현재 저널 뒤에 채널에 키를 넣는 생성기는 없으며, 이 경로는 정적 주광원, 투과 표시 등 색 / 불투명도 키폼을 쓰는 생성기를 위해 준비한 것입니다.
- 이전에는 이런 키폼에 대한 캔버스 편집을 일반 `canvas_geometry`로 썼는데, 재생할 때 파라미터가 아직 없어 재빌드 전체가 실패하고 편집을 커밋할 수 없었습니다. 이제는 커밋할 때 재정의로 다시 씁니다.
- 생성기가 삭제되거나, 베이크되거나(흔들림), 베이크가 취소되거나(시뮬레이션), 축이 바뀐 뒤에는 키가 더 이상 생성된 격자점에 대응하지 않으므로, 재정의는 적용되지 않고 고아로 보고되며 그 아래의 정지 형태에 떨어지지 않습니다. 메시를 다시 생성한 뒤 정점 수가 바뀌어도 마찬가지로 고아로 보고합니다.
- 생성 파라미터의 기본값에서의 편집은 여전히 일반 편집이며 정지 형태를 수정합니다. 이전 프로젝트의 명령은 바뀌지 않으며, 새 커밋만 재정의를 씁니다.
- Bezier 편집과 키폼 `set`(MCP `rig_deform` 포함)이 생성된 격자점에 쓸 때도 재정의로 다시 씁니다. 자식 위치를 유지하는 편집, 생성된 격자점으로/로부터의 복사, 생성기의 축에서 키를 추가·삭제하는 것은 재정의로 표현할 수 없으므로 기록할 때 거부합니다(`GeneratedOverrides.ownedWrites`).
- 다른 객체에서 생성 파라미터를 사용할 때(키 넣기, 채널 키폼, 이름 변경, 범위 변경)는 먼저 생성기의 현재 정의대로 저널에서 그 파라미터를 만들며(`GeneratedParameterAdoption`), 이후 파라미터는 문서에 속하고 생성기는 그것을 그대로 씁니다. [실체화된 리그](MATERIALIZED_RIG.md#41-기록-계층과-적용-계층) 참고.
- 재정의는 기반 리그 생성에 영향을 주지 않습니다. 생성 기하 캐시의 키는 재정의 명령을 무시하므로, 재정의를 추가·삭제해도 기반 리그가 다시 생성되지 않습니다.
- **문제 보고**: 재생할 때마다 기록대로 적용되지 않은 재정의를 구조화된 레코드(`GeneratedOverrideIssue`: 종류 `conflict` / `orphaned`, 생성기 ID, 대상, 전체 키, 충돌한 점 수 또는 고아 재정의의 점 수, 형태의 전체 점 수, 고아일 때는 원인 `missing_keyform` / `shape_mismatch` / `superseded`)로 `BuiltRig.overrideIssues`에 저장합니다. 저널 순서로 정렬하며 병합 의미는 바꾸지 않습니다. 분할로 대체된 메시의 재정의는 원인이 `superseded`입니다.
- `core/quality/GeneratedOverrideQuality`는 이 레코드를 관찰 보고서로 변환합니다(버전 4, 도메인 `overrides`, 세 가지 검사: `generated_overrides`, `superseded_entries` — 버전 2 분할 이전에 자신이 대체하는 메시가 실패했다는 이유만으로 무작업으로 재생된 항목, 등급 info, `see_through` — 설정이 요구했지만 만들지 못한 앞머리 투과 복제본, `SEE_THROUGH_DROPPED`, 등급 info). 충돌은 `GENERATED_OVERRIDE_CONFLICT`, 고아는 `GENERATED_OVERRIDE_ORPHANED`이며, 등급은 규칙 열거형이 유일하게 결정하고(모두 warning, `can_proceed`는 항상 true) 텍스트로부터 추론하지 않습니다. 문제가 없으면 보고서는 완전하고 findings는 비어 있습니다. MCP `workspace_inspect`(scope `project`, 프로젝트가 로드된 경우)는 `quality.overrides`를 반환합니다. 엄격한 구조는 `WorkspaceQualitySchemas`를 참고하세요.
- 인스펙터 툴바는 문제가 있으면 개수 배지를 표시하고, 선택한 객체의 문제는 인스펙터 맨 위에 나열합니다. 배지를 클릭하면 전체 문제 목록으로 전환합니다. 문구는 종류와 원인 코드에 따라 현지화합니다(중/영/일).

뼈대 베이크의 보정 키폼은 재정의로 바꾸지 않았습니다(`skeleton.skin`이 저널이 배치한 메시에 쓰는 키폼은 예외, [저널이 배치한 메시](#저널이-배치한-메시) 참고). 뼈대는 편집 저널 앞에서 실행되고, 저널의 캔버스 편집은 원래 뼈대 뒤에서 재생되며, 메시 재빌드와 함께 새 토폴로지로 마이그레이션됩니다. 재정의로 바꾸면 오히려 메시를 다시 나눈 뒤 고아가 됩니다. 물리 그룹과 생성 모션은 기존의 전체 재정의를 그대로 씁니다(같은 ID의 사용자 물리 그룹이 생성된 그룹을 대체하고, `builtin` 모션 클립이 생성 모션을 대체).

## 측정과 생성 캐시

`GeneratorCostTool`(`PSD2LIVE_TOOLS=1`)은 tml에서 각 생성기와 그 입력의 내용 해시에 드는 시간을 측정하고 `build/tools/generator-cost/report.txt`를 출력합니다:

| 항목 | 생성 | 입력 해시 | 결론 |
| --- | --- | --- | --- |
| 뼈대 베이크(자동 뼈대) | 약 4.7 s | 약 5 ms(기반 리그의 IR + 뼈대 정의) | 캐시에 연결, 적중 후 리그 생성 약 20 ms |
| 생성 모션(모든 프리셋, 뼈대 프리셋 포함) | 약 16 ms | < 1 ms | 캐시에 연결, 적중 후 약 1 ms. 리그 IR 컴파일이 약 16 ms에서 약 2 ms로 감소 |
| 흔들림(2개) | 2.8 ms | 8.4 ms | 내용 해시 캐시를 하지 않음. 객체 수준 읽기 집합의 참조를 비교한 뒤 출력 패치를 재사용([증분 재생](#증분-재생) 참고) |
| 베이크된 시뮬레이션 반영 | 약 0.8 ms | 약 8.6 ms(베이크 JSON) | 위와 같음 |
| 물리 그룹 카탈로그 | 약 0.1 ms | 약 0.1 ms | 캐시하지 않음 |
| 시뮬레이션 베이크 자체 | 약 13 s | — | 명시적 작업이며 결과가 이미 문서에 저장되어 있으므로 다시 계산하지 않음 |

- 뼈대 캐시 키는 베이크가 실제로 읽는 내용만 담습니다. 본에 바인딩된 메시(전체, UV는 바인딩되지 않은 레이어 오프셋), 본을 거는 데, Warp를 구부리는 데, 메시를 바인딩하는 데 쓰이는 디포머(몸, 호흡, 기울기, 다리 Warp, 머리 회전, 본 자체의 ID, 바인딩된 메시의 부모)와 그 모든 조상, 파라미터, 파츠, Glue와 파라미터 트리입니다. 나머지 디포머와 Drawable은 ID, 종류, 순서, 부모만 가져옵니다. 그 밖에 뼈대 정의, 몸 프레임, 바인딩된 메시 중의 수동 토폴로지, 자세, 인터페이스 언어(생성되는 디포머와 파라미터 이름이 현지화되어 있음)를 포함합니다. 아틀라스, 원본 파일, 변형 경로는 읽지도 쓰지도 않으므로 키에 넣지 않습니다. 적중했지만 기반 리그가 다를 때, 읽지 않은 디포머와 Drawable(베이크 시 바뀐 부모 기준), 아틀라스, 원본 파일, 경로는 새 기반 리그에서 가져오고 그리기 순서를 다시 도출합니다. 베이크가 다른 방식으로 읽지 않은 객체를 바꿨다면 그 결과는 IR 전체가 같은 기반 리그에만 적중합니다. 캐시는 최근 결과 4개를 보관합니다. 실행 취소, 히스토리 전환, 내보내기 전후에 같은 리그를 반복 생성하는 경우, 그리고 본에 바인딩되지 않은 메시의 토폴로지 편집이나 메시 설정(몸 프레임을 바꾸지 않을 때)은 모두 적중합니다. 뼈대가 있는 완전한 미리보기 재빌드는 약 5.4 s에서 약 0.5 s로 줄었습니다.
- 내용 해시를 안정적으로 만들기 위해, 리그 생성의 눈과 입술 변형 경로는 메시 ID와 경로 역할에서 파생한 결정적 ID로 바뀌었습니다. 이전에는 생성할 때마다 무작위 UUID였습니다.
- 요청이 ID를 주지 않은 새 객체(캔버스와 MCP가 만든 Warp, 회전 디포머, Glue, 변형 경로, 분할 조각, 깊이 분할의 레이어와 메시, 가져오거나 추가한 레이어)는 `StableIds`가 요청 내용(`state`, `request_id` 등 전송 정보를 제외)에서 ID를 파생합니다. 같은 문서에서의 같은 요청은 재시도, 시험 실행, 커밋에서 같은 ID를 얻으며, 이미 사용 중이면 차례로 `_2`, `_3`을 붙입니다. 일괄 처리 안에서 참조해야 하는 객체는 여전히 요청에서 ID를 주어야 합니다. 저널과 문서에 이미 있는 ID는 그대로 유지합니다. 세션, 작업, 히스토리 노드, 파라미터 스냅샷, 소재 워크플로 레코드 등 리그나 문서 객체가 아닌 ID는 이 제약을 받지 않습니다.
- 생성 모션의 캐시 키는 프리셋 이름, 뼈대 정의, 조정값, 제외된 파라미터를 포함합니다.
- 기반 리그 자체는 여전히 기존의 `GeneratedGeometryCache`(생성 입력을 저장한 프로젝트)와 빠른 재생 경로가 처리합니다. 전자는 최근 결과 4개를 보관하며(가장 최신 하나만 강한 참조, 나머지는 소프트 참조로 메모리가 부족하면 해제), 실행 취소와 히스토리 전환으로 최근 입력에 돌아올 때 재사용합니다.
- `canvas_geometry` 저널 항목은 버전 2부터 실행 위치의 기하에 대한 희소 양자화 증분(`v`, `n`, `q`, 선택적 정점 인덱스 `i`, 정수 증분 `d`)을 저장합니다. 생산자는 여전히 절대 좌표 점을 제출하고 `RigAuthoringJournal.compile`이 인코딩하며, 미리보기와 커밋이 적용하는 것은 모두 디코딩된 명령입니다. 버전 1의 절대 좌표 점은 평소처럼 재생합니다.
- 에디터 미리보기의 moc3 번들은 더 이상 다시 읽어 검증(`validateBundle`)하지 않으며, 사용자에게 쓰는 내보내기는 여전히 검증합니다. 테스트 JVM(어서션 활성화)이나 `psd2live.validatePreviewBundles=true`일 때는 미리보기도 검증합니다.
- moc3 번들의 physics3/motion3 생성과 정규화(지수를 펼치는 정규식 치환)는 이전에 약 18–21 ms로 번들 전체의 거의 절반을 차지했습니다. `Moc3Target`은 입력(물리 그룹, 모션, 파라미터 집합, 파일 이름 접두사)별로 최근 텍스트 4개를 캐시하며, 기하 편집은 이 입력을 바꾸지 않습니다. 리그 IR 컴파일의 모션 목록도 입력별로 최근 4개를 캐시합니다. 이전에는 컴파일할 때마다 프리셋마다 뼈대 정의를 직렬화해 생성 모션 캐시를 조회했습니다(약 2.5 ms, IR 컴파일 2.9 → 0.3 ms). `POS_VALUES`는 전체 길이를 먼저 계산한 뒤 한 덩어리로 쓰며, 라이터는 크기가 정확히 맞으면 버퍼를 복사하지 않고 바로 넘깁니다(tml 뼈대 리그의 moc3는 약 7 MB, 쓰기 13.7 → 6.8 ms). 번들 전체는 약 48 ms에서 약 20 ms로 줄었으며, 내보내기는 바이트 단위로 바뀌지 않습니다(`ExportGoldenTool`). Drawable별 IR 캐시는 하지 않았습니다. `PuppetIr.toIr`는 배열을 감쌀 뿐이며 약 0.2 ms입니다.
- 기하 안전 검사는 객체를 비교할 때 더 이상 각 메시와 디포머의 기하를 리스트로 박싱하지 않습니다. 같은 인스턴스는 바로 같다고 보고, 나머지는 배열을 비트 단위로 비교합니다. 좌표별 샘플링은 각 대상의 참조 면적과 유효성 검사를 재사용하고, 메시 샘플링은 선택기용 정규화 영역을 건너뛰며, 기준선과 후보의 점이 같으면 상태를 재사용합니다. 전체 보고서는 이전과 바이트 단위로 같으며(`SafetyGoldenTool`이 무작위 편집 24세트를 대조), 일반 메시 편집은 약 15–30 ms에서 2 ms 이내로 줄었습니다. 본에 바인딩되어 조합 영역이 16384개 좌표로 샘플링되는 메시는 여전히 약 1 s가 걸립니다(이전 약 2–3 s). 커밋은 새로 추가된 저널 명령에 따라 비교 범위를 추가로 좁히며, 규칙은 [MCP_AUTHORING.md](../agent/MCP_AUTHORING.md#기하-검사와-시험-실행)를 참고하세요.
- 리그 생성은 아틀라스 레이아웃을 읽지 않습니다. `RigBuilder`는 먼저 바인딩되지 않은 리그(`BuiltRig.unbound`)를 생성합니다. 메시의 텍스처 좌표는 정점이 레이어 사각형 왼쪽 위 모서리에 대해 가지는 캔버스 단위 오프셋이며, 아틀라스에는 배치 없는 타일만 있고 페이지는 없습니다. 이어서 `UvBinding`이 현재 배치에 따라 페이지 UV로 환산해 페이지와 타일에 씁니다. 같은 레이어 집합을 다른 방식으로 배치하면 바인딩되지 않은 리그와 그 내용 해시는 바뀌지 않고 바인딩 결과만 바뀝니다. 0..1 레이어 단위가 아니라 오프셋을 쓰는 것은 바인딩이 기존 페이지 UV를 비트 단위로 재현하게 하기 위함입니다(내보내기는 바이트 단위로 바뀌지 않음). 뼈대는 바인딩되지 않은 리그 위에서 베이크합니다(`BAKE_VERSION` skeleton-3부터). 관절 세분화로 새로 생긴 정점은 레이어 오프셋으로 보간한 뒤 다른 정점과 함께 `UvBinding`이 페이지 UV로 환산하므로, 베이크는 아틀라스를 읽지 않으며 타일을 이동, 크기 조정, 재배치해도 모두 뼈대 캐시에 적중합니다(tml에 자동 뼈대가 있을 때 타일 고정, 밀도 변경, 예산 변경의 단일 커밋이 약 4.5–10.8 s에서 약 30–140 ms로, 레이어 하나를 추가로 소프트 삭제할 때 약 90–150 ms. `TexturePerfTool`). 이전에 페이지 UV 위에서 보간하던 것과 비교해, 새로 생긴 정점의 UV만 마지막 자리 반올림이 다릅니다. canvas, 오프셋, 래스터, 페이지 UV 사이의 환산은 모두 `LayerTexture`가 제공합니다(페인트 재매핑, 생성 리그를 현재 텍스처로 재배치, 메시 마이그레이션 저널, CMO3 가져오기가 공유).
- 아틀라스와 페인트(`AtlasLayout`): 자동 레이아웃은 정규 사각형 배치입니다(`RectPack`, MaxRects: 각 타일 둘레에 `padding`을 두고, 면적, 긴 변, 높이의 세 가지 순서 각각에 대해 "최단 변 잔여"와 "최저 아래 변" 두 가지 점수를 써서, 페이지 수가 가장 적고 마지막 페이지 높이가 가장 작은 것을 택함). 이는 문서만으로 결정되며, 새로 만들기, 다시 열기, 실행 취소, 페인트 커밋, 내보내기가 같은 레이아웃을 얻습니다. 풀이 결과는 타일 크기, 잠금, 고정, 예산 기준으로 캐시되며(최근 8개), 텍스처 크기를 바꾸지 않는 커밋은 다시 풀지 않습니다. 증분 대상은 레이아웃이 아니라 페이지입니다. 각 페이지는 "페이지 크기 + 각 타일 사각형과 픽셀 다이제스트"라는 레시피로 합성해 캐시하며(소프트 참조, 최근 8페이지), 레시피가 바뀌지 않은 페이지는 이전 모델의 같은 `AtlasPage` 인스턴스를 그대로 씁니다. 바뀐 페이지는 다시 합성하고, 교체 대상 페이지와 달라진 행을 기록합니다. "바뀌지 않은 타일은 고정하고 바뀐 타일은 다른 빈자리를 찾는" 히스토리 의존 레이아웃은 채택하지 않았습니다. 크기가 그대로이면 둘은 같고(타일을 제자리에서 다시 그림), 크기가 바뀌면 어떤 레이아웃이든 그 타일의 UV가 바뀌어 네이티브 미리보기가 메모리에서 모델을 다시 빌드해야 하므로, 정규 재배치는 페이지 합성 한 번과 걸친 행의 스트립 인코딩(약 20 ms)만 더 들 뿐이고 그 대가로 레이아웃이 편집 히스토리와 무관해집니다.
- 페이지 PNG는 지연 인코딩합니다. `AtlasPage.png`는 내보내기가 쓰는 ImageIO 정규 인코딩이며, 내보내기나 IR 컴파일이 읽을 때만 생성합니다. 에디터 런타임 번들은 `previewPng`를 쓰며, 16행 단위 스트립마다 Sub 필터와 독립된 deflate(level 1, full flush로 끝남)로 인코딩하고 스트립마다 IDAT 청크 하나를 두며, Adler-32는 각 스트립의 값을 합칩니다. 디코딩된 픽셀은 정규 인코딩과 완전히 같습니다. 파생 페이지는 더러운 행이 있는 스트립만 다시 인코딩하고 나머지 스트립은 교체 대상 페이지에서 가져옵니다. 페이지 전체를 처음부터 인코딩할 때는 스트립을 병렬 처리합니다. 바뀌지 않은 페이지의 바이트 배열은 같은 인스턴스를 유지하므로 미리보기 번들 지문을 다시 해시하지 않으며, `CubismPreviewReload`는 바뀐 페이지만 업로드합니다.
- 페인트 후보는 더 이상 두 번째 패킹을 하지 않습니다. 메시를 유지하는 페인트(그리고 이미지 교체)는 `WorkspaceRasterEdits`에서 픽셀만 잘라내고(`RasterPaintCommit.paintedSource`) 생성 입력을 고정하며, 리그, 아틀라스, 런타임 번들은 모두 그 뒤의 재빌드 한 번에서 나옵니다. 메시 재빌드가 필요한 페인트는 여전히 `RasterPaintCommit.prepare`를 호출해 마이그레이션 레코드를 얻지만, 더 이상 미리보기 런타임 번들을 컴파일하지 않습니다. 재빌드할 때 `WorkspacePreviewBuilder`는 현재 모델의 아틀라스를 `buildPreview`에 넘기며, 그 페이지와 스트립만 빌려 쓰므로 결과는 처음부터 빌드한 것과 완전히 같습니다.
- 재배치된 기반 리그는 "생성 기하 캐시 항목 + 레이아웃 + 텍스처 레이어 메타데이터(픽셀 제외) + 새로 만든 메시 ID" 기준으로 최근 4개를 캐시합니다. 타일 크기와 위치를 바꾸지 않는 페인트는 같은 기반 리그 인스턴스를 얻으므로 재생 체크포인트가 계속 적중합니다. 레이어 투명도 통계(`LayerClassifier`)는 래스터 배열의 동일성 기준으로 캐시하고, 합성 미리보기 이미지(`PreviewRenderer.composite`)는 각 레이어 래스터의 동일성과 위치 기준으로 최근 3개를 캐시하므로, 재빌드는 페인트한 레이어만 다시 스캔합니다.

## 리그 생성 단계

`RigBuilder.build`를 입력을 선언한 단계로 나누었으며, 각 단계의 출력은 `RigStageCache`(파이프라인마다 하나, `PreviewMeshCache`에 붙음)가 "그 단계가 읽는 내용만 담은" 키로 캐시합니다. 키는 기존의 저렴한 다이제스트와 설정 부분 집합을 씁니다. 래스터는 배열 동일성으로 기억하는 SHA-256(`RasterDigest`), 레이어 메타데이터(ID, 이름, 그룹, 순서, 경계, 의미, 풋프린트 경계와 무게중심, 불투명 픽셀 수), 그리고 `stageConfig`입니다. `stageConfig`는 메시, 입, 강도와 튜닝, 생성 모드, 런타임 대상만 남기며, 뼈대, 저널, 레이어별 표, 표시 여부, 그리기 순서, 텍스처/물리/모션/내보내기 설정은 일절 키에 넣지 않습니다. 뼈대를 읽는 단계는 자기가 읽는 부분을 스스로 키에 넣습니다.

| 단계 | 키(읽는 내용) | 용량 |
| --- | --- | ---: |
| 풋프린트 `footprint` | 래스터 크기와 다이제스트, 정수 위치, 알파 임계값, 해당 레이어의 메시 설정, 메시 스케일 | 512 |
| 프레임(매번 계산, 약 1 ms) | 풋프린트를 포함한 분석: 앵커, 얼굴 리그, 머리/얼굴/머리카락 프레임, 자세와 몸 프레임 | — |
| 디포머 `deformers` | 자세 내용 키, 각 프레임, 얼굴 리그의 모든 수치, 앵커, 좌우가 있는 레이어(메타데이터 + 리그 공간 경계), 상의 경계, 설정, 뼈대는 토글과 첫 번째 사용 가능한 상체 본의 양 끝만(`torsoFrame`) | 8 |
| 얼굴 앞쪽 기울기 `lean` | 디포머 목록 인스턴스 | 8 |
| 메시 `mesh:<레이어>` | 레이어 메타데이터와 픽셀 다이제스트, 리그 공간 경계와 무게중심, 부모와 그 프레임, 머리 공간, 눈 레이어는 얼굴 리그, 짝이 되는 흰자 경계, 메시 스케일, 해당 레이어의 메시 재정의, 설정 | 1024 |
| 채널 `channels` | 종류, 파라미터, 토글 키, 의미, 치아 페이드아웃 | 256 |
| 입술 `lips` | 소속 Drawable, 메시 단계 출력 인스턴스, 부모 프레임, 입술 레이어 메타데이터/픽셀/패킹 여부/그리기 순서/표시 여부, 설정 | 64 |
| 바인딩과 뼈대 `bound` | 조립된 모델(구조적 동등, 메시는 인스턴스 기준), 머리카락 시뮬레이션 토글, 아틀라스 배치와 페이지 크기, 각 레이어의 바인딩 메타데이터, 뼈대 정의와 입력, 나머지 결과 필드, 뼈대 캐시 비운 횟수 | 4 |

- 조립(마스크, 파츠, 파라미터)은 매번 다시 하며 약 1 ms입니다. 모든 단계가 적중하면 `bound`는 지난번과 같은 `BuiltRig` 인스턴스를 바로 반환하며, `generatedBase`의 재배치 캐시는 (기하 캐시 항목이 아니라) 기하 리그 인스턴스를 키로 삼습니다. 따라서 어떤 단계도 읽지 않는 내용만 바꾼 경우(예를 들어 저널 항목을 추가해 생성 기하 캐시가 불일치하는 경우)에도 기반 리그는 같은 인스턴스이며, 재생 체크포인트가 계속 적중합니다.
- `bound`에 적중하면 그 뼈대 베이크를 최근 사용으로 표시하므로(`SkeletonRig.touch`), 프로젝트를 저장할 때 헤드 캐시(`ProjectHeadCache`)가 가져오는 것은 여전히 현재 베이크입니다. `SkeletonRig.clearCache`가 증가시키는 카운트가 키에 들어가므로, 비운 뒤에는 다시 베이크합니다. `bound`는 여전히 아틀라스 배치를 키로 삼지만, 그 안의 뼈대 베이크는 배치를 읽지 않습니다. 아틀라스가 바뀌면 `bound`는 불일치하고 뼈대 캐시는 적중하여 바인딩만 다시 합니다.
- 메시 설정이 바뀌면 그 레이어의 풋프린트가 앵커와 프레임을 움직일 수 있으며, 부모 프레임이 바뀐 메시는 그에 따라 재빌드됩니다(tml에서 하의 메시를 바꾸면 메시 약 5개를 재빌드). 얼굴 각 레이어의 메시는 원래 인스턴스를 유지합니다.
- `PreviewMeshCache`의 래스터 다이제스트는 배열별로 기억하는 `RasterDigest`로 바뀌었습니다. 이전에는 호출할 때마다 모든 레이어를 다시 해시했습니다.
- `-Dpsd2live.rigStages=false`(`RigStageCache.enabled = false`)는 비교용으로 단계 캐시와 다이제스트 기억을 끕니다.

**정확성**: `ExportGoldenTool`이 변경 전(bcf919f2)과 바이트 단위로 일치합니다.

**뼈대 커밋**: 뼈대 편집(본 만들기, 바인딩, 관절 이동, 본 삭제)은 `bound`를 불일치시키고 뼈대를 다시 베이크합니다. 베이크는 `SkeletonRig` 안에서 다시 두 단계로 캐시하며, 건드리지 않은 팔다리는 다시 계산하지 않습니다:

- 단일 메시 스키닝(`skinDrawable`, 베이크의 주요 소요 시간)은 그것이 읽는 모든 내용 기준으로 캐시합니다. 그 메시와 디포머 체인(팔다리 트리의 각 본, 부모, 호스트와 모든 조상)의 무손실 IR, IR에 나타나는 파라미터와 그 트리 각 본의 파라미터의 범위와 기본값, 정지 캔버스 정점, 트리 안의 각 본과 그 부모 본, 프리셋 포즈, 소속 본, 트리 안의 블렌드 셰이프 본, 샘플링, 손으로 칠한 가중치와 호스트입니다. 값은 소프트 참조이며 최대 128항목이고, `SkeletonRig.clearCache`가 함께 비웁니다.
- 관절 세분화(`SkeletonMeshRefine`)는 메시 배열, 정지 캔버스 정점, 관절 띠와 분할 수 기준으로 캐시합니다.
- 베이크 전체의 캐시 키는 같은 기반 리그 인스턴스와 같은 입력에 대해 한 번만 계산합니다.
- 건드린 메시 자체의 스키닝: 각 샘플(어떤 본 파라미터 값 조합에서의 `computeDeltas`: 각 본의 변환, 관절 템플릿, ARAP와 표면 평활화)은 그 파라미터 값에만 의존하므로, 피팅, 키폼 격자점, 포즈 블렌드 셰이프에 필요한 샘플을 묶어서 공용 스레드 풀에서 병렬로 풀고 원래 순서대로 읽어 옵니다. 결과는 스레드 수와 무관하며 순차 풀이와 비트 단위로 같습니다(`SkeletonRig.parallelSamples`는 테스트에서 끄는 용도로만 사용). 피팅(`fittedSides`)은 각 본의 양쪽을 함께 진행하며, 매 라운드 원래 순서대로 각 구간을 검사하고 이후 구간은 소수만 미리 가져오므로, 더 계산하는 것은 실패한 구간 뒤의 샘플뿐입니다. ARAP의 전역 방정식(자유 정점의 라플라시안 행렬에 그 포즈의 유도 페널티 항을 더한 것)은 한 번의 풀이에서 모든 지역/전역 반복과 두 좌표축에 걸쳐 바뀌지 않으므로, 풀이마다 엔벨로프 Cholesky 분해를 한 번 하고(역 Cuthill-McKee 정렬과 엔벨로프는 메시마다 한 번만 계산) 전역 단계마다 삼각 후진 대입을 두 번만 하도록 바꾸어, 단계마다 최대 200회 반복하던 켤레 기울기법을 대체했습니다. 켤레 기울기법 결과와의 차이는 4096² 캔버스에서 0.0005 px를 넘지 않습니다(`SkeletonBakeDiffTool`, 모든 키폼과 블렌드 셰이프 키, 렌더링은 픽셀 단위로 같음). `BAKE_VERSION`은 skeleton-4, 스킨 캐시 버전은 skin-2이며, 이전 버전이 쓴 헤드 캐시는 더 이상 적중하지 않습니다. 피팅 허용 오차는 여전히 캔버스 1픽셀입니다. 샘플 수는 캔버스가 커질수록 늘어나지만, 현재 소요 시간에서는 이 때문에 기존 프로젝트의 키폼 수를 바꿀 필요가 없습니다.
- 디포머 단계는 토글과 상체 본만 키에 넣으므로(위 표 참고), 다른 본, 바인딩, 포즈, 가중치를 바꿔도 디포머 인스턴스는 유지됩니다.

메시 편집 정규화(`normalizeMeshEdits`)는 정점 그룹이 있으면 먼저 정점 그룹 항목을 뺀 미리보기를 한 번 빌드해 가중치를 마이그레이션하며, 이어지는 커밋 빌드는 프로세스 수준 베이크 캐시에 적중하므로 뼈대가 아닌 부분(약 60–120 ms)만 더 듭니다. 정점 그룹 항목은 `SkeletonCanvasSkin.lockedTopology`를 통해 기반 리그에 영향을 줄 수 있으므로, 앞의 빌드를 뒤의 빌드에 바로 쓰지는 않습니다.

저널만 바꾸는 커밋은 빠른 경로(`PSD2LivePipeline.canFastUpdateRig`, 캐시된 기반 리그 위에서 재생)를 타지만, 뼈대 베이크도 저널을 읽습니다. 수동 토폴로지(`canvas_topology`)의 메시, 본에 바인딩된 분할 파츠 레코드, 저널이 배치한 캔버스 스킨 메시와 그 정점 주소 지정 레코드의 정점 수(`RigBuilder.skeletonJournalInputs`)입니다. 이 내용이 바뀌면(예를 들어 본에 바인딩된 메시에 대한 토폴로지 편집과 그 실행 취소) 빠른 경로를 타지 않고 재빌드하며, 결과는 콜드 재빌드와 같습니다(`SkeletonIncrementalBakeTest`).

## 레이어별 크기

레이어의 캔버스 위치와 픽셀 수는 서로 독립적입니다(`core/LayerSpace.kt`):

- 캔버스 사각형: 부동소수점 캔버스 단위이며, 원본 레이어의 `rect`이고 기본값은 정수 경계입니다. 레이어가 캔버스의 어디에 있는지를 결정하며, 페인트나 이미지 교체 같은 픽셀 작업은 이를 바꾸지 않습니다.
- 래스터: 레이어의 실제 원본 픽셀 W×H이며, 임의의 해상도일 수 있습니다.
- 고유 밀도: 래스터 픽셀 / 캔버스 단위이며, 두 축이 다를 수 있습니다. 래스터가 정수 경계를 정확히 덮고(1픽셀당 1캔버스 단위) 분수 사각형이 없는 레이어는 이전과 완전히 같습니다.

기하(`core/CanvasDensity.kt`):

- 분석, 분류, 앵커, 윤곽, 메시 생성, 입술, 연결 요소 분할은 모두 캔버스 단위로 래스터를 읽습니다. 밀도가 1이 아니거나 사각형이 분수인 레이어는 분석할 때 캔버스 해상도 뷰 `CanvasDensityLayer`로 바뀝니다. 같은 레이어이지만, 래스터를 면적 평균(확대할 때는 쌍선형)으로 정수 경계에 맞춰 1픽셀당 1캔버스 단위로 리샘플링하고, 사각형 밖은 투명입니다. 따라서 `meshTrace = CANVAS`에서는 32단위 사각형 위의 1024² 래스터와 32² 래스터가 같은 메시를 생성합니다. 완전히 투명한 자리 표시자 래스터는 뷰를 바꾸지 않습니다. `meshTrace = TEXTURE`(새 프로젝트의 기본값)에서는 메시 윤곽만 텍스처 자체를 읽으며(원래 밀도로 정수 경계에 펼치고, 최대 알파로 메시 단위보다 최대 4배 촘촘한 작업 해상도까지 축소), 정점 간격과 오프셋은 여전히 캔버스 단위입니다. [메시 토폴로지](MESH_TOPOLOGY_AND_SPLIT.md#윤곽-추적-해상도)를 참고하세요. 분류, 앵커 등 나머지 분석은 여전히 캔버스 뷰를 읽습니다.
- 생성기의 텍스처 좌표는 여전히 정수 경계 왼쪽 위 모서리에 대한 캔버스 단위 오프셋입니다. `UvBinding` / `LayerTexture`는 텍스처 레이어(`textureLayer`, 뷰 뒤의 원래 래스터)의 공간에 따라 오프셋을 원래 래스터로, 다시 타일로 환산합니다: `raster = (offset − (rect − bounds)) × 밀도`. 사각형이 정수이면 빼는 항이 0이므로 결과는 이전과 비트 단위로 같습니다.
- 미리보기 합성(`PreviewRenderer.drawLayer`), 소재 워크플로, 관찰 렌더링은 래스터를 캔버스 사각형으로 늘려 그립니다.

아틀라스(`AtlasLayout`):

- 각 타일의 텍스처 픽셀 = 래스터 픽셀 × `textureUpscale` × 밀도 배율(`textureOverrides.density`, 기본값 1, 즉 래스터의 원래 해상도) × fit입니다. `textureUpscale`은 여전히 다이제스트 기준으로 캐시되는 원본 이미지 전처리이며 효과는 이전과 같습니다.
- 페이지 크기는 예산의 `pageSize`를 쓰며, 이전과 마찬가지로 가장 큰 레이어의 캔버스 해상도 크기를 담을 수 있을 때까지 늘어납니다(다음 2의 거듭제곱, 최대 16384). 밀도로 인한 초과분은 fit이 처리합니다.
- fit ≤ 1은 잠기지 않은 모든 레이어가 공유하는 계수 하나입니다. 먼저 fit 1로 배치해 `maxPages` 페이지를 넘지 않으면 1을 씁니다. 그렇지 않으면 1/4096 정수 단계에서 들어맞는 최대 단계를 이진 탐색합니다. 결과는 문서만으로 결정되며, 같은 입력은 같은 레이아웃을 얻습니다. 잠긴 레이어(`lock`)는 fit 1을 유지하고, 고정된 레이어(`pin`)는 먼저 지정된 페이지 위치에 놓이며 사각형 배치는 이를 피해 갑니다.
- 잠기거나 고정된 레이어만으로 예산을 넘을 때는 조용히 축소하지 않습니다. 잠금과 고정을 해제한 뒤 함께 fit을 구하고 `PackedAtlas.notices`에 설명을 남깁니다(프로그램 로그에만 기록). 1/4096으로도 들어가지 않으면 fit 1로 페이지 수를 초과하고 설명을 남깁니다. fit < 1일 때도 설명을 남깁니다. 설명은 내보내기 경고에 들어갑니다.
- 타일 크기가 래스터와 다를 때는 `RasterResample`(`format-compile`, 결정적, 사전 곱셈 알파)로 리샘플링합니다. 페이지 레시피는 "타일 사각형 + 픽셀 다이제스트"를 키로 삼으므로 영향을 받지 않습니다. 배치의 `scaleX/scaleY` = 타일 픽셀 / 래스터 픽셀입니다.
- 기본값(모든 래스터가 경계와 같고, 기본 밀도, 기존 설정, fit 1)에서 레이아웃, UV, 페이지, 내보내기는 이전과 바이트 단위로 같습니다(`ExportGoldenTool`).
- 저장된 배치(`atlasArrangement` 설정, `project/AtlasArrangement.kt`): 이것이 있으면 `AtlasLayout`은 더 이상 자동 레이아웃을 풀지 않고, `AtlasArrange.keep`이 저장된 위치와 fit으로 배치합니다. 여전히 예산 페이지 안에 있고, 페이지를 벗어나지 않고, 이미 배치된 타일과 충돌하지 않는 타일은 제자리에 둡니다. 나머지(새로 추가된 레이어, 커져서 이웃과 겹치거나 페이지를 벗어난 타일)는 페이지의 4×4 픽셀 셀 격자에서 첫 번째 빈자리에 넣습니다. 원래 저장 위치가 무효가 된 타일만 설명을 남기며, 새로 추가된 레이어(분할로 대체되었지만 아직 압축되지 않은 원래 레이어 포함)는 조용히 넣습니다. 사각형 타일끼리는 `padding` 간격으로 판단하고, 메시 커버리지 영역이 관련되면 셀 단위로 판단하며 `ceil(2×padding/4)`칸만큼 확장합니다. 저장된 커버리지 영역은 빌드할 때마다 타일의 현재 래스터에 맞춰 보정합니다(`AtlasArrange.covering`). 셀 격자가 래스터 크기와 맞지 않으면(페인트나 이미지 교체가 잘라내기를 바꿈) 폐기하고 전체 사각형으로 처리합니다. 래스터에서 alpha ≥ 8인 픽셀이 커버리지 영역 밖에 있으면(페인트가 메시를 넘어섬) 그 셀을 보충하므로, 인접 타일이 이와 충돌하면 서로 덮어쓰지 않고 빈자리로 밀려납니다. 빈자리로 옮겨진 타일도 커버리지 영역으로 탐색하며 자기 셀에만 씁니다. 정규 레이아웃을 고정해 얻은 배치는 바이트 단위로 같은 페이지를 다시 빌드합니다.
- 일회성 배치(`atlas_pack`, `AtlasLayout.arrange`): 메시 커버리지 영역은 현재 모델의 최종 메시의 텍스처 좌표에서 가져오고, 래스터에서 메시 밖에 있는 픽셀 셀을 보충합니다(`WorkspaceAtlasFootprints`, 셀은 래스터 4픽셀, 변마다 최대 192칸, 삼각형이 셀과 교차하려면 0.01픽셀 이상 들어가야 하므로 레이아웃 변화 뒤의 마지막 자리 반올림이 결과를 바꾸지 않음). 면적, 높이, 긴 변의 세 가지 순서로 셀 격자 위에서 위에서 아래로, 왼쪽에서 오른쪽으로 첫 번째 적합 배치를 하고, 페이지 수가 가장 적고 마지막 페이지가 차지하는 행이 가장 적은 것을 택하며, 사각형은 서로 안에 들어갈 수 있습니다. 예산 페이지 수에 들어가지 않으면 fit은 먼저 64/4096 단계로 이진 탐색한 뒤 8/4096까지 세분화합니다. 사각형으로만 배치(`shape=rect`)하면 자동 레이아웃의 결과를 바로 고정합니다. 페이지를 합성할 때 커버리지 영역이 있는 타일은 자기 셀에만 쓰며(`TileKey.mask`가 레시피에 들어감), 업스케일된 텍스처도 이웃 쪽으로 가장자리를 확장하지 않습니다. 이후의 메시 편집이 배치 당시의 커버리지 영역을 넘으면, 아틀라스 읽기의 `notices`가 재배치를 안내합니다. 자동 배치(`auto=true`)는 저장된 배치를 삭제하며, 타일을 닫거나 옮기면 현재 레이아웃을 저장합니다. 저장된 배치에서 위치를 유지할 수 없는 타일(새 레이어, 분할 파츠, 이웃이 커져 밀려난 타일)은 재빌드할 때마다 첫 번째 빈자리에 다시 들어갑니다. 따라서 타일을 옮기거나 밀도/잠금을 수정할 때는 먼저 현재 모델의 모든 타일 위치를 배치에 다시 써 두며(`WorkspaceTextureEdits.settled`), 이 타일들은 이후 제자리를 유지하고 옮기거나 줄인 뒤 비게 된 자리를 채우지 않습니다. 동시에 커버리지 영역이 없는 타일에 그 메시의 커버리지 영역을 보충하므로(`meshed`, `WorkspaceAtlasFootprints`), 이후 타일은 메시가 실제로 쓰는 셀로만 겹침을 판단하고, 이는 아틀라스 뷰에서 드래그할 때의 판단(`WorkspaceTextureView.meshFootprint`)과 완전히 일치하여 뷰가 허용하는 위치가 곧 실제로 놓이는 위치입니다. 타일은 중심을 기준으로 회전할 수 있습니다(`ArrangedTile.rotation`, `AtlasPlacement.rotation`). 페이지 합성은 회전에 따라 역샘플링하고(`AtlasLayout.writeTurned`, 메시 셀에만 씀), 커버리지 영역은 회전한 셀로 교차를 구하며(`AtlasArrange.shape`의 `rotation`), 메시 UV는 `LayerTexture.tilePlacement`를 거쳐 Umamo의 회전 배치로 환산하고, 내보내기도 회전을 함께 내보냅니다. 아틀라스 뷰의 이동, 크기 조정, 회전은 편집 세션(`TextureWorkspaceState.session`)이며 뷰 표시만 바꿉니다. 적용할 때 밀도와 위치를 하나의 `layer_set_pixel_density` / `atlas_set_tile` 일괄 처리로 커밋하므로, 재빌드 한 번에 히스토리 노드 하나입니다. 이 두 가지 편집(단일 또는 일괄, GUI 또는 MCP)은 발행 전에 `WorkspaceTextureEdits.requireKept`가 후보 모델을 비교합니다. 이전에 위치를 유지하던 타일 중 하나라도 새 레이아웃에서 배치 위치 밖으로 밀려나면 `WorkspaceTileCollision`(`tile_collides`)을 던지고 전체를 커밋하지 않습니다. 일괄 처리는 최종 레이아웃만 검사하며, 일괄 처리에 재배치, 예산 변경, 픽셀 교체, 캔버스 사각형 이동이 포함되지 않을 때만 검사합니다. 쌍 판단(`AtlasArrange.meet`)은 먼저 간격만큼 바깥으로 확장한 회전 외접 상자를 비교하고, 교차할 때만 메시 셀을 비교하므로, 촘촘한 사각형 배치에 커버리지 영역을 보충한 뒤 셀 반올림 때문에 교차한다고 오판하는 것을 피합니다.
- 메시 정체성: 생성 입력을 바꾸는 편집(레이어 추가·삭제, 분류나 생성 설정 변경)은 정규화할 때 먼저 현재 각 메시의 ID를 `splitDrawableIds`에 써 두고(`WorkspacePreviewBuilder.pinnedIdentities`), 생성기는 이에 따라 이름을 붙입니다. 그렇지 않으면 분류와 같은 종류 안의 순번으로 파생된 ID가 바뀌거나 번호가 다시 매겨지고, 재생성 병합은 사용자의 이전 메시를 퇴역 객체로 보고 새 메시 옆에 남겨 둡니다.
- 레이어 삭제(`layer_delete`, `WorkspaceLayerEdits`)는 진짜 삭제입니다. 레이어는 원본 이미지와 생성 입력에서 빠지고, 그 메시는 저널 레코드 `layer_delete`(`LayerDeletionJournal`)를 통해 작성 리그에서 빠지며, 빌드는 그 레코드 앞에 체크포인트를 쓰고 그 이전의 생성 레코드는 더 이상 재생하지 않습니다. 실행 취소는 곧 히스토리 전환입니다. 아래의 지연 필터링은 이전 버전에서 소프트 삭제한 레이어(`deletedLayerIds`, 읽기 전용, `layer_restore`로 복원 가능)와 입술 띠 같은 파생 행에만 쓰입니다.
- 소프트 삭제된 레이어(이전 방식의 분할이 남긴 원래 레이어 포함)는 지연 필터링 모드에서 여전히 완전한 생성과 재생에 참여하며, 완전한 아틀라스가 그 타일을 패킹합니다. 필터링된 모델은 남은 레이어만으로 다시 패킹하며(`RigLayerDeletion.compact`), 남은 메시는 `RigGenerationSource.repack`을 통해 새 아틀라스로 옮겨지고 캔버스 단위로 환산되어 같은 텍셀을 샘플링합니다. 따라서 미리보기, 텍스처 작업 공간, CLI와 GUI 내보내기 모두 삭제된 레이어의 픽셀을 담지 않습니다. 기반 리그가 바인딩된 완전한 아틀라스는 `RigPreviewModel.generationAtlas`에 기록되며, 빠른 재생(`updateRigEdits`)도 필터링 뒤에 똑같이 다시 바인딩합니다. 가져온 CMO3는 원래 레이아웃을 유지하며, 남은 메시가 어느 아틀라스에서도 타일을 찾지 못하면 완전한 아틀라스로 되돌아갑니다. 레이어를 복원하면 다시 완전한 아틀라스를 얻습니다. 분할로 대체된 원래 레이어(`ArtPrimitiveJournal.visibleAnalysis`가 걸러 낸 것)도 마찬가지입니다. 생성할 때는 여전히 패킹되고, 미리보기와 내보내기는 모두 재생 뒤에 보이는 레이어로 압축합니다. 생성 기하 아틀라스(`generationSource`의 기하 리그)는 텍스처 재정의와 저장된 배치를 읽지 않으므로, 텍스처 커밋은 기하 캐시를 무효화하지 않습니다.

내보내기:

- moc3는 페이지와 페이지 UV만 읽으므로 추가 처리가 필요 없습니다.
- cmo3(`Cmo3LayerArt`, `targets/cubism`): Cubism Editor의 레이어는 1픽셀당 1캔버스 단위이며, 에디터는 레이어로부터 아틀라스를 다시 빌드합니다. 기본값 `canvas`: 밀도가 1이 아닌 레이어는 캔버스 사각형 크기로(다운샘플링) 레이어 이미지에 쓰고, 저장되는 아틀라스 페이지는 여전히 고해상도를 유지하며 타일 패킹 스케일이 그만큼 커집니다. 어떤 타일의 아틀라스 밀도(텍스처 픽셀 / 캔버스 단위)가 1보다 크기만 하면 내보내기는 `TEXTURE_SIZE` / `APPROXIMATED` 손실 항목("Cubism Editor rebuilds the atlas from canvas-resolution layers")을 내며, 기존 `textureUpscale` 프로젝트에도 똑같이 적용됩니다. 내부 설정 `layer_art=native`는 원래 해상도로 레이어를 쓰고 모델 이미지 변환으로 캔버스에 맞게 축소하지만, 아직 에디터에서 실측하지 않았으므로 기본적으로 꺼져 있습니다.

이미지 교체(`core/LayerImageReplace.kt`):

- `LayerImageReplace.replace(document, layerId, raster, fit)`는 후보 문서를 반환합니다. 캔버스 사각형과 정수 경계는 그대로이고 래스터만 교체하며(`STRETCH`는 그대로 늘리고, `CONTAIN`은 비율을 유지해 가운데 놓고 투명으로 채움), 처음 교체할 때 이전의 원본 이미지를 생성 입력으로 고정합니다(메시를 유지하는 페인트와 같음). 메시, 키폼, 바인딩은 바뀌지 않으며, 재빌드 뒤에는 바인딩의 UV와 페이지만 다릅니다. 호출자는 평소처럼 재빌드하고 커밋합니다.

가져오기(`core/LayerImport.kt`, 소재 워크플로, CMO3 가져오기):

- 이미지 파일 가져오기(`layer_import_images`)는 투명한 가장자리를 잘라낸 뒤 원래 래스터를 유지합니다. 캔버스를 넘으면 캔버스 사각형만 비율을 유지해 캔버스 안으로 축소하고 래스터는 그대로이므로 밀도가 1보다 커집니다. 캔버스에 들어가는 이미지는 여전히 1픽셀당 1캔버스 단위의 정수 경계이며 이전과 같습니다.
- 가져온 이미지는 커밋 한 번으로 작성 리그 안에 자기 메시를 가지며(`canvas_mesh_create`), 생성 입력을 고정하지 않고 자리 표시자를 쓰지 않습니다. 생성기는 생성 레코드가 소유한 레이어를 투명한 자리 표시자로 취급하고(`RigGenerationSource.createdCoverage`), 그 텍스처 타일만 만듭니다.
- 레이어 전체 변환(`layer_transform`, `application/WorkspaceLayerTransform`): 레이어의 프레임(정수 경계와 부동소수점 사각형)은 바뀌지 않으며, 픽셀, 텍스처 타일, 텍스처 좌표는 모두 프레임에 고정됩니다. 변환 `LayerTransform`(2×3 아핀)은 레이어에 기록되며, 레이어의 각 메시는 정지 자세에서 오브젝트 모드 `canvas_geometry` 하나를 씁니다. 생성기는 프레임만 읽고 변환은 읽지 않으므로, 이동은 재생성이 아니라 작성자의 편집입니다. 페인트 세션은 프레임 안에서 이루어지며, 캔버스는 완전한 변환으로 표시합니다(세션 래스터는 레이어와 함께 회전하는 사변형으로 그리고, 획과 도형은 역변환으로 프레임에 떨어뜨리며, 브러시 크기는 변환의 면적 비율로 환산). 오브젝트 모드 드래그가 어떤 레이어의 메시 전부를 덮으면 캔버스는 이 작업으로 커밋합니다(`AffineFit`가 드래그 전후의 점을 피팅하여, 순수 평행 이동, 축 방향 스케일, 일반 아핀 중 0.01 캔버스 단위 안에서 들어맞는 첫 번째를 차례로 택하므로 회전하지 않은 드래그가 부동소수점 잡음 때문에 회전으로 기록되지 않음. 변환을 합성할 때 백만분의 1 수준의 잔차는 버리며, `isAxisAligned`는 1e-5의 상대 회전각을 허용). `layer_set_canvas_rect`는 현재 표시된 사각형에서 출발하는 한 번의 변환입니다. 레이어 변환만 다른 원본 이미지는 생성과 아틀라스에 대해 같은 것이므로(`PSD2LivePipeline.sameArt`), 이동은 빠른 경로를 타고 모델은 새 원본 이미지로 바뀝니다. 생성 레코드가 소유한 레이어만 추가·삭제하거나 레이어를 이동하는 커밋은 재생성 비교를 건너뜁니다(`WorkspacePreviewBuilder.onlyUsersLayersChanged`). 개발 도구 `LayerFlowPerfTool`은 가져오기, 이동, 부모 변경, 재빌드, 삭제의 커밋 소요 시간을 측정합니다.
- 소재 레이어(`layer_add_from_asset` / `layer_set_placement`)는 소재 픽셀을 래스터로, 배치된 캔버스 사각형을 레이어 사각형으로 삼습니다. `WorkspaceCanvasPlacement.canvasUnitsPerPixelX/Y`가 실제 비율입니다. 평행 이동/스케일/명시적 미러링의 정합은 보간하지 않으며(미러링은 행과 열만 뒤집음), 회전이 있는 정합만 소재 자체의 밀도로 외접 상자에 래스터화합니다.
- CMO3 가져오기는 타일마다 모델 이미지 변환(`_materialLocalToCanvasTransform`, umamo `Cmo3AtlasIngest.canvasTransformByTile`)과 패킹 스케일로 페이지 텍셀/캔버스 단위를 구합니다. 1보다 크면 레이어는 같은 정수 경계 위에서 그 밀도로 래스터를 다시 만들고(예를 들어 고밀도 레이어가 아틀라스 페이지에만 저장되거나, 레이어 자체가 모델 이미지에 의해 캔버스로 축소되는 두 가지 방식), 그렇지 않으면 이전과 바이트 단위로 같습니다. umamo 원본 레이어 목록은 여전히 파일에 기록된 레이어 이미지 위의 사각형을 따르며 캔버스로 환산하지 않습니다.
- 크기 제한(`LayerSizeBudget`): 래스터와 캔버스 해상도 뷰(외접 상자)는 각각 16MP를 넘지 않고, 고유 밀도는 축마다 256픽셀/캔버스 단위를 넘지 않으며, 사각형은 축마다 최소 0.5단위입니다. 한도를 넘으면 명확히 거부하며, CMO3 가져오기가 한도를 넘으면 전체 밀도를 낮춥니다.

페인트(`core/PaintSpace.kt`):

- 페인트는 레이어 자신의 래스터 격자 위에서 이루어집니다(`PaintSpace`). 초안 이미지의 픽셀이 곧 레이어의 래스터 픽셀이며, 같은 밀도로 캔버스 가장자리까지 확장되고, 16MP를 넘으면 레이어 주변 여백을 비율에 맞춰 줄입니다. 제스처, 반지름, 선 굵기, 색 추출은 모두 캔버스 단위이며 아핀 매핑으로 초안 픽셀에 대응합니다. 두 축의 밀도가 다르면 브러시 반지름은 기하 평균을 씁니다. 밀도가 1이고 사각형이 정수인 레이어(그리고 완전히 투명한 레이어)의 초안은 캔버스 그 자체이며, 이전과 비트 단위로 같습니다.
- 커밋은 불투명 픽셀로 잘라낸 래스터와 그 캔버스 사각형(`WorkspacePaintRaster.rect`)을 담으며, 캔버스 해상도로 되돌려 축소하지 않습니다. 사각형은 레이어의 원래 사각형에서 잽니다. 움직이지 않은 변은 원래 좌표를 유지하고, 확장하든 잘라내든 밀도를 유지하며, 정수 경계는 외접 상자를 쓰고, 사각형이 정수 경계와 같으면 저장하지 않습니다. 커밋할 때는 레이어의 원래 영역과 획이 쓴 영역만 읽고 캔버스 전체를 복사하지 않습니다. 완전히 지운 레이어는 이전과 같이 캔버스 원점의 1×1 투명 픽셀이 됩니다.
- 깊이 분할 앞 레이어는 래스터 크기를 유지합니다. 픽셀 중심 기준으로 커밋된 픽셀에서 샘플링하며, 격자가 정렬되어 있으면 비트 단위로 복사합니다. 메시를 유지하는 페인트, 메시를 재빌드하는 페인트, 가져온 CMO3의 페인트는 모두 `LayerSpace`로 타일 주소를 지정합니다(`RasterPaintCommit`의 슬라이스 재매핑, `Cmo3ModelImport`의 페인트 텍스처 좌표). 연결 요소 분할은 원본 레이어 자신의 래스터에서 파츠를 잘라내며, 파츠는 원래 밀도를 유지합니다.

텍스처 명령(`application/WorkspaceTextureEdits`, `WorkspaceTextureOperations`): 텍스처 작업 공간(아틀라스 페이지와 밀도 히트맵, 레이어별 크기 패널, 편집 캔버스의 원본 픽셀 미리보기, [조작 빠른 참조](../guide/USER_GUIDE.md#텍스처-작업-공간) 참고)은 `WorkspaceTexturePort`를 통해 커밋하며, MCP `layer_set_canvas_rect`, `layer_replace_image`, `layer_set_pixel_density`, `atlas_set_tile`, `atlas_set_budget`, `atlas_pack`과 같은 순수 후보를 공유합니다. 모두 백그라운드 작업이자 원자적 일괄 처리의 구성원이며, 조회는 `layer_get_texture`, `atlas_get`, `atlas_check_placement`, `atlas_render_page`입니다([MCP 인터페이스](../agent/MCP_AUTHORING.md#텍스처와-아틀라스) 참고). 분수 사각형을 umamo의 원본 레이어 목록(정수)에 쓸 때는 정수 경계를 씁니다. 목록으로 텍스처를 해석하는 메시 마이그레이션(`LayerTexture.of`)은 분수 사각형에 대해서는 근사일 뿐입니다(정수 사각형은 정확함: 타일 너비와 높이가 래스터 크기, 목록이 캔버스 크기이므로 그 비율이 곧 밀도). 생성 입력의 가장자리 채우기(`RigGenerationSource.padded`, 유지된 메시, 새로 만든 메시, `art_primitive` 파츠의 텍스처 커버리지)는 고밀도 레이어에 대해 원래 밀도로 투명을 채우며 다운샘플링하지 않습니다. `art_primitive`, `canvas_mesh_create` / `canvas_mesh_rebuild`의 `canvas_uvs`는 캔버스 단위이며, `LayerTexture.of`를 통해 고해상도 타일에 매핑됩니다.

## 성능 기준선

`CommitPerfTool.baseline`(`PSD2LIVE_TOOLS=1`)은 tml 위에 자동 뼈대, 흔들림 2개(앞머리, 머리 장식), 베이크된 뒷머리 시뮬레이션 1개를 갖춘 프로젝트를 구성하고, 커밋 경로를 단계별로 측정해 `build/tools/commit-perf/baseline.json`과 `baseline.md`를 출력합니다. 수치는 Windows 개발 기기 한 대에서의 단일 실행에서 얻은 것으로, 같은 기기에서의 전후 비교에만 씁니다. 기기, JIT 워밍업, 동시 부하에 따라 절대값은 두 배 이상 차이 날 수 있으며, 단계 사이의 비율이 더 믿을 만합니다. 단계 값은 여러 번의 웜 호출의 평균이고, 커밋 값은 애플리케이션 계층 명령 경계를 거친 벽시계 시간입니다(커밋마다 히스토리 저장소에 쓰는 것 포함). 네이티브 Cubism 미리보기 리로드는 네이티브 런타임과 GL 컨텍스트가 필요하므로 측정하지 않았고, 리로드 전에 런타임 파일을 쓰는 것("쓰기")만 측정했습니다.

- 재생, 리비전 해시, 저장소 쓰기는 모두 저널 길이에 따라 선형으로 늘어납니다(이는 기준선이며, 재생 체크포인트 도입 이후 추가 커밋의 재생은 저널 길이와 무관합니다. [증분 재생](#증분-재생) 참고). 작업 저장소는 리비전마다 완전한 스냅샷 하나를 씁니다. 200개일 때 커밋마다 약 7 MB가 늘어나며, 시나리오 순서를 모두 마친 뒤 저장소는 약 1.2 GB입니다.
- 뼈대 캐시 키를 좁힌 뒤로, 관계없는 토폴로지 편집 후의 완전한 재빌드는 뼈대에 적중합니다(다시 베이크 0회). `canvas_geometry`를 양자화 증분으로 저장하도록 바꾼 뒤, 위 표에서 메시 전체를 평행 이동하는 항목은 약 17 KB에서 약 12 KB로 줄었고(저널 200개 3.6 M → 2.5 M 문자, 재생 약 82 → 66 ms), 일부 정점만 움직이는 브러시 편집은 움직인 정점 수에 따라 작아집니다.
- 기하 커밋에서 moc3 모델 전체 재컴파일과 기하 안전 검사가 원래 주요 부분이었습니다. 사이드카 텍스트와 모션 목록을 캐시하고, moc3 쓰기를 다시 작성하고, 기하 검사 범위를 좁힌 뒤, 같은 시나리오의 웜 커밋은 약 37 ms입니다(히스토리 저장소 쓰기 약 27 ms와 네이티브 리로드 제외). 런타임 재빌드 약 27 ms(그중 moc3 패킹 약 20 ms로, 주로 메시별 키폼 강등, 정지 메시를 캔버스 공간으로 옮기기, 약 7 MB 쓰기. 재생 약 5–8 ms), 기하 검사 약 4 ms, 후보 준비와 메시 정규화 약 3 ms입니다.
- 페인트와 이미지 교체는 아틀라스 패킹과 PNG 인코딩이 지배하며, 후보 준비와 재빌드에서 각각 한 번씩 처리합니다(이는 기준선입니다).
- 페인트를 레이어 래스터 공간에서 커밋하도록 바꾼 뒤(위 「레이어별 크기」의 페인트 참고), 후보는 더 이상 캔버스 전체를 복사하지 않습니다. 도구는 페인트 세션과 같은 캡처 방식(레이어의 원래 영역과 획 영역)을 쓰도록 바뀌었으며, 같은 기기에서 작은 레이어 페인트 커밋의 중앙값은 약 0.25 s → 약 0.17 s, 그중 후보 준비는 약 56 ms → 약 1.5 ms이고 나머지는 커밋 안의 재빌드입니다.
- 아틀라스를 정규 레이아웃 + 페이지 레시피 캐시 + 스트립 미리보기 PNG로 바꾸고 페인트 후보가 더 이상 패킹하지 않게 한 뒤(위 「아틀라스와 페인트」 참고), 같은 기기에서 동시 부하 아래 전후를 비교하면(두 실행 모두 절대값이 위 표의 유휴 기기 수치보다 높음): 작은 레이어 페인트 커밋의 중앙값은 약 2.5 s → 약 0.35 s(안정화 후 약 0.3 s), 그중 후보 준비는 약 1.5 s → 약 0.17 s, 커밋 안의 재빌드는 약 1.2 s → 약 0.2 s입니다. 같은 형태의 이미지 교체는 약 2.1 s → 약 0.3 s, 미러링한 이미지 교체와 메시 재빌드는 약 3.1 s → 약 0.45–0.8 s, 뼈대가 있는 완전한 재빌드(뼈대 적중)는 약 1.0–1.6 s → 약 0.25–0.4 s입니다. 페이지 전체의 미리보기 스트립 인코딩은 약 20 ms(정규 PNG는 약 0.5 s이며 내보낼 때만 생성)이고, 두 번의 분석 합계는 약 0.2 s → 약 0.03–0.06 s입니다. 내보내기 파일은 변경 전과 바이트 단위로 같으며(`ExportGoldenTool`), 미리보기 번들은 텍스처 페이지 PNG 인코딩 외에는 바뀌지 않습니다.

**프로젝트 열기**: 뼈대 베이크 캐시는 프로세스 안에만 있으므로, 콜드 스타트 뒤 뼈대가 있는 프로젝트를 처음 열 때는 여전히 약 5–7 s의 베이크가 필요합니다. 저장할 때 헤드의 베이크를 아카이브의 선택적 헤드 캐시 `cache/head/`에 쓰고(형식은 [프로젝트 형식](PROJECT_FORMAT.md#헤드-캐시) 참고), 열 때 revision, 프로그램 버전, 생성기 상수, 언어를 대조한 뒤 `SkeletonRig`의 캐시에 심습니다. 재빌드는 여전히 완전한 경로를 타며, 적중 여부는 뼈대 캐시 자체의 내용 키가 결정하므로 결과는 콜드 재빌드와 비트 단위로 같습니다. 저장되는 베이크는 읽기 집합 안의 메시와 디포머만 유지하고, 읽기 집합 밖의 객체는 ID와 순서만 남기며, 적중하면 새 기반 리그에서 가져옵니다. `OpenPerfTool.profile`은 위 시나리오(뼈대 + 흔들림 2개 + 베이크된 시뮬레이션)에서 세 가지 아카이브를 저장합니다. 애플리케이션의 현재 쓰기 방식(각 리비전의 작성 리그와 헤드 캐시. 열 때 생성도 재생도 하지 않음, [실체화된 리그](MATERIALIZED_RIG.md#10-구현-진행-상황) 참고), 헤드 캐시만(생성과 재생, 뼈대 베이크를 심음), 둘 다 없음(생성, 재생, 뼈대 베이크)입니다. 매번 열기 전에 작성 리그 저장소(`MaterializedRigStore.clear()`)와 뼈대 캐시(`SkeletonRig.clearCache()`)를 비우고, 각각 3회 열며, 세 가지가 같은 모델을 빌드하는지 대조합니다. 아래 표는 작성 리그를 도입하기 전에 뒤의 두 아카이브를 측정한 것입니다(각 3회 열기, 빈 뼈대 캐시):

| 아카이브 | 압축 해제와 심기 | 헤드 재빌드 | 합계(곧 첫 표시) | 뼈대 베이크 |
| --- | ---: | ---: | ---: | ---: |
| 둘 다 없음(5.5 MB) | 약 0.35–0.4 s | 약 4.7–5.4 s | 약 5.5 s | 매번 1 |
| 헤드 캐시만(10.9 MB, 베이크 항목 6.9 MB, 압축 후 5.4 MB) | 약 0.37–0.47 s | 약 0.18–0.25 s | 약 0.7 s | 0 |

저장은 약 0.5 s 더 걸립니다(베이크 직렬화와 압축). 연 뒤의 첫 표시는 곧 완전한 재빌드의 결과이며, 런타임 번들을 따로 캐시하지는 않았습니다. 캐시가 있으면 재빌드는 약 0.2 s만 남으므로, 이전 런타임 번들을 먼저 표시했다가 교체하는 이득은 제한적입니다.

## 분할 실체화: 아트 프리미티브 레코드 `art_primitive`

이전의 분할(`canvas_source_partition`, `canvas_depth_split`)은 원래 레이어를 원본 이미지에 남겨 두고 소프트 삭제했으며, 재생할 때 먼저 원래 메시를 비트 단위로 다시 생성하고(기하 지문과 부모를 대조) 레코드 위치에서 그 바인딩을 파츠로 복사했습니다. 여기에는 세 가지 문제가 있었습니다. 생성 규칙이 바뀌면 이전 레코드를 재생할 수 없었고, 아틀라스가 여전히 원래 레이어를 패킹해 CMO3 내보내기에 그 픽셀이 들어갔으며, "모두 복원"이 원래 레이어를 되살렸습니다. 이제 분할은 원래 레이어를 파츠로 **실체화**합니다. 파츠가 유일한 그리기 대상이고 원래 레이어는 더 이상 존재하지 않으며, 분할 이전으로는 실행 취소로만 돌아갈 수 있습니다.

**분할은 곧 재생성**(`WorkspaceArtPrimitives.materialize`, `RigRegenerationCheckpoint.split`): 분할은 원본 이미지를 바꾸므로(원래 레이어가 파츠로 대체됨) [체크포인트](#체크포인트) 방식으로 병합합니다. G는 현재 생성 결과, G′는 파츠가 원래 레이어를 대신한 뒤의 생성 결과입니다. G와 현재 작성 리그 M의 원래 메시는 모두 분할 자체(`SplitParts`: 연결 요소/다각형은 `SourcePartitionJournal.splitParts`, 앞뒤 레이어 분리는 `DepthSplit.splitParts`)가 같은 파츠로 잘라냅니다. 각자 자기 몫의 원래 메시에서 정지 위치, 키폼, 채널, 블렌드 셰이프, 경로, 정점 그룹, Glue를 가져와 같은 정점 출처 집합을 거치므로, 사용자가 건드리지 않은 파츠는 생성된 파츠와 비트 단위로 같고, 사용자가 원래 메시에 가한 수정은 파츠에 대한 수정이 되며, 3방향 병합(`RigRegeneration.merge`)이 이를 G′의 파츠로 옮깁니다(부모가 바뀌면 부모 공간을 거쳐 환산하고, 뼈대가 관절 행을 삽입하면 캔버스 텍스처 좌표를 거쳐 마이그레이션). 분할이 스스로 새로 만든 Glue(다각형 절단점 추종, 앞뒤 레이어 분리의 방향 Glue)는 M 쪽에만 있으며 사용자에게 속합니다. 분할은 `art_primitive` 레코드를 쓰고 바로 뒤에 `rig_checkpoint`(병합 결과와 G′ 스냅샷)를 쓰며, 레코드 자체는 결코 재생하지 않습니다. 이후의 빌드는 이 체크포인트에서 시작하며 기반 리그가 필요 없습니다.

- 원래 메시를 생성기가 생성했다면 레코드는 버전 2의 **선언**입니다. 각 파츠의 정지 캔버스 메시(G의 원래 메시에서 잘라낸 파츠를 생성 디포머를 거쳐 기본 자세에서 캔버스로 옮긴 것), 레이어, 분류, `fixed_topology`(파츠에 사용자 Glue, 정점 그룹, 경로가 있으면 참)를 담으며, `authored`는 빈 객체이고 `glues`는 비어 있습니다. 기반 생성은 이에 따라 파츠를 생성합니다([버전 2 레코드](#버전-2-레코드) 참고). 이후의 얼굴 설정, 자세, 뼈대, 분류 변경도 다음 병합을 거쳐 파츠에 똑같이 도달합니다.
- 원래 메시가 생성된 것이 아니라면(저널이 만든 메시, 예를 들어 생성 입력이 고정된 뒤 가져온 이미지) 레코드는 버전 1이며, 파츠는 모든 데이터를 담고 그 레이어는 기반 생성에 들어가지 않으며, 파츠는 병합에서 사용자 객체입니다.
- 버전 1 대체 경로, 두 번의 캡처, 가드가 없습니다. 병합은 실패하지 않으며, 깔끔하게 마이그레이션되지 않은 곳은 병합 문제로 보고합니다. 원래 메시의 토폴로지를 손으로 고쳤다면 G 쪽에서 같은 파츠를 잘라낼 수 없으므로, 파츠는 사용자 토폴로지대로 유지됩니다(병합에서 사용자가 토폴로지를 바꾼 경우의 규칙과 같음, [실체화된 리그 · 재생성 병합](MATERIALIZED_RIG.md#5-재생성-병합) 참고).


**레코드**(저널 항목, 버전 1 — 지금은 생성되지 않은 원래 메시에 대해서만 쓰며, 이전 버전의 분할은 모두 이것을 씀. 버전 2는 [아래](#버전-2-레코드) 참고):

| 필드 | 내용 |
| --- | --- |
| `op`, `v`, `origin` | `art_primitive`, `1`, `split`(다각형/연결 요소) 또는 `depth`(앞뒤 레이어 분리) |
| `texture_source_id` | 파츠 텍스처가 있는 원본(생성 모델은 `art-0`) |
| `supersedes`, `supersedes_layers` | 이 위치에서 삭제하는 메시 ID와 그 원본 레이어 ID |
| `replace` | 대체되는 메시 → 파츠 메시. 파츠 트리에서의 위치에 쓰이며, `masks`가 없으면 다른 메시의 마스크에도 쓰임 |
| `masks` | 선택 사항. 대체되는 메시가 마스크일 때 어떤 파츠가 대신 맡는지(앞뒤 레이어 분리는 뒤 레이어만 사용) |
| `primitives` | 파츠마다 한 항목: `id`, `layer_id`, `source_id`, `source_bounds`(텍스처가 덮어야 하는 캔버스 사각형), `neutral_bounds`, 이름, 부모, 파츠, 블렌드 모드, 정적 재질과 표시 여부, 마스크, `user_data`. 부모 공간 정점 `positions`, `triangles`, 캔버스 단위 텍스처 좌표 `canvas_uvs`. 사용하는 파라미터 정의, 기하 키폼 `geometry`, 채널 키폼 `channels`, 블렌드 셰이프 `blends`(제한 곡선 포함), 경로 `paths`, 정점 그룹 `vertex_groups` |
| `glues` | `replaced`: 모델 순서대로, 대체되는 메시에 닿는 각 Glue에 대응하는 대체 Glue. `appended`: 맨 끝에 추가하는 Glue(연결 요소 분할의 절단점 추종, 앞뒤 레이어 분리의 방향 Glue) |
| `depth` | 앞뒤 레이어 분리에만: `back`, `front` 레이어 ID와 `glue_id`. `DepthSplit.isFrontLayer`가 이에 따라 앞 레이어 페인트가 토폴로지를 유지하게 함 |

**재생**(`ArtPrimitiveReplay.replay`, 레거시 재생이며 레코드 뒤에 체크포인트가 없는 이전 저널에서만 수행, [레거시 재생](#레거시-재생) 참고): 없는 파라미터는 레코드대로 만듭니다. `supersedes`의 메시를 삭제하고, 파츠를 원래 메시의 목록 위치와 파츠 트리 위치에 둡니다(원래 메시가 이미 없으면 레코드의 파츠나 루트에 추가). 다른 메시의 마스크는 `masks`/`replace`에 따라 다시 씁니다. 대체되는 메시에 닿는 Glue는 차례로 `replaced`의 대응 항목으로 바꾸고(개수가 현재와 맞지 않으면 닿는 Glue를 모두 삭제한 뒤 대체 항목을 순서대로 추가), 이어서 `appended`를 추가합니다. 대체되는 메시의 경로와 정점 그룹은 삭제하고, 파츠의 경로와 정점 그룹은 레코드대로 씁니다. 재생은 대체되는 메시의 기하를 읽지 않으며 그 지문도 대조하지 않습니다. 텍스처 좌표는 캔버스 단위로 저장하며, 재생할 때 현재 아틀라스를 거쳐 환산합니다.

**분할 시 캡처하는 상태**: `RigEditOverlay.authored`는 레거시 편집과 저널 전체를 적용한 뒤, 흔들림과 시뮬레이션 반영 전의 모델을 제공합니다. 파츠는 이 모델에서 가져오므로 흔들림과 시뮬레이션이 생성한 축은 레코드에 쓰이지 않습니다. 연결 요소/다각형 파츠의 정점, 키폼, 블렌드 셰이프, 경로, 정점 그룹, Glue는 원래의 분할 알고리즘으로 마이그레이션합니다. 시뮬레이션 대상, 베이크 오프셋, Glue 역할은 파츠로 옮기며(앞뒤 레이어 분리는 뒤 레이어로), 이후 시뮬레이션이 평소처럼 반영합니다.

**생성 입력**: 분할은 생성 입력(`generationSource`)을 고정하며, 원래 레이어는 그 안에만 남습니다. 생성할 때:

- 대체된 생성 레이어는 여전히 기반 리그 생성에 참여하며, 그 대체 레이어가 현재 원본 이미지에서 차지하는 위치(대체 레이어 중 가장 높은 `order`)에 놓입니다. 따라서 다른 레이어의 그리기 순서, 디포머 프레임, ID는 분할 전과 같고, 레코드 이전의 저널은 평소처럼 재생됩니다.
- 파츠가 있는 레이어는 레코드가 소유하며 기반 생성에 들어가지 않습니다. 그 현재 픽셀은 `source_bounds`에 따라 투명 커버리지를 채운 뒤 패킹합니다.
- 대체된 레이어는 아틀라스에서 1×1 투명 자리 표시자만 차지하며, 레코드 이전의 저널 항목이 주소를 지정하는 데 쓰입니다. 레코드를 재생한 뒤 `BuiltRig.withRigEdits`가 리그의 아틀라스 타일과 아트 목록에서 이를 삭제하고, 미리보기 분석도 더 이상 나열하지 않으므로, 내보낸 CMO3에는 이 레이어가 없습니다.
- 입이 레이어로 분리될 때는 그 생성된 입술이 유지됩니다. 분리되는 것이 입술 자체라면 그 입술이 대체됩니다.

**파츠 이후의 편집**: 파츠는 일반 원본 레이어이며, 페인트, 삭제/복원, 재분할(분할된 파츠도 마찬가지로 대체됨)이 가능합니다. 파츠의 메시 설정을 수정하면 `MaterializedMeshRebuild`가 `canvas_mesh_rebuild`를 추가하고 키폼과 바인딩을 마이그레이션합니다. 파츠는 더 이상 생성 규칙에 따라 자동으로 다시 생성되지 않습니다.

**뼈대 스키닝**(버전 1 파츠, 레거시 재생): 뼈대는 저널 앞에서 기반 리그를 베이크하지만 파츠는 레코드를 재생해야 나타나므로, 기반 리그만 보면 본에 바인딩된 파츠는 존재하지 않습니다(그래서 좌우를 한 장에 그린 뒤 분할한 다리와 신발은 스키닝되지 않았고, 다리 본에는 키폼 없는 파라미터만 남았습니다). 그래서 뼈대 단계(`RigBuilder`)는 먼저 레코드에서 본에 바인딩된 파츠를 디코딩하고(`ArtPrimitiveReplay.skinnable`: 캔버스 단위 텍스처 좌표, 타일과 마스크 없음) 기반 리그와 함께 베이크한 뒤, 스키닝된 파츠와 베이크가 그것들에 추가한 Glue를 기반 리그에서 꺼내 `BuiltRig.primitiveSkins`에 저장합니다. 기반 리그는 여전히 대체된 원래 메시만 담으므로 레코드 이전의 저널은 평소처럼 재생됩니다. 레코드를 재생할 때는 스스로 디코딩하는 대신 스키닝 결과를 쓰며(부모는 본 디포머, 텍스처 좌표는 현재 아틀라스를 거쳐 환산, 마스크는 레코드에서 가져옴), 양 끝이 모두 자리 잡은 Glue는 그 뒤에 추가합니다. 다음 파츠는 여전히 레코드가 스스로 디코딩합니다. 부모나 키폼 파라미터를 더 앞선 저널 항목이 만들어야 하는 파츠, 경로나 정점 그룹이 있는 파츠(베이크는 이를 새로 추가된 정점으로 마이그레이션하지 않음)입니다. 레코드의 부모를 기반 생성이 더 이상 만들지 않으면, 디코딩은 [더 이상 생성되지 않는 부모](#더-이상-생성되지-않는-부모)에 따라 부모를 바꿉니다. 재생 체크포인트는 `primitiveSkins`의 인스턴스를 키의 일부로 삼습니다. `RigEditOverlay.applyTo` / `authored`와 시뮬레이션 베이크는 모두 이를 넘겨야 합니다(`authored(BuiltRig)`).

**소유 관계**: 파츠는 편집 저널 노드(`journal`이 소유한 `rig:authored`)에 속하며, 생성기 의존성 그래프에 따로 나열되지 않습니다. 흔들림과 시뮬레이션은 평소처럼 이를 읽습니다. 대체된 메시에 있던 `generated_override`는 대상을 잃으면 고아로 보고됩니다.

**대체된 ID 참조**: 문서 작업의 참조 필드(`layer_id`, `target`, `source_id`, `middle_ids`, `meshes` 등)가 대체된 레이어나 메시를 가리키면, 오류를 반환하고 그것을 대체한 현재 ID를 나열합니다(여러 번의 분할을 거치면 단계별로 펼침). `source_get_components`도 마찬가지입니다. `layer_restore`는 원래 레이어를 되살릴 수 없습니다(`deletedLayerIds`에 없기 때문).

**호환**: 이전의 `canvas_source_partition`, `canvas_depth_split`은 원래 규칙대로 재생되며, 처음 편집할 때 체크포인트로 고정됩니다([레거시 재생](#레거시-재생) 참고). `LegacySplitReplayTest`는 이전 버전이 저장한 프로젝트로 각 히스토리 노드를 재생한 뒤의 IR 해시가 이전 버전과 같은지 대조하며, 이전 프로젝트의 소프트 삭제된 원래 레이어는 여전히 복원할 수 있고, 이전 프로젝트에서의 새 분할은 실체화 규칙을 따릅니다. 가져온 CMO3 모델의 분할은 여전히 이전 규칙(원래 레이어 소프트 삭제)을 씁니다.

### 더 이상 생성되지 않는 부모

저널이 어떤 레코드 이전에 만든 디포머는 재생이 그 레코드에 도달했을 때 모두 다시 존재합니다. 따라서 레코드의 부모가 재생 위치에서 없다면, 기반 생성이 더 이상 그것을 만들지 않는 경우뿐입니다. 분할 뒤에 생성 설정을 바꾼 경우입니다(뼈대를 켜면 팔 늘어뜨림 Warp `DeformArmHang_L/R`을 더 이상 생성하지 않고 본이 팔을 맡음). 이때 레코드는 아래 규칙으로 재생되며, 저장된 레코드는 다시 쓰지 않습니다. 규칙은 `VanishedParent`와 각 레코드의 재생 구현이 담당하며 결과는 결정적입니다:

- **버전 1 파츠**(`ArtPrimitiveReplay.rehome`, 레거시 재생): 파츠를 그것이 대체하는 메시(`replace`의 키)가 현재 있는 부모 아래로 옮깁니다. 그 메시 자체가 더 이른 레코드의 파츠이고, 뼈대 베이크 디코딩 시점에 기반 리그에 아직 없다면(`skinnable`의 `earlier`), 그 레코드를 따라 계속 앞으로 가며 그것이 대체하는 메시를 찾습니다. 위치는 "레코드 정점 → 캔버스 텍스처 좌표"의 최소 제곱 아핀 피팅(규칙적인 정지 메시나 강체 프레임에서는 정확함)으로 기본 자세의 캔버스 위치로 복원한 뒤, 새 부모 공간으로 역변환합니다. 키폼과 블렌드 셰이프의 변위는 피팅의 선형 부분으로 캔버스 변위로 환산한 뒤 똑같이 옮깁니다. 대체되는 메시를 찾지 못하면 이전처럼 `Art primitive parent is missing` 오류를 냅니다.
- **`canvas_mesh_rebuild`**(`RasterMeshJournal.replay`): 메시가 이미 다른 부모 공간에 있으므로 기하 지문을 더 이상 대조할 수 없어 정점 수(`glue_map` 길이)만 대조합니다. 레코드의 `points`와 `previous_parent_points`는 같은 아핀 피팅으로 메시의 현재 부모 공간으로 옮깁니다.
- **구조 편집 `bind`(메시)와 `move`(디포머)**(`RigStructureEdits.replay`): 대상 부모가 없으면 그 항목은 적용되지 않고 객체는 원래 자리에 남습니다. 새로 커밋하는 편집은 `RigStructureEdits.apply`를 거치며, 부모가 없으면 여전히 오류를 냅니다.
- **`canvas_mesh_create`**는 따라갈 대체 메시가 없으므로, 부모가 없으면 이전처럼 오류를 냅니다.

본에 바인딩되었지만 저널이 본이 아닌 디포머 아래로 건 메시는 베이크에서 부모를 바꾸지 않고 저널 뒤에서 스키닝합니다. [저널이 배치한 메시](#저널이-배치한-메시)를 참고하세요.

### 저널이 배치한 메시

뼈대 베이크는 저널 앞에서 본에 바인딩된 메시를 본의 회전 디포머 아래로 옮기며, 위치와 키폼을 모두 본 공간으로 바꿉니다. 저널이 이후에 이 메시를 스스로 배치하면, 즉 구조 편집 `bind`로 본이 아닌 디포머에 걸거나 `warp` 레코드로 새 Warp에 감싸면, 이 레코드들은 메시의 로컬 좌표(`space=local`, `fit_local`)를 유지하므로 본 공간의 메시 위에서는 올바르게 재생할 수 없습니다. 이런 메시는 `SkeletonCanvasSkin.placedByRecords`가 뼈대 정의와 편집(먼저 레거시 `structureEdits` / `warpEdits`, 그다음 저널을 순서대로 읽음. 메시가 마지막으로 본 디포머에 `bind`된 경우는 제외)으로부터 결정하며, 아래 규칙으로 처리합니다. 저널에 체크포인트가 있으면 스키닝 단계에는 그 밖에도 체크포인트 작성 리그에서 자기 팔다리의 어떤 본에도 끌려가지 않는 바인딩된 메시(`SkeletonCanvasSkin.placed` / `unskinned`, 체크포인트 뒤에 본 디포머에 `bind`된 것은 제외)가 포함되며, 레코드, 재생성 병합, 이전 버전 중 무엇이 그것을 그곳에 두었는지는 상관없습니다. 베이크는 레코드만으로 결정합니다. [실체화된 리그 · 구조 인계와 병합 충실성](MATERIALIZED_RIG.md#11-구조-승계와-병합-충실성)을 참고하세요.

- **베이크**(`SkeletonRig.apply`의 `canvasSkinned`): 팔다리의 다른 메시와 마찬가지로 관절을 세분화하고, 같은 팔다리의 파츠와 용접하며(`GlueSkel__` Glue), 블렌드 셰이프 계획에 포함됩니다. 다만 부모를 바꾸지 않고 스키닝 키폼을 쓰지 않으며, 생성된 부모 아래에 남습니다. 원래 그것이 걸렸어야 할 본의 디포머는 평소처럼 유지됩니다(메시가 없다는 이유로 잘라내거나 접지 않음). 이 메시는 캔버스에서 본 체인 전체를 따라 움직이므로, 계획은 체인 위의 모든 본 파라미터를 서로 결합된 것으로 봅니다(블렌드 셰이프로 만들지 않음). 나머지 메시의 경로는 바뀌지 않습니다. 저널이 배치한 메시가 없는 프로젝트는 베이크와 내보내기가 바이트 단위로 바뀌지 않습니다(`ExportGoldenTool`).
- **스키닝**(생성 노드 `skeleton.skin`, 저널 뒤, 흔들림과 시뮬레이션 앞): 본의 작용은 캔버스 공간에서 정의됩니다. 어떤 자세에서 각 정점은 그 가중치(`SkeletonWeights` / `SkeletonManualWeights`)에 따라 본의 캔버스 변환(`SkeletonPoseSolver.frames`: 디포머가 있는 본은 디포머를 읽고, 나머지는 부모 본에 따라 회전)에 끌려가며, 이어서 베이크와 똑같이 관절 템플릿, ARAP, 표면 평활화로 보정합니다(`SkeletonRig.corrected`). 얻은 캔버스 위치는 메시의 최종 부모 체인을 같은 자세에서 역매핑해 부모 로컬 공간으로 옮기며, 정지 상태와의 차이를 메시의 본 파라미터에 대한 키폼으로 씁니다. 블렌드 셰이프 계열 파라미터(계획이 독립이라고 판정한 본, 뼈대 포즈)는 블렌드 셰이프로 씁니다. 축은 그 메시를 움직이는 팔다리 본, 그 위쪽 몸 절반, 뼈대 포즈 파라미터이며, 베이크와 같은 허용 오차로 가장 적은 키를 택합니다. 메시는 부모를 바꾸지 않으며, 그 위에 사용자 Warp가 몇 겹이 있든 저널의 배치는 그대로 유지됩니다.
- **기존 키폼**: 스키닝 키폼은 메시의 기존 키폼과 더해집니다(파라미터를 공유하면 양쪽의 키를 합침). 이 셀들에 대한 캔버스 편집은 `GeneratedOverrides.capture`가 `skeleton.skin`의 `generated_override`로 쓰며, 재생할 때 3방향 병합합니다. 저널이 이미 메시에 준 같은 파라미터의 블렌드 셰이프는 사용자 데이터로 보고 그대로 둡니다.
- **Glue**: 다른 스키닝 메시와 짝을 이루는 정점은 각 키에서 같은 캔버스 목표를 가집니다. 반대쪽이 베이크로 스키닝되었으면(본 아래에 걸림) 리그가 평가한 위치를 쓰고, 양쪽 모두 이 단계에서 스키닝되면 Glue 양쪽의 가중치로 만나는 점을 정하며, 둘이 공유 파라미터에서 같은 키를 쓰게 합니다. 이 정점들은 ARAP에서 고정점이 되어 메시가 이음매까지 매끄럽게 이어집니다.
- **토폴로지**: 관절 세분화는 저널 앞에서 일어나므로, 이후의 정점별 레코드는 세분화된 메시를 대상으로 합니다. 저널에서 그 메시를 대상으로 하는 정점별 레코드(`canvas_geometry`, `vertex_group_put`, 메시의 `generated_override`)의 정점 수가 세분화 전의 정점 수와 같으면(그 메시를 세분화하지 않는 버전에서 기록됨), 그 레코드들이 불일치하지 않도록 그 메시를 세분화하지 않습니다(`SkeletonCanvasSkin.lockedTopology`, 수동 토폴로지와 같음). 관절 본에 바인딩된 다른 메시도 이런 레코드가 모두 세분화 전의 정점 수로 기록되었다면(뼈대 이전에 쓴 정점 그룹 등) 마찬가지로 세분화하지 않으며, 세분화 후의 정점 수로 기록된 레코드가 있으면 평소처럼 세분화합니다.
- **비용과 캐시**: 팔다리의 루트 본과 위쪽 몸 절반은 팔다리 전체를 강체로 끌고 갈 뿐이므로, 풀이할 때는 이들을 먼저 빼고 풀고 나서 그 변환을 적용합니다. 필요한 풀이 수는 팔다리 내부 관절의 키에만 달려 있습니다. 출력은 `GeneratorReuse`가 읽은 내용 기준으로 재사용하며, 이런 메시가 있으면 뼈대 캐시 키가 그 집합을 포함합니다.


### 버전 2 레코드

버전 1은 원래 레이어를 분할하는 순간의 작성 상태를 통째로 파츠에 스냅샷했습니다. 기반 생성은 여전히 원래 레이어(승객)만 보고 파츠는 보지 못했으며, 생성기가 메시에 쓴 키폼(눈 여닫기, 뼈대 스키닝 등)도 레코드 안에 고정되어 이후의 얼굴 설정, 자세, 뼈대 변경이 파츠에 도달하지 못했습니다. 버전 2는 파츠를 기반 생성에 참여시킵니다. 생성된 원래 메시의 분할은 모두 버전 2를 쓰며, 스위치는 없습니다. 지금의 버전 2 레코드는 선언일 뿐입니다(`authored`는 비어 있고, 사용자 데이터는 그 뒤의 체크포인트에 있음, [분할은 곧 재생성](#분할-실체화-아트-프리미티브-레코드-art_primitive) 참고). 이전 버전이 쓴 버전 2 레코드는 `authored`에 작성자 데이터를 담고 있으며, 아래의 잔차, 두 번의 캡처, 승객 허용, 재생은 그런 레코드를 설명하는 것으로, [레거시 재생](#레거시-재생)에서만 쓰입니다.

**해석된 레이어 집합**(`core/PrimitiveResolution`): 생성 레이어에서 v2 레코드가 대체한 레이어를 빼고 v2 파츠 레이어를 더한 것입니다. 앵커, 얼굴 리그, 머리 공간, 프레임, 자세와 다리, 몸 프레임, 디포머(쌍 Warp, 팔 늘어뜨림 Warp 포함), 눈 흰자, 마스크 원천이 되는 메시, 입술의 얼굴 리그와 뼈대 바인딩은 모두 이 집합만 읽으며, 미리보기 분석도 이와 일치합니다. 파츠 픽셀은 현재 픽셀을 `source_bounds`에 따라 투명으로 채워 쓰고, 메시는 여전히 레코드 값을 씁니다. 분류는 `layerOverrides`(분할 시 상속)를 쓰고, 없으면 레코드의 `classification`을 씁니다. 분할 기준선(`splitBaselineLayerIds`)이 있는 컨텍스트도 마찬가지로 파츠를 포함하고 대체된 레이어를 제외하며, 디포머를 유지하는 빌드(`buildPreservingDeformers`, 페인트 커밋용)도 같습니다.

**승객**: 대체된 레이어는 여전히 원래 위치에서 생성되며(태그 개수로 정해지는 ID와 기본 그리기 순서는 그대로), 자신의 고정된 픽셀과 레이어별 키폼만 쓰고, 위의 집계 단계를 읽기는 하지만 거기에 되먹이지 않으며, 본에 바인딩되지 않습니다. 이는 레코드 이전의 저널 항목이 주소를 지정하기 위해서만 존재하며, 레코드를 재생할 때 삭제됩니다.

**주차**: 파츠는 기반 리그 안에서 레코드의 정지 캔버스 메시대로 생성되어(다시 메시화하지 않으며, 텍스처 좌표는 캔버스 단위) 생성 키폼, 채널, 마스크, 파츠 트리 위치, 뼈대 스키닝을 얻습니다. UV를 바인딩한 뒤 통째로 `BuiltRig.primitiveSkins`로 옮겨집니다(용접 Glue, 생성 경로, 파츠를 가리키는 생성 마스크, 파츠 슬롯, 소유 관계, 지연 부모, 중립 경계와 함께). 기반 리그에서 파츠를 가리키는 참조는 그 승객으로 다시 쓰므로, 레코드 이전에 보이는 것은 "분할 전"의 리그입니다. `BuiltRig.resolvedPuppet()`은 승객을 빼고 파츠를 넣으며, 생성 마이그레이션(`RigGenerationMigration.generatedRig`)의 previous / desired는 이것으로 비교하므로, 얼굴 설정, 분류 등의 변경도 파츠에 똑같이 도달합니다.

**레코드 필드**(`v: 2`, 나머지 최상위 필드는 버전 1과 같음): 각 파츠에는 `id`, `layer_id`, `source_id`, `source_bounds`, `neutral_bounds`, `name`, `classification`, `mesh{canvas_positions, triangles, canvas_uvs}`(정지 캔버스 메시: 파츠가 아직 원본의 생성 부모 아래에 있으면 기반 리그의 생성 디포머를 거쳐 환산하며, 저널의 부모 체인 편집은 재생할 때 한 번만 작용함. 저널이 부모를 바꿨다면 작성 부모를 거침)가 있습니다. `parent`, `part`가 비어 있으면 생성 결과를 쓴다는 뜻이며, 저널 편집이 원래 레이어를 바꿨을 때만 씁니다. 재질 필드는 생성 값과 다를 때만 씁니다. `masks`가 비어 있으면 생성 마스크를 씁니다. `parameters`는 사용자 축만 담습니다. `geometry_residual`, `channels_residual`. `blends`, `paths`, `vertex_groups`는 사용자 데이터만 담습니다(뼈대 포즈 블렌드 셰이프와 생성 경로 제외). `fixed_topology`(파츠에 정점별 사용자 데이터가 있으면 참이며, 뼈대가 관절 행을 삽입해서는 안 됨). `frozen_axes`. `glues`는 사용자 Glue만 담습니다(`GlueSkel__` 용접 제외).

**잔차**: 캡처할 때 A는 원래 레이어의 작성 상태, G는 기반 생성 출력(뼈대 포함)이며, 잔차 A − G는 분할의 정점 출처를 거쳐 파츠 정점으로 옮겨집니다. 키에 기본값이 아닌 생성기 축이 있는 셀은 레코드 바로 뒤의 `generated_override`로 쓰며(`base`는 후보 기반 파츠의 셀, `points`는 `base`에 잔차를 더한 것, `generator`는 그 축을 소유한 노드), 나머지는 `geometry_residual` / `channels_residual`에 씁니다. 재생할 때 파츠 메시 = 주차된 생성 메시 ⊕ 잔차이며, 재정의는 평소처럼 모든 생성기 뒤에 3방향 병합합니다. 기반이 키폼을 생성하지 않는 파츠(제로 메시: 입술 띠의 조각, 지연 부모의 파츠)는 되돌려 더할 생성 운동이 없으므로, 잔차로 작성 상태의 키폼 전부(A − 0)를 씁니다. 같은 레코드의 입 파츠는 각자의 경계가 아니라 모든 입 파츠를 합친 입구로 입 모양을 생성합니다. 그렇지 않으면 반쪽 입이 각자 입 전체인 것처럼 벌어져 절단면에서 찢어집니다.

**재생**: 승객을 삭제하고, 주차된 파츠를 배치하고(캔버스 텍스처 좌표는 현재 아틀라스를 거쳐 환산, 지연 부모는 그 부모 공간으로 옮김), 생성 마스크와 파츠 슬롯을 복원하고, 양 끝이 모두 있으면 용접을 추가하고, 생성 경로를 쓴 뒤, 잔차와 작성 계층을 더합니다. 주차된 토폴로지가 레코드와 다르면(뼈대가 관절 행을 추가, 이후의 메시 재빌드) 정점별 데이터를 캔버스 텍스처 좌표에 따라 새 메시로 마이그레이션합니다.

**두 번의 캡처와 가드**(이전 버전): 분할은 먼저 기본 필드를 쓰고, 이어서 후보 기반으로 파츠를 생성한 뒤 그것과 대조해 잔차와 재정의를 썼습니다. 후보 기반이 기존 저널이 참조하는 모든 객체를 여전히 생성하고 저널 전체를 그 위에서 재생할 수 있을 때만 버전 2를 썼으며, 그렇지 않으면 버전 1로 대체하고 `v2_fallback {reason, detail}`을 달았습니다. 지금의 분할은 병합으로 이를 대신하므로 대체가 없으며, 이전 레코드의 `v2_fallback`은 기록으로만 남습니다.

**승객 허용**: 레코드 이전의 항목이 참조하는 메시가 모두 이후 v2 레코드의 승객이라는 이유만으로 실패하면, 무작업으로 재생하고 설명 하나를 남깁니다(`SupersededEntryNote`: 저널 순번, `op`, 대상, 원인). 다른 실패는 평소처럼 오류를 냅니다. 설명은 재생 체크포인트와 함께 저장되어 체크포인트에서 이어서 재생해도 완전하며, `BuiltRig.supersededEntryNotes`를 거쳐 `workspace_inspect`의 `quality.overrides`에 들어갑니다(`SUPERSEDED_ENTRY_SKIPPED`, info, 차단하지 않음).

**재분할**: 파츠는 다시 분할할 수 있으며, 일반 레이어를 분할하는 것과 같습니다. G와 M의 파츠가 각각 잘린 뒤 병합됩니다. 더 이른 버전 1 레코드가 v2 파츠를 대체하면, 그 파츠는 투명 자리 표시자와 고정 메시로 해석된 집합에 남으며 기반 프레임은 바뀌지 않습니다.

**파츠 이후의 편집**: 페인트는 픽셀만 바꾸며 파츠 메시는 레코드 값을 유지합니다. `rebuild_mesh` 페인트나 레이어별 메시 설정 수정은 레코드 뒤에 `canvas_mesh_rebuild`를 추가하고 키폼과 바인딩을 마이그레이션합니다.

**소유 관계와 캐시**: `DocumentGenerators`의 문서 입력 `document:primitives`(v2 레코드의 고정 입력)는 풋프린트, 프레임, 메시, 뼈대가 읽습니다. 파츠의 `keyform:mesh:<파츠>@<파라미터>`는 주차 시의 소유 관계에 따라 `mesh:<레이어>` / `rig.meshes`(특징 축) 또는 `skeleton`(본 축)에 속하며, `GeneratedOverrides.capture`는 이에 따라 이후 이 셀들에 대한 편집을 재정의로 씁니다. 단계 캐시와 바인딩 캐시의 키는 v2 레코드의 고정 입력 다이제스트를 포함합니다.

**호환**: 이전 버전이 쓴 버전 1 레코드와 작성자 데이터가 있는 버전 2 레코드는 그 뒤에 체크포인트가 없으면 이전처럼 재생되며(뼈대 스키닝과 자체 디코딩 포함), 읽을 때 다시 쓰지 않고, 처음 편집할 때 체크포인트로 고정됩니다([레거시 재생](#레거시-재생) 참고). v2 레코드가 없는 문서는 원래 코드 경로를 탑니다(`ExportGoldenTool` 바이트 단위 일치). v1과 v2 레코드는 섞어 쓸 수 있으며, v2 레코드가 v1 파츠를 대체하면 그것을 삭제합니다. 선언형 레코드를 재생할 때는(예를 들어 체크포인트가 없는 빌드에서) 생성된 파츠대로 배치합니다. 이전 버전의 명시적 업그레이드 명령(`source_upgrade_split_records`)은 제거되었습니다.

**알려진 제한**:

- 분할된 입의 생성 입술은 여전히 파츠의 현재 픽셀을 합성한 것이 아니라 대체된 입(승객의 고정된 픽셀)에서 가져옵니다. 분할 시점에는 둘이 같지만, 이후 파츠에 페인트하면 입술 텍스처는 따라오지 않으며(일반 입의 입술 텍스처도 메시 입력에서 가져오므로 메시를 재빌드하기 전에는 따라오지 않음), 파츠 메시를 재빌드해도 입술을 다시 생성하지 않습니다.
- `frozen_axes`: 쓰는 쪽이 항상 비워서 쓰므로 현재는 나타나지 않습니다. 기반 생성이 비어 있지 않은 값을 읽으면, 생성 메시의 축에 고정된 축이 있을 경우 그 파츠의 생성 메시 전체를 0으로 만들고 작성자 데이터만 남깁니다. 레거시 재생은 비어 있지 않은 값을 만나면 바로 오류를 냅니다(지원하지 않음).
- 파츠 메시를 재빌드한 뒤, 그 생성 셀을 대상으로 하는 `generated_override`는 마이그레이션되지 않으며, 형태가 맞지 않으면 고아로 보고합니다.
- 입 모양 윤곽이 켜져 있으면, 입 파츠의 고정 메시는 원본의 윤곽 메시이며 풋프린트가 원본의 래스터 메시와 약간 다릅니다. 입이 프레임을 정하는 생성 입술의 정지 위치는 약 0.4 px 차이 나며, 파츠 자체의 입구 형태에는 윤곽의 기여(약 0.13 px)가 들어 있지 않습니다.
- v2 파츠는 프레임 생성에 참여합니다. 고정 메시의 캔버스 위치는 부모를 왕복하면서 부동소수점 반올림이 생기므로, 분할되지 않은 메시의 로컬 좌표와 프레임 제어점이 몇 ulp 차이 날 수 있습니다(월드 좌표 < 1e-4 px). 버전 1은 비트 단위로 바뀌지 않습니다.
- 원래 메시의 토폴로지를 손으로 고쳤다면, 파츠는 사용자 토폴로지대로 사용자 객체로 유지되며, 이후 생성기의 변경은 더 이상 이 파츠들의 기하에 도달하지 않습니다.

**테스트**: `PrimitiveResolutionTest`(손으로 쓴 v2 레코드의 기반 생성), `ArtPrimitiveRecordV2Test`(이전 버전 레코드의 인코딩, 잔차, 재생, 승객 허용, 체크포인트에서 이어서 재생할 때의 설명. 인코더는 테스트 안의 `LegacyArtPrimitiveV2`), `SplitPartsCheckpointTest`(분할의 체크포인트, 쌍 Warp, 뼈대 스키닝). tml에서의 분할 효과는 `ArtPrimitiveV2VisualTool`로 육안 검사합니다(분할하지 않은 것과 분할한 것의 각 자세별 차이, 이전의 버전 2 레코드와 같음).

## 레거시 재생

이전 버전은 일부 편집을 기반 리그 위에서 재생해야 하는 레코드로 썼습니다. 분할의 `art_primitive`(버전 1, 그리고 작성자 데이터가 있는 버전 2), 생성 마이그레이션(`rig_generation_transition`, `rig_generation_frames`, `rig_generation_scaffold`, `rig_mesh_activation`), 이전의 `canvas_source_partition` / `canvas_depth_split`, 그리고 저널 앞의 레거시 정적 필드입니다. 생성된 모델은 더 이상 이것들을 쓰지 않습니다. 가져온 CMO3 모델은 병합할 생성 결과가 없으므로 여전히 마이그레이션 레코드와 이전 분할을 쓰지만, 그것을 쓴 커밋이 곧바로 그 뒤에 가져온 모델의 체크포인트를 쓰므로(`WorkspacePreviewBuilder.importedRecordsCheckpointed`), 레코드는 이 빌드에서만 재생되고 이후의 빌드, 열기, 실행 취소는 모두 체크포인트에서 시작합니다. 따라서 `core.legacy`는 두 곳에서만 실행됩니다. 체크포인트로 고정된 적 없는 이전 저널이 처음 편집되기 전, 그리고 가져온 모델이 이런 레코드를 쓰는 그 한 번의 커밋입니다.

- **한 번만 고정**: 저널의 마지막 체크포인트 뒤에 여전히 이런 레코드가 있을 때(체크포인트가 없으면 레거시 정적 필드도 포함, `RigEditOverlay.replaysLegacy`), 그것을 이어 가는 첫 편집은 먼저 원래 저널 끝, 새 항목 앞에 현재 작성 리그의 체크포인트를 쓰며(`WorkspacePreviewBuilder`), 생성 스냅샷이 있으면 함께 저장합니다. 이 레코드들은 이로써 마지막으로 재생되고, 이후의 빌드는 모두 체크포인트에서 시작합니다. 열기, 히스토리 전환, 저장은 저널을 다시 쓰지 않으며, 이전 리비전은 이전처럼 레코드대로 빌드합니다.
- **코드**: 이 경로와 가져온 모델에서만 쓰이는 부분은 `core.legacy`에 있습니다. `ArtPrimitiveReplay`(버전 1과 작성자 데이터가 있는 버전 2 레코드의 재생, 뼈대 베이크 전 버전 1 파츠 디코딩, 재생성 병합 시 버전 1 파츠 배치), `StubTolerance`와 `SupersededEntryNote`(승객 허용), `VanishedParent`, 그리고 생성 마이그레이션의 쓰기와 재생(`RigGenerationMigration`, `RigGenerationJournal`, `RigGenerationFrames`, `RigGenerationScaffold`, `RigMeshActivation`, `RigGenerationResidual`, `RigGenerationTextures`)입니다. `ArtPrimitiveJournal`은 레코드 형식과 문서 조회(대체 관계, 소유한 레이어, 텍스처 커버리지)를 유지합니다. 편집이 생성 결과를 바꾸는지 판단하는 `RigGenerationChange`는 병합 경로의 트리거 조건이며 `core`에 있습니다. 병합(`RigRegenerationCheckpoint`)은 여전히 `core.legacy`에서 이전 마이그레이션 레코드가 디포머에 붙인 이름과 버전 1 파츠를 읽어, 이전 저널의 G와 G′가 같은 방식으로 배치되게 합니다. 이는 호환을 위한 읽기이며 새 기능과 함께 확장하지 않습니다(`LegacyReplayBoundaryTest`가 이를 참조할 수 있는 파일을 고정).
- **잠금**: `LegacySplitReplayTest`는 이전 버전이 저장한 프로젝트로 각 히스토리 노드를 레코드대로 빌드한 IR 해시를 대조합니다.

## 후속 작업

- 분류 수정의 남은 소요 시간은 분석에 있습니다. 생성된 모델은 병합으로 바뀐 뒤 더 이상 생성 마이그레이션을 거치지 않으며, 남은 것은 가져온 CMO3 모델의 마이그레이션과 분할 기준선이 새 래스터에 대해 `CharacterAnalyzer.analyze`(레이어별 분류 약 0.5 s/회)를 반복 실행하는 것입니다. 레이어 메타데이터와 래스터 다이제스트로 분류 결과를 캐시할 수 있습니다.
- 블렌드 셰이프로 반영하는 시뮬레이션 키폼의 재정의. 재정의 보고서가 통합 품질 검사 프레임워크에 합쳐진 뒤에는 그 규칙 레지스트리와 펜스를 사용.
- 채널 재정의의 알려진 제한(현재 저널 뒤에서 채널에 키를 넣는 생성기가 없으므로 이 경로는 일어나지 않음. 첫 번째 그런 생성기가 추가되기 전에 처리):
  - 키폼 `set`이 생성된 채널 트랙의 정지 격자점(키에서 생성기의 파라미터가 기본값)에 쓸 때, `journalOnly`는 기하 편집에 대해서만 기본값에 있는 생성기 축을 벗겨 내므로, 채널 편집의 키에는 여전히 이 축이 붙어 있어 저널 재생 시 사용자 자신의 트랙에 이 축이 만들어집니다.
  - 채널 재정의가 추가되기 전의 버전은 모든 재정의를 정점이나 제어점 좌표로 읽어 값의 개수가 짝수일 것을 요구하므로, 스칼라(1개)와 색(3개) 재정의는 모두 "Invalid override form"을 내며, 채널 재정의가 있는 프로젝트는 이전 버전에서 재생에 실패합니다.
- 프로젝트를 열 때 실체화된 결과를 바로 읽기: 작성 리그의 저장과 읽기, 체크포인트, 재생성 병합, 시험 실행은 모두 구현되었습니다([실체화된 리그 · 구현 진행 상황](MATERIALIZED_RIG.md#10-구현-진행-상황)). 가져온 CMO3 모델은 가져오기 기준선 위에서 체크포인트부터 재생하며, 작성 리그만으로 따로 빌드하지 않습니다.


## 내부 조형 생성기

선택적 `interiorEffect:<id>` 노드는 작성 저널 뒤, 생성 결과 재정의 앞에서 실행됩니다. `NativeInteriorEffect`는 `rigEdits.interiorEffects`에 레시피, 압축된 네이티브 blend 필드, 물리 그룹을 저장합니다. 기존 입력 파라미터는 읽기 전용이며, 생성 파라미터와 대상 Mesh 축은 소유자가 하나뿐입니다. 레시피 수정, 추가·삭제, 토글은 모두 무효화 전파에 참여합니다. 메시, 소재, 바인딩이 맞지 않으면 레시피는 유지하되 오래된 정점은 건너뜁니다. 네이티브 UI/MCP는 `interior_put`을 공유하며, 임시 시험 재생은 문서에 들어가지 않습니다. 비활성화되었거나 무효화된 효과의 쓰이지 않는 자체 파라미터는 내보내기 사본에서만 정리합니다. 발표되지 않은 밀집 실험은 호환성을 유지하지 않습니다. 삭제는 `interior_delete`를 통해 같은 재생 경로에 들어갑니다. [내부 조형](INTERIOR_SURFACE.md)을 참고하세요.
