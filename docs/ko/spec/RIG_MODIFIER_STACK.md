## 현재 구현 상태

이 문서는 리팩터링 중인 내부 인터페이스를 기록합니다. 순서 있는 평가 코어, 일부 알고리즘 어댑터, 프로젝트 리비전, 저장과 복원, 미리보기/내보내기, 원자적 작업 공간 명령, MCP 프로세스 작업이 구현되었습니다. 기본 바인딩에는 정지 구조, 여섯 가지 레거시 알고리즘, 눈/눈썹/입의 피팅 알고리즘, 머리카락 체인이 연결되었습니다. 추가 모듈에는 웃는 눈, 홍채 압축, 크게 뜨기, 눈꺼풀 선 페이드, 하이라이트 시차, 시선 눈꺼풀, 눈 감정, 눈썹 모양, 눈썹 스프링, 깜빡임 여진, 깜빡임 따라가기, 눈썹-눈 결합, 모음 입 모양, 입-눈 결합, 입 모양 캡처, 혀 내밀기, 턱 따라가기, 입 안 깊이, 입 스프링, 볼 홍조, 그늘, 피부 클리핑, 목 따라가기, 머리·얼굴 깊이 회전, 가슴 따라가기, 팔 지연, 치마, 리본과 장식, 동물 귀/꼬리/날개 체인, 눈과 눈썹의 앞머리 비침, 토글 연출, 입 윤곽선이 연결되었습니다. 레거시 프로젝트 변환은 전체 결과를 비교한 뒤 커밋하며, 차이가 있는 사례는 안전하게 거부합니다. 생성 키폼의 오브젝트 간 복사는 아직 제한됩니다. 새 UI와 이번 진입점은 아직 전체 검수가 필요하며, 이전 검수 범위를 이번에 완료된 것으로 간주할 수 없습니다. 명시적 모디파이어 스택이 없는 레거시 프로젝트는 여전히 원래 경로를 따릅니다.

`core/modifier`는 다음 기반을 제공합니다.

- `RigModifierStack`: 순서 있는 인스턴스, 버전, 고정 대상 참조, 프리셋 그룹 출처, 오버라이드, 적용된 기능, 퇴역 ID, 단조 증가 ID 할당기. 엄격한 JSON 인코딩/디코딩.
- `RigModifierRegistry`: 타입과 알고리즘 버전으로 정의를 찾고, 알 수 없는 의존성, 중복 버전, 의존성 순환을 검사합니다.
- `RigModifierEvaluator`: 중립 `RigIR` 위에서 차례로 평가하며 대상, 순서, 배타 알고리즘, 공유 파라미터 정의, 쓰기 충돌을 검사하고 실제 기여를 출력합니다.
- `RigModifierAlgorithms`: 기존 흔들림, 베이크된 시뮬레이션, 물리 그룹, 모션 클립을 어댑터로 감싸며, 이 알고리즘들의 움직임 설계는 바꾸지 않습니다.
- `RigSourceModifiers` / `RigLegacyBindings` / `RigSourceBinding`: `rig.scaffold`는 캡처한 소스 원화로부터 정지 바인딩 구조를 생성합니다. `body/legacy`, `face/legacy`, `eye/legacy`, `brow/legacy`, `mouth/legacy`, `hair/legacy`는 각자의 원래 알고리즘을 덧붙입니다. `eye/fitted`(버전 2), `brow/fitted`, `mouth/fitted`는 원래 피팅 알고리즘을, `hair/chains`는 원래 분절 체인을 사용합니다. 눈의 `eye.smile`, `eye.squash`, `eye.wide`, `eye.lid-fade`, `eye.highlight`, `eye.aftershock`, `eye.gaze-lid`, `eye.emotion`, 눈썹의 `brow.shape`, `brow.spring`, `brow.blink`, `brow.lid-coupling`, 그리고 입의 `mouth.vowel`, `mouth.cheek-lid`, `mouth.capture`, `mouth.tongue`, `mouth.jaw`, `mouth.interior-depth`, `mouth.spring`과 `expression.cheek`/`expression.gloom`, `face.skin-clip`/`face.neck`/`face.depth-turn`, `body.bust`/`body.arms`, `outfit.skirt`/`outfit.ribbons`/`outfit.creature`는 각자의 원래 모듈 바인딩을 덧붙입니다. 피팅과 모듈의 조정 가능한 값은 인스턴스의 `values`에 저장되며, 범위는 원래 카탈로그에서 옵니다. 몸과 머리·얼굴의 강도, 부위별 고급 값(`tuning`)은 인스턴스에 저장되며, 레거시 전역 바인딩 강도나 값을 읽지 않습니다. 대상 메시는 원래 토폴로지와 작성 편집을 유지하고, 상류 작성 디포머는 계속 적용됩니다. 구조 분기 ID는 구조 인스턴스와 고정 대상으로 결정되며, 현재 부모로 다시 묶지 않습니다. 새로 추가되는 파라미터 폴더도 인스턴스별로 ID를 할당하며, 호환되는 표준 파라미터와 파라미터 쌍은 재사용할 수 있습니다. 같은 소스 원화를 공유하는 작성 복사본도 각각 다른 인스턴스를 받을 수 있습니다.
- `RigModifierPipeline`: 일반 소재 메시와 작성 저널로 입력을 만들고, 인스턴스 순서대로 생성기를 실행합니다. 미리보기 모델과 내보내기 IR은 같은 평가 결과를 공유하며, 항목별 실제 기여 보고서가 함께 붙습니다. 빈 스택은 바인딩, 물리, 모션을 암묵적으로 생성하지 않으며, 기존 일반 파라미터의 이름 때문에 프리셋 물리가 다시 생성되지도 않습니다.
- `WorkspaceModifierEdits`: 단일 항목/그룹 추가, 업데이트, 켜기/끄기, 제거, 이동, 앞부분 적용이 순수 후보를 공유하며, `WorkspaceDocumentCommands`를 거쳐 격리된 재구성, CAS, 단일 히스토리 노드 커밋으로 들어갑니다. 명시적 인스턴스 ID는 같은 일괄 처리의 이후 구성원이 참조할 수 있습니다. 추가할 때 0부터 시작하는 `index`를 지정할 수 있으며, 생략하면 끝에 덧붙입니다. 이는 의존성이 빠진 소비자 앞에 제공자를 명시적으로 끼워 넣기 위한 것이며, 기존 항목은 자동으로 재정렬하지 않습니다.
- 추가 미리보기는 `workspace_preview_regeneration`의 읽기 전용 백그라운드 후보를 재사용합니다. `modifiers`는 후보 스택의 실제 기여, 의존성 상태, 오버라이드 충돌을 반환하며 문서, 히스토리, 모델을 게시하지 않습니다. 같은 입력 상태와 요청으로 커밋하면 인스턴스 할당과 후보 리비전이 그대로 유지됩니다.
- `modifier_catalog` / `modifier_stack`: 카탈로그와 캡처된 버전의 설정, 상태, 실제 기여. 시뮬레이션은 베이크 요약만 반환합니다. 모든 모디파이어 작업은 엄격한 결과 및 작업 스키마를 선언하며, CORE MCP의 `modifier` 계열, FULL 작업, `workspace_call` 모두에서 호출할 수 있습니다.

`ModelPresetsSection`은 명시적 스택 프로젝트에서 모디파이어 패널을 표시하고, 레거시 프로젝트는 원래 패널을 계속 표시합니다. 인스턴스 제목에는 부위와 알고리즘이 들어가며, 고정 대상과 활성, 비활성, 의존성 누락 상태를 표시합니다. 기여, 값, 고정 제공자를 펼쳐 볼 수 있으며, 켜기/끄기, 제거, 앞부분 적용, 드래그 정렬은 애플리케이션 계층 명령을 공유합니다. 연속적인 값 조작은 로컬 필드 초안을 유지하다가 제스처/필드가 끝날 때 한 번만 커밋하고, 캡처된 상태를 검증합니다. 실패하면 표시 값을 되돌립니다. 기여는 종류별로 접히며, 새로 추가된 오브젝트의 이름도 보고서에 들어갑니다. 추가하기 전에 인코딩된 내부 오브젝트 ID를 표시하지 않습니다.

소스 원화 바인딩 추가는 `modifier_plan`을 사용합니다. 대상을 고정하고, 필요한 제공자를 재귀적으로 나열하며, 현재 유효하거나 이미 실체화된 제공자를 재사용하고, 새 항목에 안정적인 정체성을 미리 할당합니다. 그룹 카탈로그는 레거시/새 알고리즘 × 최소/표준/풍부의 여섯 가지 조합을 제공하며, 소재 적합성에 따라 추가 항목을 거릅니다. `fitted`는 `modern-standard`의 별칭으로 남아 있습니다. `face/fitted`와 `face/legacy`는 같은 배타 계열을 공유하며, 전자는 호환되는 머리·얼굴 의존 기능을 제공합니다. 새 진입점은 더 이상 레거시 얼굴과 독립된 `face.depth-turn`을 조합하지 않습니다. 계획 자체는 문서를 커밋하지 않으며, 확인 전에는 기존 읽기 전용 후보로 평가해 실제 기여를 보여 주고, 확인한 뒤에는 그룹 작업 하나만 커밋합니다. 대화 상자에서 선택을 바꿔도 이미 캡처한 대상은 바뀌지 않으며, 커밋은 여전히 같은 상태 CAS의 제약을 받습니다. 이 추가 진입점은 등록된 소스 원화 바인딩과 네이티브 흔들림, 물리, 시뮬레이션, 모션의 생성과 값 편집을 지원합니다. 시뮬레이션에는 이름 있는 가중치 그룹, 충돌체, 블렌드 셰이프 출력 방식, 정적 입력 축 설정이 연결되었습니다. 학습 클립은 상류 모션을 참조하며, 없으면 평가를 일시 중지하고, 잘못된 순서는 거부됩니다.

인스턴스 상태는 `RigEditOverlay.modifierStack`에 저장되며, 기본값은 `null`로 명시적 빈 스택과 구별됩니다. 이 필드는 작업 공간 리비전 정체성에 참여합니다. 기본값은 레거시 문서의 리비전 텍스트에서 생략되므로 기존 리비전 ID가 유지됩니다. 작업 저장소와 아카이브는 완전한 인스턴스, 순서, 버전, 설정, 휴면 오버라이드, 퇴역 정체성을 저장합니다. 변환으로 캡처한 계층, 파라미터 폴더, 물리 그룹, 모션은 인스턴스의 outputAliases에 원래 출력 ID를 저장하며, 이후 업데이트로 다시 쓸 수 없습니다. 새 인스턴스는 자기 정체성을 사용하며 제거된 항목의 별칭을 물려받지 않습니다. 빈 별칭 필드는 레거시 인스턴스의 직렬화에 참여하지 않습니다. 이 필드를 포함한 v2 rig 노드는 스키마 6을 사용하며, 기존 필드는 원래 스키마를 계속 사용합니다.

현재 스택 프로젝트는 레거시의 생성 입력 병합과 작성 상태 캐시 지름길을 쓰지 않고, 권위 있는 소스 원화, 작성 저널, 완전한 스택으로 재구성합니다. 순서가 잘못 굳거나 캐시로 사라지는 것을 막기 위해서입니다. 이후의 성능 최적화도 같은 평가 결과를 유지해야 합니다. 아직 변환하지 않은 레거시 프로젝트는 원래 생성 흐름을 유지합니다. 스택 프로젝트에서 레거시 프리셋 설정을 쓰면 거부되며 모디파이어 작업으로 안내합니다.

소스 원화 어댑터는 고정 대상별로 그 항목 앞의 유효한 기본 알고리즘과 적용된 기능을 모으고, 추가 전후의 원래 알고리즘 차이를 계산한 뒤 실제 상류 기하, 채널, 관계에 병합합니다. 국소 메시 보정은 각자의 정지 조상 투영을 사용해 조상 움직임을 중복 계산하지 않습니다. 피팅이 중립 부모 좌표를 바꾸면, 먼저 일반 DCC 재바인딩 원시 연산으로 작성 기하를 이전해 캔버스 위치를 유지합니다. 소스 원화 템플릿은 의존성이 충족된 앞선 항목만 포함하며, 일시 중지된 모듈이 하류의 다른 부위에 의해 다시 켜지지 않습니다. 모듈을 켜도 추가하지 않은 인접 모듈은 켜지지 않습니다. 같은 격리 후보 안에서만 순수 소스 원화 템플릿과 파라미터 정의를 캐시하며, 최종 스택 결과는 캐시하지 않습니다. 작성 편집, 흔들림 등 템플릿이 아닌 내용은 여전히 실제 입력에서 옵니다. 적용된 기능은 이후 바인딩 평가에 필요한 소스 원화 알고리즘 버전, 정체성, 출력 별칭, 설정을 저장하며, 시뮬레이션 베이크처럼 그런 의존이 필요 없는 큰 데이터는 복사하지 않습니다.

메시와 Warp의 독립 블렌드 셰이프는 실제 기본 키폼을 기준으로 삼아, 작성 기여와 이 모듈 추가 전후의 네이티브 기여 차이를 병합합니다. 파라미터, 키, 기여가 0인 위치, 가중치 제한 곡선을 유지하며, 이를 모든 파라미터 조합의 키폼으로 펼치지 않습니다. 메시 토폴로지는 원래 소재 매핑으로 이전하며, 기본 기하와 채널이 바뀌면 블렌드 셰이프 기준값을 다시 표현합니다. 소스 원화 평가에서 운반 Warp가 새로 생기면, 그것을 처음 만든 영속 인스턴스가 출력 ID를 할당하며, 이후 업데이트나 앞선 항목의 실체화로 이름이 바뀌지 않습니다. 작성자가 메시와 원래 부모 사이에 추가한 Warp는 계속 유지됩니다. 좌표 변환은 공통 앵커 아래의 작성 경로만 역으로 풀어, 영역 밖의 피팅 조상 때문에 해가 여러 개 생기는 것을 피합니다. 현재 어댑터 범위는 원래 알고리즘이 원래 경로 아래에 덧붙이는 운반 구조이며, 원래 경로를 대체하거나 재배열하는 기본 알고리즘은 따로 어댑터가 필요합니다.

## 평가와 적용

평가 입력은 일반 작성 내용과 스택 스냅숏입니다. 어댑터는 앞 항목의 실제 결과를 받으며, 순수 함수여야 하고, 비용이 큰 작업에서는 전달받은 취소 검사를 호출해야 합니다. 평가기는 프로젝트를 저장하지 않고, 히스토리를 커밋하지 않으며, UI에 접근하지 않습니다. 호스트가 격리된 후보에서 호출한 뒤, 작업 공간 CAS를 거쳐 완전한 최종 상태를 한 번 커밋합니다.

비활성 항목은 평가하지 않습니다. 의존 기능은 모든 대상을 덮어야 하며, 빠졌으면 그 항목을 유지한 채 평가를 일시 중지하고, 그 하류도 함께 일시 중지됩니다. 활성화된 의존성이 소비자 뒤에만 있으면 그 순서를 거부하며 자동으로 정렬하지 않습니다. 기본 알고리즘은 같은 대상에서의 배타 계열을 선언할 수 있습니다. 의존성은 구체적인 제공자 정체성에 고정할 수도 있습니다. 바인딩 인스턴스의 `scaffold` 설정은 해당 구조 인스턴스를, 모듈의 `base` 설정은 소속 부위의 기본 인스턴스를 고정 참조하며, 눈썹-눈 결합과 입-눈 결합은 `dependencies`로 `eye/fitted` 인스턴스도 고정 참조합니다. 같은 타입의 구조나 기본 바인딩을 따로 만들어도 이들을 몰래 대신하지 않습니다. 앞부분을 적용한 뒤에도 적용된 기능이 그 정체성을 유지하므로, 하류는 실체화된 일반 오브젝트를 계속 찾을 수 있습니다.

스택 작성 상태는 독립된 일반 소재 진입점으로 구성되며, 작성 저널보다 먼저 레거시 생성기가 암묵적으로 함께 만들던 표준 파라미터, 의미 그룹, 키폼, 의미 마스크를 지웁니다. 소스 원화 폴더와 원래의 클리핑 관계는 유지하며, 그다음 작성 저널이나 실체화 지점이 명시적 작성 내용을 복원합니다. 가져온 CMO3 작성 내용은 이 정리를 거치지 않습니다.

파라미터의 범위, 기본값, 종류, 반복 속성, 키 정의가 호환되면 공유할 수 있습니다. 실제 기여는 추가, 수정, 제거, 재사용을 구분합니다. 같은 오브젝트에 대한 쓰기는 기본적으로 모디파이어 사이에서 겹칠 수 없으며, 양쪽 어댑터가 모두 그 종류의 내용을 조합할 수 있다고 명시했을 때만 허용됩니다.

오버라이드는 인스턴스에 속하며, 그 인스턴스가 생성된 뒤에 재생됩니다. 비활성화나 제거는 오버라이드를 버리지 않습니다. 제거된 인스턴스 ID는 영구히 퇴역하며, 새로 만든 인스턴스는 그 오버라이드를 물려받지 않습니다. 오버라이드 재생기가 없으면 비어 있지 않은 오버라이드는 명시적으로 실패하며 조용히 무시하지 않습니다.

생성 키폼 편집 캡처가 연결되었습니다. 평가 보고서는 실제로 추가된 메시/Warp 기하 축과 채널 축을 기록하고, `DocumentGenerators`는 캡처된 버전의 보고서로 소유 관계를 세우며, 기존 키폼과 캔버스 편집은 원래의 3방향 병합으로 인스턴스 오버라이드로 기록됩니다. 기본값 위치의 생성 키폼도 인스턴스에 속합니다. 여러 모디파이어를 조합한 키폼은 그 파라미터 축을 마지막으로 제공하는 항목 다음에 병합해, 모든 좌표 차원이 이미 존재하도록 합니다. 생성된 감싸기 Warp의 정지 키폼도 그 인스턴스에 속합니다. 오버라이드는 스택보다 먼저 재생되는 작성 저널에 섞이지 않습니다. 보고서의 `owned_keyforms`는 오브젝트, 파라미터, 선택 사항 `channel` 참조를 제공하고, `override_issues`는 병합 충돌과 매칭할 수 없는 오버라이드를 구분합니다. 매칭할 수 없는 기록은 계속 유지되며 앞부분 실체화를 막습니다. 생성 파라미터 정의, 오브젝트 구조, 회전 기하, 모든 블렌드 셰이프 편집은 아직 여기에 포함되지 않습니다.

"여기까지 적용"은 먼저 전체 스택을 평가하고, 다음으로 앞부분을 평가해, 앞부분의 유효한 내용과 오버라이드를 일반 작성 내용으로 바꿉니다. 앞부분의 비활성 항목은 함께 제거되지만 내용을 만들지 않으며, 적용되지 않은 그 오버라이드는 계속 휴면 상태로 저장됩니다. 의존성이 빠진 앞부분은 적용할 수 없습니다. 하류는 원래 인스턴스와 출력 ID를 유지하며, 적용된 기능으로 앞선 내용을 계속 식별합니다. 하류를 다시 평가한 결과가 원래 전체 결과와 완전히 같아야 하며, 그렇지 않으면 후보를 거부합니다.

작업 공간 적용 명령은 기하와 키폼을 표준 작성 상태 실체화 지점에 쓰고, 앞부분이 생성한 물리 그룹과 모션을 일반 문서 내용으로 덧붙인 뒤, 후보 문서에서 콜드 재구성을 해 완전한 IR을 비교하고, 그다음에야 작업 공간 커밋에 넘깁니다. 적용된 모션의 `MotionClip.fileStem`은 표시 이름과 독립적이며 `file`로 저장됩니다. 이 필드가 있는 clips 노드는 스키마 6을 사용합니다. 일반 교체 작업은 파일 이름을 유지하고, 새로 만든 복사본은 자기 파일 이름을 할당받으며, 필드가 없는 레거시 클립은 기존 리비전 정체성을 바꾸지 않습니다.

시뮬레이션 어댑터는 입력과 일치하는 유효한 베이크가 이미 있어야 하며, 다중 키 바인딩을 유지하고, 현재 미리보기 프레임을 실체화하지 않습니다. 물리 그룹과 모션은 `RigIR`의 일반 사이드카 내용으로 적용 결과에 들어가며, Puppet 변환을 거친 생성기도 이 사이드카를 유지합니다.

## 연결 전에 남은 작업

1. 기본 부위 바인딩, 추가 모듈, 모든 레거시 바로가기 프리셋을 상류 내용을 읽는 소스 원화 인식 어댑터로 나누고, 대상, 의존성, 조합 가능한 쓰기 선언을 채웁니다. 스택 순서를 무시하는 전역 레시피 투영으로 이를 대신할 수 없습니다.
2. 레거시 프로젝트의 명시적 변환을 완성하고, 변환 전후 결과가 같음을 검증합니다. 이미 구현된 독립 모디파이어 트랜잭션으로 레거시 프리셋 마이그레이션 전체를 대신할 수 없습니다.
3. 기존 키폼 오버라이드 캡처를 확장해 생성 파라미터 정의, 오브젝트 구조, 블렌드 셰이프 편집의 소유권을 채우고, 토폴로지 변경, 참조, 충돌 이전을 검증합니다.
4. 흔들림, 물리 그룹, 생성 모션의 추가 계획과 스택 안 값 컨트롤, 그리고 시뮬레이션 생성/백그라운드 베이크와 기본 재질/입력 컨트롤은 이미 있습니다. 모션 이벤트/곡선 핸들과 생성 내용의 모든 편집 진입점을 계속 채우고, 새 어댑터를 추가할 때 카탈로그, 추가 계획, 공개 설정 스키마도 함께 확장합니다.
5. 오브젝트 위치 찾기, 시작 페이지 추천 그룹, 모든 바로가기 조합과 튜토리얼을 채우고, 모든 언어, 테마, 배율, 동적 시각 검수를 계속 완료합니다. 현재 기본 스택 패널과 추가 흐름에는 이미 네 언어의 문구가 있습니다.

## 기존 테스트 범위

`RigModifierStackTest`는 순서에 민감한 조합, 독립 대상, 의존성 체인, 배타성, 쓰기 충돌, 안정적인 정체성, 휴면 오버라이드, 앞부분 적용, 직렬화, 취소를 검증합니다. `RigModifierAlgorithmsTest`는 실제 생성기 어댑터, 사이드카 유지, 물리 설정 내보내기 후 다시 읽기, 모션 이벤트, 그리고 시뮬레이션 베이크 유효성과 적용 후 바인딩 일치를 검증합니다.

`RigModifierPersistenceTest`는 작업 저장소와 `.psd2live` 아카이브의 저장 후 다시 열기, 히스토리 리비전 정체성, v2 노드 분할/재결합을 검증합니다. `RigModifierPipelineTest`는 빈 스택, 일반 파라미터가 암묵적 프리셋을 일으키지 않음, 작업 공간 미리보기, 콜드 재구성, 모델 재구성, 켜기/끄기 후 새로 고침, 런타임 물리와 모션 파일 다시 읽기를 검증합니다.

`WorkspaceModifierCommandsTest`는 실제 작업 공간 트랜잭션으로 그룹, 일괄 참조, 실행 취소/다시 실행, 상태 충돌, 취소, 앞부분 적용, 일반 내용의 이후 편집을 검증합니다. 생성 키폼 오버라이드의 휴면, 복원, 정체성 분리, 충돌 병합, 매칭할 수 없을 때의 유지와 실체화 거부, 생성된 감싸기 Warp의 정지 키폼도 검증합니다. 모디파이어 그룹의 추가 미리보기는 실제 기여와 커밋의 일치, 자동 인스턴스 정체성의 안정성, 후보 미게시, 오래된 상태 거부를 검증합니다. `WorkspaceModifierSchemasTest`는 각 네이티브 설정의 엄격한 스키마, 일괄 처리 구성원의 컨텍스트 필드 제거, CORE MCP 계열과 작업 계약을 검증합니다. `AppliedMotionFileTest`는 적용 후 모션의 파일 정체성, 저장 버전, 그리고 이름과 이벤트에 필드처럼 보이는 텍스트가 있을 때의 레거시 리비전 정체성 호환을 검증합니다.

소스 원화 어댑터의 작업 공간 회귀 테스트는 원래 몸 알고리즘의 단일 축 자세와 조합 자세를 비교하고, 다중 대상 인스턴스, 파라미터 재사용, 고정 의존 정체성, 잘못된 이동, 빠진 의존성 복구를 검사합니다. 정지 구조나 몸 항목을 실체화한 뒤에도 콜드 재구성이 가능해야 합니다. 몸 바인딩과 흔들림의 순서를 바꾸는 테스트는 CPU 평가 후 실제 기하를 비교해, 패널만 재정렬되는 일을 막습니다. 일반 소재 회귀 테스트는 빈 스택이 표준 파라미터와 의미 그룹을 가져오지 않고, 원래 폴더와 클리핑 관계가 유지되며, 의미 태그가 마스크를 암묵적으로 만들지 않는지 검사합니다.

`WorkspaceLegacyBindingTest`는 프로그램으로 그린 작은 소재로 여섯 가지 레거시 바인딩을 조합한 뒤의 실제 기하, 투명도, 그리기 순서, 마스크, 파라미터 쌍을 비교합니다. 서로 다른 순서의 앞부분 실체화와 콜드 재구성, 입 다문 기본 키폼과 기본 눈 뜸 투명도의 인스턴스 오버라이드, 소스 원화를 공유하는 두 오브젝트의 각각의 바인딩과 실체화를 다룹니다. 피팅 눈/눈썹/입과 이미 연결된 눈, 눈썹, 입 모듈 조합은 원래 알고리즘과 동적 자세를 항목별로 비교해, 버전 선택, 인스턴스 값, 같은 대상의 베이스 배타성, 의존성 일시 중지와 복원, 잘못된 정렬, 앞선 항목 실체화 후 계속 평가를 검증합니다. 앞선 항목 삽입은 실패 시 미게시, 기존 순서 유지, 콜드 재구성, 단일 단계 실행 취소도 따로 검증합니다.

조합 모듈 회귀 테스트는 실체화된 구조 아래에 일반 작성 Warp를 추가해, 실제로 새로 생긴 운반 Warp가 이를 유지하는지 확인합니다. 조합 자세, 앞부분 실체화, 콜드 재구성을 비교하고, CMO3 내보내기 후 다시 읽어 실제 기하와 투명도를 비교합니다.

관계 변경과 아무것도 바뀌지 않는 순수 소스 원화 전환은 실제 작성 기하, 채널, 디포머 원래 값을 유지하며, 기하 잔차로 이를 다시 쓰지 않습니다. 마스크 목록과 반전 플래그는 하나의 관계로 비교합니다. 조합할 수 없는 작성 마스크는 후보 전체를 막습니다. 공유 파라미터는 재사용만 할 때 기본으로 접히고, 추가/수정된 파라미터와 관계는 기본으로 펼쳐집니다.

피부/목 조합 회귀 테스트를 통과했습니다. 원래 알고리즘의 조합 자세, 마스크 소스, 의존성 비활성화, 잘못된 이동 거부, 작성 반전 충돌 시 부분 커밋 없음, 클리핑이 기하를 바꾸지 않음, 두 단계 실체화, 일반 마스크 편집과 실행 취소를 다룹니다. 단계 보고서는 뒤 항목이 마스크를 대체/제거해도 앞 항목이 자기 실제 소스와 반전 상태를 유지함을 검증합니다. 전체 `test`가 통과했으며, 이후 추가된 작성 반전 충돌 회귀 테스트와 모든 소스 원화 바인딩 회귀 테스트도 통과했습니다.

확장된 `ModifierMouthModulesTool`은 아홉 가지 자세, 스택과 실체화 히스토리 노드가 있는 프로젝트의 저장 후 다시 열기, CMO3 마스크/기하/색 다시 읽기, 48프레임 작업 공간 재생을 검사하며 모두 통과했습니다. 관계 기여 뷰는 모든 내장 테마, 네 언어, 1×/1.5× UI와 1.1× 글꼴 배율의 스크린숏을 생성했습니다. 이 검사는 현재 구현만 다루며, 남은 프리셋, 마이그레이션, 튜토리얼은 아직 완료해야 합니다.

머리카락 체인, 치마, 리본/장식, 동물 귀/꼬리/날개는 원래 `HairChain` 기하와 물리를 사용합니다. 원래 체인 번호는 알고리즘 수치 계산에 계속 참여합니다. 템플릿 비교와 영속 출력은 소스 원화 레이어 정체성, 체인 종류, 영역/세그먼트, 인스턴스 정체성을 사용하므로, 다른 모듈의 켜기/끄기나 이동으로 원래 번호가 다시 매겨져도 파라미터, 디포머, 물리 그룹 ID는 바뀌지 않습니다. 실제 대상 분기가 사용하는 체인 파라미터만 게시합니다. 같은 종류의 체인 인스턴스는 서로 다른 대상에 따로 작용할 수 있으며, 같은 대상에 겹치는 체인 쓰기는 거부됩니다.

새 운반 분기는 필요한 오브젝트 그룹을 덧붙일 수 있으며, 처음 만든 인스턴스와 고정 대상으로 ID를 할당합니다. 소스 원화 분기 교체는 작성 좌표계와 잔차를 유지합니다. 작성 편집을 운반할 필요가 없는 레거시 오브젝트는 평가 경로를 우회할 수 있지만 참조 정체성은 유지됩니다. 새 체인, 가슴 따라가기, 팔 지연은 움직임 입력을 얻기 위해 몸과 머리·얼굴 제공자를 고정합니다. 물리 패널은 단계 보고서의 `physics_slot`으로 실제 그룹을 찾고 인스턴스 안에 설정을 저장하며, 비활성이거나 빠진 그룹을 최종 파라미터에서 다시 추론하지 않습니다.

체인 회귀 테스트는 분리된 대상 인스턴스, 비활성/복원과 제거 후 새 인스턴스, 같은 대상 배타성, 물리 값 편집, 원래 알고리즘이 번호를 다시 매길 때의 정체성 안정성, 완전한 의존성 계획, 원래 물리 규칙과 연속 출력, 앞부분 실체화와 콜드 재구성을 다룹니다. `ModifierChainModulesTool`은 프로그램으로 생성한 머리카락, 의상, 동물 귀/꼬리/날개로 다섯 가지 조합 자세를 검사하고, 같은 토폴로지에서 원래 알고리즘과 스택 결과를 검증합니다. 스택과 실체화 히스토리가 있는 프로젝트의 다시 열기, CMO3 다시 읽기, 60프레임 실제 작업 공간 물리 시계도 검증합니다.

머리·얼굴 깊이 회전은 `face/legacy`에 고정 의존하며, 스타일 선택은 원래 패널 컨트롤을 재사용하고 그 항목의 다른 값을 기본값으로 돌립니다. 옆머리 레이어 순서의 각도 트랙은 고개 돌림 범위 전체를 덮으며, 레이어를 바꾸지 않는 쪽은 상수로 유지해 CMO3가 기하 트랙과 병합할 수 있게 합니다. 전용 회귀 테스트는 원래 알고리즘의 조합 자세, 옆머리 레이어 순서, 실체화 후 재구성을 비교하며, 체인 이미지 도구가 저장 후 다시 열기와 CMO3 다시 읽기를 검증했습니다.

레거시 앞머리/뒷머리 흔들림과 젤리 눈은 물리 추가 계획으로 일반 물리 모디파이어 설정으로 캡처할 수 있습니다. 계획은 필요한 파라미터와 출력 점유를 검사합니다. 자연스러운 대기, 깜빡임, 끄덕임, 고개 젓기, 말하기는 모션 모디파이어 설정으로 트랙을 캡처합니다. 생성 모션은 일반 클립의 파라미터 범위와 곡선 제어점 규칙을 그대로 따르므로, 실체화할 때 일관된 클립을 얻을 수 있습니다. 물리 프리셋은 필요한 파라미터가 없으면 기본 바인딩을 추가 계획에 넣습니다. 자연스러운 모션을 명시적으로 고를 때도 빠진 기본 바인딩을 추가 계획에 넣습니다. 추가 창에서 마지막 항목의 설정을 편집하면 계획과 그 선행 항목을 유지하고 미리보기를 다시 실행합니다. 레거시 프로젝트 변환은 완전한 IR 동등 비교를 커밋 조건으로 하며, 결과를 유지하지 못한 프로젝트는 원래 상태를 유지합니다.

물리와 모션 편집은 현재 평가된 기여에서 파라미터 제공자를 캡처할 수 있습니다. 같은 그룹에서 바인딩과 소비자를 함께 추가하면, 그룹 전체를 격리 평가한 뒤 실제 앞부분 기준으로 캡처합니다. 바인딩은 인스턴스의 `parameterProviders`에 저장되며, 조회와 추가 미리보기는 `parameter_providers`를 출력합니다. 제공자가 무효가 되면 소비자를 유지하되 일시 중지하고, 제공자를 복원하거나 실체화하면 평가를 이어 갑니다. 소비자를 활성화된 제공자 앞으로 옮기면 커밋을 거부합니다. 일반 작성 파라미터에는 인스턴스 의존성이 필요 없습니다.

변환 후보는 원래 계층의 공유 디포머를 재사용할 수 있으며, 같은 인스턴스는 공유 디포머마다 원래 알고리즘 차이를 한 번만 병합합니다. 공유 지지 구조는 원래 템플릿의 빈 파츠, 디포머 순서, 파츠 자식 순서를 유지합니다. 공유 지지 구조는 완전한 대상 범위가 필요하며, 일부 대상만으로 다른 메시의 공통 조상을 다시 쓸 수 없습니다. 입 기본 바인딩은 입 벌림 소재의 정지 자세를 명시적으로 제공하며, 적용 후에는 작성 체크포인트의 IR frame과 함께 저장되고, 콜드 재구성은 현재 파라미터 목록에 따라 복원합니다. 기본 레거시 바인딩 사례는 완전한 변환 결과 비교, 콜드 재생, 실행 취소/다시 실행, 스택 전체 적용을 통과했습니다. 다른 조합은 아직 검증이 필요하며, 최종 동등성 검사가 일치하지 않는 변환의 커밋을 계속 막습니다.

변환 인스턴스는 파라미터 트리와 파라미터 링크의 원래 템플릿 순서를 유지하며, 작성 항목의 위치는 바뀌지 않습니다. 바인딩 키폼은 축, 좌표, 형태 내용으로 동등성을 판단해, 참조는 다르지만 내용이 같은 메시가 차분 샘플링에 들어가는 것을 막습니다. 모션 설정은 런타임 파라미터 역할을 명시적으로 기여할 수 있으며, 역할은 기여 보고서와 적용 체크포인트에 들어갑니다. 표준 역할은 컴파일할 때 고정된 순서를 사용해, 앞부분 적용이 출력 순서를 바꾸지 않게 합니다.

구조 모디파이어는 메시가 원래 소재와 정확히 같을 때만 네이티브 국소 좌표를 재사용하며, 기하, UV, 토폴로지, 부모를 편집한 메시는 여전히 차분 이전을 거칩니다. 이후 바인딩은 인스턴스가 수정하기 전의 공유 부모 상태로 작성 차이가 있는지 판단하며, 편집하지 않은 네이티브 키폼의 데이터 표현을 유지합니다. 모션을 적용할 때 파라미터 범위를 기록하며, 일반 컴파일은 범위가 바뀌었을 때만 그 트랙을 정리합니다. 실체화된 파일 이름은 실제로 생성된 파일과 다른 일반 클립과의 충돌만 검사합니다.

모던 프리셋 변환은 체인 파라미터, 정규화된 체인 디포머, 모듈 물리 그룹의 원래 ID를 유지합니다. 공유 구조는 모든 대상에 정렬 인덱스를 세우며, 운반 노드를 교체할 때 내용이 바뀌지 않았고 자식 오브젝트 참조가 없는 기존 노드만 삭제합니다. 편집하지 않은 메시와 Warp 블렌드 셰이프는 네이티브 표현을 유지하며, 작성 차이가 있으면 계속 병합을 거칩니다. 이전된 디포머 목록은 현재 네이티브 템플릿 순서를 따르며, 물리 그룹 순서는 기존 `physicsOrder` 필드에 들어갑니다. 물리 기여자를 드래그하면 새 스택 순서에 따라 생성 그룹의 위치가 갱신되며, 일반 물리 그룹은 각자의 위치를 유지합니다. 변화가 없는 이동은 히스토리를 추가하지 않습니다. 모던 조합은 변환, 콜드 재생, 앞부분 및 스택 전체 실체화, 실행 취소 복원의 전용 회귀 테스트를 통과했습니다.

시작 페이지의 최소, 기본, 전체, 사용자 지정 조합은 중립 `WorkspaceInitialPreset`이 캡처하며, GUI와 MCP가 가져오기 후보를 공유합니다. 입력을 읽기 전에 상태를 캡처합니다. 레거시 알고리즘 생성, 시뮬레이션 베이크, 명시적 변환, 완전한 동등성 검증은 모두 설치 전에 끝나며, 초기 히스토리 노드 하나만 게시합니다. 앞머리/뒷머리의 네이티브 흔들림 제외 항목은 구조 인스턴스 설정에 들어가며, 이후 GUI 설정 쓰기에 의존하지 않습니다. 기존 0–4 강도 범위는 유지됩니다.

이전된 흔들림과 시뮬레이션의 출력 정체성은 인스턴스 별칭으로 유지되며, 파라미터와 물리 그룹을 포함합니다. 이전 템플릿은 빈 파라미터 폴더와 메시 자식이 없는 디포머를 유지합니다. 빈 디포머는 앞선 템플릿과 정확히 같을 때만 다음 템플릿으로 교체해, 작성 차이를 덮어쓰지 않습니다. 캡처한 모션 파라미터 범위는 정확한 곡선 스냅숏도 함께 식별하며, JSON 복원은 같은 시각의 연속 키포인트를 유지합니다. 일반적인 새 편집은 여전히 기존 키포인트 정규화 규칙을 따릅니다.

변환할 때 실제 파라미터 기여에 따라 물리, 모션, 시뮬레이션의 선행 인스턴스를 캡처합니다. 선행 항목이 비활성화되면 시뮬레이션은 유지되되 일시 중지되며, 빠진 입력으로 다시 베이크하려 하지 않습니다. 모듈의 물리 활성 상태는 인스턴스 `physicsEnabled` 설정에 저장됩니다. 머리카락 체인 알고리즘은 원래 알고리즘으로 돌아갈 때 존재하던 일반 머리카락 파라미터를 계속 유지합니다.

이번 회차의 관련 회귀 테스트와 전체 `test`가 통과했습니다. UI 이미지는 네 언어, 여덟 테마, 100%/150% 배율을 다룹니다. 개발 도구는 정렬 상호작용, 연속 값 편집, 추가 창의 격리 미리보기와 커밋도 함께 검증합니다. 체인 조합 도구는 원래 알고리즘 비교 자세, 적용 후 콜드 재구성, 저장 후 다시 열기, CMO3 내보내기 후 다시 읽기, 물리로 구동되는 동적 프레임을 검증하며, 산출물은 `build/tools/modifier-stack/`과 `build/tools/modifier-chain-modules/`에 있습니다.

## 이번 회차의 진입점과 UI 업데이트

프리셋은 간결한 목록과 아래쪽 인스펙터를 사용하며, 조정 항목을 바로 표시합니다. 드래그는 파라미터 목록 구현을 재사용합니다. Layout 생성과 매니페스트 가져오기는 빈 스택을, 소스 원화 데이터로 새로 만들 때는 추천 그룹을 씁니다. 명시적 스택의 `rig_generate`는 소재 메시를 유지하며, 아직 구조가 캡처하지 않은 대상에 지정한 그룹을 추가합니다. 기존 프로젝트를 읽을 때 자동으로 변환하지 않습니다. 이전 스크린숏과 전체 검증은 이번 회차의 UI 검수로 볼 수 없으며, 이번 회차에는 사용자 요청에 따라 테스트를 실행하지 않았습니다.
