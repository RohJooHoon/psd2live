# 컨텍스트 메뉴: 위치별 현황과 개선 제안

이 문서는 실제 UI 위치를 기준으로 어디를 오른쪽 클릭하는지, 지금 어떤 동작을 하는지, 무엇이 불편한지, 어떻게 바꾸면 좋을지 설명합니다. 기술 근거는 [소스 코드 현황](CONTEXT_MENU_AUDIT.md)을 참고하세요. 여기의 변경 사항은 모두 제안이며 아직 UI를 수정한 것은 아닙니다.

2026-10-20: 첫 부분 “우선 처리할 사항”의 삭제 범위, 다중 선택 범위, 소재의 여러 참조 위치 찾기와 파라미터 이름 컨텍스트 메뉴는 `context-menu-cleanup` 브랜치에 구현되었습니다. [구현 상태](CONTEXT_MENU_AUDIT.md#0-구현-상태2026-10-20)를 참고하세요. UI 동작은 실제 기기 검수가 필요합니다.

## 유지하기로 확인한 상호작용

파라미터 패널과 키포인트 편집 컨트롤은 각각 Cubism과 Photoshop의 상호작용 관례를 따릅니다. 컨트롤과 작업이 다르므로 오른쪽 클릭 동작이 다른 것은 합리적입니다. 스냅과 직접 삭제를 유지하며 충돌로 분류하지 않습니다.

도킹 탭 사이 빈 곳에서 “모두 닫기”를 제공하는 것도 합리적이므로 유지합니다. 텍스처 아틀라스는 보통 여섯 페이지 이하이므로 대상 페이지를 계속 펼쳐서 표시합니다. 메뉴가 가용 높이를 넘으면 스크롤바를 제공하고 하위 메뉴를 강제하지 않습니다.

일반 메시를 오른쪽 클릭할 때 현재 선택을 대상으로 하는 것도 합리적입니다. 마우스 위치로 오브젝트를 다시 선택하도록 바꾸지 않습니다. 상단 메뉴의 정보 구성과 작업 순서는 별도 개선 항목으로 계속 정리할 수 있습니다.

## 우선 처리할 사항

**계층 트리 메뉴가 수정 대상을 명확히 설명하지 않습니다.** 다중 선택 상태에서 한 행을 오른쪽 클릭하면 화면은 다중 선택을 유지하지만 메뉴 동작은 해당 행만 처리할 수 있습니다. 여러 디포머를 한 행으로 합쳐 표시하면 메뉴 제목은 한 디포머를 가리키지만 삭제에는 병합 체인 전체가 전달됩니다. 메뉴 이름, 선택 강조와 실제 적용 범위를 먼저 일치시켜야 합니다.

**긴 메뉴는 스크롤할 수 있어야 합니다.** 아틀라스 대상 페이지는 계속 직접 나열하되 작은 창이나 큰 UI 배율에서 스크롤바로 모든 내용에 접근할 수 있는지 중점적으로 확인합니다.

**같은 오브젝트의 트리 메뉴와 캔버스 메뉴가 충분히 일치하지 않습니다.** 예를 들어 앞뒤 레이어 분할은 트리에서 최초 설정으로 들어갈 수 있지만 캔버스에서는 주로 기존 분할의 빠른 작업을 제공합니다. 워프 디포머를 선택해도 트리의 생성 작업이 캔버스보다 더 완전합니다. 필요한 차이인지 항목별로 결정하고 나머지는 통일해야 합니다.

## 현재 컨텍스트 메뉴가 있는 위치

현재 **독립적인 컨텍스트 메뉴 구현 17곳**을 찾았습니다. 구현 하나가 여러 위치를 담당할 수 있습니다. 예를 들어 소재 라이브러리의 트리, 카드와 목록은 같은 메뉴를 쓰므로 UI 전체에서 오른쪽 클릭 가능한 위치가 17개뿐이라는 뜻은 아닙니다.

| 오른쪽 클릭 위치 | 현재 가능한 주요 작업 | 제안 |
|---|---|---|
| 주 편집 캔버스 | 현재 도구 조정, 현재 선택 작업. 참고 이미지 선택 시 해당 작업 표시 | 유지하되 대상과 개수 명시 |
| 소재 독립 편집 창의 캔버스 | 페인팅 도구 조정, 소재 페인팅 처리 | 유지하고 주 캔버스의 같은 도구와 통일 |
| 계층 트리의 디포머 행 | 부모·자식 디포머 생성, 흔들림, 가져오기, 펼치기·접기, 삭제 | 유지하되 하나를 삭제하는지 체인 전체인지 먼저 설명 |
| 계층 트리의 메시 오브젝트 행 | 참고 이미지 변환, 표시·숨김, 생성, 분할, 그리기 순서, 삭제 | 유지하고 그룹화해 최상위 메뉴 단축 |
| 계층 트리의 독립 전경·배경 참고 이미지 행 | 표시 위치, 표시·숨김, 불투명도, 잠금, 고정, 제거 | 유지하고 표시 위치는 단일 선택 하위 메뉴로 변경 |
| 소재 라이브러리의 폴더, 소재와 빈 영역 | 편집, 배치, 가져오기, 폴더 정리, 참고 이미지, 삭제 등 | 유지하고 소재·폴더·빈 영역 구분 |
| 시작 화면의 최근 파일 카드·목록 행 | 열기 또는 생성, 폴더 표시, 최근 기록 제거 | 유지. 현재 구조가 대체로 적합 |
| 파라미터 패널의 폴더 행 | 이름 변경, 하위 항목 생성, 태그 색, 폴더 삭제 | 유지하고 색은 하위 메뉴로 이동 |
| 파라미터 스냅샷 버튼 | 덮어쓰기, 이름 변경, 삭제 | 유지. 하위 메뉴 불필요 |
| 모션 목록 행 | 편집, 재생, 복사, 복원, 삭제. 사용자 모션은 이름 변경 가능 | 유지하고 복원·삭제 위치 정리 |
| 물리 그룹 목록 행 | 복사, 흔들림 편집 열기, 순서 조정, 복원 또는 삭제 | 유지하고 이름 변경 추가 |
| 시뮬레이션 바디 목록 행 | 베이크, 베이크 지우기, 삭제 | 유지. 짧은 현재 메뉴가 적합 |
| 텍스처 아틀라스의 타일 또는 빈 곳 | 밀도, 회전, 페이지 이동, 잠금, 배치, 저장, 보기 작업 | 유지. 대상 페이지를 펼쳐 표시하고 높이가 넘으면 스크롤바 추가 |
| 도킹 패널의 제목·탭 | 띄우기, 도킹으로 복귀, 현재 또는 같은 그룹 패널 닫기 | 유지하고 닫기 범위 명시 |
| 도킹 탭 사이 빈 곳과 그룹 드래그 핸들 | 모두 닫기만 제공 | 유지. 패널 그룹 작업 진입점 |
| 상단 작업 공간 탭 | 이름 변경, 복사, 현재·다른·오른쪽 작업 공간 닫기 | 유지하고 패널 닫기와 구분 |
| 로그 표 헤더 | 시간·출처·태그 표시 전환, 기본 열 배치 복원 | 유지하고 메뉴 스타일 통일 |

그 밖에 “메뉴 없이 오른쪽 클릭으로 바로 실행하는” 컨트롤 다섯 종류가 있습니다. 파라미터 이름의 속성 열기, 1차원 파라미터 트랙의 키값 스냅, 2차원 파라미터 패널의 교차점 스냅, 파라미터 키포인트 축의 직접 삭제, 그리기 순서 눈금자의 수치 창 열기 또는 드래그 이동입니다. 각각 판단해야 하며 모두 메뉴 누락으로 취급하면 안 됩니다.

## 편집 캔버스: 가까운 작업은 유지하고 메뉴 위치 안정화

### 현재 동작

캔버스 메뉴는 현재 모드와 도구에 따라 바뀝니다. 선택 도구에서는 오브젝트, 선택과 생성 작업을 제공하고 메시 편집에서는 분할·세분화·연결·병합 등이 있습니다. 브러시는 크기·강도·경도, 페인팅은 크기·불투명도·페인트 지우기를 제공하며 뼈대, 가중치와 글루 도구도 각각 내용이 있습니다.

주 캔버스와 소재 편집 창에서 같은 종류의 페인팅 도구가 메뉴를 공유하는 것은 합리적입니다. 툴바와 컨텍스트 메뉴 양쪽에서 브러시를 조정할 수 있는 것도 합리적입니다. 크기 하나를 바꾸려고 그리던 위치를 벗어날 필요가 없어야 합니다.

### 조정할 부분

- 일반 메시의 오른쪽 클릭은 계속 현재 선택을 대상으로 하며 선택 규칙을 바꾸지 않습니다. 메뉴 상단의 이름, 선택 개수와 자주 쓰는 항목 표시는 개선할 수 있지만 정보 구성 문제이지 상호작용 결함은 아닙니다.
- 빈 곳에서도 현재 도구나 현재 선택의 작업을 제공할 수 있습니다. 클릭 위치가 비었다는 이유만으로 다른 오브젝트 선택 규칙을 요구하지 않습니다.
- 일부 그룹은 메뉴가 길어지면 자동으로 하위 메뉴에 들어가고 내용이 조금 바뀌면 다시 펼쳐집니다. “생성”, “메시”, “소재”, “미러” 등의 위치와 계층을 고정할 것을 권장합니다.
- 메시 편집 메뉴의 “삭제”는 현재 “병합”과 “복사” 사이에 있습니다. 복사를 일반 편집 작업 근처로 옮기고 삭제는 구분선과 함께 그룹 끝에 배치해야 합니다.
- 사용자가 오른쪽 버튼에 다른 마우스 명령을 지정하면 주 캔버스와 아틀라스의 메뉴·마우스 명령 처리 순서가 다릅니다. 현재 제스처와 마우스 바인딩을 먼저 존중한 뒤 메뉴를 열지 결정하도록 통일해야 합니다.

### 권장 순서

위에서 아래로 현재 작업의 완료·한 단계 취소·취소, 도구 종류, 크기·강도 등 자주 쓰는 설정, 현재 오브젝트 작업, 생성·메시·미러 등의 하위 메뉴를 배치합니다.

삭제와 지우기는 관련 그룹 끝에 둡니다. 경로 생성 중의 “취소”는 여전히 “완료” 가까이에 있어야 하며 취소 동작이라는 이유로 오브젝트 삭제 영역에 옮길 필요가 없습니다.

### 상단 메뉴는 별도 개선

상단 메뉴의 기능 그룹, 자주 쓰는 작업의 순서, 툴바·컨텍스트 메뉴와의 대응 관계는 계속 정리할 수 있습니다. 구체적인 방안은 별도로 만들며 일반 메시의 오른쪽 클릭 동작 변경을 전제로 하지 않습니다. 진입점이 여러 곳에 남아 있다는 사실 자체를 문제로 삼지도 않습니다.

## 계층 트리: 오브젝트를 먼저 설명한 뒤 작업 구성

### 메시 오브젝트 행

현재 메뉴 하나에 참고 이미지 변환, 표시·숨김, 디포머 생성, 흔들림, 경로, 가져오기, 앞뒤 분할, 그리기 순서, 메시 분할과 삭제가 함께 있어 최상위가 깁니다.

권장 순서는 다음과 같습니다.

1. 오브젝트 이름, 참고 이미지로 변환
2. 표시·숨김, 단독 표시
3. “생성” 하위 메뉴: 부모 워프 디포머, 부모 회전 디포머, 경로, 흔들림 등 적용 가능한 동작
4. “메시” 하위 메뉴: 재구축, 독립 메시 분할, 앞뒤 분할 등 적용 가능한 동작
5. 그리기 순서, 여기에 가져오기
6. 구분선 뒤 레이어 삭제

다중 선택에서는 “오른쪽 클릭한 항목만”인지 “선택한 항목 전체”인지 명확해야 합니다. 다중 선택 강조를 유지하면서 범위 안내 없는 삭제가 하나만 지우게 해서는 안 됩니다. 어떤 오브젝트에 가능한 동작이 하나도 없으면 이름만 있는 메뉴를 띄우지 않아야 합니다.

### 디포머 행

부모·자식 디포머 생성은 “생성” 하위 메뉴로 묶고, 흔들림·가져오기·펼치기·접기는 별도 그룹, 삭제는 마지막에 둘 수 있습니다.

먼저 합쳐 표시하는 디포머 체인을 확인해야 합니다. 이름 하나를 오른쪽 클릭한 뒤 그 디포머를 삭제하는지 체인 전체를 삭제하는지 명확해야 합니다. 두 동작은 “현재 디포머 삭제”, “체인 전체 삭제”로 구분하고 선택 안내도 맞춰야 합니다. “디포머 삭제”라고만 쓰고 범위를 추측하게 해서는 안 됩니다.

병합 행의 각 이름 조각에서 오른쪽 클릭 위치도 확인해 메뉴가 행 왼쪽으로 치우치지 않고 실제 클릭한 곳에 나타나게 해야 합니다.

### 참고 이미지 행

트리와 캔버스 모두 같은 참고 이미지 오브젝트를 다루므로 양쪽 작업을 유지해야 합니다.

권장 순서는 이름·유형 변환, 표시·숨김·불투명도·잠금, 표시 위치·파라미터 고정, 마지막 제거입니다.

“배경, 레이어 내부, 전경”은 셋 중 하나이므로 “표시 위치: 현재값”으로 합치고 펼쳤을 때 단일 선택 표시를 쓰는 것이 적합합니다. 불투명도는 슬라이더를 유지하고 조정 중 메뉴를 열어 둡니다. “파라미터 고정”은 전용 트랙이나 2차원 패널을 유지하며 긴 파라미터 값 텍스트 목록으로 펼치면 안 됩니다.

### 계층 트리의 빈 곳

현재 컨테이너 메뉴가 없습니다. “루트에 레이어 가져오기”, “전체 선택”, “선택 해제”, “모두 펼치기”, “모두 접기”를 제안합니다. 구체적인 대상이 없으면 “현재 오브젝트에 부모 추가” 같은 동작은 제공하지 않습니다.

## 레이어 표: 컨텍스트 메뉴를 우선 추가할 곳

레이어 표에는 이미 선택, 표시·숨김, 앞뒤 이동, 참고 이미지 변환, 태그와 소재 연결이 있지만 이름 영역에 대응하는 컨텍스트 메뉴가 없어 많은 동작을 툴바에서 찾아야 합니다.

이름과 행 배경에 메뉴를 추가하는 것을 제안합니다. 레이어 이름이나 선택 개수를 먼저 표시한 뒤 유형 변환, 표시·숨김과 단독 표시, 정렬, 소재 작업, 태그, 마지막 삭제를 제공합니다. 정렬은 레이어 스택에서 이동 가능한 오브젝트에만 허용하며 생성 후 메시의 그리기 순서와 혼동하지 않습니다.

태그와 파라미터 이름 등 편집 가능한 셀은 여전히 자체 내용에 따라 오른쪽 클릭을 처리해야 하며, 텍스트 편집 중 갑자기 행 전체의 레이어 메뉴를 띄우면 안 됩니다.

## 파라미터 패널: 값 조정과 파라미터 관리 분리

### 파라미터 이름

현재 왼쪽과 오른쪽 클릭이 모두 속성 창만 열어 오른쪽 버튼이 추가로 제공하는 것이 없습니다. 명백히 중복된 진입점입니다.

왼쪽 클릭은 속성 열기를 유지하고, 오른쪽 클릭은 “속성”, “현재값 초기화”, “잠금 또는 잠금 해제”, “파라미터 복사”, “파라미터 ID 복사”, 마지막 “파라미터 삭제”를 표시하도록 제안합니다. 삭제는 기존 절차를 유지하고 오른쪽 클릭 즉시 삭제하지 않습니다.

### 파라미터 키값과 키포인트 편집

파라미터 패널의 1차원 트랙과 2차원 교차점 오른쪽 클릭은 키값으로 빠르게 이동하며, 키포인트 편집 창에서는 점을 직접 삭제합니다. 각각 Cubism과 Photoshop의 방식이며 컨트롤과 작업이 다르므로 하나의 키포인트 메뉴로 통일하지 않고 각 동작을 유지합니다. 기존 키보드 삭제도 유지합니다.

### 파라미터 폴더

먼저 “하위 파라미터 생성”, “하위 폴더 생성”, 이어 이름 변경과 태그 색, 마지막 폴더 삭제를 둡니다. 색은 하위 메뉴로 묶고 무색, 프리셋 색상과 사용자 색상을 유지합니다.

색상에는 이름이나 툴팁이 있어야 하며 색만 보고 추측하게 하면 안 됩니다. 폴더 삭제가 멤버에도 영향을 주는지 먼저 확인한 뒤 문구와 위험 안내를 결정해야 합니다.

### 파라미터 스냅샷

현재 “덮어쓰기, 이름 변경, 삭제”는 이미 짧아 하위 메뉴가 필요 없습니다. 첫 항목에 “스냅샷 적용”을 추가하고 “현재값으로 덮어쓰기”, “이름 변경”, 구분선 뒤 삭제를 둘 수 있습니다.

왼쪽 클릭은 적용, 오른쪽 클릭은 관리라는 역할 분담은 합리적이며 제거할 중복이 아닙니다.

## 애니메이션: 모션 메뉴는 있지만 트랙·키프레임 메뉴는 없음

### 모션 목록

기존 메뉴는 대체로 완전합니다. 행의 편집·재생 버튼과 컨텍스트 메뉴의 같은 작업은 함께 유지할 수 있습니다. 버튼은 고빈도 작업에, 메뉴는 식별과 찾기에 편리합니다.

권장 순서는 편집·재생 또는 일시 정지, 이름 변경·복사, 기본값 복원, 삭제입니다. 내장 모션과 사용자 모션의 내용은 구분해야 합니다. 내장 모션은 사용자 모션으로 복사하고 기본값으로 복원할 수 있으며 사용자 모션은 이름 변경과 복사가 가능합니다. 복원과 삭제를 뜻이 모호한 한 그룹으로 붙이지 않습니다.

### 트랙 행

현재 키프레임 추가와 트랙 제거는 주로 행 내부 버튼에 의존하고 오른쪽 클릭 진입점이 없습니다. “트랙에 초점 맞추기”, “재생 헤드 위치에 키프레임 추가”, 구분선 뒤 “트랙 제거”를 제안합니다. 여기에 “모션 전체 삭제”를 넣으면 안 됩니다.

### 타임라인과 곡선 키프레임

복사·붙여넣기·삭제·전체 선택 기능은 있지만 메뉴가 없으므로 우선 추가할 곳입니다.

키프레임을 오른쪽 클릭하면 복사, 붙여넣기, 보간 방식, 베지어 핸들 초기화, 마지막 선택 프레임 삭제를 제공할 것을 제안합니다. 보간 방식은 하위 메뉴에 적합합니다. 빈 곳에서는 붙여넣기, 현재 포즈에 키프레임 넣기, 전체 선택과 화면 맞추기를 제공합니다.

여러 키프레임을 선택한 뒤 그중 하나를 오른쪽 클릭하면 선택을 유지하고 메뉴가 전체를 처리해야 합니다. 선택하지 않은 키프레임을 오른쪽 클릭할 때는 선택을 바꿀지 명확히 해야 합니다.

## 물리와 시뮬레이션: 짧은 메뉴 유지, 관리 작업 보완

### 물리 그룹

물리 그룹 목록의 오른쪽 클릭에는 복사·정렬·복원·삭제가 있고 편집기 제목의 “더 보기”에는 이름 변경도 있습니다. 목록 메뉴에도 이름 변경을 넣어 편집기에 들어가지 않고 바꿀 수 있게 하는 것을 제안합니다.

권장 순서는 이름 변경·복사·흔들림 편집, 위로·아래로 이동, 생성값 복원 또는 사용자 그룹 삭제입니다. 짧으므로 하위 메뉴를 추가할 필요가 없습니다.

“기본값 복원”과 “삭제”를 합치면 안 됩니다. 전자는 수정한 자동 생성 그룹을 되돌리고 후자는 사용자가 만든 그룹을 제거합니다. 출처가 다르므로 출처에 따라 표시하거나 비활성화하고 의미를 명확히 써야 합니다.

### 시뮬레이션 바디

기존 “베이크 또는 다시 베이크, 베이크 지우기, 삭제” 구조가 적합하므로 유지합니다. 결과 지우기와 바디 삭제 사이에 구분선을 두고 작업 중에는 실행할 수 없는 이유를 설명합니다. 모션 목록과 대칭을 맞추려고 실제 필요 없는 하위 메뉴를 강제로 추가하지 않습니다.

## 뼈대 트리와 히스토리 트리: 선택은 가능하지만 제자리 관리 진입점 부족

뼈대 트리의 본 행은 주로 선택과 펼치기만 지원하고 추가·삭제는 툴바에서 합니다. 바인딩 메시의 해제는 행 내부 버튼에 의존합니다. 본 행에 “본 추가”, “펼치기 또는 접기”, “본 삭제”, 바인딩 메시 행에 “레이어 선택”, “바인딩 해제”를 제안합니다. 읽기 전용이나 포즈 모드에서는 구조 편집을 열어 두면 안 됩니다.

히스토리 트리는 클릭으로 살펴보고 더블 클릭으로 버전을 전환하지만 제목·메모·숨김 등은 상세 화면에서 처리합니다. “상세 보기”, “이 버전으로 전환”, “제목과 메모 편집”, “숨김 또는 표시”, “노드 ID 복사”를 추가할 수 있습니다. 이번 정리를 계기로 히스토리 분기 삭제 등 새 기능을 추가하지는 않습니다.

두 곳 모두 오브젝트 이름과 행 배경의 오른쪽 클릭에 적합하며 펼치기 화살표나 입력란 등 하위 컨트롤의 동작을 가로채면 안 됩니다.

## 소재 라이브러리: 진입점은 충분하며 내용과 범위 정리가 핵심

### 소재 항목

트리·카드·목록이 같은 소재 메뉴를 쓰는 것은 합리적이므로 유지합니다. 자주 쓰는 편집·배치·선택 레이어 교체·참고 이미지 추가를 앞에, 참조 위치 찾기를 그다음에 둡니다. 이어 이름 변경·태그·기본 참고 상태·벡터 해상도, 뒤쪽에는 이동·삭제를 놓는 것을 제안합니다.

“참고 이미지 추가”는 배경·레이어 내부·전경의 세 대상이 있어 하위 메뉴가 합리적입니다. 모델에 들어가는지도 계속 명확히 설명해야 합니다.

**“참조 레이어 위치 찾기”는 문구와 동작을 바로잡아야 합니다.** 메뉴는 여러 참조가 있다고 표시할 수 있지만 현재 동작은 첫 번째만 찾습니다. 참조가 하나면 직접 이동하고 여러 개면 고르게 하는 것을 제안합니다. 선택기를 당장 만들지 않으면 “첫 번째 참조 위치 찾기”라고 명시합니다.

### 폴더

권장 순서는 열기·내부 소재 배치, 하위 폴더 생성·파일 가져오기·폴더 가져오기, 이름 변경·태그 등 정리 작업, 내보내기·이동, 마지막 삭제입니다.

폴더의 “참고 이미지 추가”는 현재 레이어 내부만 유효하므로 한 단계 더 펼치게 할 필요가 없습니다. “레이어 내부 참고 이미지로 배치”라고 바로 쓸 수 있습니다. 폴더의 모든 소재를 다루는 작업은 어떤 내용을 포함하는지 설명해야 합니다.

### 빈 영역

빈 곳의 “새 폴더, 파일 가져오기, 폴더 가져오기”는 유용하므로 유지합니다. 보기 설정은 뒤에 둡니다. 격자와 목록은 둘 중 하나이므로 단일 선택, 폴더 트리 표시는 독립 스위치이므로 체크 표시를 씁니다.

탐색 경로에는 현재 컨텍스트 메뉴가 없습니다. 트리와 빈 영역 진입점이 충분하므로 급히 추가할 필요는 없습니다. 나중에 추가한다면 현재 열린 폴더가 아니라 실제 오른쪽 클릭한 단계의 폴더를 대상으로 해야 합니다.

## 텍스처 아틀라스: 타일과 페이지를 구분해 정리

### 타일 오른쪽 클릭

선택 타일 이름이나 개수를 먼저 표시하고 “선택에 초점 맞추기”를 앞에 둡니다. 이어 밀도, 회전, 페이지 이동, 잠금, 뒤에 선택 타일 배치와 단일 타일 이미지 교체를 제안합니다.

“밀도”를 그룹으로 묶을지는 전체 길이로 판단할 수 있습니다. “어느 페이지로 이동”은 보통 여섯 페이지 이하라는 사용 규모에 맞춰 계속 펼쳐 두고 한 번 더 클릭하게 하지 않습니다. 메뉴가 창의 가용 높이를 넘으면 스크롤바를 제공해 대상 페이지와 모든 작업에 접근할 수 있게 합니다.

다중 선택의 잠금 상태가 다를 때는 “일부 잠김”을 볼 수 있어야 하며 모두 잠김 또는 모두 잠금 해제처럼 표시하면 안 됩니다.

### 빈 곳 오른쪽 클릭

페이지 메뉴는 현재 페이지 이름, 이 페이지 전체 선택·페이지에 맞추기, 모두 배치, 현재 페이지 저장 순서를 제안합니다.

타일 메뉴는 선택한 타일, 빈 곳 메뉴는 페이지를 담당합니다. 이전에 다른 타일을 선택했더라도 현재 메뉴의 범위를 한눈에 알아볼 수 있어야 합니다.

## 패널, 작업 공간, 로그와 최근 파일

### 패널 제목과 작업 공간 탭

둘 다 “닫기”가 있어도 닫는 대상이 다르므로 중복이 아닙니다. 패널 메뉴는 “현재 패널 닫기”, “같은 그룹의 다른 패널 닫기”, “그룹의 모든 패널 닫기”로, 상단 탭은 “작업 공간 닫기”, “다른 작업 공간 닫기”, “오른쪽 작업 공간 닫기”로 씁니다.

패널 띄우기나 도킹 복귀는 닫기 앞에 둡니다. 메뉴는 클릭 지점 근처에 나타나고 외형을 통일해야 합니다. 제목 내부의 보기 옵션·배경 등 버튼은 자체 역할을 유지하며 패널 메뉴까지 함께 열지 않아야 합니다.

탭 사이 빈 곳과 그룹 드래그 핸들의 “모두 닫기”는 유지합니다. 패널 그룹 전체를 다루는 진입점이며 개별 탭 메뉴의 같은 작업과 공존하는 것이 합리적이므로 불필요한 트리거로 분류하지 않습니다.

### 로그

표 헤더의 오른쪽 클릭은 유용하므로 유지합니다. 시간·출처·태그는 독립 스위치 세 개로 연속 체크할 수 있어야 하며 “기본 열 배치 복원”은 구분선 뒤에 따로 둡니다. 외형은 다른 메뉴와 통일합니다.

로그 본문은 이미 텍스트 선택과 복사 진입점이 있으므로 복사가 전혀 없다고 할 수 없습니다. 향후 “기록 전체 복사”나 “이 출처로 필터”가 필요할 때 행 메뉴를 추가하되, 선택한 텍스트의 정상 복사를 덮어쓰지 않도록 합니다.

### 최근 파일

“열기 또는 생성”, “폴더 표시”, 구분선 뒤 “최근 기록에서 제거”를 유지하며 하위 메뉴는 필요 없습니다. 카드와 목록이 같은 작업을 지원하는 것도 합리적입니다.

최근 기록 제거는 디스크 파일 삭제가 아니므로 문구를 혼동하지 않습니다.

## 컨텍스트 메뉴를 추가하지 않아도 되는 곳

인스펙터 수치, 메시 설정, 도구 상세, 물리 파라미터와 내부 효과 폼은 직접 편집과 기존 초기화 버튼을 계속 사용하면 됩니다. 모든 필드의 오른쪽 클릭에 오브젝트 메뉴를 붙일 필요는 없습니다. 입력란의 기존 복사·붙여넣기도 유지해야 합니다.

설정 탐색, 도움말 본문, 시작 화면 빈 곳과 생성·내보내기 설정에 모델링 명령을 복제할 필요는 없습니다. 도구 모음, 보기 스위치, 드래그 핸들과 분할선은 자기 클릭·드래그를 처리하며 오른쪽 클릭을 아래 캔버스로 전달하면 안 됩니다.

미리보기 캔버스에는 화면 맞추기·보기 초기화·재생 일시 정지를 고려할 수 있지만 우선순위가 낮습니다. 이미 직접 진입점이 있으며 편집 캔버스의 모델링 메뉴도 필요하지 않습니다.

## 메뉴 내부의 통일 방식

**순서는 사용, 관리, 마지막 삭제입니다.** 오브젝트 메뉴는 열기·편집·재생 등 주요 작업, 이름 변경·복사·정리, 마지막 삭제를 둡니다. 생성 중 완료와 취소는 작업에 따라 함께 놓고 오브젝트 관리 순서를 그대로 적용하지 않습니다.

**하위 메뉴는 작업별로 묶고 위치를 고정합니다.** 생성·메시 처리·미러 등을 작업별로 묶되 유효한 선택지가 하나뿐이면 최상위에 둡니다. 동작 서너 개의 짧은 메뉴는 다시 중첩하지 않습니다. 아틀라스 대상 페이지는 펼쳐 두고 긴 메뉴에는 스크롤바를 제공합니다. 하위 메뉴의 방향은 창 공간에 따라 바뀌어도 최상위 메뉴를 밀어내면 안 됩니다.

**컨트롤은 실제 관계를 표현해야 합니다.** 셋 중 하나는 단일 선택, 독립 스위치는 체크, 크기·강도·불투명도는 값이 표시되는 슬라이더를 쓰고 정밀값 입력도 허용합니다. 색상에는 이름을 붙이고 다중 선택의 서로 다른 상태는 “일부”로 표시할 수 있어야 합니다. 메뉴는 완전한 인스펙터가 아니므로 전체 폼 페이지를 넣지 않습니다.

**작업 후 포커스는 알맞은 곳으로 돌아갑니다.** 일반 동작 후에는 메뉴를 닫고, 불투명도 조정이나 연속 체크 중에는 유지합니다. 이름 변경 상자나 새 창을 열면 입력 포커스를 보존합니다. 애니메이션 작업 후에는 타임라인으로 돌아가야 하며 모든 동작이 주 캔버스로 포커스를 빼앗아서는 안 됩니다.

**비활성 이유를 설명하고 빈 메뉴는 띄우지 않습니다.** 작업 중, 대상 없음, 미지원 오브젝트, 참조 중인 소재 등은 이해할 수 있게 안내해야 합니다. 하위 메뉴 전체를 사용할 수 없으면 정상 사용 가능한 것처럼 보이면 안 됩니다.

## 권장하는 세 단계

첫 단계는 적용 범위 확인입니다. 디포머 체인 삭제 범위, 다중 선택 메뉴의 실제 범위, 여러 참조 중 첫 번째만 찾는 동작, 메뉴가 오른쪽 버튼 명령을 가로채는 문제를 확인합니다. 파라미터 컨트롤별 다른 오른쪽 클릭 동작과 일반 메시의 현재 선택 작업은 기존 방식대로 유지합니다.

둘째는 기존 메뉴 정리입니다. 상단 메뉴의 정보 구성과 순서를 개선하고 동종 메뉴의 스타일·위치를 통일하며 필요한 그룹을 정리합니다. 아틀라스 대상 페이지는 펼쳐 두고 스크롤바를 개선하며 도킹 빈 곳의 “모두 닫기”를 유지합니다. 참고 이미지 위치를 단일 선택 하위 메뉴로 묶을지는 실제 사용 후 재평가합니다.

셋째는 빠진 진입점 추가입니다. 레이어 표, 파라미터 이름, 애니메이션 키프레임·트랙, 뼈대 트리를 우선하고 그다음 히스토리 노드와 계층 트리 빈 곳을 다룹니다. 미리보기 캔버스, 소재 경로와 로그 본문은 실제 필요에 따라 추가합니다.

이 문서는 소스 코드를 읽고 작성했습니다. 작은 창, 다른 언어와 배율, 마우스·키보드에서의 실제 메뉴 동작은 후속 UI 검수가 필요합니다. 제안을 이미 완료된 것으로 표시하지 않습니다.
