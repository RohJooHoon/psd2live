# 알고리즘 템플릿 목록: 얼굴

> 이 목록은 부위·모듈 아키텍처보다 먼저 작성되어 “슬롯 / 템플릿”이라는 표현을 유지합니다. 같은 슬롯에서 서로 배타적인 방법은 해당 부위의 **기본 알고리즘**으로, 함께 적용할 수 있는 기능은 **모듈**로 등록됩니다. `*/current`는 각 부위의 `legacy` 기본 알고리즘에 해당합니다. 구현 상태는 등록표(MCP `module_catalog`)를 기준으로 합니다. 이 페이지의 P0/P1/P2는 계획 우선순위일 뿐이며, “구현됨”은 등록표를 도입하기 전에 이미 존재했던 알고리즘을 뜻합니다. [리그 프리셋 아키텍처](RIG_PRESETS.md)를 참고하세요.

[문서 목록](../../README.md) · [프리셋 아키텍처](RIG_PRESETS.md) · 템플릿 목록: [얼굴](RIG_TEMPLATES_FACE.md) · [머리카락과 몸](RIG_TEMPLATES_HAIR_BODY.md) · [물리와 모션](RIG_TEMPLATES_PHYSICS_MOTION.md) · [구조와 표현](RIG_TEMPLATES_STRUCTURE.md)

이 페이지는 [리그 프리셋 아키텍처](RIG_PRESETS.md)의 템플릿 목록 중 하나입니다. 각 영역 슬롯에는 여러 알고리즘 템플릿을 등록할 수 있으며, 모델 프리셋은 슬롯별 템플릿 하나와 파라미터 값을 선택합니다. 같은 문제를 해결하는 서로 다른 방법은 같은 슬롯의 별도 템플릿으로 공존합니다. 일반적인 Live2D 제작 관행을 바탕으로 설계했으며, 수치는 모두 권장 기본값과 조절 범위입니다. 구현 후 출력 결과에 맞춰 조정합니다. 각 슬롯의 `*/current`는 기존 알고리즘이며 기본 템플릿으로 등록됩니다. 이를 선택하면 출력은 바뀌지 않습니다.

관련 문서: 기존 디포머와 파라미터는 [DEFORMER_AND_PARAMETER_SPEC.md](DEFORMER_AND_PARAMETER_SPEC.md), 내보내기 대상과 손실 보고서는 [EXPORT_TARGETS.md](EXPORT_TARGETS.md)를 참고하세요. 이 문서의 상태는 “설계 중”이며, 미구현 템플릿은 현재 제공되는 기능을 뜻하지 않습니다.

## 0. 규약

### 0.1 기호(모두 상대량 사용)
- H_e: 눈 높이(위 눈꺼풀의 닫힘 이동 거리), W_e: 눈 너비, R_i: 홍채 반지름, G_x / G_y: 홍채의 시선 이동 거리.
- W_f / H_f: 얼굴 너비 / 높이, W_m: 입 너비, H_m: 완전히 벌린 입의 높이, E: 동물 귀 길이(귀뿌리 → 귀끝).
- 파라미터 최대값은 ±1(또는 0..1)의 끝점을 뜻합니다. “실제 물리 출력”은 보통 최대값의 20–40%까지만 도달합니다.
- 물리 진자 체인은 Cubism 물리를 따릅니다. 질점 길이 r, 이동성 m(mobility), 지연 d(delay), 가속도 a(acceleration)를 사용합니다. 입력 유형은 X(변위, 변화에만 반응하고 정지하면 중앙으로 복귀) 또는 Angle(각도, 지속적으로 매핑)입니다. 출력은 k번째 질점 v_k에서 얻으며 reflect(반전)와 scale 배율을 적용할 수 있습니다.
- 템플릿 ID: `<slot>/<name>`. 각 슬롯의 `*/current`는 기존 알고리즘이며 기본 템플릿으로 등록합니다. 이를 선택하면 기존 출력을 바이트 단위로 재현해야 합니다.
- 새 파라미터는 Cubism 표준 이름(`ParamEyeLSmile`, `ParamBrowLAngle`, `ParamBrowLForm`, `ParamBrowLX`, `ParamCheek`) 또는 VBridger/ARKit에서 통용되는 이름(`ParamJawOpen`, `ParamMouthX`, `ParamCheekPuff`, `ParamMouthShrug`, `ParamMouthFunnel`, `ParamMouthPuckerWiden`, `ParamMouthPressLipOpen`, `ParamTongueOut`)을 따릅니다. 파생 파라미터(물리 출력, 섀도 파라미터)는 결정적인 `Param<부위><작용>{L|R}` 형식을 쓰며 임의 ID를 사용하면 안 됩니다.

### 0.5 등록표 요구 사항(이 템플릿 그룹에서 도출)
1. **파생 파라미터 + 물리 그룹은 템플릿의 일급 출력물입니다**. 템플릿의 거의 절반이 “섀도 파라미터/물리 출력 파라미터 → 키폼 또는 블렌드 셰이프”를 만듭니다. 템플릿은 물리 그룹(입력, 체인, 출력 v_k)과 파생 파라미터를 선언할 수 있어야 하며, 이 선언으로 ID, 캐시 키, `DocumentGenerators` 소유 관계를 생성해야 합니다.
2. **템플릿은 트리를 수정하는 대신 삽입 위치를 선언합니다**. 결합은 대부분 “특정 부모 아래, 특정 자식 위에 warp 한 층 삽입(또는 특정 warp에 블렌드 셰이프 작성)”으로 구현합니다. 슬롯이 정의하는 앵커(`eye.lidGroup.outer`, `iris.betweenGaze`, `mouth.stack[jaw|offset|width|shape]` 등)와 층 순서 규칙이 필요하며, 템플릿은 앵커와 축만 선언합니다.
3. **템플릿이 자체 키 위치를 선언합니다**. 각 키의 형태는 규칙/투영으로 평가합니다. 기존 `ninePoseAxes`, `mouthAxes`, 눈 깜빡임 0/1 두 키는 모두 `current` 템플릿의 선언값이 되어야 합니다.
4. **파라미터 범위 변경은 템플릿 버전을 통해 처리합니다**. EyeOpen `[0,1] → [0,1,2]`, MouthOpenY `[0,1] → [0,2]`, AngleX ±45 → ±60은 기존 프로젝트 외형을 바꾸므로 새 템플릿 버전이어야 합니다. 기존 프로젝트는 “생성 결과 업데이트” 전까지 이전 버전을 유지합니다.
5. **블렌드 셰이프를 우선하고, 키폼 베이크를 하위 호환 수단으로 사용합니다**. 중첩 형태 보정(보조 입 모양, 눈썹→눈, 감정 형태, 모음)은 Cubism 5 대상에서 블렌드 셰이프를 사용합니다. 더 낮은 버전으로 내보낼 때는 “단일 형태 × 주축”을 베이크하고 손실 보고서에 기록합니다.
6. **의미 역할을 세분화해야 합니다**. 하이라이트를 IRIDES에서 분리하거나 IRIDES의 하위 역할로 지정하고, `ANIMAL_EAR`를 추가합니다. “웃는 눈”을 더 이상 `EYE_CLOSE`에 합치지 않으며, 입안 요소는 구강/치아/혀/입안 어두운 층을 구분합니다. 눈 덮개층(아이섀도, 눈꺼풀 가장자리 그림자, 반사광)과 눈물/기호층도 독립 역할이 필요합니다. 그렇지 않으면 대부분의 눈 템플릿을 연결할 수 없습니다.
7. **같은 문제의 서로 반대인 방법을 선택지로 함께 유지합니다**(0.6 참고). “평균값”으로 합치지 않습니다.

### 0.6 같은 문제를 해결하는 서로 다른 방법(선택지로 유지)
| 문제 | 방법 A | 방법 B | 이 목록의 처리 |
| --- | --- | --- | --- |
| 고개를 돌릴 때 하이라이트 움직임 | 광원을 따라 고정되어 눈에 대해 반대로 움직임(또는 홍채보다 적게 이동) | 각막이 홍채보다 앞에 있어 홍채보다 많이 이동 | `eye.highlight/parallax-layer`의 `turnMode` |

| 동물 귀가 처지는 방식 | 바깥쪽 아래로 회전 | 바깥으로 뒤집어 평평하게(비행기 귀) / 뒤로 눌러 내림 | `animal-ear/emotion-mood`의 `droopStyle` |
| 혀가 입술선을 넘어 나오기 | 정/반전 마스크를 적용한 혀 두 장을 엇갈려 전환 | 마스크 국소 확장 + 그리기 순서 올리기 | `mouth.interior/tongue-handoff`와 `tongue-mask-expand` |

## 1. face.turn — 머리 방향 전환(AngleX × AngleY)

### `face.turn/current` 아홉 포즈 경위망(기존)
- **목적**: 머리를 X/Y로 돌릴 때 얼굴을 “저주파 표면 + 이목구비 고주파 보정” 경위망으로 변형하여 모든 얼굴 템플릿의 부모로 사용합니다.
- **적용 대상**: FACE 레이어 또는 머리 그룹. 이목구비 영역은 눈/홍채/눈썹/코/입/귀 태그에서 추론합니다.
- **출력**: 파라미터 `ParamAngleX{-45,0,45}`, `ParamAngleY{-30,0,30}`. 디포머 `DeformHeadRotation`(회전) → `DeformHeadContainer`(4×5) → `DeformFaceNinePose`(8×8) → `DeformFaceContour` / 선택적 `DeformFeatureDisplacement` / 각 이목구비 `Deform*Shape{L,R}`. AngleY 축이 있는 모든 warp에 `ParamBodyLean` 축을 추가합니다.
- **알고리즘**: `NinePoseFaceRig.surfacePoint`(가까운 쪽 평탄부 이동, 먼 쪽 압축, 고개 들기 ^ / 숙이기 V, 모서리 상호작용 항 Cxy). `featureOffset`은 EYE/IRIS/BROW/NOSE/MOUTH/EAR 분기에 따라 형태를 보정합니다. 키는 양 끝점과 중간점에만 있으며 키 사이는 선형 보간합니다.
- **조절 파라미터**: `RigTuning`의 머리 관련 약 20개 항목(`faceTurn*`, `faceLift`, `faceTilt`, `faceArch`, `faceCorner`, `eyeFarShrink` 등)과 `headTurnStrength`.
- **실패 양상과 확인**: AngleX 중간 포즈가 양 끝의 선형 평균이어서 정점이 원호 대신 현을 따라 움직이며 큰 각도에서 얼굴이 “줄어듭니다”. 키 위치 `{-45,0,45}`가 하드코딩되어 있습니다.
- **엔진 기능**: warp, 회전, 다차원 키폼.
- **난이도 / 우선순위**: 구현됨 / 기본 템플릿으로 등록(P0: 등록만 하고 출력은 변경하지 않음).

### `face.turn/depth-layered` 깊이별 그룹의 중첩 각도 warp
- **목적**: 머리의 각 깊이층(뒷머리 < 귀 < 얼굴 < 이목구비 < 앞머리 < 정수리 장식)이 고개 회전 시 서로 다르게 이동해 입체 시차를 만들고, 그룹 안에서 이목구비 원근을 추가합니다.
- **적용 대상**: 식별된 머리 하위 그룹(뒷머리, 귀, 얼굴, 이목구비, 앞머리, 머리 장식). 각 그룹은 얼굴 표면에 대한 상대 깊이 z(머리 너비 단위)를 추정할 수 있어야 합니다.
- **출력**: `DeformHeadContainer` 아래에 깊이 그룹마다 AngleX×AngleY warp 생성(얼굴·앞머리는 ≥ 20×20칸, 귀·장식은 5×5–9×9). 이목구비 그룹 내부에는 각 요소별 세밀한 warp(3×3 키)를 생성합니다. 파라미터는 추가하지 않습니다.
- **알고리즘**:
  1. 기본 깊이: 뒷머리 −0.4, 귀 −0.3, 얼굴 0, 눈썹 +0.02, 눈 0, 코 +0.12, 앞머리 +0.12. 정수리 바보털/후광은 3차원 위치에 따릅니다.
  2. 그룹 warp의 가로 이동 = `sinψ · R_head · (1 + k·z)`. 먼 쪽은 `cosψ`로 압축합니다(구형 모델). 뒤쪽 그룹(z<0)은 방향을 반전합니다.
  3. 이목구비 세부 warp: 너비 × `cos(ψ ± φ_feature)`(φ는 얼굴 중심선에 대한 해당 요소의 방위각). 뒤집힘을 막기 위해 먼 쪽 너비 비율의 하한은 0.5입니다.
  4. 대각선 포즈는 두 축을 조합하며 필요하면 별도로 보정합니다.
- **조절 파라미터**: `depth.<group>`(깊이, 머리 너비 단위)의 기본값은 위와 같고 범위는 −0.6–0.3. `parallaxK`(시차 계수) 기본 0.2, 범위 0.1–0.3. `minFarWidth` 기본 0.5, 범위 0.4–0.7.
- **실패 양상과 확인**: 깊이 그룹 사이 이음새(앞머리 뿌리와 이마, 귀뿌리와 옆머리)가 ±끝점에서 어긋남 → 아홉 포즈를 렌더링하여 겹침 영역을 확인합니다. 층 수가 늘면 키폼 비용도 증가합니다.
- **엔진 기능**: 중첩 warp, 다차원 키폼.
- **난이도 / 우선순위**: medium / P1.
- **차이점**: 기존 경위망에는 이목구비 변위와 앞·뒷머리의 머리 표면 추종이 이미 포함되어 있지만, 그룹별 깊이 계수와 각 앞머리 그룹의 독립 각도 warp가 없습니다.

### `face.turn/arc-keys` 투영으로 평가하는 중간 키
- **목적**: 선형 보간 때문에 “중간 포즈가 납작해지거나 줄어드는” 현상을 없애고, 정점이 머리의 곡면을 따라 움직이게 하며 더 큰 회전 범위를 지원합니다.
- **적용 대상**: AngleX/AngleY를 축으로 하는 모든 얼굴 warp. 큰 각도(> ±30°) 또는 3/4 측면이 강한 스타일.
- **출력**: AngleX 키를 15–20° 간격으로 변경(예: ±30 범위는 `{-30,-15,0,15,30}`, ±60 범위는 20° 간격). 얼굴 윤곽 warp와 머리 주 warp가 같은 키 집합을 사용합니다. 한쪽 요소(옆머리 번, 귀 장식)는 “먼 쪽으로 회전”하는 쪽에만 ±R/3 키를 추가합니다.
- **알고리즘**:
  1. 각 키의 형태는 끝점과 같은 투영 공식을 해당 각도에서 정확히 평가합니다(끝점 보간이 아님).
  2. 키 선택: 먼저 3개 키로 평가하고, 중간점에서 “정확한 평가”와 “선형 보간”의 최대 정점 오차를 비교합니다. 얼굴 너비의 1.5%를 초과하면 그 구간 중간에 키를 추가하고, 기준을 만족하거나 최소 간격에 도달할 때까지 재귀합니다.
  3. 한쪽 요소: 오차가 기준을 초과한 쪽에만 키를 추가합니다.
- **조절 파라미터**: `keyStepDeg` 기본 15, 범위 10–20. `maxChordError`(얼굴 너비 비율) 기본 0.015, 범위 0.005–0.03. `angleXRange` 기본 45, 범위 30–60.
- **실패 양상과 확인**: 차원마다 키 수가 곱해져 증가(AngleX 5키 × AngleY 3키 × BodyLean 3키 = 45) → 얼굴 윤곽과 머리 주 warp만 촘촘하게 하고 이목구비 세부 warp는 3키를 유지합니다. ±60에서는 먼 쪽 얼굴 뒤로 빈틈이 드러날 수 있어 먼 쪽 윤곽/머리카락의 가림을 확인해야 합니다.
- **엔진 기능**: 비균일 다중 키.
- **난이도 / 우선순위**: medium / P1.
- **차이점**: 키 위치 `{-45,0,45}`가 `ninePoseAxes`에 하드코딩되어 있으며, 오차에 따른 자동 키 삽입이 없습니다.

### 인접 슬롯 설명
- 단단한 소품(안경, 모자, 헤드폰)은 독립적인 성긴 warp로 강체 투영을 적용하며 표정 보정의 영향을 받지 않습니다. `hair.accessory`에 속합니다.
- “카메라에 가까이 다가가기”를 위한 전체 전방 이동 파라미터는 `body.lean`에 속합니다.
- 고개 돌림에 따른 롤은 `face.tilt/turn-coupled-roll`을 참고하세요.

## 2. face.tilt — 머리 기울기(AngleZ)

### `face.tilt/current` 입선 중심을 피벗으로 전체 회전(기존)
- **목적**: AngleZ로 머리 전체를 입선 중점 주위로 회전합니다.
- **적용 대상**: 항상 생성합니다.
- **출력**: `DeformHeadRotation`, 축 `ParamAngleZ{-30,0,30}` × BodyLean × 머리·몸 비율. 피벗 `(centerX, mouthLineY)`, 초기 각도 = 원화에서 추정한 머리 기울기.
- **알고리즘**: 파라미터의 도 단위를 회전각으로 직접 사용합니다. 목은 몸 warp를 따릅니다.
- **조절 파라미터**: 전용 항목 없음.
- **실패 양상과 확인**: 머리가 30°까지 돌아도 목이 휘지 않아 “목이 꺾인” 것처럼 보입니다. 몸도 머리 기울기를 따르지 않습니다.
- **난이도 / 우선순위**: 구현됨 / 기본 템플릿(P0 등록).

### `face.tilt/neck-split` 머리는 일부만 회전하고 나머지는 목 굽힘과 몸에 배분
- **목적**: 기울기를 척추를 따라 배분해 목의 S자 곡선을 만들고, 목뿌리에서 머리가 꺾이는 것을 방지합니다.
- **적용 대상**: 목 레이어가 있거나 얼굴 아래 가장자리부터 옷깃까지 피부 영역이 있는 경우.
- **출력**: `DeformHeadRotation` 각도 = `headShare × AngleZ`. 목 warp `DeformNeckTilt` 추가(AngleZ 축, 6×6–8×8), 몸 warp 아래에 연결하고 목과 목에 붙는 장식을 감쌉니다. 선택적 물리 그룹 `PhysicsBodyFollowZ`: AngleZ(Angle형) → `ParamBodyAngleZ`.
- **알고리즘**:
  1. 머리 회전각 = 0.65 × 파라미터 각도.
  2. 목 warp: 위쪽 가장자리는 머리 회전 후 목뿌리 위치를 따릅니다(목 위쪽에서 머리 회전의 변위를 구함). 아래쪽은 0이며, 중간은 smoothstep으로 연결해 굽힘을 만듭니다.
  3. 목에 붙는 장식(choker, 나비넥타이)은 목 warp를 따릅니다. 가슴과 이어지도록 아래쪽 가장자리 변위는 반드시 0이어야 합니다.
  4. 몸 추종: 물리 출력을 머리 각도의 약 0.3으로 하거나 호스트 매핑으로 처리합니다(중복되지 않도록 둘 중 하나 선택).
- **조절 파라미터**: `headShare` 기본 0.65, 범위 0.5–1.0(1.0이 현재 상태). `bodyFollow` 기본 0.3, 범위 0–0.5. `neckBendFalloff` 기본 smoothstep.
- **실패 양상과 확인**: 목 위쪽과 턱 그림자가 분리됨 → AngleZ 끝점에서 목-턱 이음새를 확인합니다. 호스트의 “몸이 머리를 따라가기” 매핑과 겹치면 과도하게 적용됩니다.
- **엔진 기능**: 회전 + warp, 선택적 물리.
- **난이도 / 우선순위**: easy / P1.
- **차이점**: 현재는 머리가 전체 각도를 회전하며 몸은 머리를 따르지 않습니다.

### `face.tilt/turn-coupled-roll` 고개 돌림에 결합된 롤과 호흡 끄덕임
- **목적**: 고개를 돌릴 때 롤을 조금 더하고(경추 결합), 호흡할 때 머리를 살짝 끄덕여 “평행 이동하는 가면” 같은 느낌을 없앱니다.
- **적용 대상**: 항상 사용 가능하지만 실제 사람 추적에서는 가중치를 줄여야 합니다.
- **출력**: 물리 그룹 `PhysicsHeadRollCouple`이 출력하는 파생 파라미터 `ParamAngleZ2`(±30). 머리 회전을 `AngleZ2` 축으로 변경하거나 AngleZ와 AngleZ2 두 축을 중첩합니다. 선택적으로 `ParamAngleY2` = AngleY + 호흡.
- **알고리즘**:
  1. 물리 입력: AngleZ(Angle형, 주 입력, 가중치 60–80%) + AngleX(X형, 가중치 20–30%, 방향 규약에 따라 reflect 결정) + AngleY(X형, 5%).
  2. 두 모드:
     - `steady`: X형 입력이 진자 체인을 거쳐 정상 상태 오프셋을 만듭니다. 고개 돌림 최대값에서 롤 정상값 ≈ Z 범위의 10–20%(약 3–5°). 방향은 고개 돌림의 반대(정수리가 회전 반대쪽으로 기움)입니다.
     - `transient`: AngleX의 X형 입력이 무겁고 느린 단진자를 독립 구동합니다. 회전 “변화”에만 순간 롤이 발생하고 멈추면 바로 섭니다. 크기는 AngleZ 범위의 0.3–0.5이며, 회전하는 쪽 안쪽으로 기웁니다.
  3. 호흡: AngleY2 물리에 Breath(Angle형, 5–10%) 추가.
  4. 검증: AngleX 최대값에서 Z2 정상값 ≤ Z 범위 25%.
- **조절 파라미터**: `rollMode` steady|transient, 기본 steady. `rollWeight` 기본 0.25, 범위 0.15–0.35. `rollSign` ±1(전환 옵션 제공, 렌더링으로 확인). `breathToPitch` 기본 0.07, 범위 0.03–0.1.
- **실패 양상과 확인**: 추적에 이미 실제 Z가 포함되면 중첩이 과도함 → 실제 사람 추적 프리셋은 가중치를 0.15로 낮춥니다. 고개 숙이기 + 돌리기 조합이 비뚤어 보임 → AngleY 끝점에서 결합을 줄입니다.
- **엔진 기능**: 물리(다중 입력, X/Angle형, reflect), 파생 파라미터.
- **난이도 / 우선순위**: easy / P1.
- **차이점**: 머리 X와 Z가 서로 독립적이며 결합층이 없습니다.

### 인접 슬롯 설명
- 머리 Z로 상체를 원호 모양으로 옆으로 기울이고, 몸 Z가 물리를 통해 반대로 머리를 세우는 동작은 `body.lean`에 속합니다.
- 머리카락 조각 자체의 AngleZ warp로 끝부분을 되돌려 흔드는 동작은 `hair.*`에 속합니다.

## 3. face.contour — 얼굴 윤곽과 아래턱

### `face.contour/current` 왼쪽 윤곽 안쪽 수축(기존)
- **목적**: 고개를 돌릴 때 가까운 쪽 광대뼈 윤곽을 안으로 당깁니다.
- **적용 대상**: FACE 레이어.
- **출력**: `DeformFaceContour`(8×16, AngleX만 사용).
- **알고리즘**: `faceContourPoint`: `turn = clamp(−AX/45·s, 0..1)`. 눈선 ±0.18 및 `u<0.35` 범위에서 두 개의 3차 Bezier 감쇠로 왼쪽 윤곽을 `faceContour%`만큼 안으로 밉니다.
- **실패 양상과 확인**: 왼쪽 윤곽만 처리하고 AngleX<0에서만 작동하며 대칭 방향이 없습니다. 리팩터링 시 대칭을 보완해야 합니다(새 버전 등록, 이전 프로젝트 호환을 위해 구버전 선택도 유지).
- **난이도 / 우선순위**: 구현됨 / P0(등록 + 대칭 보완 v2).

### `face.contour/jaw-follow` 입 벌림에 아래턱 연동
- **목적**: 입을 벌릴 때 턱과 얼굴 아래쪽 윤곽을 아래턱과 함께 내려 “얼굴에 구멍을 낸 입”처럼 보이지 않게 합니다.
- **적용 대상**: FACE 레이어와 입 영역이 있는 경우. 턱 그림자, 목 그림자 레이어와 독립 `ParamJawOpen`은 선택 사항입니다.
- **출력**: `DeformFaceNinePose` 아래, `DeformFaceContour` 위에 `DeformJaw` 삽입(≥ 8×10, 코 아래부터 턱까지 덮고 10% 확장). 축은 `ParamMouthOpenY`(`mouth.shape`와 같은 키). `ParamJawOpen`(0..1)을 활성화하면 두 번째 축으로 사용합니다. 턱·목 그림자를 그 아래에 연결합니다.
- **알고리즘**:
  1. 아래턱 변위장: 가중치 `w(y)`는 입선에서 0, 턱끝에서 1(smoothstep)이며 입선 위는 0입니다. 수평 방향에서는 얼굴 윤곽에 100%를 유지하고 중심선 쪽으로 바꾸지 않습니다.
  2. `MouthOpenY = 1`: 턱끝을 `jawRatio × H_m`만큼 내립니다(H_m은 완전히 벌린 입 높이). 얼굴 아래쪽 양 볼은 `cheekNarrow`에 따라 안으로 당깁니다(하강량의 0–0.3배).
  3. `JawOpen = 1`(“입술을 닫고 턱 벌리기”, mmm 입 모양): 같은 양만큼 내리되, 입술층은 `mouth.shape`의 MouthClose 보상으로 닫힌 상태를 유지합니다.
  4. 코 추종은 선택 사항입니다(`nose/mouth-follow` 참고).
  5. 목은 따라가지 않습니다. 얼굴 아래 가장자리와 목 이음새를 확인합니다.
- **조절 파라미터**: `jawRatio` 기본 0.15, 범위 0.05–0.25(H_m 기준). `cheekNarrow` 기본 0.15, 범위 0–0.3. `jawFalloff` smoothstep|linear, 기본 smoothstep. `useJawOpenParam` 기본 false.
- **실패 양상과 확인**: 턱이 내려가 목의 빈 부분이 드러나거나 목 그림자와 어긋남 → 입 벌림 최대값을 렌더링해 얼굴-목 이음새를 확인합니다. `DeformFaceContour`의 회전 보정과 중첩될 때 윤곽이 매끄럽지 않음 → 아홉 포즈 × 입 벌림 끝점을 확인합니다.
- **엔진 기능**: warp 다차원 키폼.
- **난이도 / 우선순위**: easy / **P0**.
- **차이점**: 현재 입 모양 생성 시 얼굴 윤곽은 입 벌림을 따라 움직이지 않습니다.

### `face.contour/mouth-spring` 입 움직임에 따른 연부조직 반동
- **목적**: 입 모양이 급변한 뒤(립싱크의 급격한 발음) 아래턱과 볼에 작은 잔진동을 주어 연부조직처럼 보이게 합니다.
- **적용 대상**: `face.contour/jaw-follow` 활성화 상태.
- **출력**: 파생 파라미터 `ParamJawSpring`(±1). 물리 그룹 `PhysicsJawSpring`: MouthOpenY(X형 80%) + MouthForm(X형 20%) → v1(입술), v2(아래턱/치아·혀). `DeformJaw`와 입 warp의 블렌드 셰이프 또는 추가 축으로 사용합니다.
- **알고리즘**: 단진자 또는 질점 3개 체인. 반동 최대값 = 입 벌림 이동 거리의 0.1–0.2배이며 수직으로 작용합니다. 입술은 v1, 아래턱은 v2를 사용해 한 박자 늦게 움직입니다.
- **조절 파라미터**: `springAmp` 기본 0.15, 범위 0.05–0.25. `springDamping`(delay) 기본 0.9, 범위 0.7–1.2.
- **실패 양상과 확인**: 크기가 지나치면 경련처럼 보입니다. 입을 닫아도 입술이 떨림 → 마지막 질점의 감쇠 하한이 필요합니다. 입 벌림 속도의 영향을 받습니다.
- **엔진 기능**: 물리 다중 출력, 블렌드 셰이프.
- **난이도 / 우선순위**: medium / P2.

### `face.contour/radial-mesh` 방사형 얼굴 메시(메시 토폴로지 옵션)
- **목적**: 얼굴 피부 메시를 “바퀴살 + 동심원”으로 배치해 고개 회전 변형에서 변이 등변위선과 정렬되게 합니다. 가장 바깥 고리는 윤곽 위에 놓여 윤곽을 매끄럽게 유지하며, 같은 토폴로지의 덮개층은 키폼을 공유할 수 있습니다.
- **적용 대상**: FACE 레이어 윤곽이 대략 별 모양인 경우(머리카락 가림으로 홈이 생기면 먼저 닫힌 윤곽을 구함).
- **출력**: FACE 레이어의 적응형 메시를 교체합니다.
- **알고리즘**: 중심 c는 두 눈을 잇는 선 중점보다 조금 아래에 둡니다. 각도 θ마다 c에서 윤곽까지 거리 R(θ)를 구하고, i번째 고리 반지름을 `R(θ)·i/N`, 바퀴살 수를 M으로 합니다. 윤곽 밖에 여유 고리를 한 개 더 추가합니다. 홍조·그림자처럼 얼굴과 윤곽이 같은 덮개층에는 토폴로지를 복사하고 UV를 다시 매핑합니다.
- **조절 파라미터**: `rings` 기본 10, 범위 8–12. `spokes` 기본 40, 범위 32–48.
- **실패 양상과 확인**: 오목한 윤곽에서는 R(θ)가 여러 값을 가질 수 있습니다. 정점 수가 적응형 메시보다 많습니다.
- **엔진 기능**: 메시 생성.
- **난이도 / 우선순위**: medium / P2(`mesh.density`에 속하며 여기서는 얼굴 윤곽 관련 옵션으로 등록).

### 인접 슬롯 설명
- 얼굴 피부를 얼굴의 모든 겹침층에 공통 마스크로 쓰거나, 얼굴 실루엣 복사본을 옆머리의 반전 마스크로 쓰는 기능은 `mask`에 속합니다(`ear/face-stencil-occlusion`이 이 방식을 참조).

## 4. cheek — 볼, 볼 부풀리기, 입 가로 이동에 따른 얼굴 전체 연동

### `cheek/current` 없음(기존)
- **목적 / 현황**: 볼 파라미터가 없습니다. 홍조는 FACE_DETAIL로 `DeformFaceNinePose` 아래에 연결되어 고개 돌림만 따릅니다.
- **난이도 / 우선순위**: — / P0에서 “빈 템플릿”으로 등록.

### `cheek/aux-spread` 보조 입 모양 파라미터를 주변 영역으로 확산(블렌드 셰이프)
- **목적**: 볼 부풀리기, 입 가로 이동, 아래턱, 삐죽거림, 입 너비 등의 보조 입 모양 파라미터가 입뿐 아니라 얼굴 피부, 코, 홍조, 아래 눈꺼풀, 눈썹도 비례해서 당겨 “근육 연동”을 만듭니다. 블렌드 셰이프로 중첩해 주 입 모양 키폼과 곱해지는 것을 방지합니다.
- **적용 대상**: 보조 입 모양 파라미터 중 하나 이상 활성화(`mouth.vowel/arkit-factorized`에서 제공하거나 개별 활성화). 얼굴과 입 영역이 필요하며 코, 홍조, 눈, 눈썹 영역은 선택 사항입니다.
- **출력**: 필요에 따라 활성화하는 파라미터 `ParamMouthX`(±1), `ParamCheekPuff`(0..1), `ParamJawOpen`(0..1), `ParamMouthShrug`(0..1), `ParamMouthPuckerWiden`(±1). 각 영역의 가장 바깥 변형 warp(얼굴 피부는 `DeformFaceNinePose` 아래 보정 warp, `DeformNoseShape*`, 홍조 warp, `DeformEyeShape*`, `DeformBrowShape*`)에 파라미터별 블렌드 셰이프를 하나씩 추가합니다.
- **알고리즘**:
  1. 변위장 템플릿(얼굴 너비 W_f, 높이 H_f, 입 너비 W_m, 눈 높이 H_e 단위). 입 중심을 원점으로 삼고 거리에 따라 감쇠합니다(거리 > 0.6 H_f에서 0).
     - CheekPuff: 볼의 가장 넓은 윤곽을 법선 방향으로 0.03 W_f 확장(가우시안, σ = 0.15 H_f). 입 너비 −20%, 중앙을 살짝 내밉니다. 홍조를 0.1 W_m 올리고, 아래 눈꺼풀을 0.06 H_e 밀어 올리며, 선택적으로 양 눈썹을 0.1 H_e 올립니다.
     - MouthX: 입을 가로로 0.06 W_f 이동. 같은 쪽 볼은 입 변위의 0.6배만큼 같은 방향으로 이동하고 0.03 W_f 상승합니다. 홍조는 0.5, 얼굴 피부는 0.25 비율로 추종합니다. 같은 쪽 아래 눈꺼풀을 0.05 H_e 올리고, 눈·눈썹은 입 변위의 0.1–0.15배, 코는 0.3배만큼 같은 방향으로 이동합니다.
     - JawOpen: 턱을 0.06 H_f 내리고 입 아래 얼굴 피부를 늘립니다. 양 볼을 0.02 W_f 좁히며 눈 영역 전체를 0.02 H_e 내립니다.
     - Shrug: 아랫입술과 턱을 0.02 H_f 밀어 올립니다.
     - PuckerWiden: 입 너비 ±15%.
  2. 영역별 이득: 입 1, 코 0.6, 얼굴 피부 0.4–1, 눈 0.3, 눈썹 0.2.
  3. 작성: 각 영역의 **가장 바깥쪽** 보정 warp에 블렌드 셰이프를 작성합니다. 이목구비와 얼굴 피부가 같은 변위장에서 샘플링하므로 이목구비가 얼굴 위에서 떠다니지 않습니다.
  4. 조합 제한 테스트: 모든 보조 파라미터가 동시에 ±1일 때 아래 눈꺼풀이 동공 중심을 넘어가거나 위·아래 입술이 교차하면 안 됩니다. 초과하면 해당 영역 이득을 비례 축소합니다.
- **조절 파라미터**: `<param>.amp`(각 파라미터의 주 크기) 기본값은 위와 같고 범위는 기본값의 0.5–2배. `<region>.gain` 기본값도 위와 같습니다. `spreadRadius` 기본 0.6 H_f, 범위 0.4–0.8.
- **실패 양상과 확인**: 여러 파라미터가 동시에 최대값이면 눈꺼풀이 동공을 넘어갈 수 있습니다. 대상 런타임이 블렌드 셰이프를 지원하지 않으면(Cubism < 5) 키폼으로 베이크하거나 제외하고 손실 보고서에 기록해야 합니다. 얼굴 추적을 연결하지 않으면 파라미터는 항상 0이므로 기본 입 모양에 영향을 주지 않습니다.
- **엔진 기능**: 블렌드 셰이프(필수), 내보내기 시 베이크를 통한 하위 호환.
- **난이도 / 우선순위**: medium / P1.
- **차이점**: 현재는 MouthForm과 MouthOpenY만 있습니다. 데이터 모델은 블렌드 셰이프를 지원하지만 생성기는 만들지 않으며 영역 간 결합이 없습니다.

### `cheek/global-field` 고해상도 얼굴 전체 평활장 + 이목구비의 동일 장 샘플링(`aux-spread`의 키폼 구현)
- **목적**: `aux-spread`와 같지만 블렌드 셰이프를 지원하지 않는 대상에서 촘촘한 얼굴 보정 warp 하나에 연속 변위장을 담습니다. 이목구비는 각 계층에서 같은 장을 샘플링해 동기 보정합니다.
- **적용 대상**: 대상 런타임에 블렌드 셰이프가 없거나, 눈 보정과 눈 개폐의 상호작용이 필요한 경우.
- **출력**: 얼굴 피부 그룹의 AngleXY warp 아래에 ≥ 15×15 `DeformFaceMuscle` 삽입(MouthX × CheekPuff 축 또는 두 층으로 분리). 각 이목구비의 AngleXY warp 아래에도 같은 파라미터의 보정 warp를 삽입합니다. 눈 보정은 `EyeOpen × MouthX` 2차원 키로 만듭니다.
- **알고리즘**:
  1. 장 Δ(p)는 `aux-spread`의 템플릿과 같으며, 외형을 유지하기 위해 얼굴 윤곽에서 0.3까지 감쇠합니다.
  2. 이목구비 앵커(눈썹 중심, 눈 중심, 입 중심, 홍조 중심)에서 Δ를 샘플링해 해당 보정 warp의 평행 이동으로 사용한 뒤 특징 보정을 추가합니다. 같은 쪽 아래 눈꺼풀을 0.15–0.2 H_e 올리고, `EyeOpen = 0` 행은 변형 없이 이동만 적용합니다(감은 눈을 다시 찡그려 눈선이 교차하는 것을 방지).
  3. 입을 가로로 옮길 때 먼 쪽 입꼬리는 늘이고 가까운 쪽은 조여 올립니다.
- **조절 파라미터**: `aux-spread`와 동일. 추가로 `fieldGrid` 기본 16, 범위 12–20.
- **실패 양상과 확인**: 이목구비 계층과 얼굴 피부 계층의 이동이 불일치함 → 반드시 같은 장을 샘플링해야 합니다. 입 가로 이동과 고개 돌림을 합친 총변위는 ≤ 0.15 W_f입니다.
- **엔진 기능**: 다차원 키폼(블렌드 셰이프 불필요).
- **난이도 / 우선순위**: hard / P2.

### `cheek/squint-lid-push` 볼 상승으로 아래 눈꺼풀 밀어 올리기
- **목적**: 웃거나 눈을 가늘게 뜨거나 볼을 올릴 때 광대 부위가 아래 눈꺼풀을 밀어 눈이 휘는 “뒤센 미소”를 만듭니다.
- **적용 대상**: 눈과 얼굴 영역. `eye.smile/*`, `eye.emotion/additive-shapes`와 함께 사용합니다.
- **출력**: 파라미터 `ParamCheekSquintL/R`(0..1, `eye.smile` 또는 `mouth.shape`의 MouthForm에서 파생 가능). 얼굴 보정 warp(볼 상승)와 눈 warp(아래 눈꺼풀 상승)에 블렌드 셰이프를 함께 작성합니다.
- **알고리즘**: 볼 상승량은 입꼬리 높이 단위의 0.7배(약 0.03 H_f). 아래 눈꺼풀은 0.15 H_e 올라가며 평평해집니다. 선택적으로 CheekPuff를 질점 2개, 높은 delay의 진자(저역 통과)에 통과시켜 `lowerLidPush`를 파생합니다.
- **조절 파라미터**: `lidPush` 기본 0.15 H_e, 범위 0.08–0.25. `cheekLift` 기본 0.03 H_f, 범위 0.01–0.05. `deriveFrom` none|MouthForm|CheekPuff, 기본 none.
- **실패 양상과 확인**: `eye.smile`의 아래 눈꺼풀 상승과 중복 계산됨 → 둘 중 max를 취합니다. 아래 눈꺼풀이 동공 중심을 넘어가지 않는지 확인합니다.
- **엔진 기능**: 블렌드 셰이프 또는 2차원 키폼. 선택적 물리 저역 통과.
- **난이도 / 우선순위**: easy / P1.

### `cheek/blush-overlay` 얼굴 피부를 마스크로 사용하는 홍조/수줍음 덮개층
- **목적**: 홍조, 수줍음 사선 등의 덮개층이 얼굴 회전을 따르면서 항상 얼굴 윤곽 안에 있도록 합니다. 얼굴보다 크게 그려도 됩니다.
- **적용 대상**: 홍조/수줍음 레이어 또는 생성된 타원/사선 소재와 FACE 레이어.
- **출력**: 덮개층을 얼굴 보정 warp 체인 안에 연결합니다(이목구비와 동급). 마스크 = 얼굴 피부 메시. 선택적 스위치 파라미터 `ParamCheek`(0..1, Cubism 표준 “照れ”)으로 불투명도를 제어합니다.
- **알고리즘**: 홍조 중심은 볼이 가장 넓은 곳보다 조금 아래이며 크기는 약 0.25 W_f입니다. 불투명도는 0→1 선형입니다. 곱하기 또는 일반 블렌딩은 원래 레이어 속성을 따릅니다. `aux-spread`에 참여하면 홍조는 해당 영역 이득에 따라 추종합니다.
- **조절 파라미터**: `blushOpacityMax` 기본 1, 범위 0.4–1. `blushBlend` 원본 레이어|multiply.
- **실패 양상과 확인**: 아홉 포즈에서 얼굴 피부 밖으로 나오는 덮개층 면적이 0이어야 합니다.
- **엔진 기능**: 마스크, 불투명도 채널.
- **난이도 / 우선순위**: easy / P1.

## 5. nose — 코

### `nose/current` 깊이 척도 보정(기존)
- **목적**: 고개 회전 시 코를 “깊이 척도”에 따라 얼굴 표면보다 더 이동시켜 콧대가 돌출된 모습을 만듭니다.
- **적용 대상**: NOSE 레이어.
- **출력**: `DeformNoseShape{side}`(3×4, 아홉 포즈). 부모는 항상 얼굴이며 이목구비 변위층 아래에는 연결하지 않습니다.
- **알고리즘**: `featureOffset`의 NOSE 분기: `depthByLatitude = 0.58 + 0.52v`, `noseShift%`와 여러 하드코딩 항목.
- **실패 양상과 확인**: 이목구비 변위를 켜도 코가 `DeformFeatureDisplacement` 아래에 연결되지 않아 문서 설명과 다릅니다(리팩터링 시 확인).
- **난이도 / 우선순위**: 구현됨 / P0 등록.

### `nose/mouth-follow` 아래턱과 입 모양을 따라 미세하게 움직이는 코
- **목적**: 입 벌림, 볼 부풀리기, 삐죽거림에 따라 코를 약간 내리거나 올려 코가 고정된 느낌을 없앱니다.
- **적용 대상**: NOSE 레이어. `face.contour/jaw-follow` 또는 `cheek/aux-spread` 활성화.
- **출력**: `DeformNoseShape*`에 MouthOpenY 축 또는 블렌드 셰이프와, 보조 입 모양 파라미터의 블렌드 셰이프 추가.
- **알고리즘**: 입 벌림 최대값에서 코 하강량 = 턱 하강량의 0.1배. 볼 부풀리기·삐죽거림은 각각 영역 이득 0.6(`cheek/aux-spread` 참고).
- **조절 파라미터**: `noseFollow` 기본 0.1, 범위 0–0.2.
- **실패 양상과 확인**: 코와 얼굴 피부 보정이 일치하지 않으면 “떠다닙니다”.
- **엔진 기능**: 키폼 또는 블렌드 셰이프.
- **난이도 / 우선순위**: easy / P2.

## 6. ear — 사람 귀

### `ear/current` 먼 쪽 페이드아웃을 통한 가림 보정(기존)
- **목적**: 고개를 돌리면 귀를 반대 방향으로 이동하고 먼 쪽 귀를 좁히면서 사라지게 합니다.
- **적용 대상**: EARS / EARWEAR 레이어.
- **출력**: `DeformEarOcclusion{L,R}`(3×3, 아홉 포즈) + AngleX 불투명도 채널. 부모는 항상 얼굴입니다.
- **알고리즘**: `featureOffset`의 EAR 분기(반대 방향 이동 `earShift%`, 먼 귀 수축 `earFarShrink%`). `earOpacity`의 먼 귀 = `1 − |yaw|·earFade%`.
- **난이도 / 우선순위**: 구현됨 / P0 등록.

### `ear/face-stencil-occlusion` 얼굴 실루엣 반전 마스크로 연속 가림
- **목적**: 옆머리, 귀, 귀걸이가 “볼 뒤로 숨는” 가림을 회전에 따라 연속적으로 변화시켜, 전체 페이드아웃이나 그리기 순서 전환을 대체합니다.
- **적용 대상**: 반전 마스크를 지원하는 런타임(Cubism ≥ 4.0). 후보 객체는 “정지 시 얼굴과 겹침 < 5%, AngleX 끝점 중 하나에서 겹침 > 10%”를 만족해야 합니다.
- **출력**: 보이지 않는 얼굴 실루엣 복사본 `<FaceId>_Stencil`(얼굴 메시·키폼 복사, AngleX만 남겨 차원 축소 가능), 부모 warp 공유. 후보 객체에 해당 복사본을 inverse mask로 추가합니다.
- **알고리즘**:
  1. 얼굴 피부 메시를 복사합니다(결정적인 ID). 불투명도 0이며 마스크 소스로만 사용합니다.
  2. 겹침 비율 임계값으로 후보를 선택합니다.
  3. 특정 끝점에서 객체가 얼굴 앞에 완전히 있어야 하면 그쪽은 그리기 순서로 처리하거나 반쪽 얼굴 복사본을 만듭니다.
  4. 얼굴 실루엣을 마스크로 쓰는 모든 객체는 같은 마스크 소스를 공유합니다.
- **조절 파라미터**: `overlapRestMax` 기본 0.05. `overlapPoseMin` 기본 0.1. `stencilAxes` X|XY, 기본 X.
- **실패 양상과 확인**: 런타임 < 4.0이면 그리기 순서로 대체하고 손실 보고서에 기록합니다. 전역 마스크 버퍼 상한도 확인합니다.
- **엔진 기능**: 반전 마스크, 복사본(`SeeThroughLayers` 복사 방식 재사용).
- **난이도 / 우선순위**: medium / P2(방식 자체는 `mask`에 속함).

## 7. animal-ear — 동물 귀

동물 귀에는 새 의미 역할이 필요합니다(`ANIMAL_EAR` 권장, 좌우 구분. 식별 기준: 머리 윗부분 윤곽 위, 삼각형, 헤어라인 위, 또는 사용자 지정). 아래 템플릿은 표시 지점을 공유합니다. 귀뿌리 = 귀와 머리카락/머리 윗윤곽이 만나는 선분의 중점. 귀 축 = 뿌리 → 끝. 귀 길이 E, 귀 바깥 기울기 β.

### `animal-ear/current` 없음(기존)
- **현황**: 동물 귀 의미 역할이 없습니다. EARS로 표시되면 사람 귀 가림 보정만 적용하고, 아니면 일반 머리 요소로 `DeformHeadContainer`에 연결합니다.
- **난이도 / 우선순위**: — / P0에서 빈 템플릿으로 등록.

### `animal-ear/local-frame-stack` 동물 귀 변형 스택: 위치 → 로컬 좌표 회전 → 물리 → 로컬 시점
- **목적**: 동물 귀에 고정 순서 변형 스택을 제공합니다. 물리 흔들림은 귀 자체 좌표에서 발생하고, 회전 시 외형 변화(귀 안쪽 또는 뒤쪽 노출)는 가장 안쪽에서 수행한 뒤 물리 굽힘과 머리 이동을 적용합니다.
- **적용 대상**: `ANIMAL_EAR` 레이어. 선택적 하위 레이어: 바깥 윤곽, 안쪽 귀(분홍색), 솜털, 귀 뒷면.
- **출력**(바깥 → 안쪽):
  1. `DeformAnimalEarCarry{L,R}`: 2×2 warp, AngleX×AngleY 축. 키폼 = 머리 방향 전환 변위장에서 귀뿌리의 이동·크기를 샘플링한 값.
  2. `DeformAnimalEarRoot{L,R}`: 회전 디포머, 피벗 = 귀뿌리 중점, 기준각 = β(자식 warp 격자를 귀 축에 정렬). 머리 yaw×pitch 축에서 ±3–5°, `ParamAnimalEarSwing` 축으로 뿌리 주위를 회전합니다.
  3. 물리 warp 층(1–3층, 9×9, 13키): `ParamAnimalEarFold`(접기/세우기), `ParamAnimalEarTip`(끝 굽힘). AngleY 축을 더해 고개 숙이기/들기에서 접히는 방향을 다르게 할 수 있습니다.
  4. 귀 메시마다 로컬 시점 warp 하나(AngleX[×AngleY] 축). yaw에 따라 너비 × `cos(ψ ± β)`. 먼 쪽 안쪽 귀를 0.3–0.5까지 압축해 바깥 윤곽/뒷면을 드러내며 가까운 쪽은 반대로 처리합니다.
  5. 메시 수준 `ParamAnimalEarTurn` 키폼(방향). 안쪽 귀 너비를 바깥 가장자리 쪽으로 0.4(−1) / 1.15(+1)로 압축·확장하고 바깥 귀는 반대로 조금 움직입니다.
- **알고리즘**:
  - 접기 −1: 귀 위쪽 70%를 귀뿌리 주위로 바깥쪽 35–45° 회전, 높이 −20%. +1: 수직으로 8% 늘립니다.
  - 귀끝 ±1: 위쪽 30%를 높이 0.7 지점 주위로 ±25° 굽힙니다. 굽힘 가중치는 귀 축을 따라 뿌리 0에서 끝 1까지 2차 증가합니다.
  - 하위 요소(안쪽 털, 귀 뒷면)는 스택 안에 앞 두 단계 물리 파라미터를 축으로 하는 2차원 보정 키를 추가하고 바깥 윤곽보다 10–20% 늦게 반응합니다.
  - 안쪽 털은 바깥 귀를 마스크로 사용합니다. 안쪽·바깥 귀의 공유 변에 글루를 추가합니다(정점 거리 < 2 px끼리 연결).
  - 귀뿌리 근처 머리카락은 귀 위에 그리거나 헤어라인 메시로 귀뿌리를 반전 클리핑하여 회전 시 뿌리가 머리카락을 뚫고 나오지 않게 합니다.
- **조절 파라미터**: `foldAngle` 기본 40°, 범위 30–45. `tipBend` 기본 25°, 범위 15–30. `turnCompress` 기본 0.45, 범위 0.3–0.6. `innerLag` 기본 0.15, 범위 0.1–0.2. `rootLocalFrame` 기본 true.
- **실패 양상과 확인**: 귀 일부가 머리카락에 가려져 있으면 방향 키폼에서 그리지 않은 부분이 드러날 수 있습니다. 여러 귀 메시의 ID 순서가 달라 글루 쌍이 어긋남 → 결정적인 ID로 연결합니다. 귀가 매우 짧으면(머리 높이의 < 15%) 물리층을 1층으로 줄입니다.
- **엔진 기능**: 회전 디포머, 중첩 warp, 13키, 글루, 마스크, 반전 마스크.
- **난이도 / 우선순위**: medium / P1.
- **차이점**: 동물 귀 의미 역할과 구조가 없으며, 귀에는 단일 층의 고개 회전 보정만 있습니다.

### `animal-ear/blink-twitch` 눈 깜빡임으로 귀 움찔하기(+ 머리 관성 흔들림)
- **목적**: 눈을 깜빡일 때마다 귀가 무의식적으로 움찔하게 합니다(동물의 반사 동작). 좌우 귀는 각각 같은 쪽 눈에 연결되어 한쪽 눈만 깜빡이면 귀 하나만 움직입니다. 머리의 가로 이동은 관성 흔들림을 만듭니다.
- **적용 대상**: `animal-ear/local-frame-stack` 생성 후 사용. 머리에 붙은 부드러운 삼각형 조각(인형 귀, 리본 날개)에도 적용할 수 있습니다.
- **출력**: 귀마다 물리 그룹 `PhysicsAnimalEarTwitch{L,R}` 하나. `ParamAnimalEarSwing`(뿌리 흔들림), `ParamAnimalEarFold`, `ParamAnimalEarTip`, 선택적 `ParamAnimalEarTurn`으로 출력합니다. 선택적 공유 그룹 `PhysicsAnimalEarSway`: 머리 X/Y(X형) + 머리 Z(Angle형) → `ParamAnimalEarSway`(병렬 배치한 양 귀 warp의 같은 방향 이동 + 회전).
- **알고리즘**:
  1. 움찔 그룹 입력: 같은 쪽 EyeOpen(가중치 50–100), 머리 AngleX/AngleY(X형, 각각 15–25, 0도 가능).
  2. 체인: 질점 4–5개. 첫 구간을 더 무겁고 감쇠가 크게 만들어 짧게 움찔하고 지속되지 않게 합니다. 질점 길이는 E × {0.4, 0.3, 0.2, 0.1}로 줄이고 m/d도 끝으로 갈수록 0.05–0.1 감소시킵니다.
  3. 체인 순서대로 더 먼 끝의 변형에 매핑합니다. v1 → 뿌리 흔들림, v2 → 중간/방향, v3 → 접기, v4 → 귀끝. “먼저 회전 → 옆으로 회전 → 접기 → 귀끝이 마지막으로 흔들림” 순서를 만듭니다.
  4. reflect로 깜빡일 때 귀가 뒤로 움찔하게 합니다. 정규화 각도 음수 쪽(뒤집혀 뒤로 가기)을 양수 쪽의 1.5배로 설정해 지나치게 뒤집히지 않게 합니다.
  5. 양 귀 비동기: 좌우는 각각 같은 쪽 눈에 연결하고, 한쪽 v1에 0.9를 곱할 수도 있습니다.
  6. 보정: 표준 깜빡임 1회(0.15 s 닫기, 0.1 s 열기) 뒤 최대값 ≤ 귀 높이 0.25, 0.3–0.6 s 동안 감쇠.
- **조절 파라미터**: `blinkWeight` 기본 70, 범위 30–100. `headWeight` 기본 20, 범위 0–30. `swingDeg` 기본 ±12°, 범위 8–20. `asymNegRatio` 기본 1.5, 범위 1.3–2. `chainLength` 4|5, 기본 4.
- **실패 양상과 확인**: 오래 눈을 감으면 귀가 한쪽에 멈춤 → 닫힌 눈 정상 상태가 중립에 가깝도록 출력 scale을 조절합니다. 추적의 눈 깜빡임 노이즈가 귀 떨림을 만듦 → EyeOpen 입력에 0.05 데드존 추가. 토끼 귀처럼 긴 귀는 질점을 늘리고 가속도를 줄여야 합니다. 단단한 돌출부에는 적용하지 않습니다.
- **엔진 기능**: 물리(다중 출력 v_k, reflect, 비대칭 정규화).
- **난이도 / 우선순위**: medium / P1(이 그룹에서 가장 새로운 기법 중 하나이며 동물 귀 의미 역할이 먼저 구현되어야 함).
- **차이점**: 현재 눈 깜빡임은 눈만 구동하며 “눈 깜빡임 → 눈이 아닌 부위”의 보조 물리가 없습니다.

### `animal-ear/emotion-mood` 감정에 따른 귀 처짐/세우기
- **목적**: 동물 귀를 “두 번째 눈썹”처럼 사용합니다. 눈살을 찌푸리거나 입꼬리를 내리면 처지고, 기쁘면 세웁니다. 입을 한쪽으로 삐죽이면 같은 쪽 귀를 누릅니다.
- **적용 대상**: 동물 귀 스택이 생성되어 있고 눈썹 파라미터(BrowY 또는 BrowForm), MouthForm이 있는 경우. MouthX는 선택 사항입니다.
- **출력**: 파라미터 `ParamAnimalEarMood{L,R}`(±1)를 귀뿌리 위치층 아래 자세 warp에 연결합니다. 물리 그룹 `PhysicsAnimalEarMood`: BrowForm/BrowY(Angle형, 40–45) + MouthForm(15)[+ MouthX, 한쪽 반전] → Mood(부족 감쇠 단진자, 순간값이 아닌 지속값). 선택적으로 표정 스위치 E가 자세 warp에 E[0, 0.5] 축의 귀 누르기 층을 추가하고 E의 후반 구간에서 대체 귀 형태로 전환할 수 있습니다.
- **알고리즘**:
  - Mood −1(처짐): 뿌리 주위로 바깥 아래쪽 25–35° 회전, 귀 윤곽을 15% 납작하게 합니다. 또는 “비행기 귀”(바깥으로 70–90° 뒤집고 귀 축으로 30° 회전해 안쪽이 앞을 향함), 또는 “뒤로 누르기”(뿌리의 수평축 주위로 뒤로 60–80° 눕히고 투영 길이 0.4–0.6).
  - Mood +1(세우기): 안쪽 위로 8–12° 회전, 3–5% 늘립니다.
  - 키폼은 “귀뿌리 주위 3차원 강체 회전 + 직교 투영”으로 계산하며 귀를 살짝 휜 얇은 조각으로 봅니다.
  - 눈썹을 추적하지 않으면 Mood가 항상 0 → 보조 수단으로 MouthForm 가중치를 30%로 높입니다.
- **조절 파라미터**: `droopDeg` 기본 30, 범위 20–40. `raiseDeg` 기본 10, 범위 5–15. `browMouthRatio` 기본 3:1. `droopStyle` outward|flatten|backward, 기본 outward.
- **실패 양상과 확인**: 처질 때 귀끝이 머리카락 안으로 들어감 → 귀끝이 정수리 윤곽보다 머리 높이의 0.15 이상 낮아지지 않게 제한합니다. 바깥으로 뒤집힌 뒤 모자·머리카락과의 그리기 순서를 파라미터에 따라 전환해야 합니다. 표정 모션이 Mood를 직접 쓰면 물리와 충돌하므로 모션은 입력 파라미터를 써야 합니다.
- **엔진 기능**: 물리(Angle형 지속 입력, 부족 감쇠), 다차원 키폼.
- **난이도 / 우선순위**: medium / P2.

### `animal-ear/combo-correction` 큰 각도 조합 보정 키
- **목적**: 움찔, 바깥 뒤집기, 아래 누르기, 고개 돌림은 모두 큰 각도 운동이므로 중첩 warp를 선형 합성하면 오류가 드러납니다. 가장 눈에 띄는 귀 표면 하나를 3차원 강체 조합으로 정확히 평가합니다.

- **알고리즘**: 각 격자점에서 축별 변형을 더하는 대신 “귀뿌리 주위 강체 회전 조합 + 투영”을 다시 계산합니다. 절차적 생성은 정확한 키 계산에 적합합니다.
- **조절 파라미터**: `comboAxes`로 참여 축 선택. `keysPerAxis` 기본 3.
- **실패 양상과 확인**: 키 수 폭증(메시 하나에만 적용). 나머지 레이어의 중첩 근사와 극값에서 어긋날 수 있습니다.
- **엔진 기능**: 고차원 키폼.
- **난이도 / 우선순위**: hard / P2(research).

### `animal-ear/flick-motion` 모션 안의 귀 움찔 펄스
- **목적**: 인사, 감동, 노래 등의 모션에서 귀를 빠르게 2–3번 움찔하게 하고 잔진동은 물리에 맡깁니다.
- **적용 대상**: 동물 귀 스택 생성 후.
- **출력**: 모션 트랙에 `ParamAnimalEarFold` 또는 충격 입력 파라미터 작성. 2–3회 교대 펄스, 각 0.1–0.2 s, 크기는 범위의 30–80%. 또는 0.1 s 동안 30% 접었다가 튕겨 돌아옵니다.
- **조절 파라미터**: `pulses` 기본 3. `pulseSec` 기본 0.17. `amp` 기본 0.5.
- **실패 양상과 확인**: 물리가 구동하는 파라미터를 모션에서 직접 쓰면 덮어써짐 → 충격 입력 파라미터를 사용합니다.
- **엔진 기능**: 모션 트랙, 물리 충격 입력.
- **난이도 / 우선순위**: easy / P2(`motion.idle`과 협력).

## 8. eye.lid — 눈꺼풀 개폐, 시선에 따른 눈꺼풀, 깜빡임 잔진동

눈 템플릿의 공통 표시: 흰자 / 위 눈꺼풀 선(속눈썹, 아이라인) / 아래 눈꺼풀 선 / 쌍꺼풀 선 / 아이섀도 / 감은 눈 선 / 홍채 / 동공 / 하이라이트(여러 조각 가능). H_e = 위 눈꺼풀 닫힘 이동 거리(눈 높이), W_e = 눈 너비, G_x/G_y = 홍채 시선 이동 거리, R_i = 홍채 반지름.

### `eye.lid/current` U자 눈 감기(기존)
- **목적**: EyeOpen 0에서 위 눈꺼풀이 깊은 U자 감은 눈 선으로 내려오되 속눈썹 두께는 유지합니다.
- **적용 대상**: EYEWHITE, EYELASH, EYE_CLOSE.
- **출력**: 파라미터 `ParamEyeL/ROpen{0,1}`(기본 1), 메시 키폼 `eyeClosureGrid`. 감은 눈 선은 불투명도 `1 − open`만 사용합니다. Side.NONE이면 정점 x에 따라 두 파라미터로 나눕니다.
- **알고리즘**: `edgeY = top + h·blinkCorner%`, `curveY = edgeY + max(1.5, h·blinkDepth%)·(1 − nx²)`. 속눈썹은 세로로 `eyelashSquash%`를 유지하고 흰자는 약 1.2 px 띠로 압축합니다. 속눈썹은 열마다 알파 가중 중심선에 고정합니다(원화가 기울어져 있으면 비활성화).
- **실패 양상과 확인**: 0/1 두 키뿐이라 반쯤 감을 때 위 눈꺼풀 곡선이 선형 보간으로 평평해집니다. 감은 눈 선과 뜬 눈 그룹이 동시에 반투명하면 “선이 튑니다”.
- **난이도 / 우선순위**: 구현됨 / P0 등록.

### `eye.lid/arc-blink` 곡선을 유지하는 중간 키와 감은 눈 선의 빠른 전환
- **목적**: 위 눈꺼풀이 곡선을 따라 내려오게 하고(중간이 먼저 처져 눈알을 감싸듯), 거의 닫혔을 때 손으로 그린 감은 눈 선으로 깔끔하게 전환합니다.
- **적용 대상**: 흰자 + 위 눈꺼풀 선. 감은 눈 선은 선택 사항이며 없으면 중간 키만 추가합니다.
- **출력**: EyeOpen 키 `{0, ε, t_mid, 1}`(감은 눈 선 있음) 또는 `{0, t_mid, 1}`. 홍채 마스크인 흰자도 같은 키 집합을 사용해야 합니다. 불투명도 채널: 뜬 눈 그룹 `{0:0, ε:1}`, 감은 눈 선 `{0:1, ε:0}`.
- **알고리즘**:
  1. `1`: 원화.
  2. `ε`(0.05): 위 눈꺼풀 윤곽을 열마다 아래 눈꺼풀 선까지 옮깁니다(눈꺼풀 선만 옮기고 속눈썹 두께 유지). 흰자 높이 ≈ 0. 감은 눈 선 위치를 ε 형태의 눈꺼풀 선과 일치시켜 전환이 보이지 않게 합니다.
  3. `t_mid`(0.3–0.5): 열마다 하강량 = `h(x)·(1 − f(t_mid))`. f는 중간 눈꺼풀이 양 끝보다 10–25% 먼저 처지게 합니다. 위 눈꺼풀 곡선 꼭대기는 여전히 양 끝보다 높게 유지하고(원래 곡선 높이 약 50% 유지), 곡선 길이 파라미터로 뜬 눈 곡선과 감은 눈 선 사이를 보간합니다.
  4. `t_mid`에서 속눈썹과 흰자 가장자리가 교차하지 않고 홍채가 흰자 마스크 밖으로 새지 않는지 확인합니다.
- **조절 파라미터**: `epsSwap` 기본 0.05, 범위 0.03–0.08. `midKey` 기본 0.35, 범위 0.25–0.5. `midSagLead` 기본 0.15, 범위 0.1–0.25. `midArcKeep` 기본 0.5, 범위 0.3–0.7.
- **실패 양상과 확인**: 흰자 마스크 키와 눈꺼풀 키가 다르면 중간 키에서 홍채가 새어 나옵니다. 감은 눈 선과 ε 형태가 일치하지 않으면 선이 튑니다.
- **엔진 기능**: 비균일 다중 키, 불투명도 채널.
- **난이도 / 우선순위**: easy / **P0**.
- **차이점**: 현재는 0/1 두 키뿐이며 감은 눈 선과 개폐가 선형 교차합니다.

### `eye.lid/wide-overrange` 눈 뜨기 범위 초과(놀라서 크게 뜨기)
- **목적**: 개폐 파라미터 하나로 “감음 → 중립 → 크게 뜸” 세 상태를 표현합니다. 크게 뜨면 위 눈꺼풀이 올라가고 아래 눈꺼풀이 내려가며 홍채와 동공은 작아집니다(만화식 놀람). 중립은 여전히 변형 없는 원화입니다.
- **적용 대상**: 눈이 완전히 분리된 레이어와 개폐 추적의 호스트 매핑을 사용하는 대상(VTube Studio 등).
- **출력**: `ParamEyeL/ROpen` 범위를 `[0, 1, Omax]`로 확장, 기본값 1. `Omax` 키 추가(중간 키 `(1+Omax)/2` 선택 가능). 홍채 그룹 바깥에 EyeOpen 축 warp `DeformIrisWide{L,R}`를 씌웁니다. 눈썹도 선택적으로 EyeOpen에 따라 상승합니다(`brow/blink-dip`의 wide-raise 옵션 참고). 호스트 매핑 내보내기: 추적 개폐 0..1 → 파라미터 0..`hostMax`, 평소 눈 뜬 상태가 1이 되도록 합니다.
- **알고리즘**:
  1. `Omax` 키폼: 위 눈꺼풀 행 +0.2 H_e(중심이 최대, cos로 눈꼬리에서 0.3배까지 감쇠), 아래 눈꺼풀 −0.1 H_e. 흰자도 함께 확장합니다.
  2. 홍채 그룹은 중심 기준 0.85배(동공 0.75배). 하이라이트는 축소하지 않도록 크기층 밖에 두거나 같은 비율로 축소합니다.
  3. 아이섀도/눈꺼풀 주름 그림자는 크게 뜨기에 따라 바뀌지 않습니다.
  4. 호스트 매핑: `hostMax = Omax × 중립 추적 보정값`(권장 1.8–2.0). 중립 근처 노이즈로 크게 뜨는 구간을 드나들지 않도록 홍채 축소는 `1 + 0.2·(Omax−1)`에서 시작합니다(데드존).
  5. 호환성: 기존 프로젝트는 `[0,1]`을 유지합니다. 새 템플릿 버전에서만 범위를 확장합니다(파라미터 범위는 조용히 바꾸지 않고 템플릿 버전을 거쳐야 함).
- **조절 파라미터**: `openMax` 기본 2.0, 범위 1.3–2.0. `wideLift` 기본 0.2 H_e, 범위 0.12–0.3. `irisShrink` 기본 0.85, 범위 0.75–0.92. `shrinkDeadzone` 기본 0.2. `hostMax` 기본 1.9, 범위 1.6–2.0.
- **실패 양상과 확인**: 추적 노이즈로 동공이 깜빡거림(데드존으로 대응). `Omax`와 웃는 눈·표정 조합을 각각 확인해야 합니다(`eye.smile/closed-row`의 wide-row 규칙 참고). 표준 모션 파일이 0..1만 제공하면 크게 뜨는 구간에 도달할 수 없습니다(표정 또는 이득으로 구동).
- **엔진 기능**: 파라미터 범위 확장, 호스트 매핑 내보내기.
- **난이도 / 우선순위**: easy(기하) / medium(호환성) / P1.
- **차이점**: EyeOpen은 0..1뿐이며 크게 뜬 상태가 없습니다. 호스트 매핑은 1:1입니다.

### `eye.lid/gaze-follow` 시선에 따른 눈꺼풀 움직임
- **목적**: 위를 보면 위 눈꺼풀이 올라가고 아래를 보면 내려와 홍채를 더 가립니다. 옆을 보면 눈꺼풀 곡선의 최고점이 시선 쪽으로 이동해, 눈알이 안와 안을 미끄러지는 스티커처럼 보이지 않게 합니다.
- **적용 대상**: 눈꺼풀 그룹(위 눈꺼풀 선, 속눈썹, 아래 눈꺼풀, 흰자, 쌍꺼풀 선, 눈 주변 그림자)과 홍채 그룹을 따로 연결할 수 있는 경우.
- **출력**: `DeformEyeShape{L,R}` 안쪽, 눈꺼풀 그룹 바깥에 `DeformEyeLidGaze{L,R}` 삽입(3×3 키, EyeBallX × EyeBallY, lattice ≥ 5×5). 홍채 그룹은 기존 `DeformEyeGaze` 분기에 둡니다. 선택적 `lagged`: 물리(중간 진자 길이, 감쇠 0.9)로 EyeBallX/Y에서 `ParamEyeBallX2/Y2{L,R}`를 파생하고 눈꺼풀 warp의 축으로 사용해 “눈알이 먼저 도착하고 눈꺼풀이 뒤따르는” 효과를 만듭니다.
- **알고리즘**:
  1. 수직: Y+(위 보기)에서 위 눈꺼풀 제어 행은 `kUp·G_y`, 아래 눈꺼풀은 0.2·G_y 올라갑니다. Y−(아래 보기)에서는 위 눈꺼풀이 `kDown·G_y`, 아래 눈꺼풀이 0.25·G_y 내려갑니다.
  2. 수평: 위 눈꺼풀 곡선 꼭대기가 시선 방향으로 `kX·G_x` 이동합니다. 눈 테두리 전체는 `kShift·G_x` 이동하고 시선 쪽 눈꼬리는 살짝 좁아집니다.
  3. 안쪽·바깥쪽 눈꼬리 가중치는 0으로 고정합니다.
  4. 눈을 감으면 결합이 0에 가까워져야 합니다. 눈꺼풀 스택이 눈 감기 warp 바깥이면 `EyeBall × EyeOpen` 조합 키를 사용해 닫힌 끝점에서 30%만 유지하거나, 이 warp를 개폐 warp 안에 넣어 계층 곱으로 자연스럽게 처리합니다.
  5. 25/50/75% 닫힘과 시선 극값 조합을 확인합니다.
- **조절 파라미터**: `kUp` 기본 0.6, 범위 0.4–0.7. `kDown` 기본 0.7, 범위 0.5–0.8. `kX` 기본 0.3, 범위 0.2–0.45. `kShift` 기본 0.15, 범위 0–0.3. `lagged` 기본 false. `closedKeep` 기본 0.3.
- **실패 양상과 확인**: 결합이 지나치면 눈 전체가 얼굴 위에서 미끄러지는 것처럼 보입니다. 눈 영역 warp에 이미 여러 축이 있는데 시선 3×3을 곱하면 키폼이 9배가 됨 → 블렌드 셰이프 또는 독립 warp 층을 사용합니다.
- **엔진 기능**: 중첩 warp, 선택적 물리 파생 파라미터.
- **난이도 / 우선순위**: easy / **P0**.
- **차이점**: 현재 시선은 홍채만 이동하며(`gazePoint`) 눈꺼풀은 시선을 따르지 않습니다.

### `eye.lid/blink-aftershock` 깜빡임 잔진동: 눈꺼풀 오버슈트·반동·속눈썹 흔들림
- **목적**: 눈을 깜빡인 뒤 위 눈꺼풀이 조금 지나쳤다 내려오고, 속눈썹이 가는 털처럼 한 번 튕기게 하여 셔터 같은 움직임 대신 “탄력”을 줍니다.
- **적용 대상**: 위 눈꺼풀 선/속눈썹이 분리된 레이어. 속눈썹 끝을 별도 영역으로 나누거나 눈꺼풀 선과의 거리로 가중할 수 있어야 합니다.
- **출력**(눈마다, 모두 파생 파라미터 + 물리 그룹):
  - `ParamEyeLidOvershoot{L,R}`(−1..1 또는 −1..2): EyeOpen과 2차원 키를 구성하거나 눈 테두리 warp의 블렌드 셰이프로 사용.
  - `ParamEyeLidBounce{L,R}`(±1): 위 눈꺼풀 곡선의 수직 반동.
  - `ParamEyeLash1..3{L,R}`(±1 또는 단방향 0..1 누르기): 속눈썹 구간별 흔들림 블렌드 셰이프.
  - 물리 그룹 `PhysicsEyeLid{L,R}`: 같은 쪽 EyeOpen(X형 100)[+ 눈썹 Y X형 30, 선택적으로 + MouthForm 5] 입력. 속눈썹 그룹 `PhysicsEyeLash{L,R}`: EyeOpen(X형 100)[+ EyeSmile 10].
- **알고리즘**:
  1. 눈꺼풀 오버슈트: 단일 노드의 긴 진자(무겁고 느림). 완전한 깜빡임 1회의 최대값이 최대 범위의 약 0.3이 되도록 출력 scale을 정합니다. 키폼 (open=1, overshoot=+1)에서 위 눈꺼풀이 0.08–0.1 H_e 더 올라가고 아래 눈꺼풀은 조금 내려갑니다. (open=0, overshoot=−1)에서는 눈선을 위로 누릅니다.
  2. 눈꺼풀 반동: 질점 2개. 위 눈꺼풀 곡선을 수직 ±0.25 H_e 움직이며, 가장자리를 따라 코사인 분포(중앙 1, 눈꼬리 0)를 적용합니다. 흰자는 50% 추종하고 아래 눈꺼풀은 움직이지 않습니다.
  3. 속눈썹: 질점 4개, 큰 가속도(“한 번 휘두르기”). 다음 두 방식 중 하나로 세 형태를 구성합니다.
     - 층 방식(`layers`): B1 전체 누르기(단방향, 0.05 H_e), B2 안쪽 눈꼬리를 피벗으로 ±3° 기울기, B3 속눈썹 끝에만 작용하며 눈꺼풀 선과의 거리에 따라 ±5° 회전. B1←v1, B2/B3←v2.
     - 구간 방식(`segments`): 속눈썹 선을 안쪽/중간/바깥 세 구간으로 나누고 각각 “올리기/누르기” 형태(0.08–0.1 H_e)를 둡니다. k구간은 v_k를 읽으며 중간 구간은 반전해 위상을 다르게 합니다.
  4. 감은 눈에서는 잔진동이 보이지 않아야 합니다. 기하층을 눈 감기 warp 안에 두거나 변형 크기를 Open에 따라 감쇠합니다.
  5. 보정: 표준 깜빡임 1회 후 눈에 보이는 진동 ≤ 2회, 0.4–0.8 s 안에 안정. 최대값은 각 요소 크기의 2–4%입니다.
  6. 물리 정규화 중심을 “눈을 뜨고 쉬는 상태”에 둡니다. 그렇지 않으면 휴지 상태에서 지속적인 오프셋이 생깁니다.
- **조절 파라미터**: `overshootAmp` 기본 0.08 H_e, 범위 0.06–0.12. `lidBounceAmp` 기본 0.2 H_e, 범위 0.15–0.3. `lashMode` layers|segments, 기본 segments. `lashAmp` 기본 0.08 H_e 또는 6°, 범위 0.04–0.1 H_e / 4–10°. `browInput` 기본 0, 범위 0–30. 마지막 질점 감쇠 ≥ 0.7.
- **실패 양상과 확인**: 빠른 연속 깜빡임에서 잔진동이 쌓여 줄지 않음(마지막 질점 감쇠 하한, 출력 크기 제한). 깜빡임 추적 신호 노이즈로 지속 미세 떨림(EyeOpen 입력 0.05 데드존 또는 오버슈트 체인 d ≥ 0.85). 매우 빠른 깜빡임(< 80 ms)에서 오버슈트가 커짐. 웃는 눈과 결합할 때 오버슈트 방향도 바뀌어야 함(Smile=1을 2차원 키로 처리). 속눈썹 형태가 눈꺼풀 마스크 밖으로 나와 삐죽거림. 앞머리를 투과하는 복사본에도 같은 블렌드 셰이프를 상속해야 합니다(기존 복사본은 이미 공유).
- **엔진 기능**: 물리 다중 출력(v_k, reflect), 블렌드 셰이프, 2차원 키폼.
- **난이도 / 우선순위**: medium / P1(`eye.iris/jelly-layered`와 함께 구현하고 “깜빡임 자극” 물리 도구 공유).
- **차이점**: 기존 `PhysicsEyeJelly`는 `ParamEyeBallForm`만 출력하며 눈꺼풀 오버슈트·반동·속눈썹 관성이 없습니다.

### `eye.lid/overlay-early-fade` 눈꺼풀 덮개층을 미리 페이드아웃
- **목적**: 아이섀도, 눈꺼풀 가장자리 그림자, 가산/스크린 반사층을 눈이 닫히기 전에 아래로 가라앉히며 없애 닫힌 선에 색 덩어리나 밝은 점이 남지 않게 합니다.
- **적용 대상**: 위 눈꺼풀에 붙어 흰자로 클리핑되는 얇은 층, 눈 안의 모든 Additive/Screen 층, 아이섀도층.
- **출력**: 해당 층의 불투명도 채널과 선택적 그리기 순서 키에 EyeOpen 축 사용.
- **알고리즘**:
  - 눈꺼풀 가장자리 그림자/반사광: EyeOpen에 중간 키 t₀ 추가. [0, t₀]에서 불투명도 0, 그리기 순서를 흰자 아래로 내립니다. [t₀, 1]에서는 원래 값으로 선형 복귀합니다.
  - Additive/Screen 반사광: 불투명도 = 원래 값 × EyeOpen(선형, 0에서 0).
  - 아이섀도: 눈을 감을 때 약 55% 유지(절반 정도만 사라짐).
- **조절 파라미터**: `fadeStart` 기본 0.25, 범위 0.2–0.3. `eyeshadowClosed` 기본 0.55, 범위 0.4–1.
- **실패 양상과 확인**: “위 눈꺼풀에 붙은” 층을 식별하려면 표시 또는 위치 기준(중심이 흰자 위쪽 1/3에 있고 흰자로 클리핑됨)이 필요합니다.
- **엔진 기능**: 불투명도 채널, 그리기 순서 키폼(지원하지 않으면 불투명도만 적용).
- **난이도 / 우선순위**: easy / **P0**.
- **차이점**: 눈 안 덮개층이 개폐에 따라 사라지는 처리가 통합되어 있지 않습니다.

## 9. eye.smile — 웃는 눈

### `eye.smile/current` 독립적인 웃는 눈 없음(기존)
- **현황**: “웃는 눈/가늘게 뜬 눈” 별칭을 `EYE_CLOSE`에 합쳐 감은 눈 선의 불투명도로만 표시합니다. `ParamEyeL/RSmile`과 웃는 눈 변형이 없습니다.
- **난이도 / 우선순위**: — / P0 등록.

### `eye.smile/closed-row` 웃는 눈이 닫힘 경로만 변경
- **목적**: 반쯤 감거나 완전히 감을 때만 아래 눈꺼풀을 올리고 감은 눈 선을 ^ 형태로 만듭니다. 눈을 뜬 상태는 전혀 바꾸지 않아 추적된 웃음 값이 계속 흔들려도 뜬 눈이 뒤틀리지 않으며, “웃으면서 깜빡이면 ^^”가 됩니다.
- **적용 대상**: 표준 눈 레이어 분리. 새 파라미터 `ParamEyeL/RSmile`(0..1, 기본 0, Cubism 표준 이름).
- **출력**: 눈 메시/눈꺼풀 warp의 키 격자를 `EyeOpen{0, t_mid, 1[, Omax]} × EyeSmile{0, 1}`로 확장합니다. 눈 주변 장식(눈물점, 화장점, 눈밑 장식)도 같은 격자에 바인딩합니다. 표정·추적 매핑: MouthSmile 0.3–0.5부터 EyeSmile에 매핑합니다.
- **알고리즘**:
  1. (Open=1, Smile=1) ≡ (Open=1, Smile=0)을 강제합니다.
  2. (0, 1)의 웃는 눈 닫힘 선: `y(x) = y_c(x) − k·(1 − (2x'/W_e)²)`, k = 0.3 H_e(중앙이 위로 솟음), 눈꼬리는 0.05 H_e 내려갑니다. 아래 눈꺼풀은 0.1 H_e 밀어 올립니다(광대 근육). 일반 닫힘 (0, 0)은 기존의 아래로 처진 곡선을 유지합니다.
  3. (t_mid, 1): 아래 눈꺼풀을 0.3 H_e 올리고 위 눈꺼풀 곡선을 살짝 누릅니다.
  4. 크게 뜬 행(`wide-overrange` 활성화 시): (Omax, 1) = (1,0) + 0.3 × [(Omax,0) − (1,0)]. “웃으면서 공포에 질린” 모습을 피합니다.
  5. 눈 주변 장식은 아래 눈꺼풀과의 거리에 따라 감쇠하며 추종합니다.
  6. (0.5, 0.5), (0.25, 1) 등의 조합에서 위·아래 눈꺼풀 선이 교차하지 않는지 확인합니다.
- **조절 파라미터**: `smileArc` 기본 0.3 H_e, 범위 0.2–0.4. `smileLowerPush` 기본 0.1 H_e, 범위 0.05–0.3. `wideKeep` 기본 0.3, 범위 0.2–0.5. `hostSmileStart` 기본 0.4, 범위 0.3–0.5.
- **실패 양상과 확인**: `eye.smile/mouthform-coupled`와 함께 켜면 중복 계산됩니다(하나만 선택하거나 max 적용). 웃는 눈 닫힘 선과 일반 감은 눈 선의 차이가 너무 작으면 표현이 드러나지 않습니다.
- **엔진 기능**: 2차원 키폼.
- **난이도 / 우선순위**: easy / **P0**(새 파라미터이므로 기존 프로젝트에 영향 없음).
- **차이점**: 표준 파라미터에 EyeSmile이 없습니다.

### `eye.smile/mouthform-coupled` 입 형태를 눈의 두 번째 축으로 사용
- **목적**: 여러 추적 방식에서 제공하지 않는 EyeSmile 입력 없이도 입꼬리가 웃으면 눈도 웃게 합니다. MouthForm 음수 쪽은 불만/억울함을 표현합니다.
- **적용 대상**: EyeSmile 추적이 없는 대상. MouthForm이 주로 립싱크가 아닌 추적으로 구동되는 경우.
- **출력**: 눈의 각 디포머(눈 테두리, 속눈썹, 흰자, 홍채, 눈물, 홍조)의 EyeOpen 축을 `EyeOpen × MouthForm{-1, 0, d, 1}`로 확장합니다(d = 데드존 키). 눈썹의 눈 감기 연동층에도 MouthForm 축을 추가합니다.
- **알고리즘**:
  1. MouthForm = +1: 아래 눈꺼풀을 입꼬리 이동 거리의 0.4배(약 0.15–0.25 H_e) 올리고 바깥 눈꼬리를 살짝 올립니다. EyeOpen = 0이면 감은 눈 선이 위로 휜 웃는 눈 곡선이 됩니다. 홍채는 아래 눈꺼풀에 조금 가려집니다.
  2. MouthForm = −1: 아래 눈꺼풀은 조금 내리고 위 눈꺼풀은 조금 누릅니다.
  3. 눈썹: +1에서 전체를 입꼬리 이동 거리의 0.2배만큼 올리고 펼칩니다.
  4. 데드존: MouthForm 축에 d = 0.3 중간 키를 추가하여 0–0.3 구간의 눈 변화는 매우 작게 합니다(말할 때 MouthForm이 흔들릴 수 있음).
- **조절 파라미터**: `couple` 기본 0.4, 범위 0.2–0.5. `positiveOnly` 기본 true. `deadzone` 기본 0.3, 범위 0–0.4.
- **실패 양상과 확인**: 립싱크가 MouthForm을 구동하는 앱에서는 말할 때 눈이 함께 요동합니다(데드존 또는 물리 평활화로 대응, `brow/emotion-fanout` 참고).
- **엔진 기능**: 2차원 키폼.
- **난이도 / 우선순위**: medium / P1.

## 10. eye.emotion — 눈의 감정 형태와 표정 요소

### `eye.emotion/current` 없음(기존)
- **현황**: 표정은 파라미터 오프셋 집합(`ModelSidecars`)일 뿐이며 눈 감정 형태, 교체 동공, 눈물, 그림자층을 생성하지 않습니다.
- **난이도 / 우선순위**: — / P0 등록.

### `eye.emotion/additive-shapes` 중첩 가능한 눈 감정 형태
- **목적**: 놀람(크게 뜨기 + 동공 축소), 위 눈꺼풀 처짐(졸림/깔봄), 아래 눈꺼풀 상승(가늘게 뜸)을 가산층으로 만들어, 어떤 조합에서도 키폼 차원을 더 늘리지 않게 합니다.
- **적용 대상**: 표준 눈 레이어 분리, 블렌드 셰이프를 지원하는 대상. 지원하지 않으면 추가 축으로 베이크하되 단일 형태 × 개폐만 베이크합니다.
- **출력**: 눈마다 블렌드 셰이프 파라미터(0..1) `ParamEyeWide{L,R}`, `ParamEyeLidDroop{L,R}`, `ParamEyeSquint{L,R}`. 눈꺼풀 그룹 메시/warp와 홍채 그룹 warp에 적용합니다.
- **알고리즘**:
  - Wide: 위 눈꺼풀 +0.15 H_e, 아래 눈꺼풀 −0.05 H_e, 홍채 그룹을 중심 기준 0.85배로 축소.
  - LidDroop: 위 눈꺼풀 −0.23 H_e(곡선 유지).
  - Squint: 아래 눈꺼풀 +0.15 H_e 및 평평하게 만들기.
  - 조합 확인: 가산층 공간의 각 꼭짓점에서 평가합니다. 위 눈꺼풀 선은 항상 아래 눈꺼풀 선보다 위에 있어야 합니다. 교차하면 비례 축소하거나 조합 보정 키 하나를 추가합니다.
  - 개폐와 곱해질 때의 수렴: 각 형태를 EyeOpen 키마다 따로 계산해 완전 닫힘에서 같은 선으로 수렴시킵니다(`eye.emotion/expression-blink-matrix`와 같은 규칙).
- **조절 파라미터**: `wideLift` 기본 0.15 H_e, 범위 0.1–0.2. `wideIris` 기본 0.85, 범위 0.8–0.9. `droop` 기본 0.23 H_e, 범위 0.2–0.3. `squint` 기본 0.15 H_e, 범위 0.1–0.2.
- **실패 양상과 확인**: Wide와 `eye.lid/wide-overrange`가 겹칩니다. “놀라서 크게 뜨기”의 주 구현은 하나만 선택합니다(추적 지향은 overrange, 표정 지향은 additive).
- **엔진 기능**: 블렌드 셰이프, 베이크 하위 호환.
- **난이도 / 우선순위**: medium / P1.

### `eye.emotion/tension-axis` 양극 긴장 축
- **목적**: 중앙이 중립인 파라미터 하나로 “가늘게 뜨기”(의심, 의기양양, 졸림)와 “부릅뜨기”(놀람)를 함께 표현합니다. 개폐와 2차원 눈꺼풀 공간을 이루어 표정 중에도 깜빡일 수 있습니다.
- **적용 대상**: 모션/표정 구동이 중심인 모델(게임 일러스트, 짧은 극).
- **출력**: 파라미터 `ParamEyeTension{L,R}`(0..1, 기본 0.5). 눈 메시 키 `Tension{0, 0.5, 1} × EyeOpen{0, 1}`(6개 꼭짓점 모두 키 생성).
- **알고리즘**: Tension = 1: 위 눈꺼풀 중앙 +0.15 H_e, 곡률 +20%, 아래 눈꺼풀 −0.05 H_e. Tension = 0: 위 눈꺼풀 −0.2 H_e, 곡률을 평평하게 하고 안쪽 눈꼬리를 조금 내리며 아래 눈꺼풀 +0.05 H_e. 닫힌 눈 행에서는 세 긴장 값마다 다른 곡률의 감은 눈 선을 사용합니다. 홍채·속눈썹 메시도 추종합니다.
- **조절 파라미터**: `wide` 기본 +0.15 H_e, 범위 0.1–0.2. `narrow` 기본 −0.2 H_e, 범위 0.15–0.25. `curvatureDelta` 기본 0.2.
- **실패 양상과 확인**: `additive-shapes`의 Wide/Squint와 중복되므로 하나만 선택합니다.
- **엔진 기능**: 2차원 키폼.
- **난이도 / 우선순위**: medium / P2.

### `eye.emotion/expression-blink-matrix` 표정 눈 형태 × 깜빡임
- **목적**: 표정으로 눈 모양이 바뀐 뒤(성난 눈, 눈물 눈, 반쯤 뜬 눈)에도 깜빡일 수 있고, 감은 형태가 해당 표정의 눈 모양과 맞도록 합니다.
- **적용 대상**: 차분 레이어 또는 `additive-shapes`에서 제공하는 표정 눈 형태가 있는 경우.
- **출력**: 내부에서는 각 표정을 가산 형태 Δ_E로 표현하고 EyeOpen 키마다 따로 계산합니다. 블렌드 셰이프를 지원하지 않는 대상으로 내보낼 때는 “깜빡임 × 단일 표정”만 베이크하고 표정 × 표정은 베이크하지 않습니다. 감은 눈 선 그룹 불투명도 = `(EyeOpen < ε) × (기호 눈/웃는 눈 표정이 없음)`.
- **알고리즘**: 표정 눈 형태 B_E를 기준으로, B_E의 위 눈꺼풀을 자체 곡선을 따라 아래 눈꺼풀 선까지 눌러 깜빡임을 만듭니다. 완전히 닫히면 모든 Δ_E가 같은 선으로 수렴해야 합니다.
- **조절 파라미터**: `bakeLimit`(메시당 키폼 상한) 기본 64, 범위 32–128.
- **실패 양상과 확인**: 데카르트 곱 베이크 폭증(표정 × 표정 × 깜빡임). 완전 닫힘에서 가산 조합이 수렴하지 않으면 감은 눈 선이 두 줄로 나타납니다.
- **엔진 기능**: 블렌드 셰이프, 내보내기 베이크 전략.
- **난이도 / 우선순위**: medium / P2.

### `eye.emotion/replacement-pupil` 교체 동공과 눈 안 기호
- **목적**: 별 눈, 하트 눈, 소용돌이 눈, 무늬 동공, 텅 빈 눈, 어두운 동공 등을 홍채 체인 가장 안쪽에 연결해 시선, 고개 회전 시차, 감을 때 압축, 눈 젤리 효과, 놀람 동공 축소를 자동 상속합니다. 변형 하나라도 켜지면 기존 하이라이트는 사라집니다.
- **적용 대상**: 홍채 크기에 맞게 배치한 교체 동공 소재(원화 차분 또는 소재 라이브러리), 흰자 마스크.
- **출력**: 변형마다 스위치 파라미터 하나(0..1, 불투명도 선형 0→1). 변형 레이어를 `eye.iris/jelly-layered`의 가장 안쪽 warp 또는 `DeformEyeGaze` 아래에 연결하고 흰자로 마스킹하며 보통 가산 블렌딩을 사용합니다. 충돌하는 원본 레이어(하이라이트, 동공 텍스처)는 `eye.highlight/gate`로 제어합니다. 선택적 작은 물리: 스위치 자체(X형 40–50), 같은 쪽 EyeOpen(40–100), 호흡(40–50) → 변형 warp의 크기 ±10–15%, 회전 ±15°, 처짐 블렌드 셰이프. 회전 기호(소용돌이)는 회전 디포머 + 순환 파라미터(0 → 0°, max → N·360°)를 사용합니다.
- **알고리즘**:
  1. 상대 소재 크기: 하트는 홍채 지름의 0.6, 별빛 0.5, 소용돌이는 0.9 R_i를 채웁니다.
  2. 하이라이트와 같은 층에 삽입하고 같은 2차원 젤리 키를 공유합니다.
  3. 텅 빈 눈 = 홍채 그룹 전체 페이드아웃. 어두운 동공 = 홍채를 곱하기 블렌딩으로 어둡게 하거나 교체.
- **조절 파라미터**: `variantScale`은 홍채와 동일. `suppressHighlight` 기본 true. `variantPhysics` 기본 false.
- **실패 양상과 확인**: 일반 하이라이트와 겹쳐 과노출됨(게이트 사용). 변형이 홍채 체인 안에 없으면 시선/깜빡임 시 위치가 어긋납니다.
- **엔진 기능**: 마스크, 가산 블렌딩, 불투명도 채널, 곱셈 게이트, 선택적 물리와 회전 순환 파라미터.
- **난이도 / 우선순위**: easy(바인딩) / hard(소재) / P1.

### `eye.emotion/symbol-mode` 만화 기호 눈 모드
- **목적**: ○ 눈, >< 눈, ^^ 등의 기호 표정은 그림체 전환입니다. 사실적인 눈 전체는 사라지고 기호 눈이 나타나며 눈썹·홍조도 바꾸고 사실적인 작은 특징은 숨깁니다.
- **적용 대상**: 기호층 소재, 사실층/기호층 표시(흰자, 속눈썹, 홍채, 하이라이트, 코, 눈밑 그림자 대 ○, ><, 땀, 검은 선).
- **출력**: 기호 표정 파라미터 E(0..1). 사실층 그룹 불투명도 1−E(그룹 수준 warp 불투명도), 기호층 E. 기호층 세부를 기호 본체 그룹 아래에 연결해 E²로 나타나게 합니다. 기호 그룹은 각 눈의 AngleX warp 아래에 두되 시선 warp에는 연결하지 않습니다. 기호층에도 EyeOpen 키를 두어 깜빡일 수 있게 합니다.
- **알고리즘**:
  1. 특징별 전환 방식 분류(`toggle` 슬롯에서 구현). 맞춰 겹칠 수 있는 단단한 선(^^, 감은 눈 선, 성난 눈썹)은 먼저 일치하도록 변형하고 마지막 1%에서 전환합니다. 입 모양은 먼저 전환한 뒤 변형합니다. 부드러운 가장자리 덮개층은 선형 교차하며, 정합할 수 없는 기호도 선형 교차하되 [0.3, 0.7]로 구간을 압축합니다.
  2. 기호 표정에서는 사실적 연동을 끕니다(감은 눈 선 숨김, 시선이 기호에 영향을 주지 않음).
  3. 진입 시 교체 요소는 0.6–0.85 축소 상태 또는 이동된 위치에서 펼쳐져 제자리로 옵니다(기하 키와 불투명도 동기화).
- **조절 파라미터**: `crossBand` 기본 [0.3, 0.7]. `detailExp` 기본 2. `enterScale` 기본 0.75, 범위 0.6–0.85. `hiddenRealFeatures` 목록.
- **실패 양상과 확인**: 선형 교차의 0.5에서 두 세트가 반투명으로 겹쳐 지저분해질 수 있습니다. 기호층은 흰자로 클리핑하면 안 됩니다. 교체 요소가 개폐 키를 상속하지 않으면 깜빡일 때 어색함이 드러납니다.
- **엔진 기능**: 그룹 수준 불투명도, 중첩 페이드인.
- **난이도 / 우선순위**: medium(구성) / hard(소재) / P2.

### `eye.emotion/tears` 눈물막과 눈물방울
- **목적**: 눈물막은 눈알 위 물빛으로, 눈 형태에 클리핑되고 개폐에 따라 변형됩니다. 눈물방울은 아래 눈꺼풀 가장자리에 걸쳐 있으며 눈 밖으로 넘칠 수 있고, 아래 눈꺼풀의 미세 움직임을 따르며 자체 시차가 있습니다.
- **적용 대상**: 눈물 소재 또는 생성된 소재, 흰자, 아래 눈꺼풀 선.
- **출력**: 스위치 파라미터 `ParamTear{L,R}`(0..1). 눈물막은 흰자 형태 메시 복사본이며 흰자 마스크, 흰자와 같은 EyeOpen 키, 스위치에 따른 불투명도를 사용합니다. 눈물방울은 아래 눈꺼풀 선 바깥쪽 0.7 지점에 고정하고 `EyeOpen{0, t_mid, 1}` warp → 독립 AngleX/AngleY warp 아래에 연결하며 클리핑하지 않습니다. 선택적 물리(EyeOpen + 스위치 + 호흡)로 눈물빛을 흔듭니다.
- **알고리즘**: 눈물방울 변위 = 앵커에서 아래 눈꺼풀 선 변위 × 0.9. 눈물빛이 나타날 때 추가로 0.2–0.3 H_e 아래로 이동합니다. 눈물방울 시차 계수는 하이라이트와 같습니다.
- **조절 파라미터**: `anchor` 기본 0.7, 범위 0.6–0.8. `lidFollow` 기본 0.9, 범위 0.8–1.0. `tearSlide` 기본 0.25 H_e.
- **실패 양상과 확인**: 깜빡임 입력 가중치가 너무 크면 눈물빛이 눈꺼풀 밖으로 드러납니다(마스크에 의존).
- **엔진 기능**: 마스크, 불투명도 채널, 선택적 물리.
- **난이도 / 우선순위**: easy(바인딩) / P2.

### `eye.emotion/gloom` 침울한 얼굴: “커튼” 그림자 + 하이라이트 제거 + 눈 누르기
- **목적**: “어두운 얼굴/침울함”을 여러 단서로 구성합니다. 얼굴 위쪽 그림자가 이마에서 커튼처럼 내려오고, 눈 하이라이트가 사라지며, 위 눈꺼풀이 내려오고 눈썹이 바뀝니다. 파라미터 하나로 모두 제어합니다.
- **적용 대상**: FACE 레이어, 분리된 하이라이트. 보조 텍스처(세로 그라데이션, 선택적 세로 선)를 생성하거나 원화에 그림자층이 있어야 합니다.
- **출력**: 파라미터 `ParamGloom`(0..1). 층 A: 세로 그라데이션 곱하기(위쪽은 어둡고 아래쪽은 투명. 피부색에 따라 짙은 보라/청보라 색상 사용, 순수 회색은 피함). 얼굴 피부와 앞머리로 마스킹하며 얼굴 보정 warp 체인 내부, 이목구비 위, 앞머리 아래에 둡니다. 층 B(선택): 눈 영역 곱하기, 흰자/눈꺼풀로 마스킹하고 P > 0이면 눈 위로 그리기 순서를 올립니다. 선택적 세로 선층, 하이라이트 게이트(`eye.highlight/gate`), 눈 테두리 warp의 위 눈꺼풀 누르기를 추가합니다.
- **알고리즘**:
  1. 0키: A를 얼굴 위에 배치(1–1.2 H_f 이동, 마스크 바깥에 완전히 위치), 불투명도 0. 1키: A가 눈 아래 가장자리까지 덮고 불투명도 0.6–0.7.
  2. 하이라이트 불투명도는 P의 0–0.6 구간에서 0까지 낮춥니다.
  3. 위 눈꺼풀을 0.05–0.08 H_e 누릅니다. 눈썹은 `brow/shape-axes`의 성난 형태를 약하게 적용합니다.
- **조절 파라미터**: `slide` 기본 1.0 H_f, 범위 0.8–1.2. `maxOpacity` 기본 0.65, 범위 0.5–0.8. `lidPress` 기본 0.06 H_e. `tint`는 피부색에 맞춤.
- **실패 양상과 확인**: 마스크가 얼굴 전체가 아니면 이동 중 가장자리가 드러납니다. 반투명 앞머리 사이로 그림자가 비쳐 지저분해질 수 있으므로 앞머리 아래에 둡니다.
- **엔진 기능**: 보조 텍스처 생성 훅, 마스크, 곱하기 블렌딩, 불투명도·변위 키폼, 곱셈 게이트.
- **난이도 / 우선순위**: easy(바인딩) / medium(텍스처 훅) / P2(`lighting`, `effect`와 협력).

### `eye.emotion/shock-tremor` 상시 진동기 × 표정 게이트
- **목적**: 놀랄 때 동공을 고주파로 떨리게 합니다. 표정은 정적 값만 줄 수 있으므로 “항상 실행되는 진동기 × 게이트 파라미터”의 2차원 키로 정적 스위치를 애니메이션으로 바꿉니다.
- **적용 대상**: 반복 대기 모션이 있는 내보내기 대상.
- **출력**: 진동 파라미터 `ParamTremor`(±1), 게이트 파라미터 `ParamShockGate`(0..1). 홍채 그룹 warp에 `Gate{0,1} × Tremor{-1,0,1}` 키를 생성합니다. Gate = 0에서 세 Tremor 키는 동일합니다. 모든 반복 대기 모션에 Tremor 트랙 추가(무작위 전신 신호처럼 60–120 ms마다 ±A 전환, 무작위 0 삽입, 반복 ≥ 15 s). 표정 파일은 Gate만 작성합니다.
- **조절 파라미터**: `tremorAmp` 기본 0.1 H_e, 범위 0.05–0.12. `switchMs` 기본 90, 범위 60–120.
- **실패 양상과 확인**: 대기 모션이 교체되면 진동이 사라집니다. 같은 진동기를 땀방울 떨림, 분노 기호 움직임, 몸 떨림에 재사용할 수 있습니다.
- **엔진 기능**: 곱셈 게이트(2차원 키폼), 모션 트랙.
- **난이도 / 우선순위**: easy / P2(`motion.idle`과 협력).

## 11. eye.iris — 홍채, 동공, 시선

### `eye.iris/current` 동공 유지 + 시선 평행 이동 + 홍채 젤리(기존)
- **목적**: 고개를 돌릴 때 홍채가 `featureOffset IRIS`에 따라 반대 방향으로 이동하고 너비를 보정합니다. 시선은 평행 이동만 적용하고 깜빡임 물리로 홍채를 질량중심 기준 확대·축소합니다.
- **적용 대상**: IRIDES(하이라이트와 홍채가 같은 태그).
- **출력**: `DeformIrisPreserve{L,R}`(3×3, 아홉 포즈) → `DeformEyeGaze{L,R}`(2×2, EyeBallX/Y, `gazePoint` 평행 이동만 적용). 홍채 메시 키폼 `irisJellyGrid`(`ParamEyeBallForm{-1,0,1}`). 물리 `PhysicsEyeJelly`: EyeL/ROpen(X형 50) → `ParamEyeBallForm`(양 눈이 출력 하나 공유). 마스크 = 같은 쪽 흰자.
- **실패 양상과 확인**: 하이라이트와 홍채가 함께 움직이며, 양 눈이 젤리 출력 하나를 공유하고, 형태/위치 원근 층이 분리되어 있지 않습니다.
- **난이도 / 우선순위**: 구현됨 / P0 등록.

### `eye.iris/perspective-split` 형태 원근과 위치 원근을 나누고 시선을 사이에 배치
- **목적**: 고개를 돌린 뒤 옆을 봐도 홍채가 회전한 안와를 따라 이동하게 합니다. 홍채 형태의 원근 압축(좁은 타원으로 변함)은 시선 위치와 독립적입니다.
- **적용 대상**: 홍채 그룹을 독립적으로 연결할 수 있는 경우.
- **출력**(바깥 → 안쪽): 위치 원근층(AngleX×AngleY, 흰자 warp와 같은 원근, 현재 `DeformIrisPreserve`) → 시선 이동층(EyeBallX×Y) → 개폐층(선택, `eye.iris/close-squash`) → 형태 원근층 `DeformIrisShape{L,R}`(AngleX×AngleY, `cos(yaw)`의 가로 압축과 먼 쪽 기울임만 수행하고 위치 이동은 하지 않음) → 젤리층(`jelly-layered`) → 메시.
- **알고리즘**: 시선 이동 거리는 흰자 너비의 15–20%. Y는 X보다 약간 크게 할 수 있습니다(세로로 긴 애니메이션 눈은 1.2–2배). 형태층 압축 계수 k: `cos(θ·k)`, k는 0.7–0.8. 모든 층은 흰자 마스크 아래에 둡니다.
- **조절 파라미터**: `gazeRangeX` 기본 0.18 W_e, 범위 0.13–0.25. `gazeYRatio` 기본 1.2, 범위 1–2. `shapeCompressK` 기본 0.75, 범위 0.6–0.85.
- **실패 양상과 확인**: 안팎 두 층에 압축이 중복 적용되지 않도록 합니다(안쪽은 형태만, 위치 이동 없음).
- **엔진 기능**: 중첩 warp.
- **난이도 / 우선순위**: medium / P1.

### `eye.iris/depth-parallax` 눈 안의 깊이별 시차
- **목적**: 홍채는 구면에 붙고 동공·하이라이트는 서로 다른 깊이에 둡니다. 고개를 돌리면 셋의 이동·압축이 달라져 “렌즈/유리체” 같은 깊이감을 만듭니다.
- **적용 대상**: 눈 안이 최소 {홍채 바탕, 동공, 하이라이트}로 나뉜 경우. 더 세밀하게는 {눈동자 선, 눈동자 채색, 홍채 색, 동공, 동공 장식, 하이라이트, 반사}로 나눌 수 있습니다.
- **출력**: 시선층 아래에 깊이 그룹별 AngleX[×AngleY] warp `DeformIrisDepth<k>{L,R}` 생성(축당 3키, 5×5 lattice).
- **알고리즘**:
  1. 깊이 d_r(0..1): 눈동자 선 0, 채색 0.2, 홍채 색 0.4, 동공 0.6, 하이라이트 0.9, 반사 1.0.
  2. 끝점 키폼에서 부모에 대해 `δ_r = s·(d_r − 0.5)·W_iris·sign(AngleX)`만큼 추가 이동하고, 회전에 따라 `cos(θ·k)`로 압축합니다.
  3. 동공: 홍채 변위보다 10–20% 더 이동합니다(더 깊음).
  4. 방향 부호 설정: `deeperLags`(깊은 층이 표면보다 뒤처짐, 혀/동공 모델) 또는 `frontLeads`(각막이 앞에 있어 하이라이트가 더 이동). 하이라이트 방향은 `eye.highlight/parallax-layer`에서 별도로 정합니다.
  5. 모든 층은 흰자 마스크 안에 두고 이동 후 경계를 벗어나지 않는지 확인합니다.
- **조절 파라미터**: `parallaxMax` 기본 0.08 W_iris, 범위 0.05–0.12. `pupilExtra` 기본 0.15, 범위 0.1–0.2. `depthSign` 기본 deeperLags. 눈이 작은 SD 스타일에서는 끌 수 있습니다.
- **실패 양상과 확인**: 시차가 너무 크면 눈꼬리에서 흰자에 잘립니다.
- **엔진 기능**: 중첩 warp.
- **난이도 / 우선순위**: medium / P1.
- **차이점**: 기존 홍채와 눈꺼풀은 같은 얼굴 변형을 공유하며 깊이에 따른 독립 시차가 없습니다.

### `eye.iris/jelly-layered` 깜빡임이 자극하는 층별 젤리 물리(`PhysicsEyeJelly` 확장)
- **목적**: 깜빡임과 웃는 눈·눈썹 움직임을 충격 입력으로 사용해 눈 테두리, 홍채, 동공, 각 하이라이트가 서로 다른 주파수·위상으로 반동하게 합니다. 눈 전체가 함께 떨리는 대신 수분과 탄력이 있는 눈알처럼 보이게 하며 추적 채널을 차지하지 않습니다.
- **적용 대상**: 눈 내부 레이어 분리(최소 홍채 그룹과 하이라이트 분리), 좌우 눈에 각각 한 세트.
- **출력**(눈마다):
  - 파생 파라미터: `ParamEyeJellyX/Y{L,R}`(홍채 그룹 2차원), `ParamEyePupilPulse{L,R}`(동공 크기), `ParamEyeGlint1..k{L,R}`(각 하이라이트 또는 X/Y 2차원), 선택적 `ParamEyeFrameJelly{L,R}`(눈 테두리 전체의 작은 강체 이동).
  - 디포머: 시선 warp 아래, 홍채 그룹 위에 `DeformEyeJelly{L,R}` 삽입(5×5, JellyX × JellyY). 하이라이트마다 warp 한 층을 둡니다. 눈 테두리 젤리 warp는 눈 전체를 감싸되 강체 이동 + 2–3° 회전만 적용하며 감은 눈의 위·아래 눈선을 벌리지 않습니다.
  - “무게별 층” 물리: 느린 체인(홍채, 질점 3–4개, 인접 v1/v2 출력 중 하나를 반전해 2차원 warp 두 축으로 연결, 타원/리사주 궤적 생성), 중간 체인(동공, 질점 3개, 조금 큰 가속도), 빠른 체인(하이라이트, 질점 2개, 가장 짧고 가볍고 감쇠가 낮음). X/Y 체인 길이 비율은 1:1.5–1:2(정수배를 피하여 같은 위상 방지).
  - 입력: 같은 쪽 EyeOpen(X형 50–100)[+ EyeSmile 15–25][+ 눈썹 Y 20–35. 동공 체인은 눈썹 Angle형 100으로 바꾸어 지속적인 감정 매핑 가능][+ 호흡 30–50은 하이라이트 체인에만 입력하여 정지 중에도 반짝임].
- **알고리즘**(크기는 H_e 단위, 파라미터 ±1 최대값 기준. 실제 물리 출력은 최대값의 20–40%):
  - 홍채 JellyX: 수평 0.08 W_e 이동 및 3% 가로 압축/전단. JellyY: 수직 0.1 H_e 이동 및 아래 가장자리를 앵커로 세로 크기 ±8%.
  - 동공: 동공 중심 기준 크기 ±15%.
  - 하이라이트 i: 0.05–0.25 H_e 이동. 하이라이트 면적으로 정렬해 선형 배분합니다(작고 밝고 안쪽 층일수록 진폭이 큼). 인접 하이라이트 방향 차이는 ≥ 45°. 홍채 타원으로 이동을 제한합니다(`eye.highlight/blink-wobble`의 부드러운 제한 참고).
  - 깊이에 따라 진폭 증가: `A_r = A_0·(1 + 3.5·d_r)`.
  - 눈을 감으면 젤리 변형을 Open에 따라 감쇠하거나 계층 곱에 맡깁니다.
  - 보정: 0.15 s 깜빡임 1회 후 홍채 최대값 ≤ 0.1 H_e, 하이라이트 ≤ 0.3 R_i. 1 s 이내에 10% 미만으로 감쇠합니다. “눈이 완전히 정지한” 프레임은 물리가 수렴한 상태를 사용해야 합니다.
- **조절 파라미터**: `irisAmp` 기본 0.1 H_e, 범위 0.05–0.2. `pupilPulse` 기본 0.15, 범위 0.1–0.2. `glintAmp` 기본 0.2 H_e, 범위 0.1–0.35. `frameJelly` 기본 0(끔), 범위 0–0.13 H_e. `chainRatioXY` 기본 1.5. `inputs.smile` 기본 0. `inputs.brow` 기본 0. `inputs.breathGlint` 기본 0. `stereoJitter`(좌우 결정적 미세 조정) 기본 0.05.
- **실패 양상과 확인**: 출력이 크면 “경련”처럼 보입니다. 반쯤 뜬 상태의 추적 노이즈로 눈이 계속 흔들림(EyeOpen 0.05 데드존 또는 깜빡임 속도로 구동). 홍채 체인의 delay가 높으면 끌리는 느낌. 작은 SD 눈도 반드시 H_e 기준으로 계산해야 합니다. 좌우 파라미터는 대칭 일관성이 필요합니다. 하이라이트는 반드시 흰자로 클리핑합니다. 눈썹 입력 노이즈가 크면 추적 쪽에서 평활화합니다.
- **엔진 기능**: 여러 물리 체인, 다중 출력 v_k, reflect, 2차원 warp, 선택적 블렌드 셰이프.
- **난이도 / 우선순위**: medium / **P0**(정교한 애니메이션풍 모델에서 흔히 쓰는 “생동감” 기법. 기존 `PhysicsEyeJelly`에서 “홍채 2차원 + 하이라이트 독립”을 먼저 구현하고 동공·눈 테두리를 추가하는 순서로 확장 가능).
- **차이점**: `PhysicsEyeJelly`는 양 눈이 단일 출력 `ParamEyeBallForm`을 공유하며 홍채 크기만 바꿉니다. 요소별·주파수별 분리, 하이라이트·동공·눈썹/웃음 입력이 없습니다.

### `eye.iris/pupil-scale` 독립 동공/홍채 크기층
- **목적**: 동공 크기는 강한 감정 신호입니다(놀람은 축소, 호감은 확대). 독립 층으로 만들어 교체 동공을 포함한 모든 동공 텍스처에 함께 적용하고, 여러 표정이 다른 강도로 재사용하며 개폐·시선 키폼에 곱해지지 않게 합니다.
- **적용 대상**: 홍채 그룹.
- **출력**: 파라미터 `ParamPupilScale{L,R}`(−1..1, 기본 0, 좌우 공통 `ParamPupilScale`도 가능). 시선층 안쪽, 형태 원근층 바깥에 `DeformPupilScale{L,R}` 삽입(홍채 중심 기준 크기 변경). 교체 동공은 그 아래에, 하이라이트는 기본적으로 바깥에 두어 크기를 바꾸지 않습니다. 선택적 “임계값 구동”: 눈썹 올림으로 동공 축소. 홍채 그룹 바깥에 BrowY warp를 두고 키 `{-1, 0, t, 1}` 사용, 0→t는 거의 변화 없고 t→1에서 홍채를 10–20% 축소합니다.
- **알고리즘**: 키 −1/0/1 → 크기 0.75 / 1 / 1.15. 표정 프리셋: 놀람 −1, 공포 −0.7, 어두운 얼굴 −0.5, 호감 +0.6.
- **조절 파라미터**: `shrinkMin` 기본 0.75, 범위 0.45–0.85(만화식 동공 축소는 0.5 가능). `growMax` 기본 1.15, 범위 1.1–1.2. `browThreshold` 기본 끔, 켜면 t = 0.75.
- **실패 양상과 확인**: 크기 변화가 지나치면 흰자 대비 홍채 비율이 왜곡됩니다. 하이라이트까지 축소하면 가짜처럼 보이므로 바깥층에 둡니다.
- **엔진 기능**: warp, 표정 프리셋.
- **난이도 / 우선순위**: easy / **P0**.
- **차이점**: `ParamEyeBallForm`은 물리 전용이며 표정 프리셋에서 쓰지 않고 교체 동공도 포함하지 않습니다.

### `eye.iris/close-squash` 눈 감을 때 홍채 압축
- **목적**: 눈을 감을 때 동공을 위 눈꺼풀에 따라 세로로 압축하고 아래 눈꺼풀에 고정하여, 홍채가 스티커처럼 눈꺼풀 뒤로 미끄러지는 느낌을 피합니다.
- **적용 대상**: 홍채 그룹.
- **출력**: 홍채 그룹 안에 EyeOpen 축 warp `DeformIrisClose{L,R}`(`eye.lid`와 같은 키).
- **알고리즘**: 닫힌 끝점에서 세로를 0.8로 줄이며 앵커는 아래 눈꺼풀입니다. 중간 키는 눈꺼풀 곡선과 동기화합니다.
- **조절 파라미터**: `squash` 기본 0.8, 범위 0.75–0.9.
- **난이도 / 우선순위**: easy / P1.

### `eye.iris/inertia` 시선 이동 관성과 동공 시차 보정
- **목적**: 빠른 시선 이동이나 고개 회전 뒤 홍채가 약간 지나치게 움직입니다. 시선이 한쪽으로 향하면 동공이 홍채에 비해 눈꼬리에 더 가까워지고, 고개 회전 때는 카메라 쪽으로 돌아와 구면감을 줍니다.
- **적용 대상**: 추적 또는 대기 모션에서 시선 입력을 받는 경우.
- **출력**: 파생 파라미터 `ParamEyeBallInertiaX/Y`(물리: EyeBallX/Y(X형) + 머리 AngleX/Y(Angle형, 60), 짧고 활발한 진자, 작은 scale) → 홍채 그룹 이동 5–10% H_e. `ParamPupilCorrX/Y`(물리: −0.5·HeadX − 0.5·EyeBallX, 과감쇠) → 동공층 이동 0.1–0.15 홍채 지름.
- **조절 파라미터**: `inertiaAmp` 기본 0.07 H_e. `pupilCorr` 기본 0.12 홍채 지름, 범위 0.1–0.15.
- **실패 양상과 확인**: `eye.lid/gaze-follow`의 lagged 옵션과 겹치면 눈 영역이 떠다닐 수 있습니다. 시선 변위는 홍채 안으로 clamp해야 합니다.
- **엔진 기능**: 물리(X/Angle 혼합 입력, 과감쇠).
- **난이도 / 우선순위**: medium / P2.

### `eye.iris/arc-path` 곡선을 따라 이동하는 촘촘한 키(점눈/움직이는 장난감 눈)
- **목적**: Live2D 키 사이는 선형 보간뿐이므로 동공이 안와를 따라 원호로 움직이려면 키를 많이 배치해야 합니다. 메시 키로 이동만 하고 자체 회전은 없는 “점눈/장난감 눈”을 만들며, 물리로 구동해 머리를 흔들면 동공이 안와를 굴러 다시 아래로 떨어지게 합니다.
- **적용 대상**: SD 점눈, 움직이는 장난감 눈(googly eye). 지침, 진자 추처럼 경로를 따라 움직이는 객체에도 확장할 수 있습니다.
- **출력**: 파라미터 `ParamEyeRoll`(−1..1), 키 수 `K = ⌈2Φ/Δφ⌉ + 1`. 물리: 머리 X/Y(X형 50) + 머리 Z(Angle형 100), 가볍고 작은 체인.
- **알고리즘**: k키의 객체 중심 = `c + R·(sinφ_k, cosφ_k)`, `φ_k = −Φ + kΔφ`, R = 안와 반지름 − 동공 반지름. Δφ ≤ 18°(현 오차 ≤ 1.2% R). 경로 길이를 등분하여 키를 놓는 방식으로 일반화할 수 있습니다(변형 경로 베이크 재사용).
- **조절 파라미터**: `arcSpan` Φ 기본 90°, 범위 90–180. `keyStepDeg` 기본 15, 범위 10–20.
- **실패 양상과 확인**: K가 너무 크면 키폼이 늘어나며 다른 축과 곱하면 키 수가 배로 증가합니다.
- **엔진 기능**: 다중 키, 물리.
- **난이도 / 우선순위**: easy / P2.

### `eye.iris/color-palette` 곱하기 색으로 눈동자 색 팔레트
- **목적**: 색마다 텍스처를 준비하지 않고 시청자/방송자가 세 슬라이더로 눈동자 색을 자유롭게 조절하면서 원화의 명암을 유지합니다.
- **적용 대상**: 홍채층 또는 밝은 색 복사본. 곱하기 색 키폼을 지원하는 대상.
- **출력**: 스위치 `ParamIrisTintOn`, `ParamIrisHue`(5–9키), `ParamIrisSat`(5키), `ParamIrisVal`(3키). 덮개층 키폼은 기하를 바꾸지 않고 곱하기 색만 변경합니다. 스위치 0에서는 덮개층 불투명도가 0입니다.
- **알고리즘**: 각 키의 곱하기 색 = HSV→RGB(H_i, S_j, V_k). RGB 선형 보간 때문에 인접 색상 사이가 다소 회색으로 흐를 수 있으므로 색상환 H 키를 더 촘촘히 둡니다.
- **조절 파라미터**: `hueKeys` 기본 7, 범위 5–9. `valMin` 기본 0.5, 범위 0.4–0.6.
- **엔진 기능**: 곱하기 색 키폼.
- **난이도 / 우선순위**: easy / P2(`lighting`과 협력).

## 12. eye.highlight — 눈 하이라이트(보충 슬롯)

일반 제작 관행에서 하이라이트는 홍채와 별도로 처리하는 독립 변형 단위입니다. 현재 PSD2Live는 하이라이트와 홍채를 같은 태그·변형으로 처리합니다. 이 슬롯은 먼저 하이라이트를 구분할 수 있어야 합니다(밝기가 높고 면적이 홍채 10% 미만인 흰색에 가까운 조각 또는 사용자 표시). 더 나아가 “정반사 하이라이트”(작고 밝고 흰색)와 “난반사/텍스처 하이라이트”를 구분할 수 있습니다.

### `eye.highlight/current` 홍채와 함께 움직임(기존)
- **현황**: 하이라이트 레이어는 IRIDES에 속하며 홍채와 `DeformIrisPreserve → DeformEyeGaze`, `irisJellyGrid`를 공유합니다.
- **난이도 / 우선순위**: — / P0 등록.

### `eye.highlight/parallax-layer` 하이라이트 독립 시차층
- **목적**: 하이라이트는 광원 반사이므로 눈알·머리가 회전할 때 홍채와 다르게 이동하여 곡면이 있는 젖은 눈알로 보이게 합니다.
- **적용 대상**: 하이라이트가 홍채와 구분된 경우.
- **출력**: 눈마다 하이라이트 그룹을 독립 warp `DeformEyeGlint{L,R}`에 연결(시선 축 3×3 + 머리 AngleX×AngleY 3×3 또는 두 층), 흰자를 마스크로 사용. 정반사 하이라이트는 선택적으로 홍채 형태 원근층 밖에 연결해 시선·눈 감기·젤리만 적용합니다.
- **알고리즘**:
  1. 시선: 하이라이트 변위 = 홍채 시선 변위 × (f_x, f_y). 큰 하이라이트 (0.9, 0.8), 작은 하이라이트 (0.9, 0.6). 홍채보다 적게 움직여 고정 광원의 반사처럼 보입니다.
  2. 머리 회전은 서로 배타적인 두 모드(`turnMode`)를 제공합니다.
     - `light-fixed`: 눈에 대해 홍채 변위의 50–70%를 반대로 보상하여 광원 방향에 대략 고정합니다. 물리 평활화 가능: AngleX/Y(Angle형 reflect 60) + EyeBallX/Y(50) + EyeOpen(40) → `ParamGlintParallaxX/Y`. 노드 2개, 가벼운 지연, ±1에서 ±0.25 R_i 이동. 하이라이트가 여러 개면 홍채 중심에서 멀수록 덜 이동합니다(중심 1.0, 가장자리 0.6).
     - `cornea-front`: 하이라이트가 각막 표면에서 홍채보다 앞에 있으므로 머리를 돌릴 때 홍채 변위의 β = 0.1–0.5배만큼 더 이동합니다. 방향은 머리 회전과 같습니다.
  3. 전부 홍채 안으로 clamp하여 위치를 제한하고, 흰자 마스크로 가시성을 제한합니다.
- **조절 파라미터**: `gazeFactorX` 기본 0.9, 범위 0.85–0.95. `gazeFactorY` 기본 0.7, 범위 0.55–0.85. `turnMode` light-fixed|cornea-front, 기본 light-fixed. `turnAmount` 기본 0.6(light-fixed 보상 비율) / 0.2(cornea-front의 β), 범위 0.3–0.7 / 0.1–0.5. `specularBypassShape` 기본 true.
- **실패 양상과 확인**: 시선 추종과 더해져 하이라이트가 홍채를 벗어남 → clamp. 머리 X의 reflect 방향은 통일된 렌더링 테스트가 필요합니다(light-fixed: 머리가 오른쪽으로 돌면 하이라이트는 눈에 대해 왼쪽). 홍채 가장자리 하이라이트가 흰자 밖으로 밀리지 않는지도 확인합니다.
- **엔진 기능**: 중첩 warp, 선택적 물리, 마스크.
- **난이도 / 우선순위**: easy / **P0**(`turnMode` 두 방식을 스타일 옵션으로 함께 제공, 기본 light-fixed).
- **차이점**: 동공 유지/시선은 있지만 하이라이트와 홍채가 함께 움직이고, 머리 회전에 따른 하이라이트 시차가 없습니다.

### `eye.highlight/lid-follow` 눈꺼풀을 따라 내려가는 하이라이트
- **목적**: 반쯤 감았을 때 하이라이트가 원위치에 있으면 흰자 마스크에 잘려 즉시 생기가 없어 보입니다. 하이라이트를 눈꺼풀과 함께 내려 좁은 틈에도 반사가 남게 합니다.
- **적용 대상**: 독립 하이라이트. `eye.lid/arc-blink`와 함께 사용.
- **출력**: 하이라이트 그룹 바깥에 EyeOpen warp를 씌웁니다(하이라이트만 포함하고 홍채는 영향 없음).
- **알고리즘**: EyeOpen = t_mid에서 하이라이트 그룹을 0.15–0.3 H_e 내리고 세로를 70%로 압축합니다. → ε까지 계속 압축한 뒤 그룹 전체를 숨깁니다(불투명도는 뜬 눈 그룹 추종).
- **조절 파라미터**: `slide` 기본 0.2 H_e, 범위 0.15–0.3. `squashAtMid` 기본 0.7.
- **난이도 / 우선순위**: easy / P1.

### `eye.highlight/blink-wobble` 홍채 중심 주위 하이라이트 흔들림과 부드러운 제한
- **목적**: 깜빡인 뒤 하이라이트가 직선 대신 눈알 표면의 곡선을 따라 미끄러지고, 큰 진폭에서는 홍채 가장자리에 붙어 경계를 넘지 않게 합니다.
- **적용 대상**: 독립 하이라이트. `eye.iris/jelly-layered` 하이라이트 체인의 기하 구현 옵션.
- **출력**: 하이라이트 조각마다 회전 디포머 `RotEyeGlint<k>{L,R}` 하나. 축은 하이라이트 중심이 아닌 홍채 중심에 두고, 하이라이트 물리 체인의 파라미터를 사용합니다. 또는 2차원 이동 warp + 부드러운 제한 중간 키를 사용합니다.
- **알고리즘**:
  1. “홍채 가장자리에서 미끄러지는 최대 호 길이 = 0.3 R_i”로 회전각 θ를 환산합니다. 하이라이트 위치 쪽에 대해 비대칭으로 하며 멀어지는 쪽은 0.75θ를 사용합니다.
  2. 부드러운 제한(이동 구현): +0.4 위치에 중간 키를 추가하고 0.4 → 1 구간에서는 15%만 더 전진합니다. 상한은 홍채 반지름입니다.
- **조절 파라미터**: `arcLen` 기본 0.3 R_i, 범위 0.2–0.4. `asym` 기본 0.75. `softLimitKnee` 기본 0.4, 범위 0.3–0.5.
- **실패 양상과 확인**: 출력 scale이 너무 크면 경련처럼 보입니다. 마스크는 반드시 흰자여야 합니다.
- **엔진 기능**: 회전 디포머, 비균일 다중 키.
- **난이도 / 우선순위**: easy / P1.

### `eye.highlight/gate` 하이라이트 곱셈 게이트
- **목적**: 교체 동공, 어두운 얼굴, 텅 빈 눈 중 하나라도 켜지면 원래 하이라이트를 없앱니다(논리 NOR). 추가 파라미터 없이 서로 충돌하지 않게 합니다.
- **적용 대상**: 하이라이트와 충돌하는 스위치가 하나 이상 있는 경우.
- **출력**: 하이라이트 그룹 바깥에 게이트 warp `DeformEyeGlintGate{L,R}`. 불투명도 키폼은 모든 충돌 스위치의 곱 격자이며 모두 0인 꼭짓점만 1입니다. 스위치가 3개를 넘으면 게이트 warp를 연쇄 배치합니다(층마다 스위치 2개).
- **알고리즘**: 게이트 warp의 기하는 항등이고 불투명도 키만 있습니다. 충돌 스위치 목록은 활성화된 템플릿이 자동 등록합니다(`replacement-pupil`, `gloom`, `symbol-mode`).
- **조절 파라미터**: `gateFadeBand` 기본 [0, 0.6](스위치 0.6에서 하이라이트가 이미 0).
- **실패 양상과 확인**: 게이트가 너무 많으면 여러 상태에서 하이라이트가 사라지므로 품질 검사에서 조합을 나열합니다.
- **엔진 기능**: 다차원 불투명도 키폼(곱셈 게이트).
- **난이도 / 우선순위**: easy / P1.

### `eye.highlight/sweep-loop` 하이라이트 스윕 반복과 반짝임
- **목적**: “반짝이는” 감정은 시선과 독립적입니다. 하이라이트가 조명 방향을 따라 홍채를 쓸고 지나가거나, 추가 텍스처 없이 스크린 채널로 반짝이게 합니다.
- **적용 대상**: 독립 하이라이트, 모션의 감정 박자.
- **출력**: 파라미터 `ParamEyeSparkle`(0..1, 반복). 하이라이트 메시를 “홍채 왼쪽 위 → 오른쪽 아래” 경로의 8–9키로 이동하며 크기·불투명도 포락선과 가산 블렌딩을 적용합니다. 또는 `jelly-layered`의 빠른 체인이 구동하는 `ParamEyeGlintFlicker`로 하이라이트·홍채 반사층의 스크린 색을 제어합니다(screen color에 흰색 0.15–0.25 추가).
- **조절 파라미터**: `sweepLen` 기본 0.8 홍채 지름. `flickerStrength` 기본 0.2, 범위 0.1–0.3.
- **실패 양상과 확인**: 어두운 홍채에서는 스크린이 회색으로 보일 수 있어 홍채 주색에 맞춰 조절합니다.
- **엔진 기능**: 다중 키 경로, 가산 블렌딩, 스크린 색 키폼, 순환 파라미터.
- **난이도 / 우선순위**: easy–medium / P2.

## 13. brow — 눈썹

### `brow/current` 전체 수직 이동(기존)
- **목적**: 눈썹 Y 파라미터로 눈썹 전체를 위아래로 이동합니다.
- **적용 대상**: EYEBROW 레이어.
- **출력**: `ParamBrowL/RY{-1,0,1}`, `DeformBrowShape{L,R}`(3×3, 아홉 포즈). 메시 키폼 `eyebrowGrid`: `dy = −value·h·browLift%`. Side.NONE은 `BrowRY`에 연결합니다. 앞머리를 투과하는 복사본은 키폼·블렌드 셰이프를 공유합니다.
- **실패 양상과 확인**: 회전, 형태 변화, X가 없으며 눈썹과 눈이 완전히 독립적입니다.
- **난이도 / 우선순위**: 구현됨 / P0 등록.

### `brow/lid-coupling` 눈썹이 위 눈꺼풀을 구동(같은 피부)
- **목적**: 눈썹을 올리면 위 눈꺼풀도 당겨져 눈이 커집니다. 찌푸리거나 역팔자 눈썹이 되면 위 눈꺼풀의 바깥/안쪽이 눌려 눈이 좁고 사나워집니다. 앞머리에 가려진 눈썹의 감정을 보이는 눈으로 전달합니다.
- **적용 대상**: 눈썹과 같은 쪽 눈이 모두 있는 경우.
- **출력**: 눈 그룹(위 눈꺼풀, 속눈썹, 아이라인, 흰자, 선택적 홍채 그룹) 바깥, `DeformEyeShape{L,R}` 안에 `DeformEyeBrowPull{L,R}` 삽입(lattice 5×(≥10), 눈 바운딩 박스를 덮고 위로 눈썹까지 확장). 축은 기존 눈썹 파라미터 `BrowY`, `brow/shape-axes`를 켜면 `BrowAngle`도 추가하며 `BrowForm`은 별도 층으로 둡니다. 대상이 블렌드 셰이프를 지원하면 눈 warp에 같은 이름의 블렌드 셰이프를 작성해 눈 개폐 키와 곱해지지 않게 할 수 있습니다.
- **알고리즘**:
  1. 키폼 = 해당 키에서의 눈썹 변위 Δbrow(x)(같은 x 위치 눈썹의 수직 변위) × 감쇠장 c(y). 눈썹 선에서 c = 1, 위 눈꺼풀 선에서 `c_lid`, 아래 눈꺼풀에서 ≈ 0. 그 사이는 수직 거리를 따라 smoothstep 보간합니다.
  2. `c_lid`: Y축 0.4–0.8, Angle축 0.3–0.6. Angle 회전 피벗은 눈 중심이 아니라 눈썹 자체 피벗을 사용합니다.
  3. 가림 적응: 정지 포즈에서 앞머리에 가려진 눈썹 픽셀 비율 cov를 구하고 `c_lid(Y) = 0.4 + 0.5·cov`(0.4–0.95로 제한)로 정합니다. 눈썹이 보이면 낮은 값을 사용해 과장되지 않게 합니다.
  4. 눈 변형: BrowY = +1이면 위 눈꺼풀이 올라가고 눈 틈이 세로로 열립니다(눈 전체 세로 +5%). −1에서는 위 눈꺼풀 0.12–0.15 H_e, 바깥 눈꼬리 0.05 H_e 하강. Angle은 위 눈꺼풀 안팎을 비대칭으로 움직여 분노/슬픔을 만듭니다.
- **조절 파라미터**: `cLidY` 기본 0.6, 범위 0.4–0.95. `cLidAngle` 기본 0.45, 범위 0.3–0.6. `coverageBoost` 기본 0.5, 범위 0–0.5. `useBlendShapes` 기본은 대상 기능에 따라 자동.
- **실패 양상과 확인**: 눈썹 올림 + 눈 감기에서 위 눈꺼풀이 눈썹을 통과하면 안 됩니다. 결합이 높으면 추적 노이즈로 눈 전체가 눈썹과 함께 떨립니다(추적 평활화 또는 `brow/spring` 병용). 앞머리를 투과하는 눈썹/눈 복사본은 같은 변형을 공유해야 합니다(부모 디포머 공유로 충족).
- **엔진 기능**: 중첩 warp 또는 블렌드 셰이프.
- **난이도 / 우선순위**: medium / **P0**.
- **차이점**: 현재 눈썹과 눈은 각자 독립적으로 변형됩니다.

### `brow/blink-dip` 깜빡임과 크게 뜨기에 연동하는 눈썹
- **목적**: 눈을 감을 때 눈둘레근이 눈썹을 조금 끌어내리고, 크게 뜨면 눈썹을 올립니다(놀람). 단, “깜빡일 때 억울해 보이는” 모습은 피합니다.
- **적용 대상**: 눈썹과 같은 쪽 눈이 모두 있는 경우.
- **출력**: 눈썹 형태 warp 바깥에 `DeformBrowEyeFollow{L,R}` 삽입. 축 = 같은 쪽 `EyeOpen`(`eye.lid`와 같은 키, Omax 포함)[× `EyeSmile`]. 모드:
  - `static`: 직접 키폼 적용.
  - `physics`: 파생 파라미터 `ParamBrowBlinkDip{L,R}`. 물리 EyeOpen(X형 80–100)[+ EyeBallY 20] → 단일 노드 긴 진자(느리고 부드러운 과감쇠). 음수 쪽에만 키를 만들고 양수 쪽은 0.
  - `wide-raise-only`: 파생 파라미터 C = 스프링(clamp((EyeOpen − 1)/(Omax − 1), 0, 1)). 크게 뜰 때만 눈썹을 올리고 깜빡임에서는 누르지 않음.
- **알고리즘**:
  1. EyeOpen = 0: 눈썹 전체를 `dip·H_e` 내립니다. 안쪽 끝 1.2배, 바깥 끝 0.8배 또는 스타일에 따라 눈꼬리 쪽을 더 내립니다.
  2. EyeOpen = Omax: 눈썹을 0.2 H_e 올리고 형태를 약간 바깥쪽 곡선으로 만듭니다.
  3. EyeSmile = 1(감은 눈 행): 눈썹이 이완되어 0.05–0.1 H_e 올라가고 살짝 휘어 “눈썹과 눈이 함께 웃는” 모습이 됩니다.
- **조절 파라미터**: `dipMode` none|static|physics|wide-raise-only, 기본 static. `dip` 기본 0.05 H_e, 범위 0.02–0.2(physics 모드는 0.15–0.25 가능). `innerOuterRatio` 기본 1.2, 범위 1.0–1.3. `wideRaise` 기본 0.2 H_e, 범위 0.1–0.25. `smileRelax` 기본 0.08 H_e.
- **실패 양상과 확인**: dip이 크면 억울해 보입니다(static 모드 ≤ 0.06 H_e). 추적 EyeOpen 매핑이 크면 wide-raise로 눈썹이 항상 올라갑니다(중립 ≈ 1 필요). 앞머리에 가린 눈썹은 앞머리 투과 표시와 함께 사용합니다.
- **엔진 기능**: 2차원 키폼, 선택적 물리.
- **난이도 / 우선순위**: easy / **P0**(static 모드). physics와 wide-raise 옵션은 P1.
- **차이점**: 눈썹은 BrowY만으로 제어됩니다.

### `brow/shape-axes` 눈썹 각도·형태·X
- **목적**: 눈썹 감정은 위치보다 각도와 형태가 중심입니다. 위치 파라미터 크기는 작게 두고, 각도는 촘촘한 키로 원호를 근사하며, 웃음/의문/분노 형태를 획을 따라 긴 좁은 warp에서 조합합니다.
- **적용 대상**: EYEBROW 레이어. 눈썹 시작·봉우리·끝의 세 점과 획 중심선을 추정할 수 있어야 합니다.
- **출력**: 파라미터 `ParamBrowL/RAngle`(±1), `ParamBrowL/RForm`(±1, Cubism 표준 이름, 또는 Smile/Puzzled/Angry 0..1 단방향 형태 파라미터로 분리), `ParamBrowL/RX`(±1). 디포머 순서(바깥 → 안쪽): 깜빡임 연동 → 시선(선택) → `BrowY × BrowX`(3×3 키, 5×5 lattice) → `BrowAngle`(촘촘한 키, 7×10 lattice) → 형태 warp(획을 따라 3행 × ≥ 15열).
- **알고리즘**:
  1. 위치: Y ±0.15 H_e, X ±0.06 W_e(작은 범위).
  2. 각도: 눈썹 중점 또는 시작점을 중심으로 ±15° 회전. 각도 변화 > 10°인 회전성 운동은 구간마다 ≤ 5°가 되도록 키를 추가하고, 각 키를 피벗 기준 정확한 회전으로 계산합니다(끝점 보간이 아님).
  3. 형태: 웃음 = 중간을 올리고 양 끝을 누름. 의문 = 한쪽 끝을 올림. 분노 = 눈썹 시작점을 내리고 급경사로 만듦. 세 형태는 2×2×2 키 또는 블렌드 셰이프로 조합합니다. 주 감정량은 형태에 약 0.5 H_e를 주고 위치량은 작게 유지합니다.
- **조절 파라미터**: `posY` 기본 0.15 H_e. `posX` 기본 0.06 W_e. `angleDeg` 기본 15, 범위 10–25. `angleStepDeg` 기본 5, 범위 3–6. `formAmp` 기본 0.5 H_e, 범위 0.3–0.6. `formStyle` bipolar|tri-shape, 기본 bipolar.
- **실패 양상과 확인**: 촘촘한 키 × 다른 축으로 키 수가 증가합니다(각도층은 별도 warp로 두어 형태와 곱하지 않음). 앞머리를 투과하는 눈썹 복사본도 형태·블렌드 셰이프를 상속해야 합니다.
- **엔진 기능**: 다중 키, 길고 좁은 warp, 선택적 블렌드 셰이프.
- **난이도 / 우선순위**: medium / P1.
- **차이점**: 표준 파라미터에는 BrowY만 있습니다.

### `brow/spring` 눈썹 스프링(부족 감쇠 반동)
- **목적**: 눈썹은 표정에서 가장 빠른 부위이며 “눈썹 올리기”에는 도착 충격이 있습니다. 부족 감쇠 단진자로 충격을 만들고, 눈썹이 움직일 때 눈에도 살결 같은 지연 반동을 줍니다.
- **적용 대상**: `brow/shape-axes` 또는 최소 BrowY 활성화.
- **출력**: 눈썹 입력 파라미터 B마다 섀도 파라미터 `B2`(예: `ParamBrowLY2`) + 단일 질점 물리 그룹(B를 Angle형으로 입력). 눈썹 메시와 선택적 눈 영역 warp를 B2가 구동하도록 변경합니다(B 자체는 기하 영향 없음, 또는 B가 직접 구동하고 B2가 오버슈트 블렌드 셰이프를 중첩).
- **알고리즘**: 물리 m 0.6–0.7, d 0.5–0.8, a 1.4–1.6. 출력 scale = 범위 × 0.6. B2의 ± 형태는 원래 눈썹 키폼입니다. 눈 영역에서는 B2로 눈 전체(동공 스택 + 눈꺼풀 스택)를 눈썹 움직임 방향으로 ±0.2 H_e 작게 이동합니다(블렌드 셰이프). 검증: 눈썹 계단 입력에서 B2 오버슈트 10–20%, 0.3 s 이내 안정.
- **조절 파라미터**: `overshoot` 기본 0.15, 범위 0.05–0.25. `eyeCarry` 기본 0.1 H_e, 범위 0.05–0.25.
- **실패 양상과 확인**: 고주파 추적 노이즈로 눈도 떨립니다(scale 감소 또는 추적 평활화). 표정 모션이 B2를 직접 쓰면 물리 중첩과 충돌하므로 모션은 B를 작성합니다.
- **엔진 기능**: 물리, 블렌드 셰이프.
- **난이도 / 우선순위**: easy / P1.

### `brow/emotion-fanout` 물리를 “믹서”로 사용: 감정 입력 하나를 눈썹·눈·동공으로 분배
- **목적**: 추적 눈썹 신호는 1차원이고 약하며 노이즈가 있지만 실제 눈썹 움직임은 복합적입니다. 물리로 BrowY, MouthForm, MouthX를 섞어 여러 형태 파라미터에 분배하고, 두 번째 노드 출력으로 “먼저 올리고 나중에 휘기”의 지연을 만듭니다. 웃으면 웃는 눈썹, 입꼬리 옆 이동은 의아한 눈썹, 입 찌푸림은 성난 눈썹과 동공 축소를 유도합니다.
- **적용 대상**: `brow/shape-axes`(형태 파라미터), `brow/lid-coupling`의 성난 눈 형태, `eye.iris/pupil-scale` 활성화.
- **출력**: 원본 입력(BrowY, MouthForm, MouthX)은 기하에 직접 바인딩하지 않습니다. 파생 파라미터는 각 측의 `BrowY2`, `BrowAngle2`, `BrowSmile`, `BrowPuzzled`, `BrowAngry`, `EyeAngry`, `PupilScale2`. 각 측에 물리 그룹 하나(질점 3개, 중간 노드 m 0.6, 끝 노드 m 0.45, Angle형 입력). 선택적으로 “입 → 눈썹” 지연 체인: MouthForm → 진자 → 진자 → 진자 → `BrowSmileSad`(“슬픈 미소 눈썹”: 안쪽 끝 상승, 바깥 끝 처짐, 눈을 조금 가늘게 뜸).
- **알고리즘**:
  1. 혼합 행렬 M(행 = 출력, 열 = 입력, 가중치는 설계 기본값). Smile ← BrowY 0.4 + MouthForm⁺ 0.3. Angry ← BrowY⁻ 0.4 + MouthForm⁻ 0.3. EyeAngry ← Angry와 동일. Angle ← 0.3 BrowY + 0.3 MouthForm + 0.2 MouthX. Puzzled ← |MouthX|(v2 사용, 한 박자 지연). PupilScale ← −Angry(화나면 동공 축소).
  2. 형태 파라미터는 단방향(Smile/Puzzled [0,1], Angry [−1,0])으로 두어 물리의 양·음 방향이 자연스럽게 분기합니다.
  3. 동작마다 warp 한 층, 고정 순서: (시선) → BrowY2 → Angle(촘촘한 키) → Angry × 표정 → 형태.
  4. 좌우 각각 한 그룹. MouthX를 한쪽에서 reflect하여 비대칭을 만듭니다.
  5. 검수: 웃음 → 눈썹이 웃는 곡선이 되고 중립에서 0으로 복귀. 떨림 없음, 지연 < 150 ms.
- **조절 파라미터**: `mouthMix` 기본 0.3, 범위 0–0.4. `mouthXMix` 기본 0.2, 범위 0–0.3. 각 출력 가중치, `delayedOutputs`(v2를 사용하는 출력 목록). `sadSmileChain` 기본 false, 단계 수 2–3.
- **실패 양상과 확인**: 복귀 시 반대 형태로 오버슈트(Smile → 잠깐 Angry) → 끝 노드 m을 낮추고 d ≈ 1. MouthForm 가중치가 크면 말할 때 눈썹이 튑니다(≤ 0.3, 물리 자체도 평활화). 표정 모션은 형태 파라미터 대신 입력 파라미터를 작성해야 합니다. 원래 추적에서 눈썹 형태도 제공하면 입 → 눈썹 가중치를 줄입니다.
- **엔진 기능**: 물리 다중 출력(v1/v2), 파생 파라미터 체인(물리 연쇄).
- **난이도 / 우선순위**: medium / P2(research: 혼합 행렬 기본값은 출력 결과로 조정해야 함).
- **차이점**: 눈썹은 BrowY가 직접 구동하며 이목구비 간 결합이 없습니다.
