# 컨텍스트 메뉴 점검과 정리 제안

UI 위치별 현황, 문제와 제안은 먼저 [컨텍스트 메뉴: 위치별 현황과 개선 제안](CONTEXT_MENU_REVIEW.md)을 읽어 주세요. 이 문서는 구현 통계와 소스 코드 근거를 보존합니다.

점검 일자: 2026-10-20, 점검 당시 작업 트리의 소스 코드 기준. 이 문서는 정적 감사와 후속 정리 방안이며 **완료된 UI 개선이나 실제 기기 검수 기록이 아닙니다**. 상호작용 기준은 [UI_INTERACTION_CONSISTENCY.md](UI_INTERACTION_CONSISTENCY.md)를 참고하세요.

사용자가 확인한 설계 경계: 파라미터 패널과 키포인트 편집은 각각 Cubism / Photoshop 방식을 따르며 컨트롤이 다르다고 해서 상호작용 충돌은 아닙니다. 도킹 탭 그룹 빈 곳의 “모두 닫기”는 유지합니다. 아틀라스는 보통 여섯 페이지 이하이므로 대상 페이지를 펼쳐 표시하고 너무 길면 스크롤바를 제공합니다. 일반 메시를 오른쪽 클릭할 때 현재 선택을 대상으로 하는 동작은 유지합니다. 상단 메뉴의 정보 구성과 배열은 별도 개선 항목이며 이를 근거로 오브젝트 선택(picking) 전략을 바꾸지 않습니다.

## 0. 구현 상태(2026-10-20)

P1-A는 `context-menu-cleanup` 브랜치에 구현되었으며, 삭제 범위와 위치 찾기 행의 선택 로직을 다루는 `ui/views/ContextMenuScopeTest`도 추가했습니다. UI 동작은 아직 실제 기기 검수가 필요합니다.

- **C03**: 접힌 체인의 삭제를 “현재 디포머 삭제”와 “체인 전체 삭제(N)”로 나눴습니다. 체인 안의 이름 조각을 오른쪽 클릭할 때 메뉴 위치는 행 좌표를 사용하며 더 이상 조각의 로컬 좌표로 정하지 않습니다.
- **C04**: 다중 선택 중 선택된 행을 오른쪽 클릭하면 메뉴 이름 아래에 “이 항목에만 적용 · N개 선택됨”을 표시합니다. 동작은 여전히 해당 행에만 적용되며 일괄 작업인 것처럼 보이게 하지 않습니다.
- **C06**: 소재의 “참조 레이어 위치 찾기”는 참조가 하나면 바로 이동하고, 여러 개면 레이어별 하위 메뉴로 펼칩니다. 삭제되었거나 원본에 존재하지 않는 참조는 더 이상 세지 않습니다.
- **U01**: 파라미터 이름의 왼쪽 클릭은 여전히 속성을 열고, 오른쪽 클릭은 파라미터 관리 메뉴(속성, 현재값 초기화, 잠금/잠금 해제, 파라미터 복사, 파라미터 ID 복사, 파라미터 삭제…)로 바꿨습니다. 삭제와 복사는 속성 대화 상자의 확인 절차를 재사용합니다.
- **X02/X04**: `layerId`가 없고 참고 이미지도 아닌 계층 행은 더 이상 제목만 있는 메뉴를 띄우지 않습니다. 주 캔버스의 오른쪽 버튼 명령이 컨텍스트 메뉴보다 우선하며 아틀라스와 같습니다.

이상은 소스 코드 구현과 테스트 결과이며 **실제 기기 UI 검수는 하지 않았습니다**. P1-B, P1-C는 아직 시작하지 않았습니다. 아래 각 표는 변경 전의 점검 근거를 그대로 보존합니다.

## 1. 범위, 기준과 통계

`src/main/kotlin/io/github/psd2live/ui/`의 사용자 정의 오른쪽 클릭 트리거, 메뉴 호스트, 메뉴 내용, 도구 옵션 카탈로그, 그리고 오른쪽 클릭 진입점이 없는 주요 오브젝트 목록을 다룹니다. 모델 샘플은 읽지 않았고 제품 로직도 변경하지 않았습니다.

“메뉴 호스트”는 독립적인 트리거 상태와 메뉴 렌더링 구현 하나를 뜻합니다. 같은 호스트가 오브젝트 유형에 따라 내용을 바꾸거나, 항목을 몇 개 렌더링하거나, 여러 캔버스에서 재사용되더라도 중복으로 세지 않습니다. 따라서 아래의 **17은 호스트 수이며, 화면에서 오른쪽 클릭할 수 있는 위치 수도, 동적 메뉴 상태 조합 수도 아닙니다**.

| 항목 | 수량 | 기준 |
|---|---:|---|
| 구현된 사용자 정의 컨텍스트 메뉴 호스트 | 17 | 목록 C01–C17 |
| `PressMenu`를 사용하는 호스트 | 7 | C01–C07. 그중 C04는 오브젝트에 따라 ArtMesh / 참고 이미지 내용을 전환 |
| `TreeContextMenu` + `CompactMenuItem`을 직접 사용하는 호스트 | 8 | C08–C15. 외형 셸은 공유하지만 행과 강조는 새 규칙대로 통일되지 않음 |
| 기타 메뉴 셸 | 2 | C16의 `TabStripDropdown`, C17의 자체 `Popup` |
| 오른쪽 클릭 동작은 있지만 메뉴가 없는 컨트롤 | 5 | R01–R05, 17에 포함하지 않음 |
| 메뉴를 우선 추가할 것을 권장하는 모듈 | 7 | M01–M07. 기존 기능에 이미 진입점이 있어 업무 기능을 재사용 가능 |

일반 입력란과 선택 가능한 텍스트의 시스템/Compose 기본 편집 메뉴는 사용자 정의 호스트로 세지 않습니다. 예를 들어 로그 본문에는 이미 `SelectionContainer`가 있으므로 “로그에 복사 기능이 전혀 없다”고 단정할 수 없습니다. 왼쪽 클릭 버튼이 띄우는 선택기도 오른쪽 클릭 진입점으로 세지 않습니다.

### 3.1 현재 접기 전략

`MENU_ROW_BUDGET = 10`. 멤버가 세 개 이상인 그룹만 자동 접기 대상이며, 예산을 넘으면 가장 큰 그룹부터 접고 크기가 같으면 뒤에 나오는 그룹을 먼저 접습니다. 생성, 소재, 미러 등 `alwaysFolds`로 표시된 그룹은 항상 접힙니다. 가로 배열이 아닌 긴 옵션도 2차로 접을 수 있습니다. 가로 배열의 선택 항목과 변형 종류(variant)는 세그먼트 컨트롤을 쓰며 옵션 수만큼 여러 행으로 펼치지 않습니다.

이 방식은 길이를 제어할 수 있지만 같은 그룹이 브러시 팁, 대상, 소재 연결에 따라 1차와 2차 사이를 오갑니다. 작업 그룹은 고정하고 예산은 넘칠 때의 대비책으로만 쓰는 것을 권장합니다. 자주 쓰는 동작이 상태에 따라 계층을 반복해서 바꾸지 않게 해야 합니다.

### 3.2 목표 순서

1. 현재 작업의 확인/완료, 한 단계 되돌리기, 취소. 대상이 없다는 설명은 이 동작들 바로 옆에 둡니다.
2. 도구 종류/작업 모드.
3. 자주 쓰는 값: 크기/반경, 강도 또는 불투명도, 경도, 각도, 감쇠/스냅 등.
4. 현재 선택과 직접 관련된 명령.
5. 안정적인 2차 그룹: 선택, 생성, 토폴로지, 메시, 소재, 미러, 가중치 그룹. 현재 모드와 관련된 그룹만 표시합니다.
6. 지우기/삭제 등 내용을 바꾸는 동작은 **소속 그룹의 끝**에 두고 일반 동작과 구분선으로 분리합니다.

특히 토폴로지 그룹의 “삭제 → 복사”를 조정해야 합니다. 복사는 일반 편집 그룹으로 옮기고 삭제는 마지막으로 옮깁니다. 확인/취소의 도구 세션 의미는 유지하며 오브젝트 메뉴의 삭제 규칙을 그대로 적용하면 안 됩니다.

| 일반 소재 | 이름 → 편집 → 배치 → 선택한 레이어 교체(대상 있을 때) → 참고 이미지 추가 2차 → 해상도 조정(벡터) → 참조 레이어 위치 찾기(참조 있을 때)｜이름 변경 → 태그 → 기본으로 참고 이미지로 사용 → 상위로 이동(상위 폴더 있을 때) → 삭제 |
| 폴더 | 이름 → 열기 → 폴더 내 소재 배치 → 참고 이미지 추가 2차(레이어 내부) → 참조 레이어 위치 찾기(참조 있을 때)｜이름 변경 → 태그 → 기본으로 참고 이미지로 사용 → 하위 폴더 생성 → 여기로 가져오기 → 폴더를 여기로 가져오기 → PSD 내보내기 → 상위로 이동(상위 폴더 있을 때) → 삭제 |
| “참고 이미지 추가” 2차 | 단일 소재: 배경, 레이어 내부, 전경. 폴더: 레이어 내부만. 배경/전경에는 모델에 포함되지 않는다는 표시가, 레이어 내부에는 모델에 포함된다는 표시가 붙음 |

목표 정리:

- 소재: 편집 → 배치/대상 교체 → 참고 이미지 추가 2차｜위치 찾기｜이름 변경, 태그, 기본 참고 상태, 벡터 해상도｜이동｜삭제.
- 폴더: 열기 → 모두 배치/레이어 내부 참고 이미지 추가｜하위 폴더 생성, 파일 가져오기, 폴더 가져오기｜이름 변경, 태그, 기본 참고 상태｜PSD 내보내기, 이동｜삭제.
- 루트/빈 곳: 새 폴더 → 파일 가져오기 → 폴더 가져오기｜보기 2차. 격자/목록은 상호 배타적인 단일 선택이고 “폴더 트리 표시”는 독립 체크 항목입니다.
- 폴더의 “참고 이미지 추가”에 유효한 대상이 하나뿐이면 “레이어 내부 참고 이미지로 배치”라고 바로 쓰고, 선택지 하나를 위해 2차를 두지 않습니다.
- “참조 레이어 위치 찾기(N)”는 현재 `users.first()`를 실행하므로 개수와 실제 위치 찾기 범위가 일치하지 않습니다. 참조가 하나면 바로 위치를 찾고, 여러 개면 참조 목록에서 고르게 하거나 “첫 번째 참조 위치 찾기”라고 명시해야 하며, 이를 일괄 위치 찾기가 구현된 것으로 셀 수 없습니다.
- 이동은 현재 “상위로 이동”뿐입니다. “다른 위치로 이동…”을 추가한다면 폴더 선택기가 필요하며, 기존 메뉴가 이미 임의 폴더를 지원한다고 가정하면 안 됩니다.
- 삭제 비활성 이유(레이어/참고 이미지 참조 수)는 유지해야 합니다. 폴더 작업은 하위 소재 전체에 적용된다는 의미를 보여 줘야 합니다.

## 6. 누락된 메뉴와 선택적 후보 모듈

다음은 기존 UI 기능에 대한 진입점 제안입니다. **“누락”은 사용자 정의 컨텍스트 메뉴를 찾지 못했다는 뜻이며 해당 업무 명령이 없다는 뜻이 아닙니다**. 설계 중 새로 추가하는 동작은 별도로 평가해야 하며, 진입점 정리를 새 편집 기능으로 확장해서는 안 됩니다.

| D07 | 최근 파일 카드/목록, 더블 클릭 열기와 메뉴 열기 | 탐색 레이아웃과 조작 방식이 다름 | 이미 `RecentFileMenuHost`를 공유. 같은 파일 작업 유지 |
| D08 | 그리기 순서 눈금자의 짧은 오른쪽 클릭과 더블 클릭이 모두 수치 대화 상자를 엶 | 같은 정밀 편집 기능의 빠른 진입점이며 오른쪽 드래그에는 별도의 팬 이동 역할이 있음 | 짧은 클릭/드래그 임계값을 명확히 유지. 짧은 클릭을 작은 메뉴로 바꾸더라도 더블 클릭은 수치 대화 상자로 바로 연결 |

스냅샷 왼쪽 클릭 적용과 오른쪽 클릭 관리는 서로 다른 조작입니다. 도킹 탭과 최상위 작업 공간의 닫기는 서로 다른 컨테이너 범위입니다. 이들은 같은 명령의 중복으로 세지 않지만 문구에서는 여전히 “스냅샷”, “이 그룹의 패널”, “작업 공간”을 명확히 해야 합니다.

물리 메뉴의 “기본값 복원”과 “삭제”는 둘 다 `removePhysicsGroup`을 호출하지만 **불합리한 중복이 아닙니다**. `PhysicsGroup.overridden`은 `CUSTOM`을 명시적으로 제외하므로 복원은 생성된 그룹의 재정의를 제거하는 것이고, 삭제는 사용자 그룹에만 사용할 수 있습니다. 출처에 따라 사용 가능한 항목과 문구를 구분해야 하며 하나의 모호한 삭제 동작으로 합치면 안 됩니다.

## 8. 여전히 확인 또는 조정이 필요한 트리거

| ID | 상황 | 결론 |
|---|---|---|
| X01 | 파라미터 이름 오른쪽 클릭이 왼쪽 클릭의 속성을 그대로 중복 | 파라미터 관리 메뉴로 바꿀 수 있음. 진입점 최적화 제안이며 R02–R04의 컨트롤 전용 로직과 섞지 않음 |
| X02 | 계층 ArtMesh에 `layerId`가 없어도 메뉴가 뜸 | 현재 내용은 오브젝트 이름뿐. 실제 실행 가능한 항목으로 판단해 제목만 있는 메뉴를 띄우지 않아야 함. 이 상태가 일반 흐름에서 도달 가능한지는 실제 기기 확인 필요 |
| X03 | 소비되지 않은 하위 컨트롤의 오른쪽 클릭이 행 전체 메뉴로 계속 버블링 | 모션 행, 물리 행, 시뮬레이션 행, 스냅샷, 파라미터 폴더 등은 이름/행 배경과 내장 입력란, 버튼 각각의 범위를 정해야 함. 기존 분기 대부분이 `isConsumed`를 통일되게 확인하지 않으며 실제 충돌은 이벤트 테스트로 확인 필요. 모든 하위 컨트롤을 오브젝트 메뉴 트리거 영역으로 취급하지 않음 |
| X04 | 캔버스가 브러시 조정, 팬, 줌, 사용자 정의 마우스 명령에 점유됨 | 메뉴를 겹쳐 열지 않음. 주 캔버스는 제스처를 먼저 매칭하지만 일반 마우스 명령 분배 전에 메뉴를 열고, 아틀라스는 마우스 명령을 먼저 실행함. 우선순위를 통일해 오른쪽 클릭 명령을 다시 바인딩한 뒤 메뉴에 가로채이지 않게 해야 함 |

R02/R03의 스냅, R04의 직접 삭제, R05의 눈금자 드래그는 모두 각 컨트롤의 의미를 유지합니다. 도킹 그룹 빈 곳의 “모두 닫기”, 일반 메시 오른쪽 클릭의 현재 선택 작업도 합리적이라고 확인되었으므로 트리거 문제로 세지 않습니다. 빈 곳에서 현재 선택을 대상으로 하는 동작을 클릭 위치 기준 선택으로 바꿀 필요는 없습니다.

## 9. 모듈별 목표 순서와 계층

이 절은 제안 목표이며 현재 구현이 아닙니다. `｜`는 구분선, “…”는 창/대화 상자를 연다는 뜻입니다. 1차는 가능한 한 기존 도구 메뉴의 10행 예산을 넘지 않게 하며, 제목/설명과 내장 컨트롤도 높이에 포함합니다.

| 모듈 | 제안 목표 구조 | 2차와 컨트롤 |
|---|---|---|
| ArtMesh 트리 | 이름 → 유형 변환｜표시/숨김, 단독 표시｜생성 → 메시 → 그리기 순서…｜여기로 가져오기…｜레이어 삭제 | 생성: 부모 워프/부모 회전/경로/흔들림. 메시: 재구축/독립 메시 분할/앞뒤 분할, 유효한 기능에 따라 표시. 그리기 순서 초기화는 같은 관련 그룹에 둠 |
| 디포머 트리 | 이름｜생성 → 흔들림…(해당 시) → 하위 레이어 가져오기…｜펼치기/접기｜현재 삭제/체인 삭제… | 생성은 2차 사용. 현재/체인 범위를 먼저 정한 뒤 선택 강조와 문구를 맞춰야 함 |
| 참고 이미지 | 이름 → 변환(해당 시)｜표시/숨김 → 불투명도 → 잠금(해당 시)｜표시 위치 → 파라미터 고정｜제거 | 표시 위치는 현재값을 표시하는 단일 선택 2차. 고정 2차는 트랙/2차원 패널과 해제를 유지하고 연속 조작을 지원 |
| 파라미터 폴더 | 이름｜하위 파라미터 생성, 하위 폴더 생성｜이름 변경, 태그 색｜폴더 삭제 | 색 2차: 무색, 프리셋 색상 견본, 사용자 지정…. 위험 수준은 삭제가 폴더만 제거하는지/멤버에 영향을 주는지로 판단 |
| 파라미터 스냅샷 | 적용 → 현재값으로 덮어쓰기 → 이름 변경｜삭제 | 동작 3–4개를 평면으로 두며 2차 불필요. 덮어쓰기에는 현재 파라미터 값의 출처를 명확히 해야 함 |
| 모션 | 편집 → 재생/일시 정지｜이름 변경(사용자), 복사/사용자 모션으로 복사｜기본값 복원(내장이며 수정됨)｜삭제 | 평면 유지, 복원과 삭제는 다른 그룹. 무효한 조작은 비활성화하고 이유 설명 |
| 물리 그룹 | 이름 변경 → 복사 → 흔들림 편집(해당 시)｜위로 이동, 아래로 이동｜생성값 복원(재정의 있을 때)/사용자 그룹 삭제 | 2차 불필요. 활성 상태는 기존 체크박스로 유지할 수 있으며 중복 설정 폼을 추가할 필요 없음 |
| 시뮬레이션 바디 | 베이크/다시 베이크 → 베이크 지우기｜삭제 | 짧은 메뉴 유지. 이름 변경 등 관리 기능은 필요성을 먼저 확인하고, 대칭을 위해 무작정 추가하지 않음 |
| 아틀라스 타일 | 선택 이름/개수 → 선택에 초점 맞추기｜밀도와 회전 작업 → 각 대상 페이지｜잠금/잠금 해제｜선택 배치 → 이미지 교체(단일 선택) | 보통 여섯 페이지 이하이므로 페이지 이동 대상은 계속 평면으로 표시. 가용 높이를 넘으면 스크롤바 표시. 밀도와 회전을 계층으로 나눌지는 전체 레이아웃으로 평가 |
| 아틀라스 빈 곳 | 페이지 이름｜이 페이지 전체 선택 → 이 페이지에 맞추기｜모두 배치｜현재 페이지 저장… | 다른 선택 타일이 남아 있어도 “현재 페이지” 범위는 영향받지 않음 |
| 도킹 탭 | 패널 이름｜띄우기/도킹으로 복귀｜현재 닫기, 같은 그룹의 다른 항목 닫기, 이 그룹 모두 닫기 | 현재 패널 유형과 맞지 않는 캔버스 닫기 문구를 표시하지 않음. 닫기 범위를 명시 |
| 도킹 그룹 빈 곳/핸들 | 모두 닫기 | 항목 하나짜리 그룹 메뉴를 유지하며 확장하거나 진입점을 없앨 필요 없음 |
| 최상위 작업 공간 | 작업 공간 이름｜이름 변경, 복사｜작업 공간 닫기, 다른 작업 공간 닫기, 오른쪽 작업 공간 닫기 | 평면 유지. 전역 페이지 탭을 닫을 수 있는지는 기존 제약을 따름 |
| 최근 파일 | 열기/생성 → 폴더 표시｜최근 기록 제거 | 평면 유지. 디스크 파일 삭제는 추가하지 않음 |
| 로그 표 헤더 | 시간, 출처, 태그 세 개의 독립 체크｜기본 열 배치 복원 | 독립 스위치는 상호 배타적이지 않음. 연속 체크 중에는 메뉴를 닫지 않고 초기화 후 닫음 |

## 10. 2차 메뉴와 컨트롤 정리

### 10.1 2차 메뉴의 구체적인 문제

| 문제 | 확인된 구현/제약 | 정리 요구 |
|---|---|---|
| 동적 접기가 위치를 바꿈 | `foldedGroups`가 도구 내용과 행 수에 따라 계층을 바꿈 | 생성, 메시, 소재, 미러 등은 계층을 고정하고 크기/강도 등 고빈도 컨트롤은 1차에 고정 |
| 아틀라스 메뉴가 가용 높이를 넘음 | 아틀라스는 대상 페이지마다 1차 `CompactMenuItem`을 하나씩 생성하며 보통 여섯 페이지 이하. 컨테이너에 통일된 스크롤 보장이 없음 | 평면 구조를 유지하고 가용 높이로 제한하며 스크롤바를 제공. 페이지가 여럿이라는 이유로 2차를 강제하지 않음 |
| 2차 비활성 상태 인터페이스 없음 | `FloatingMenuSubmenuRow`에 `enabled`가 없음. 참고 이미지 고정은 편집 중에도 유휴 탐색 셸을 열 수 있고, 소재 2차도 모든 하위 항목이 비활성일 수 있음 | “읽기 전용 보기 허용”과 “실행 가능한 하위 항목 없음”을 구분. 비활성이 필요하면 통일된 시각 표현과 적중 규칙을 지원 |
| 2차 컨테이너에 통일된 스크롤 없음 | `MenuSecondLevel`은 `heightIn(max = 540.dp)`뿐이고 일반 `GlidingColumn`은 스크롤하지 않음. 참고 이미지 고정은 내부에 따로 340dp 스크롤이 있음 | 공유 레이어에서 뷰포트 제약과 스크롤을 처리하고, 하위 내용마다 따로 보완하는 데 의존하지 않음 |
| 키보드 탐색 규칙이 완성되지 않음 | 2차 Popup은 `focusable = false`이고 행은 클릭/호버만 제공. 통일된 위/아래·왼쪽/오른쪽, Home/End, Esc 계층 탐색이 보이지 않음 | 공유 포커스/활성 항목 모델을 추가. 방향키로 2차를 열고 닫으며, Esc는 2차를 먼저 닫은 뒤 1차를 닫고, Enter로 동작 실행. Popup을 포커스 가능하게만 바꾸면 안 됨 |
| 호버 즉시 열기와 영역 이탈 시 닫힘 | `FloatingMenuSubmenuRow`는 호버하면 즉시 `onOpen`. 1차에서 다른 행에 들어가면 2차를 닫음 | 공유 Motion 단계에 따라 지연/영역 이탈 허용을 평가. 가장자리에서 왼쪽으로 펼치기, 대각선 진입과 좁은 창을 실측해 잘못 닫히지 않게 함 |
| 이름이 매우 김 | 여러 곳이 236dp 고정, 하위는 196dp, 텍스트는 한 줄 생략 | 기존 토큰과 네 언어로 측정하고 필요한 ID/전체 이름 툴팁을 유지. 고정 너비라고 해서 사용자가 생략된 조작 대상을 추측하게 해서는 안 됨 |

### 10.2 컨트롤 선택

| 데이터 의미 | 사용할 컨트롤 | 현황과 개선 |
|---|---|---|
| 일회성 명령 | `FloatingMenuRow`, 아이콘/단축키 포함 가능 | 기존 `CompactMenuItem` 컨텍스트 메뉴 내용을 이전하고 위험 행은 따로 구분. 모든 일반 명령에 아이콘을 강제하지 않음 |
| 상호 배타 선택 | `FloatingMenuRadio` 또는 짧은 세그먼트 컨트롤 | 참고 이미지 표시 위치, 소재 격자/목록을 명확한 단일 선택으로 변경. 강조색 세로 막대만으로 상호 배타 관계를 표현하면 안 됨 |
| 독립 스위치 | 메뉴 체크/공유 스위치 행 | 폴더 트리 표시, 로그 열 표시, 잠금 등. 혼합된 다중 선택 상태에는 혼합 표시가 있어야 하며 “일부 잠김”을 모두 꺼짐으로 그리면 안 됨 |
| 연속 도구 설정 | `FloatingMenuSlider` + 수치 표시. 정밀 입력에는 공유 수치 편집 사용 가능 | 현재 슬라이더 오른쪽은 텍스트일 뿐이라 정확히 입력할 수 없음. 크기/반경은 로그 스케일 매핑, 단위와 키보드 단계를 유지. 짧은 메뉴에 인스펙터 전체를 넣지 않음 |
| 문서 연속 편집 | 미리보기 + 종료 시 한 번 커밋 | 참고 이미지 불투명도에는 이미 `previewReferenceOpacity`/`commitReferenceOpacity`가 있음. 닫기/포커스 잃음/취소 시 세션이 종료되는지 검증해야 함. 도구의 임시 설정은 문서 히스토리에 기록할 필요 없음 |
| 색상 분류 | 이름/툴팁이 있는 색상 견본 + 사용자 지정… | 파라미터 폴더 프리셋 색에는 접근 가능한 이름/선택 상태가 있어야 하고, 별도의 사용자 색상 창은 커밋/취소가 명확해야 함. 색만으로 판단하게 하면 안 됨 |
| 파라미터 고정 | 전용 트랙/2차원 패널 | 유지. 명확한 작업 전용 컨트롤이며 수백 개의 파라미터 값 메뉴 행으로 펼치지 않음. 비활성, 스크롤과 일괄 연속 조작이 완전해야 함 |
| 다수의 대상 선택 | 검색과 스크롤이 있는 선택기 | 트랙 파라미터, 물리 파라미터, 폴더, 대상 페이지가 많을 때 사용. 왼쪽 클릭 선택기는 왼쪽 클릭을 유지하며 오른쪽 클릭으로 강제 변경하지 않음 |
| 상태/비활성 이유 | 제목, 설명, 끝 부분 안내 | 동작이 아닌 항목은 슬라이딩 강조에 참여하지 않음. 단축키 끝 열과 상태 끝 열을 구분하고 단축키는 `keymap.labelFor`에서 읽음 |

### 10.3 공유 셸과 동작 수명 주기

- 컨텍스트 메뉴는 `PressMenu + GlidingColumn + FloatingMenu*`로 통일하고 `MenuGlide` 하나를 공유합니다. `TreeContextMenu`를 직접 쓰는 호출 지점을 이미 통일된 것으로 볼 수 없습니다.
- 높이는 가용 창 크기로 제한하고 스크롤할 수 있어야 합니다. `PressMenu`는 현재 560dp 상한이 있고 `TreeContextMenu`는 기본적으로 높이/스크롤 보장이 없습니다. 고정 dp 상한은 작은 창과 높은 배율에서도 검증해야 합니다.
- 트리거 지점을 기록하고 메뉴 호스트 좌표로 변환합니다. 도킹과 작업 공간 탭은 현재 마우스 좌표를 기록하지 않습니다. 접힌 디포머 체인의 이름 조각은 **조각의 로컬 좌표**를 행 메뉴 위치에 그대로 쓰므로 행/호스트 좌표로 변환한 뒤 사용해야 합니다.
- 일반 동작은 먼저 메뉴를 닫고 실행한 뒤 소속 패널로 포커스를 복원합니다. 대화 상자/창을 여는 동작은 새 창의 포커스를 유지하고, 연속 조정은 메뉴를 유지합니다. 기존 도구 메뉴에는 `keepsMenu`/`opensDialog`와 `invokeMenuAction`이 있으므로 다른 메뉴도 같은 규칙을 재사용해야 합니다.
- 모든 동작의 포커스를 무작정 주 캔버스로 돌려보내지 않습니다. 이름 변경은 입력 포커스를 유지하고, 애니메이션은 타임라인을 유지하며, 보조 스냅샷 관리는 해당 패널 기준으로 처리합니다.
- 동작 사용 가능 여부는 업무 기능, 선택 유형, 현재 작업 공간, 백그라운드 작업/초안 상태와 콜백 존재 여부를 모두 반영해야 합니다. ArtMesh/디포머 생성은 현재 `editable`만 판단하며 호출은 nullable 콜백입니다. 연결 상태를 확인해 클릭은 되지만 아무 동작도 하지 않는 상황을 막아야 합니다.
- 오른쪽 클릭 우선순위는 컨트롤이 소비함 → 현재 제스처/마우스 바인딩 → 이 컨텍스트 메뉴로 통일합니다. 메뉴를 여는 것만으로 편집을 커밋하거나 오브젝트를 삭제하거나 포즈를 바꾸면 안 됩니다.
- 다중 선택 중 기존 멤버를 오른쪽 클릭하면 집합을 유지하고, 선택하지 않은 오브젝트를 오른쪽 클릭하면 규칙에 따라 선택을 전환합니다. 메뉴는 명령이 단일 오브젝트용인지 선택 전체용인지 설명해야 합니다. 계층은 현재 일부 다중 선택 외형을 유지하지만 ArtMesh 행 명령은 여전히 해당 행 ID를 대상으로 하므로, 사용자가 일괄 작업으로 오해하게 해서는 안 됩니다.

## 11. 실행 우선순위와 검수

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| P1-A 조작 범위와 분배 확인 | U01 파라미터 관리 진입점, C03 접힌 체인 삭제 범위, C04 단일/다중 선택 범위, C06 여러 참조 위치 찾기, X04 마우스 명령 우선순위 | 문구의 대상/개수가 실제 실행과 일치. 다시 바인딩한 명령을 메뉴가 가로채지 않음. R02–R04 컨트롤 전용 빠른 동작 유지 |
| P1-B 메뉴 표현 정리 | 상단 메뉴의 정보 구성과 자주 쓰는 항목 배열은 별도로 정리. Compact 컨텍스트 메뉴 호스트 8개와 기타 셸 2개의 공유 좌표, 스크롤, 위험 행, 비활성 이유, 포커스 규칙. 아틀라스 스크롤바 | 동종 메뉴의 외형/강조가 일치하고 좁은 창과 배율에서도 접근 가능. 아틀라스 페이지 평면 표시를 유지하고 일반 메시 오른쪽 클릭의 선택 규칙은 바꾸지 않음 |
| P1-C 주요 오브젝트 진입점 추가 | M01–M05, C11 이름 변경, 트리와 캔버스 명령 정렬 | 같은 오브젝트의 같은 동작은 사용 가능 여부가 일치. 기존 편집 기능을 호출하고 애플리케이션 계층을 우회하지 않음 |
| P2 | M06–M07, 참고 이미지 위치/소재 보기 2차, 폴더 색 2차 | 컨테이너와 오브젝트 범위가 명확. 고빈도 조작은 여전히 1차에 있음. 도킹 그룹 빈 곳의 “모두 닫기” 유지 |
| P3 | O01–O03, 접근성/검색 강화 | 구체적인 사용 시나리오가 있을 때 추가. 커버리지를 위해 모든 빈 곳에 메뉴를 붙이지 않음 |

후속 동작 변경의 검증 매트릭스:

1. 오브젝트, 빈 곳, 다중 선택 중 멤버, 선택하지 않은 오브젝트, 대상 없음, 읽기 전용, 작업 중, 생성 전/후. 내장/사용자 모션과 출처별 물리 그룹.
2. 주 캔버스, 여러 캔버스, 소재 편집 창, 도킹 플로팅 창. 창 네 모서리의 트리거 지점. 2차의 왼쪽/오른쪽 펼치기와 스크롤.
3. 밝은/어두운 테마, `uiScale`/`fontScale`, 중국어·영어·일본어·한국어. 긴 이름, 단축키 변경, 혼합 상태, 사용 가능한 하위 항목 없음.
4. 마우스 누름과 놓음, 하위 컨트롤이 소비한 이벤트, 오른쪽 드래그 바인딩, Esc, 방향키, Enter. 메뉴가 닫힌 뒤의 올바른 포커스.
5. 문서 동작은 저장소 핵심 불변 조건에 따라 히스토리 재생, 프로젝트 저장 후 다시 열기, 필요한 내보내기 결과 다시 읽기와 시각 검증을 확인합니다. 단순한 메뉴 재배열/문구 변경에는 무거운 테스트를 추가로 도입하지 않습니다.

이번에는 감사 문서만 추가했습니다. 저장소 문서 작업 규칙에 따라 테스트나 빌드는 실행하지 않았습니다. 위의 런타임 항목은 모두 **검수 대기** 상태이며, 정적 소스 코드만으로 실측 통과로 표시할 수 없습니다.
