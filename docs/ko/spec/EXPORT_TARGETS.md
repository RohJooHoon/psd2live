# 중립 리그 IR과 내보내기 대상

[문서 목록](../../README.md) · [中文](../../zh/spec/EXPORT_TARGETS.md) · [English](../../en/spec/EXPORT_TARGETS.md)

모든 내보내기는 같은 중립 리그 IR에서 시작합니다. 편집기가 현재 커밋된 리그를 IR로 컴파일하면, 각 내보내기 대상이 IR을 자기 형식으로 낮추고, 그 형식이 유지할 수 없는 것을 나열한 손실 보고서를 씁니다.

## 모듈

| 모듈 | 내용 | 라이선스 |
| --- | --- | --- |
| `:format-model` | 중립 리그 IR(`RigIR`): 파라미터, 파츠, Warp / 회전 디포머, 메시, 키폼 격자, 채널, 블렌드 셰이프, Glue, 그리기 트리, 텍스처 페이지와 타일, 물리 그룹, 모션 클립, 편집기 부가 데이터 | MIT |
| `:format-compile` | 내보내기 프레임워크: `ExportTarget`, `CapabilityProfile`, `LossEntry`, `ExportReport`, `Compiler`. 낮추기 패스: 기능 스캔, 교차항 오차를 측정하는 파라미터별 베이크(`ParameterBake`), 키프레임 축소(`KeyReduction`), 모션 클립 샘플링. 호스트 인터페이스 `FrameRenderer`, `GeometryEvaluator` | MIT |
| `:targets:raster` | `png-sequence`, `sprite-sheet`, `gif`, 그리고 ffmpeg로 인코딩하는 `mp4`, `webm`, `mov`, `apng`, `webp` | MIT |
| `:targets:spine` | `spine`: Spine 4.2 스켈레톤(JSON 또는 바이너리 `.skel`) + 아틀라스. 회전 디포머는 뼈로 쓰고, 그 밖의 변형은 호스트가 제공하는 기하 평가기로 베이크 | MIT |
| `:targets:dragonbones` | `dragonbones`: DragonBones 5.5 스켈레톤 JSON + 아틀라스. 변형은 호스트가 제공하는 기하 평가기로 베이크 | MIT |
| `:targets:runtime` | `p2lrt`: PSD2Live 런타임 모델. [런타임](RUNTIME.md) 참고 | MIT |
| `:format-eval` | Rust 런타임의 JVM 바인딩(JNA). 기하 평가기로 사용 가능 | MIT |
| `:targets:gltf` | `gltf`: glTF 2.0 바이너리(`.glb`). 변형은 파라미터 키별로 모프 타깃에 베이크하며, 호스트가 제공하는 기하 평가기로 샘플링 | MIT |
| `:targets:unity` | `unity`: Unity 프리팹(`.p2lunity` + 텍스처 + 에디터 가져오기 스크립트). 파라미터 키는 Blend Shape로 베이크하고, 모션은 Animator 클립으로 씀 | MIT |
| `:targets:web` | `web`: 웹 플레이어(런타임의 WebAssembly 빌드, WebGL 재생 스크립트, 페이지와 모델) | MIT |
| `:targets:cubism` | `PuppetModel`과 IR 간 양방향 변환기(`PuppetIr`), `moc3`, `cmo3`, `vtube-studio`, motion3 / physics3 / exp3 / pose3 라이터 | GPL-3 |
| `:targets:psd` | `psd-pose`: 지정한 포즈의 레이어 PSD | GPL-3 |
| 루트 프로젝트 | `RigIrCompiler`(미리보기 모델 → IR), `IrFrameRenderer`(호스트가 제공하는 렌더러), `ExportService`, CLI와 UI | GPL-3 |

MIT 모듈은 어떤 GPL 모듈에도 의존하지 않으며, Gradle의 의존성 그래프가 컴파일 시점에 이를 강제합니다.

## IR 규약

- 메시의 정지 위치와 모든 디포머의 키폼은 부모 디포머의 공간에 있습니다. 루트에서는 캔버스 픽셀(y 아래쪽), Warp의 자식은 0–1 격자 공간, 회전의 자식은 로컬 픽셀 좌표입니다.
- 모든 ID는 안정적이며 재생성 후에도 유지됩니다.
- 모션 클립은 이미 프리셋에서 파라미터 커브로 컴파일되어 있습니다. 베지어 제어점의 시간은 해당 구간 안으로 제한되며, 커브 매개변수는 시간에 따라 선형으로 진행하며 평가합니다(Cubism의 `AreBeziersRestricted`와 일치).
- `restPose`는 캔버스 공간의 기본 메시가 필요한 형식에서 기본 메시를 베이크할 때 쓰는 파라미터 값을 지정합니다(예: 텍스처 좌표가 이미지 전체를 덮도록 입을 벌린 상태로 유지).
- `PuppetIr`는 양방향으로 무손실입니다. `toPuppet(toIr(model))`은 원래 모델과 필드 단위로 일치합니다. 어느 쪽에든 필드를 추가하면 같은 변경에서 변환기를 업데이트해야 합니다.

## 내보내기 대상

`spine`, `dragonbones`, `gltf`는 실험적 대상입니다. 파라미터별로 베이크한 결과를 더하므로, 조합된 포즈가 편집기와 눈에 띄게 다릅니다. **파일 → 다른 형식으로 내보내기** 메뉴에는 숨겨져 있으며 명령줄에서만 내보낼 수 있습니다(`psd2live targets`가 실험적이라고 표시). `unity`는 같은 베이크를 쓰지만 **파일 → 다른 형식으로 내보내기**에 나타납니다. 내보내기 폴더를 통째로 Unity 프로젝트의 `Assets`에 복사하면, 함께 들어 있는 설치 스크립트가 가져오기 도구를 `Assets/PSD2Live/Editor`로 옮기고 스스로를 삭제하므로, 두 번째 캐릭터도 통째로 복사할 수 있습니다. 아래 실험적 대상의 설명은 현재 상태를 기록한 것입니다.

| ID | 분류 | 출력 | 주요 손실 |
| --- | --- | --- | --- |
| `moc3` | 구조화 리그 | `.moc3`, model3, physics3, motion3, exp3, pose3, cdi3, userdata3, 텍스처 | 대상 런타임 버전이 지원하지 않는 기능은 제거됨. 메시 여러 개로 된 [히트 영역](#히트-영역)은 같은 이름의 항목 여러 개가 됨 |
| `cmo3` | 구조화 리그 | Cubism Editor 프로젝트. 모션 클립이 있으면 같은 이름의 `.can3`(Cubism Animator 프로젝트)도 씀. 파라미터 반복은 `isRepeat`로 씀(Cubism 5.3 대상. 그 이전 대상은 제거하고 손실 보고서에 기록) | 생성기의 의도는 유지되지 않음. 모션 클립의 눈 깜빡임과 립싱크 효과 커브는 쓰지 않음([Cubism Animator](#cubism-animator) 참고) |
| `dragonbones` | 구조화 리그 | `_ske.json`, 페이지별 `_tex_<i>.json`과 텍스처 | Spine과 같은 파라미터 애니메이션 및 클립 베이크. 키는 프레임으로 반올림. 불투명도는 정수 백분율로 저장. 런타임이 각 애니메이션의 변형 데이터를 16비트 오프셋으로 참조하므로, 넘치면 더 큰 허용 오차로 키를 줄이고 보고(뼈대 모델의 전신 클립은 오차가 더 큼). 마스크, 스크린 색, 물리는 쓰지 않음 |
| `vtube-studio` | 구조화 리그 | 모든 `moc3` 파일 + `.vtube.json` | `moc3`와 같음. 얼굴 추적은 표준 파라미터(머리, 몸, 눈, 시선, 눈썹, 입, 호흡)에 연결하고, 모션 클립마다 단축키 하나, 표정마다 `ToggleExpression` 단축키 하나. 그 밖의 설정은 VTube Studio 기본값. 리그 모듈로 만든 모델(해당 파라미터가 있음)은 조정된 매핑을 받음: 몸은 더 많이 스무딩하여 한 박자 늦게 머리를 따름. 눈 뜸에는 데드 존과 포화가 있고 클램프됨(2까지 크게 뜰 수 있는 눈이 평범하게 뜬 눈으로 크게 떠지지 않음). 입 벌림은 과구동되고 입 모양은 가운데 근처에 데드 존이 있음. 웃음은 눈을 휘게 함. 얼굴 캡처의 입 좌우 이동과 볼 부풀림이 해당 파라미터에 도달 |
| `spine` | 구조화 리그 | 스켈레톤 JSON 또는 `.skel`, `.atlas`, 텍스처 페이지 | 회전 디포머는 뼈 체인이 되고 메시는 가장 가까운 회전 뼈에 붙음. 각 파라미터는 1초짜리 애니메이션이 됨(시간은 파라미터의 정규화된 값). 뼈 변환과 뼈 공간의 변형에 키를 두며, 교차항은 Spine의 뼈 수학으로 측정해 보고. 모션 클립은 프레임마다 샘플링하고 키프레임을 축소. Warp, 블렌드 셰이프, Glue는 없음(베이크). 마스크는 윤곽 다각형에 의한 클리핑이 됨(반전 마스크는 버림). 뼈 회전을 구동하는 진자는 물리 제약이 되고(근사), 그 밖의 물리와 스크린 색은 쓰지 않음 |
| `p2lrt` | 구조화 리그 | `.p2lrt`(PSD2Live 런타임) | 편집기 부가 데이터(원본 레이어, 타일, 편집 경로)는 쓰지 않음. GPU 그리기는 호스트에 맡기며, 런타임의 `p2l_render`(ABI 1.3부터)는 마스크와 모든 합성 모드를 CPU에서 그림 |
| `web` | 구조화 리그 | `index.html`, `p2l.js`, `p2l_runtime.wasm`, `.p2lrt` | 런타임 헤더의 합성 규칙대로 모든 색과 알파 블렌드 모드를 그림(배경을 읽는 모드는 메시 아래 픽셀을 복사해 셰이더에서 합성), 분리 그룹도 그림(자식 메시를 먼저 레이어에 그린 뒤 그룹의 불투명도, 곱하기/스크린 색, 마스크, 블렌드 모드로 합성). 마스크(그룹 마스크 포함)는 스텐실 버퍼로 근사하며 텍셀 불투명도 0.5 이상을 덮인 것으로 셈. 레이어 프레임버퍼를 만들 수 없으면 분리 그룹은 통과로 그림. http로 제공해야 함 |
| `gltf` | 구조화 리그 | `.glb`(조명 없는 재질, 모프 타깃, 가중치 애니메이션) | 파라미터 키마다 모프 타깃 하나. 파라미터 조합은 가산 근사이며 오차를 보고. 그리기 순서는 정지 값에 따라 깊이로 층을 나눔. 마스크, 블렌드 모드, 파라미터별 불투명도, 물리는 쓰지 않음 |
| `unity` | 구조화 리그 | `.p2lunity`, 텍스처 페이지, 일회용 설치 스크립트 | Unity 6.0(6000.0) 이상 필요. 그리기 순서가 인접하고 같은 텍스처에 있는 메시는 하나의 스킨드 메시로 합침. 페이지가 번갈아 바뀌는 곳에서는 각 구간이 자기 `sortingOrder`를 유지. 파라미터 키마다 Blend Shape 하나, 파라미터 조합은 가산 근사이며 오차를 보고. 모션은 기본으로 Idle이라는 클립을 재생하는 Animator에 들어가며, 프리팹은 옆의 `.controller`를 사용. 마스크, 일반이 아닌 블렌딩, 스크린 색, 불투명도 커브, 물리는 쓰지 않음. 내보내기 폴더를 통째로 `Assets`에 복사하면 설치 스크립트가 가져오기 도구를 `Assets/PSD2Live/Editor`로 옮기고 스스로를 삭제함. 두 번째 캐릭터도 같은 방식으로 통째로 복사 |
| `psd-pose` | 합성/타임라인 | 보이는 메시마다 레이어 하나, 정지 상태의 그리기 순서 | 디포머와 파라미터는 유지되지 않음. 파라미터별 그리기 순서는 정지 값을 취함 |
| `png-sequence` | 래스터 | 번호가 붙은 PNG 프레임 | 모든 구조를 픽셀로 베이크 |
| `sprite-sheet` | 래스터 | 격자 스프라이트 시트 PNG + TexturePacker(hash) JSON | 위와 같음 |
| `gif` | 래스터 | 애니메이션 GIF | 256색(모션 전체의 픽셀에 대한 메디안 컷으로 255색을 구해 모든 프레임이 공유), 1비트 투명도 |
| `mp4` | 래스터 | H.264 동영상(ffmpeg) | 투명도 없음. 배경색(기본 흰색) 위에 합성 |
| `webm` | 래스터 | 투명도가 있는 VP9 동영상(ffmpeg) | 투명도는 VP9 부가 채널에 저장되며 디코딩에 libvpx 필요 |
| `mov` | 래스터 | 투명도가 있는 ProRes 4444(ffmpeg) | — |
| `apng` | 래스터 | 애니메이션 PNG(ffmpeg) | — |
| `webp` | 래스터 | 애니메이션 WebP(ffmpeg) | 손실 압축 |

래스터 대상과 `psd-pose`는 호스트가 제공하는 `FrameRenderer`로 렌더링합니다. 편집기의 구현(`IrFrameRenderer`)은 엔진의 CPU 평가기에서 기하를 얻고, `IrColors`로 채널과 블렌드 셰이프에서 곱하기/스크린 색을 파츠의 그리기 순서 및 그룹 합성 값과 함께 해석하며, `:format-compile`의 `SoftwareRasterizer`(MIT)로 픽셀 단위로 그립니다. 프리멀티플라이된 부동소수점 버퍼, 쌍선형 샘플링, 텍스처 알파에 의한 마스크(반전 포함), 그리고 `p2l_runtime.h`의 합성 규칙(편집기와 같음)에 따른 색 블렌딩과 알파 합성을 사용합니다. Cubism의 가산/곱하기는 알파 모드를 무시하고 대상 알파를 유지하며, normal과 over의 조합은 프리멀티플라이된 source-over이고, 그 밖의 모든 조합은 W3C 블렌드 함수를 취한 뒤 알파 모드로 겹친 부분에 가중치를 주고 해당 Porter-Duff 계수(over, atop, out, conjoint/disjoint over)를 사용합니다. 그리기 순서는 렌더 트리를 따릅니다. 각 그룹은 그리기 순서로 정렬되며, 그룹은 그 포즈에서의 파츠 그리기 순서로 정렬에 참여합니다. 분리된 파츠의 그룹은 먼저 비운 레이어에 그린 뒤, 그룹의 곱하기/스크린 색을 적용하고, 불투명도와 마스크 커버리지로 알파를 조정하고, 그룹의 블렌드 모드로 합성합니다. 진자 물리는 프레임 사이에 진행합니다.

### 설정

| 대상 | 설정 키 |
| --- | --- |
| `moc3` | `physics`, `user_data`, `display_info`, `hidden_parts`, `hidden_meshes`, `guide_parts`(불리언), `pixels_per_unit`(양수). 설정하지 않은 키는 프로젝트의 내보내기 설정을 따름 |

## 표정, 포즈, 이벤트

표정, 포즈, 모션 이벤트는 모션 클립처럼 리그를 바꾸지 않는 프로젝트 데이터입니다. `core/ModelSidecars.kt`에 정의되어 있으며, `expression_*`, `pose_*`, `motion_set_event` 문서 작업으로 편집합니다([MCP 사용법과 인터페이스](../agent/MCP_AUTHORING.md) 참고). `RigIrCompiler`가 이를 IR(`advanced.expressions`, `advanced.pose`, `Clip.events`)로 컴파일하면서 모델에 더 이상 없는 파라미터와 파츠를 버리며, 모든 대상이 거기서 씁니다.

- **표정**: `RigEditOverlay.expressions`가 null인 동안 생성된 리그에는 표준 표정(`ModelExpressions.standard`: Smile, Sad, Angry, Surprised. 인터페이스 언어로 이름이 붙고, 각각 모델에 있는 표준 얼굴 파라미터만 유지하며, 하나도 남지 않은 표정은 빠짐)이 있고, 가져온 CMO3 모델에는 없습니다. 처음 편집하면 그 순간의 목록을 문서로 가져오며, 그 뒤로는 문서의 목록만 내보냅니다. 항목이 없는 표정도 호스트가 초기화할 중립 표정으로서 내보냅니다. `moc3`는 표정마다 `<base>.<id>.exp3.json`(`Type`, `FadeInTime`, `FadeOutTime`, `Id` / `Value` / `Blend`가 있는 `Parameters`)을 하나씩 쓰고, model3 `FileReferences.Expressions` 아래에 순서대로 나열합니다(`Name`은 표정의 이름, `File`은 그 파일). `p2lrt`는 `EXPR` 청크를 씁니다. 표정 ID는 파일 이름에 안전한 1–64자이며, 이름은 프로젝트 안에서 고유합니다.
- **포즈**: `moc3`는 `<base>.pose3.json`(`Type`, `FadeInTime`, 그리고 `Groups` 각각의 파츠별 `Id`와 `Link`)을 쓰고 model3 `FileReferences.Pose`에서 참조합니다. 모델에 있는 파츠만 유지하며, 그룹이 없으면 아무것도 쓰지 않습니다. `p2lrt`는 `POSE` 청크를 씁니다(파츠가 둘 이상인 그룹).
- **이벤트**: 클립 이벤트는 motion3 `UserData`(시간순, `Meta.UserDataCount` / `TotalUserDataSize` 포함), `.can3`의 장면 사용자 데이터 프레임, `p2lrt`의 클립 확장 레코드에 들어갑니다. 이벤트만 있고 커브가 없는 클립은 다른 빈 클립과 마찬가지로 빠집니다.
- **파라미터와 파츠가 바뀔 때**: 파라미터를 삭제하면 그 표정 항목도 삭제되고, 범위를 좁히면 Overwrite 값을 범위 안에 붙잡아 둡니다. `ModelSidecars.withIdRenamed`는 파라미터나 파츠 ID가 바뀔 때 모션 커브, 표정 항목, 포즈 파츠를 업데이트하는 일반적인 방법이며, ID 변환은 이를 호출해야 합니다(아직 연결되지 않음). 그 밖의 경우(흔들림, 시뮬레이션, 레이어 삭제, 재생성)에 끊긴 참조는 프로젝트에 남습니다. 편집은 자기가 쓰는 항목과 파츠만 확인하며(표정이나 포즈 그룹은 자기의 끊긴 참조만 유지), `expression_get` / `expression_list`의 `missing`과 `pose_get`의 `missing_parts`가 그것을 나열하고, 내보내기는 건너뜁니다.
- **쓰인 ID**: `moc3`의 exp3, pose3, motion3는 moc를 쓸 때 사용한 ID로 객체를 가리킵니다(`Moc3Sidecars.withWrittenIds`, cdi3와 같은 방식). 길이에 맞게 줄인 ID는 줄인 형태를 쓰고, 쓰이지 않은 파츠(`hidden_parts` / `guide_parts`로 빠진 것)는 포즈에서 빠지며 그것 때문에 비게 된 그룹도 함께 빠집니다. 그 불투명도 커브는 모션에서 빠지고 커브, 구간, 점 수도 함께 조정됩니다. 모든 ID가 그대로 쓰이면 이 파일들은 파싱하지 않습니다.
- **미리보기**: 편집기의 미리보기 번들에는 pose3가 없습니다(Cubism SDK는 pose3를 불러올 때 그룹의 첫 파츠 외에 모두 숨김). 쓰인 파일에만 들어 있습니다.
- **내보내기 변경(3.6.0 이후)**: 생성된 리그는 이제 `moc3` / `vtube-studio`에서 표준 표정의 exp3 파일, model3 `Expressions`, VTube Studio 토글 단축키도 씁니다. 표정을 편집하지 않은 가져온 CMO3는 `p2lrt`에서 더 이상 표준 표정을 담지 않습니다. 생성된 리그를 CMO3 가져오기로 교체하면 그 순간의 표준 표정을 문서로 가져옵니다.
- **다시 읽기**: `PSD2LivePipeline`의 번들 확인은 model3가 참조하는 모든 exp3, pose3, motion3를 파싱합니다. 메시 전용 내보내기는 표정이나 포즈를 쓰지 않습니다. `cmo3` / `can3`는 표정과 포즈를 저장하지 않으며 `structure` / `dropped`로 보고합니다.

## Cubism Animator

`cmo3` 대상은 `<base>.cmo3`를 쓰고, IR의 모션 클립도 `<base>.can3`(`Can3`, `:targets:cubism`)로 씁니다. 레거시 **Live2D 모델 내보내기…**도 CMO3를 체크하면 이를 씁니다. motion3/모션 내보내기가 꺼져 있거나 메시 전용 모델이면 클립이 없으므로 can3를 쓰지 않습니다.

- **컨테이너**: cmo3와 같은 CAFF이며, 난독화되고 압축된 `main.xml` 하나만 담습니다.
- **모델 연결**: can3에는 모델이 들어 있지 않습니다. 단 하나의 리소스가 같은 폴더의 `<base>.cmo3`를 파일 이름으로 참조합니다. 파라미터는 ID(`live2dParam_<Id>`)로 연결되며, 파츠 불투명도 트랙은 같은 내보내기의 cmo3에 있는 그 파츠의 GUID를 담습니다. cmo3 GUID는 내보낼 때마다 달라지므로, can3는 함께 내보낸 cmo3와만 짝을 이룹니다.
- **장면**: 클립마다 장면 하나이며, 이름은 `<base>.<file>`로 moc3 내보내기의 motion3 파일 이름과 일치합니다. 장면은 Animator의 고정 트랙 구조를 따릅니다. 루트 그룹 트랙과 모델 트랙이 있으며, 모델 트랙은 비주얼, 파라미터, 파츠 불투명도, 립싱크, 눈 깜빡임의 다섯 가지 효과를 가집니다. 각 클립의 길이, 프레임 레이트, 반복, 페이드, 사용자 데이터(이벤트)는 장면과 모델 트랙에 들어갑니다.
- **커브**: 파라미터 커브는 파라미터 효과(표시 이름은 파라미터 이름에서, 범위는 모든 키를 덮도록 넓힌 파라미터 범위에서)에, 파츠 불투명도 커브는 파츠 효과에 들어가고, 전체 불투명도는 비주얼 효과의 불투명도를 대체합니다. 커브 자체의 페이드는 트랙 옵션에 들어갑니다. 키는 가장 가까운 프레임으로 반올림하고, 베지어 제어점은 원래 시간(소수 프레임)을 유지한 채 양 끝의 핸들이 되며, 계단형과 역계단형 구간은 유형을 유지합니다.
- **손실**: 눈 깜빡임과 립싱크 효과 커브는 Animator에 대응하는 트랙이 없습니다. 모델에 없는 파라미터나 파츠를 가리키는 커브와 함께 쓰지 않으며, `timeline` / `dropped`로 기록합니다.

## Spine

Spine에는 뼈는 있지만 파라미터는 없습니다. 내보낸 스켈레톤 공간은 원점이 캔버스 아래쪽 가장자리의 중점이고 y가 위쪽이며, 다음과 같습니다.

- **뼈**: 각 회전 디포머는 뼈가 되며, 그 부모는 위쪽에서 가장 가까운 회전 디포머(없으면 루트 뼈)로, 디포머 트리를 그대로 반영합니다. 내보내기는 편집기의 회전 규칙에 따라 뼈의 셋업 포즈와 키 값을 월드 프레임으로 계산한 뒤(「평가 규칙」, [런타임](RUNTIME.md) 참고: 각도는 키폼 각도에 기본 각도를 더한 것이고, 회전 부모 아래에서는 원점이 부모 변환을 거치며 각도와 스케일이 합성되고, 부모가 수직으로 뒤집혔거나 스케일이 음수이면 반 바퀴가 추가됨. 디포머 자체의 뒤집기는 자식 좌표에만 작용함. Warp 부모 아래에서는 프레임이 강체로 유지되며 격자 방향에 따라 회전), 부모 뼈 기준의 로컬 값으로 변환합니다. 이 프레임들은 모두 회전에 균일 스케일과 뒤집기를 더한 것이고 그 곱도 같은 부류에 머무르므로, 기울이기 없이 회전과 scaleX/scaleY(뒤집기는 음수 스케일)만 사용합니다. 각 뼈에는 자기가 담은 메시의 중심을 가리키도록 고정 회전도 붙으며, 길이는 그 방향으로 메시가 가장 멀리 뻗은 범위로 설정합니다. 샘플링한 포즈 중 어디서든 스케일이 0으로 향하는 회전은 뼈가 되지 않으며, 그 자식은 위쪽 뼈에 베이크되고 보고됩니다.
- **메시**: 보이는 각 메시는 가중치 없는 메시 어태치먼트이며, 그 슬롯은 가장 가까운 회전 뼈에 매달리고 정점은 그 뼈 공간의 좌표입니다. 뼈가 표현하지 못하는 것(Warp, 메시 키폼, 블렌드 셰이프, Glue)은 그 뼈 공간의 변형 오프셋으로 씁니다. 회전 조상이 없는 메시는 이전처럼 루트 뼈에 매달립니다.
- **파라미터**: 파라미터마다 1초 길이의 애니메이션 `param/<parameter ID>` 하나이며, 시간은 파라미터의 정규화된 값(최소 0, 최대 1)입니다. 파라미터의 샘플 지점에서 뼈의 `rotate`(셋업 각도와의 차이), `translate`(차이), `scale`(셋업 스케일의 배수)와 메시 변형에 키를 둡니다. 런타임은 파라미터마다 가산 블렌딩(`MixBlend.add`) 트랙을 하나씩 열고 파라미터 값으로 트랙 시간을 설정합니다. 뼈는 부모 체인을 따라 곱해지므로, 여러 파라미터가 한 회전 체인을 동시에 돌리면 캔버스 오프셋을 더하는 대신 직렬로 합성됩니다. 키폼 불투명도는 슬롯 `rgba`로, 파라미터별 그리기 순서는 `drawOrder`로 씁니다.
- **교차항**: `sample_pairs`개의 두 파라미터 조합 포즈에서 Spine의 가산 규칙(뼈 값과 변형 오프셋을 트랙마다 더하고, 스케일은 셋업 스케일에 배수의 차이를 더하며, 뼈를 단계마다 곱함)으로 포즈를 재구성해 평가기와 비교하고, 0.5픽셀 넘게 어긋난 메시를 손실 보고서에 넣습니다. Warp 아래의 회전(예: 자동 뼈대가 몸 Warp 아래에 매다는 머리와 위팔의 회전)은 단일 파라미터의 샘플 지점에서는 정확하지만, 그 Warp를 움직이는 파라미터와 조합하면 피벗이 Warp의 변형을 따르지 않으며, 이는 근사로 보고합니다. Warp로 구현된 관절(아래팔, 손, 상체 굽힘)은 여전히 뼈 공간에서 파라미터별로 더합니다.
- 모션 클립마다 애니메이션 `clip/<name>` 하나이며, `clip_fps`로 샘플링한 뒤 `KeyReduction`이 선형 보간으로 재구성할 수 있는 키프레임을 제거합니다. 변형 허용 오차는 `key_tolerance`픽셀이고, 뼈의 회전과 스케일 허용 오차는 캔버스 대각선 기준으로 같은 픽셀 양으로 환산하며, 이동은 1000분의 1픽셀까지 유지합니다.
- 아틀라스에는 페이지마다 페이지 전체를 덮는 영역이 하나 있으며, 그 페이지 이미지의 이름(`<name>_<i>`, 이미지 `<name>_<i>.png`)을 따릅니다. 메시 어태치먼트의 `path`가 그것을 가리키고, UV는 그 페이지를 직접 참조합니다. 런타임은 아틀라스를 통해 영역을 찾습니다. Spine Editor는 데이터를 가져올 때 아틀라스를 읽지 않고 `images` 폴더(`./`)에서 같은 이름의 이미지를 찾으므로, 가져온 직후 메시가 표시됩니다.
- 마스크는 클리핑 어태치먼트가 됩니다. 마스크된 메시 앞에 클리핑 슬롯을 삽입하고(`end`가 그 메시를 가리킴), 그 다각형은 단일 마스크 메시의 바깥 윤곽이며, 마스크가 여럿이거나 윤곽이 여럿이면 볼록 껍질을 쓰고 보고합니다. 클리핑 슬롯은 모든 마스크 메시가 공유하는 뼈에, 없으면 루트 뼈에 매달립니다. 클리핑 어태치먼트는 마스크 메시와 함께 변형 키를 받으며, 그리기 순서가 바뀌면 마스크된 메시와 함께 움직입니다. Spine은 텍스처 알파가 아니라 다각형으로 클리핑합니다. 반전 마스크는 표현할 수 없으므로 버리고 보고합니다.
- **물리**: 원본이 각도인 진자 그룹의 출력에 대해, 출력 파라미터의 애니메이션이 뼈를 회전시키면 그 뼈에 Spine 4.2 물리 제약(`rotate` 1)을 설정합니다. Spine은 뼈 자체의 움직임으로 제약을 구동하며 진자의 입력 파라미터는 읽지 않습니다. 설정은 경험적으로 매핑하며(관성 1, 강도 = 100 × 가속도, 감쇠 = 이동성, 믹스 = 출력 가중치 / 100, `fps`는 물리 그룹의 프레임 레이트, 기본 60), 원래 반응을 근사할 뿐이므로 근사로 보고합니다. 같은 출력 파라미터가 키를 두는 변형은 시뮬레이션되지 않으며 보고서에 이를 적습니다. 뼈 회전을 구동하는 출력이 없는 진자 그룹(Warp에 작용하는 자동 생성 머리카락 진자 등)은 버리고 보고합니다.
- **바이너리**: `binary=true`이면 Spine 4.2 바이너리 `.skel`을 씁니다(공개된 spine-runtimes 4.2 `SkeletonBinary` 레이아웃을 따름: 빅 엔디언 숫자, varint 양의 정수, 문자열 표, 비필수 데이터 없음). 내용은 JSON과 같습니다. 바이너리 메시는 삼각형 수를 저장하지 않고 리더가 「2 × 정점 수 − 헐 − 2」로 유도하므로, 헐 길이를 메시의 삼각형 수에 맞춰 설정합니다. 그 공식이 허용하는 것보다 삼각형이 많은 메시(삼각형이 중복된 경우에만)는 사용되지 않는 첫 정점의 사본을 덧붙입니다.
- 검증(구현되었으며 아래 테스트로 다룸. 공식 Spine 런타임은 라이선스상 Spine 라이선스를 보유해야 하므로 사용하지 않음). Spine 4.3 체험판은 JSON을 가져와 모든 메시를 표시합니다(버전 불일치와 비필수 데이터 누락은 경고일 뿐). 4.2 바이너리 `.skel`은 편집기가 버전 일치를 요구하므로 가져올 수 없습니다. 애니메이션과 마스크는 편집기에서 확인하지 않았습니다.
  - 단위 테스트는 Spine 4.2 런타임의 규칙(가산 트랙, 선형 키 보간, 셋업 포즈로부터의 오프셋인 가중치 없는 변형, 일반 상속에서 단계마다 곱하는 뼈, 오프셋 알고리즘으로 재정렬하는 그리기 순서)으로 포즈를 재구성합니다. 3단계 회전 체인(메시 키폼, 뒤집기, 음수 스케일 포함)은 단일 파라미터, 키 사이의 파라미터, 모든 파라미터를 동시에 바꾼 무작위 포즈에서, 같은 회전 규칙으로 독립 구현한 테스트 평가기와 0.002픽셀 이내로 일치합니다. 모션 클립은 샘플링한 프레임에서 일치합니다.
  - 테스트에서 공개 레이아웃으로 작성한 최소한의 `.skel` 리더가 바이너리를 다시 읽습니다. 뼈, 슬롯, 물리 제약, 어태치먼트, 각 애니메이션에서 재구성한 포즈가 JSON과 일치하며, 두 번 내보낸 결과는 바이트 단위로 같습니다.

## DragonBones

Spine과 같은 베이크를 사용합니다. 뼈, 보이는 각 메시는 가중치 없는 메시 디스플레이(원점은 캔버스 아래쪽 가장자리의 중점, y 아래쪽)이며, 파라미터마다 1초짜리 애니메이션 `param/<parameter ID>` 하나에 프레임으로 반올림한 파라미터 키에서 변형(ffd) 프레임을 두므로, 호스트가 파라미터 값으로 탐색하고 애니메이션을 가산으로 겹칠 수 있습니다. 각 클립은 프레임마다 샘플링하고 축소합니다. 프레임 사이의 보간은 `tweenEasing: 0`으로 명시합니다(기본값은 계단형). DragonBones 런타임은 각 애니메이션의 변형 부동소수점 데이터를 16비트 오프셋으로 참조하므로(각 프레임이 메시의 모든 정점을 저장), 약 32,000개의 부동소수점을 넘으면 두 배씩 늘린 뒤 이분 탐색으로 찾은 허용 오차로 키프레임을 줄이며, 손실 보고서에 사용한 허용 오차를 적습니다. 검증: `DragonBonesFidelityTool`(`PSD2LIVE_TOOLS=1`, node 필요)이 `tools/dragonbones-check`(공식 DragonBones 5.7 런타임 코어, 렌더링 없음)로 내보낸 결과를 재생합니다. 뼈대가 없는 샘플의 단일 파라미터 포즈는 키프레임에서 편집기와 0.25픽셀 이내로 일치합니다. 뼈대가 있으면 위의 한도에 영향을 받는 애니메이션은 보고된 허용 오차 안에 머물며, 클립 오차는 보고서에 있습니다.

## glTF

보이는 각 메시는 정지 포즈의 조명 없는(`KHR_materials_unlit`), 양면, 알파 블렌딩된 평면 메시가 되며, 각 레이어는 그리기 순서에 따라 보는 쪽으로 0.5 mm씩 이동합니다. 단위는 미터(`pixels_per_meter`, 기본 1000), y 위쪽, 원점은 캔버스 아래쪽 가장자리의 중점입니다. 각 파라미터의 기본값이 아닌 각 키는 그것이 움직이는 메시의 모프 타깃이 됩니다(`extras.targetNames`는 `parameter=key`). 파라미터 값은 키 사이의 선형 햇 함수로 가중치에 대응하며, 파라미터와 그 키는 `extras.psd2live.parameters`에 나열됩니다. 모션 클립은 `clip_fps`로 샘플링해 가중치 애니메이션으로 만들고 `KeyReduction`으로 축소합니다. 검증: 단위 테스트가 가중치로부터 샘플링한 포즈를 재구성합니다. tml 내보내기는 Khronos glTF Validator를 오류 0개, 경고 0개로 통과하며, Godot 4.4에서 정지 포즈와 고개 젓기 모션으로 올바르게 렌더링됩니다.

## Unity

Unity 6.0(6000.0) 이상이 필요합니다. 내보내기 폴더를 통째로 Unity 프로젝트의 `Assets`에 넣을 수 있습니다. 함께 들어 있는 설치 스크립트는 `Psd2LiveUnityImporter.cs`를 `Assets/PSD2Live/Editor`에 설치한 뒤(더 오래되지 않은 기존 사본은 덮어쓰지 않음) 스스로를 삭제하므로, 두 번째 캐릭터도 통째로 복사할 수 있습니다. 가져오기 도구는 그리기 순서가 인접하고 같은 텍스처에 있는 메시를 공유 루트 뼈 위의 스킨드 메시 하나로 합칩니다. 사이에 다른 텍스처의 파츠가 끼면 구간이 끊기며, 각 구간은 자기 `sortingOrder`를 사용하므로 앞머리가 뒷머리와 페이지를 공유한다는 이유만으로 얼굴 앞에 그려지지는 않습니다. 파라미터의 기본값이 아닌 각 키는 Blend Shape가 됩니다(glTF와 마찬가지로 가중치 0–100에 대한 햇 함수). 여러 파라미터가 동시에 바뀌면 가산 근사입니다. 모션 클립은 `clip_fps`로 샘플링해 Animator 클립으로 만듭니다. Idle이라는 클립이 있으면 기본 상태가 되고, 없으면 첫 클립을 재생합니다. 나머지 클립은 같은 이름의 `.controller`에 쓰이며, 전이가 없으므로 저절로 재생되지 않습니다. 그 파일이 생성되면 프리팹의 Animator가 그것을 가리키며, 장면에서 아직 내장 컨트롤러를 가리키는 인스턴스는 가져올 때나 계층이 바뀔 때 전환됩니다. 각 파라미터는 기본 상태 머신 밖에 `param_<id>` 클립도 받으므로, 프로젝트에서 따로 재생할 수 있습니다. 단위는 `pixels_per_unit`분의 1(기본 100), y 위쪽, 원점은 캔버스 중심입니다. 텍스처 V는 PSD2Live의 왼쪽 위 원점에서 Unity의 왼쪽 아래 원점으로 뒤집습니다. 캐릭터는 화면 밖에 있을 때 애니메이션하지 않습니다. 검증: 대상 모듈의 단위 테스트가 미끄러지는 사각형의 정점, Blend Shape, 0.5초에서의 가중치를 확인합니다. 전체 tml 캐릭터는 Unity 6000.4.7f1의 내장 렌더 파이프라인 프로젝트에 정지 포즈로 가져와지며, Play 모드에서 Idle을 재생합니다.

## 히트 영역

문서의 히트 영역(`rigEdits.hitAreas`. 인스펙터, 계층의 컨텍스트 메뉴, MCP `hit_area_*` 작업으로 편집)은 테스트 순서대로 `RigIR.hitAreas`로 컴파일됩니다. 각 영역은 자체 ID(`HitAreaHead` 등), 호스트가 요청하는 이름(`Head` 등), 덮는 메시를 가집니다. 메시가 분할되면(섬, 다각형, 깊이 조각) 그 조각들이 영역 안에서 원래 메시의 자리를 대신하고, 삭제된 레이어의 메시는 영역에서 빠집니다(메시가 하나도 남지 않은 영역도 빠짐). IR은 영역이 가리키는 모든 메시를 유지합니다. 대상은 리그에 더 이상 없는 메시를 빼며 각각을 `structure` / `dropped` 손실로 기록하고, 메시가 하나도 남지 않은 영역도 여전히 문서 자신의 것이므로 런타임의 자동 영역으로 대체하지 않습니다. 히트 영역을 담지 않는 대상(`cmo3`, `spine`, `dragonbones`, `gltf`, `unity`, `psd-pose`, 래스터 대상)은 각 영역을 `structure` / `dropped` 손실로 보고합니다.

- **`moc3` / `vtube-studio`**: model3.json의 `HitAreas`에 씁니다. 각 항목의 `Name`은 영역의 이름이고 `Id`는 moc가 쓴 ArtMesh ID입니다(moc가 줄였으면 줄인 형태. 옵션으로 생략된 숨겨진 메시처럼 moc에 없는 메시는 나열하지 않고 `structure` / `dropped` 손실이 되며, 하나도 남지 않으면 `HitAreas`가 없음). model3 항목 하나는 ArtMesh 하나를 가리키므로, 메시 여러 개로 된 영역은 같은 이름의 항목 여러 개가 되며 `structure` / `approximated` 손실이 됩니다(이름별로 첫 항목만 테스트하는 호스트는 첫 메시만 테스트함). 영역 자체의 ID는 model3에 들어갈 자리가 없습니다. 히트 영역이 없는 문서는 `HitAreas`를 쓰지 않으며, 내보내기 결과는 바이트 단위로 바뀌지 않습니다.
- **`p2lrt`**: 버전 2는 선택적 `HITA` 청크(영역 ID, 이름, 메시 인덱스)를 씁니다. 히트 영역이 없는 문서는 자동 `HitAreaHead`(얼굴)와 `HitAreaBody`(상의, 없으면 목이나 하의)를 유지합니다. 버전 1에는 히트 영역이 없으므로 문서의 각 영역은 `structure` / `dropped` 손실이 됩니다.
- **히트 규칙**: 목록 순서에서, 보이고 불투명도가 0보다 크며 삼각형(가장자리 포함)이 그 점을 포함하는 메시가 있는 첫 영역입니다. 편집기 미리보기에서의 클릭, MCP `hit_area_test`, 런타임의 `p2l_hit_test`가 이 규칙을 공유합니다. Cubism SDK 샘플은 메시의 경계 사각형을 테스트하므로 결과가 다를 수 있습니다.
- 바이너리 IR(`RigIrBinary`)은 인코딩 버전 6부터 이 필드를 담으며, 이전 버전은 빈 값으로 읽습니다.

## 손실 보고서

모든 내보내기는 파일 옆에 `<name>.<target>.report.json`을 씁니다.

```json
{"target":"gif","compiler":"2.0.4","files":["model.gif"],
 "losses":[{"object":"*","feature":"structure","handling":"baked","note":"..."}]}
```

`handling`은 `baked`(외형 유지, 크기 증가), `approximated`(허용 가능한 오차), `dropped` 중 하나입니다. `object`는 안정적인 ID이며 `*`는 리그 전체를 뜻합니다. 오차를 측정했으면 `error`가 붙습니다. 보고서에는 두 내보내기 간의 차이를 추적할 수 있도록 컴파일러 버전이 기록됩니다.

## 결정성

같은 IR과 같은 컴파일러 버전은 바이트 단위로 같은 출력을 만듭니다. 내보내기는 타임스탬프나 난수를 넣지 않습니다. 예외는 `cmo3`입니다. Cubism Editor가 모든 객체에 고유한 GUID를 요구하므로, 내용은 같아도 파일 바이트는 매번 다릅니다. 내보내기 경로를 리팩터링할 때는 `ExportGoldenTool`(`PSD2LIVE_TOOLS=1`)로 전후 커밋의 파일 다이제스트를 비교하며, cmo3는 다시 읽어 moc3로 낮춘 결과의 다이제스트로 비교합니다.

## 사용법

- UI: **파일 → Live2D 모델 내보내기…**는 moc3 / cmo3를 내보냅니다. **파일 → 다른 형식으로 내보내기**는 실험적이지 않은 나머지 대상을 **런타임 및 플레이어**, **이미지 및 동영상**, **레이어 PSD**로 묶어 나열합니다. 각 대상은 자체 대화 상자를 열어 현재 커밋된 상태를 내보내고 손실을 나열합니다. 각 대상은 `ExportTarget.settings`에 자기가 읽는 설정 키(모션 선택, 토글, 범위가 있는 숫자, 텍스트)를 선언하며, 대화 상자는 그 선언으로 해당 행을 만들고 사용자가 바꾼 값만 보내며, 나머지는 대상의 기본값이나 프로젝트의 내보내기 설정을 따릅니다. 변경 사항은 현재 실행 동안 대상별로 유지됩니다. 새 대상은 메뉴 그룹(`exportMenuGroups`, `ExportTargetSettingsTest`가 확인)에 등록해야 합니다.
- 명령줄: [개발과 명령줄](../guide/DEVELOPMENT.md)의 `export` 명령을 참고하세요. `psd2live targets`는 각 대상과 그 설정 키, 값 범위, 기본값을 나열합니다.
- 편집기 자체의 Cubism 미리보기 패키지와 `moc3` 내보내기는 하나의 컴파일입니다. **Live2D 모델 내보내기…**(MCP `project_export_model`)와 **다른 형식으로 내보내기**는 모두 커밋된 모델 자체를 쓰며(`PSD2LivePipeline.export`), 원본 이미지에서 다시 빌드하거나 기반 리그를 생성하지 않습니다. 차이는 보고서뿐입니다(전자는 다시 읽어 검증하고 `.psd2live.json`을 쓰며, 후자는 손실 보고서를 씀). 명령줄은 먼저 같은 빌드 경로(`buildPreview`)로 모델을 얻은 뒤 씁니다.
