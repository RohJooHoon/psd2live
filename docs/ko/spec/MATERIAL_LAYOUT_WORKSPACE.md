# 소재와 Layout 작업 공간

[문서 목록](../../README.md) · [PSD 소재와 명명 규칙](PSD_LAYER_SPEC.md) · [Layout 매니페스트](LAYOUT_MANIFEST.md) · [문서 계층](DOCUMENT_LAYER.md) · [프로젝트 형식](PROJECT_FORMAT.md) · [사용 가이드](../guide/LAYOUT.md) · [로드맵](../ROADMAP.md)

이 페이지는 기본 Layout의 구현, 즉 소재 라이브러리, 배치, 의미 태그, 그리고 "먼저 배치하고, 그다음 생성하며, 반복해서 추가하고 다시 생성할 수 있는" 리그 생성 흐름을 설명합니다. 정렬, 배경 제거, 보완 등 외부 AI에 의존하는 기능은 여기에 포함되지 않으며, [Layout의 AI 보조](LAYOUT_AI_ASSIST.md)(설계 중)를 참고하세요. 조작 방법은 [사용 가이드](../guide/LAYOUT.md)를, MCP 계약은 [MCP_AUTHORING.md](../agent/MCP_AUTHORING.md)를 참고하세요.

## 해결하는 문제

1. **생성이 너무 일렀습니다.** 이전에는 PSD를 가져오는 바로 그 단계에서 리그를 생성했기 때문에, 프로젝트에 "그림은 있지만 아직 생성하지 않은" 상태가 없었습니다.
2. **나중에 추가한 그림을 생성기가 인수하지 않았습니다.** 이전에는 `layer_import_images`로 추가한 레이어가 사용자 메시만 가지며 이후 생성에 참여하지 않았습니다. 이제는 이들도 생성 대기로 등록되고, 명시적으로 생성할 때 기존 토폴로지를 인수합니다.
3. **해상도가 캔버스에 묶여 있었습니다.** 작은 파츠는 캔버스 픽셀만 쓸 수 있었습니다. 프로젝트 하부 구조는 이미 캔버스 사각형과 래스터 해상도를 분리해 두었지만([레이어별 크기](DOCUMENT_LAYER.md#레이어별-크기)), 파츠별로 해상도를 고르는 주 흐름이 없었습니다.
4. **분류가 고정 열거형이었습니다.** "유형 / 파츠 / 좌우" 세 열의 드롭다운으로는 조합을 표현할 수 없고, 사용자 자신의 표식도 붙일 수 없었습니다.
5. **소재 관리가 없었습니다.** 프로젝트 안의 그림은 "이미 레이어인 것"이라는 한 가지 정체성만 가졌습니다.

## 전체 구조

- **Layout은 곧 소스 레이어 자체입니다.** 소재를 캔버스에 놓는 것은 `WorkspaceDocument.source`에 소스 레이어를 하나 추가하는 것입니다. 캔버스 사각형이 위치와 크기를 정하고, 픽셀은 소재의 원래 해상도를 유지합니다. 소스 이미지와 나란히 존재하는 별도의 Layout 문서는 없으며, "보내기" 단계도 없습니다.
- **생성은 명시적인 한 단계입니다.** 문서의 Layout 상태(`WorkspaceDocument.layout`, [`WorkspaceLayout`](../../../src/main/kotlin/io/github/psd2live/project/WorkspaceLayout.kt))는 생성이 어디까지 진행되었는지를 기록합니다. 즉 프로젝트가 이미 생성되었는지, 어떤 레이어가 마지막 생성 이후에 배치되었는지, 어떤 분류 변경이 아직 대기 중인지입니다. `rig_generate`는 대기 중인 내용을 생성기에 넘기고, 기존의 3방향 병합으로 사용자 편집을 유지합니다.
- **의미 태그**가 "유형 / 파츠 / 좌우"를 대체합니다. 생성기가 아는 단어는 파츠와 좌우를 정하고, 나머지는 사용자 자신의 표식입니다. 차분(토글 / 전환)은 별도의 열입니다.
- 편집기의 "선택" 모드는 "**오브젝트**" 모드로 이름이 바뀌었습니다(UI 문구와 튜토리얼에 한함. 내부 열거형 `EditHierarchyMode.SELECT`와 단축키 동작 `MODE_SELECT`는 이름을 바꾸지 않으므로 저장된 키 바인딩이 무효화되지 않습니다).

PSD 가져오기는 여전히 한 단계로 끝납니다. 새 프로젝트는 바로 생성되며 결과는 이전과 같습니다. 동시에 PSD의 각 레이어도 소재로 등록되고 대응하는 소스 레이어와 연결되므로, 소재 패널에서 교체, 다시 배치, 내보내기를 할 수 있습니다. [Layout 매니페스트](LAYOUT_MANIFEST.md)(JSON, 또는 루트에 매니페스트가 있는 zip)를 열면 생성되지 않은 프로젝트를 새로 만듭니다. 레이어는 매니페스트의 사각형, 쌓임 순서, 그룹, 태그, 차분대로 놓이고, 마찬가지로 소재로 등록되어 연결되며, 조정한 뒤 생성합니다.

## 의미 태그

### 모델

[`LayerTags`](../../../src/main/kotlin/io/github/psd2live/core/LayerTags.kt)가 어휘와 매핑을 정의합니다.

| 분류 | 단어 | 생성기 |
| --- | --- | --- |
| 부위 단어 | `hair` `back` `front` `headwear` `face` `detail` `eye` `iris` `white` `lash` `closed` `brow` `eyewear` `ear` `accessory` `nose` `mouth` `open` `teeth` `upper` `lower` `tongue` `neck` `top` `arm` `bottom` `leg` `foot` `tail` `wings` `object` | 읽음 |
| 좌우 단어 | `left` `right` | 읽음 |
| 사용자 태그 | 그 밖의 임의 텍스트(48자 이하, 쉼표와 제어 문자 제외) | 읽지 않음 |

- 각 `SemanticTag`는 부위 단어 한 묶음에 대응합니다. 예를 들어 `{hair, front}`는 앞머리, `{eye, iris}`는 눈동자, `{mouth, open}`은 벌린 입, `{neck, accessory}`는 목 장식입니다. 태그 묶음은 "그 부위의 단어를 모두 포함하면서 단어 수가 가장 많은" 부위에 대응합니다. 똑같이 구체적인 부위가 여럿이면 표의 순서에서 첫 번째를 취하고 모호함으로 표시합니다. 어느 부위에도 대응하지 않으면 "미인식"입니다.
- `left`와 `right`가 함께 있으면 양쪽으로 보며, 편집할 때는 둘이 상호 배타적입니다.
- 부위와 좌우는 여전히 레이어의 분류 오버라이드(`layerOverrides`)에 기록되므로, 생성기가 읽는 `LayerSemantic`은 이전과 완전히 같고 메시 ID도 바뀌지 않습니다. 사용자 태그는 `layout.layerTags`에 따로 저장되어 생성 설정에 들어가지 않으므로, 바꿔도 리그를 다시 만들지 않습니다.
- 차분(`PRESET / TOGGLE / SWITCH`와 파라미터, 전환 번호)은 의미가 아니므로 레이어의 차분 속성으로 유지되며, UI에서는 태그 옆 별도 열에 표시됩니다.

### 태그의 출처

- **이름 인식**: `LayerClassifier`의 별칭 표가 이전처럼 분류를 주고, 태그는 분류에서 환산합니다. 태그 편집 상자에 별칭(예: `前发`, `eye-l`)을 입력하면 대응하는 단어로 환산됩니다.
- **소재 태그**: 소재 항목과 폴더에 태그를 붙일 수 있습니다. 배치할 때 항목과 그것이 속한 모든 상위 폴더의 태그가 합쳐집니다. 부위와 좌우 단어는 레이어 분류로 기록되고, 나머지는 레이어의 사용자 태그가 됩니다.
- **수동**: 레이어 표의 태그 셀을 열면 태그를 삭제하거나 입력해 추가할 수 있고(어휘 자동 완성 포함), 부위와 좌우를 직접 고를 수도 있습니다.

### 생성 후 분류 변경

이미 생성된 레이어의 분류나 태그를 바꾸면, 새 분류는 먼저 `layout.generation.pendingClassifications`에 들어가고 리그는 여전히 생성 당시의 분류를 따릅니다. 다음 `rig_generate` 때에야 `layerOverrides`에 기록되고 재생성 병합을 거쳐 반영됩니다. 여러 번 바꿔도 병합은 한 번만 합니다. 생성기가 아직 읽지 않은 레이어(생성되지 않은 프로젝트의 레이어, 생성 후에 배치한 레이어)는 분류를 바꾸면 즉시 기록됩니다. 자동 의미 바인딩은 아직 생성되지 않았고, 메시는 항상 편집할 수 있습니다. 생성 설정(메시 밀도, 리그 수치 등)을 바꾸면 여전히 즉시 다시 생성합니다.

## 생성 상태

| 상태 | 캔버스 | 할 수 있는 일 |
| --- | --- | --- |
| 생성 전(`project_create`로 새로 만들었거나 Layout 매니페스트를 연 프로젝트) | 모든 레이어에 정식 메시가 있고, 자동 바인딩과 파라미터는 아직 생성되지 않음 | 일반 작업 공간의 편집과 내보내기. 작성자가 만든 디포머, 파라미터, 계층 포함 |
| 생성됨, 생성 대기 내용 있음 | 이미 생성된 부분은 평소처럼 리그를 표시하고, 이후 배치한 레이어는 정식 메시를 가짐 | 모든 것이 평소와 같음. 모든 레이어를 편집하고 내보낼 수 있으며, 다음 생성 때 자동 바인딩이 추가됨 |
| 생성됨, 생성 대기 내용 없음 | 이전과 같음 | 이전과 같음 |

이전 프로젝트에는 Layout 상태가 없으므로 "생성됨, 생성 대기 내용 없음"으로 읽히며, 열기, 저장, 문서 정체성 모두 이전과 같습니다.

### 통합 편집 모델

Layout과 일반 프로젝트는 같은 완전한 `RigPreviewModel`을 사용하며, 임시 배치 메시를 덧붙이거나 별도의 생성 모델을 유지하지 않습니다. 레이어가 캔버스에 들어오면 곧바로 편집 가능한 메시와 텍스처 타일을 가집니다. 생성되지 않은 프로젝트, 메시가 0개인 프로젝트, 생성 대기 레이어 모두 파라미터, 계층, 디포머, 메시, 텍스처를 편집할 수 있고 현재 모델을 내보낼 수도 있습니다. 모든 편집은 같은 문서 후보, 히스토리, 재생 경계를 거칩니다.

`WorkspaceDocument.config`는 Layout 상태에서 `deferRig`와 `rigPendingLayerIds`를 파생합니다. 이들은 자동 의미 리그만 제어합니다. 생성 대기 레이어는 정식 메시를 가지지만, 이미 생성된 부분의 자동 디포머와 키폼에는 참여하지 않습니다. `RigBuilder`는 같은 텍스처 아틀라스와 소스 이미지 목록 위에서 두 부분을 합친 뒤, 작성자 편집을 한꺼번에 재생합니다.

`rig_generate`는 생성 대기 레이어에 대해 `rig_mesh_seed`를 기록하여, 기존 기본 메시의 캔버스 정점, 텍스처 좌표, 삼각형을 저장합니다. 생성기는 태그에 따라 이 메시들 위에 바인딩과 파라미터를 맞추고, `RigRegenerationCheckpoint`의 3방향 병합으로 작성자 편집을 유지합니다. 메시 시드는 직렬화 가능한 저널 입력이며, 재생 자체는 모델을 수정하지 않습니다. 이후 명시적으로 형상을 새로 고치면 빈 시드를 기록하여 고정을 해제합니다. 생성 상태와 편집 능력은 서로 독립적이며, 빈 캔버스도 생성할 수 있습니다. 레이어 변형, 교체, 삭제는 모두 일반 작업 공간 작업을 사용하며, 마지막 레이어도 삭제할 수 있습니다.

### 쌓임 순서

소스 이미지의 레이어 순서가 곧 생성 시의 기본 그리기 순서입니다(`order`는 맨 위 레이어부터 셉니다. 입 등은 생성기에 별도 규칙이 있으며, 그리기 순서 눈금자 `layer_draw_order`의 설정이 우선합니다). `layer_reorder`(`WorkspaceLayoutEdits.reorder`)는 1–128개의 레이어를 맨 앞이나 맨 뒤로, 움직이지 않는 레이어 하나를 건너 앞이나 뒤로, 또는 어떤 레이어의 바로 위나 바로 아래로 옮깁니다. 옮기는 레이어들 사이에서는 원래의 앞뒤 관계를 유지하고, 모든 레이어에 새 순서로 번호를 다시 매기며, 나머지 레이어의 상대 순서는 바뀌지 않습니다.

생성기가 아직 읽지 않은 레이어만 옮길 수 있습니다. 즉 생성되지 않은 프로젝트의 모든 레이어, 생성 후에 배치한 생성 대기 레이어, 참조 레이어입니다. 생성 대기 레이어의 메시는 이미 모델에 있으므로 일반 그리기 순서와 계층 편집을 사용합니다. 이미 생성된 레이어는 생성 당시의 순서를 유지하며, 옮기려 하면 오류를 반환하고 그리기 순서 눈금자를 쓰라고 안내합니다. 변화가 없으면 히스토리를 추가하지 않습니다.

### 참조 레이어

`WorkspaceLayout.referenceLayerIds`에 있는 레이어는 참조 ArtMesh입니다. 캔버스에 들어오면 곧바로 네 점짜리 사각형 메시, 텍스처 타일, 일반 편집 능력을 가지며, 먼저 생성할 필요가 없습니다. 이들은 소스 이미지와 레이어 순서에 남지만 자동 의미 생성은 이들을 읽지 않으며, 모델은 이들을 가이드 이미지 파츠로 묶습니다. 가이드 이미지 쓰기를 허용하는 대상 설정에서만 내보냅니다. 이들은 생성 대기 내용에 포함되지 않습니다.

참조 메시는 `WorkspaceLayerInsertionEdits.materialize`가 만들며, 픽셀 윤곽을 추적하지 않고 캔버스 사각형을 그대로 덮습니다. 그 텍스처는 다른 메시와 함께 패킹되며, 일반 재생, 계층, 변형 작업 모두 이에 접근할 수 있습니다. `WorkspaceReferenceMeshes.sketched`가 메시를 가이드 이미지 파츠에 넣습니다. 배경과 전경 참조 이미지는 여전히 별도의 캔버스 참조 이미지 경로로 표시됩니다.

`layer_mark_reference`(`WorkspaceLayoutEdits.markReference`)는 1–128개의 레이어를 참조로 설정하거나 되돌립니다. 생성기가 읽지 않은 레이어(생성되지 않은 프로젝트의 모든 레이어, 생성 대기 레이어, 참조 레이어)만 받으며, 이미 생성된 레이어는 오류를 반환합니다. 이미 생성된 프로젝트에서는 참조로 설정한 생성 대기 레이어가 대기 목록에서 빠지고, 되돌린 참조 레이어는 대기 목록에 들어가 다음 `rig_generate` 때 생성됩니다. 빈 프로젝트나 참조 레이어만 있는 프로젝트도 생성할 수 있으며, 참조 메시는 계속 편집할 수 있습니다. 소재 항목의 `reference` 표시(`material_mark_reference`)는 배치할 때 기본으로 참조 레이어가 될지를 정하고, `layer_place`의 `reference`로 덮어쓸 수 있습니다. Layout 매니페스트의 `reference` 레이어는 열면 곧바로 참조 레이어가 되고, 소재로 가져올 때 항목에 표시가 붙습니다.

참조 레이어는 키폼에 고정할 수 있습니다. `WorkspaceLayout.referencePins`는 레이어 ID별로 파라미터 ID → 값을 기록하고, `ReferencePins.shows`는 어떤 포즈에서 표시할지 판단합니다(고정한 각 파라미터가 고정값에서 그 파라미터 범위의 0.5% 이내일 것. 리그에 더 이상 없는 파라미터는 판단에 참여하지 않음). 고정은 Layout 상태일 뿐 리그 저널에 들어가지 않습니다. 편집 캔버스는 편집 포즈에 따라 표시하지 않는 참조를 그리기와 클릭 선택에서 제외하고(`PSD2LiveState.pinnedAwayReferenceIds`), MCP 뷰는 요청한 포즈에 따라 걸러냅니다(`WorkspaceViewRenderer.modelComposite`의 `hiddenReferenceLayerIds`). `layer_pin_reference`(`WorkspaceLayoutEdits.pinReference`)는 참조 레이어와, 존재하는 파라미터 및 범위 안의 값만 받습니다. 모델 레이어로 되돌리면 그 고정을 제거하고, 레이어를 삭제하면 `retaining`과 함께 제거됩니다. `reference_place_grid`(`WorkspaceReferenceGrid`)는 문서 편집 한 번 안에서 차례로 `crop`, `place`(참조)를 하고 고정을 기록합니다. ID는 `<접두사>_<행>_<열>`이며, 접두사를 생략하면 소재, 파라미터, 값에서 파생합니다. `view_render_pad`(`WorkspacePadSheet`)는 같은 행·열 순서로 시트를 출력하므로 둘 사이를 왕복할 수 있습니다.

### 생성과 다시 생성

`rig_generate`는 문서 편집 한 번이며 히스토리 노드 하나입니다.

1. 생성되지 않은 프로젝트: 기존 기본 메시나 인수할 작성자 메시의 시드를 기록하고, 생성됨으로 표시한 뒤, 태그에 따라 이 메시들 위에 바인딩과 파라미터를 생성합니다.
2. 이미 생성된 프로젝트: 생성 대기 레이어를 생성에 넣고, 대기 중인 분류를 `layerOverrides`에 기록합니다. 형상을 새로 고치기로 선택한 레이어(기본값은 이미지를 교체한 레이어이며, `refresh_geometry`로 지정할 수 있고 `[]`는 모두 유지)는 동결된 생성 입력(`generationSource`)에서 제거하고 현재 픽셀에서 생성합니다.
3. 그다음 평소처럼 후보를 준비합니다. 분류 변경은 `normalizeMeshEdits`의 재생성 병합을, 새 레이어는 빌드 시의 재생성 병합(`RigRegenerationCheckpoint`)을 거칩니다. 사용자가 바꾸지 않은 것은 새 생성 결과를 따르고, 사용자가 바꾼 것은 유지되며, 생성 대기 레이어는 이미 만들어진 메시 토폴로지를 그대로 씁니다. 기존 메시의 ID는 `splitDrawableIds`가 고정합니다. 가져온 이미지의 생성 기록은 히스토리가 되며, 생성이 인수한 뒤에는 그 레이어의 형상을 더 이상 제외하지 않습니다. 3방향 병합은 그 일반 메시를 원래 기준선으로 삼으므로 자동 바인딩이 정상적으로 추가될 수 있습니다. 병합으로 깔끔하게 옮기지 못한 내용은 `quality.regeneration`에 들어갑니다.

이미 생성된 레이어에 대한 `layer_transform`은 사용자의 메시 편집이며, 재생성 병합이 이를 유지하고 캔버스 사각형으로 환산해 되돌리지 않습니다.

CMO3의 완전한 모델은 여전히 `project_import_cmo3`로 가져오며 Layout 흐름에 들어가지 않습니다. 이미지 한 장은 16 MP 제한을 받고, 한 번에 최대 64개 경로, 4096개 파일, 256 MiB까지 가져올 수 있습니다.

### 저장

- 소재 라이브러리는 문서 데이터(`layout.materials`)이며 **히스토리에 들어갑니다**. 가져오기, 폴더 만들기, 이동, 이름 바꾸기, 삭제, 태그, 해상도 변경 모두 실행 취소할 수 있는 편집입니다.
- 픽셀은 내용 주소 기반의 중복 제거 래스터(작업 디렉터리 `blobs/`, 아카이브 `assets/`)를 그대로 쓰며, 소스 레이어와 같은 사본을 공유합니다. SVG 원문은 소재 노드에 직접 저장합니다. PSD 원본 파일은 따로 저장하지 않습니다.
- [v2 아카이브](PROJECT_FORMAT.md)에서 Layout 상태는 두 개의 새 노드로 나뉩니다. `layout`(사용자 태그, 소재 연결, 생성 상태)과 `materials`(소재 라이브러리)입니다. Layout 상태가 없는 문서는 이 두 노드를 쓰지 않으므로 리비전 정체성이 바뀌지 않습니다. 이 두 종류의 노드를 모르는 이전 버전은 소재를 버리는 대신 새 문서 열기를 거부합니다.
- 삭제되지 않은 레이어가 표시하고 있는 소재는 삭제할 수 없으며, 오류 메시지에 그 레이어들이 나열됩니다. 레이어를 삭제하면 소재를 삭제할 수 있고, 실행 취소하면 함께 돌아옵니다.
- 이전 프로젝트는 열 때 원래대로 읽으며 등록을 보충하지 않습니다. 소재 패널은 아직 소재가 없는 레이어 수를 안내하고, `material_adopt_layers`로 한 번에 등록합니다(`Layers` 폴더에 두며, 그룹은 하위 폴더가 됨).
- 기존 `asset_*` 작업 흐름의 PNG 소재와 `assetCatalog`는 평소처럼 동작하며, 소재 라이브러리와 분리되어 있습니다.

가져오기는 작업(job) 안에서 파일을 읽고(순수 후보에 들어가지 않음), 읽은 내용을 내용 다이제스트를 이름으로 하여 프로세스 안에 임시 저장한 뒤(`material_add`의 `staging`), 문서 편집 한 번으로 커밋합니다.

### 배치

`layer_place`는 항목이나 폴더 전체를 캔버스에 놓습니다.

- 항목은 소스 레이어 하나가 됩니다. 폴더는 각 항목이 각각 레이어 하나가 되고, 하위 폴더는 소스 그룹이 되며, 항목 사이의 상대 위치를 유지합니다.
- 기본 위치는 항목의 기본 배치(PSD 안의 위치)이며, 그것이 속한 PSD 캔버스(항목의 `placementWidth × placementHeight`)와 함께 프로젝트 캔버스로 매핑됩니다. 둘의 크기가 같으면 그대로 되돌려 놓고, 다르면 PSD 캔버스를 가운데에 놓되 넘치면 비례해 축소하며, 레이어는 그 안에서 원래 위치를 유지합니다. PSD 캔버스 크기를 모르는 이전 항목은 이 위치들의 전체 경계 상자를 캔버스로 보고 가운데에 놓습니다. 기본 배치가 없으면 "소재 1픽셀 = 캔버스 1단위"로 가운데에 놓고, 캔버스를 넘으면 비례해 축소합니다. `rect`는 단일 항목의 캔버스 사각형을 지정하고(픽셀은 리샘플링하지 않으며, 사각형이 작을수록 텍스처가 촘촘해짐), `at`은 전체 중심을 그 점에 놓습니다.
- 새 레이어는 기존 레이어 위에 그려지며, 폴더 전체를 배치할 때는 폴더 안의 쌓임 순서를 유지합니다(PSD와 Layout 매니페스트는 원래 순서). 이미 생성된 프로젝트에서는 생성 대기에 들어갑니다.
- 항목이 참조로 표시되어 있으면(`MaterialItem.reference`) 참조 레이어로 배치합니다. `reference`가 `true` / `false`이면 모든 레이어를 그에 따라 배치합니다.
- 항목과 각 상위 폴더의 태그가 레이어 태그가 됩니다(위 참고).
- `layer_replace_image`에 새 출처 `material_id`가 추가되었습니다. 레이어가 그 소재를 표시하고, 소재 연결도 그에 따라 업데이트됩니다.

### 하나의 참조, 세 가지 표시

참조는 UI에서 같은 종류의 객체이며, 표시 방식이 그것이 어느 데이터에 있는지, 모델에 들어가는지를 정합니다.

| 표시 방식 | 데이터 | 모델에 들어가는지 |
|---|---|---|
| 배경 / 전경 | 참조 이미지 `LayoutReference`(`under`로 구분) | 아니요: 문서 안의 뷰 데이터로, 편집 캔버스에만 그려지며 생성, 리그, 내보내기 모두 포함하지 않음 |
| 레이어 사이 | 참조 레이어(`referenceLayerIds`에 있는 소스 레이어) | 예: 이미 생성된 프로젝트에서는 ArtMesh 하나 |

레이어 사이의 참조는 모델에 들어갑니다(`WorkspaceReferenceMeshes`). 이미 생성된 프로젝트에서는 새 참조 레이어마다 캔버스 사각형으로 네 점, 삼각형 두 개의 메시를 곧바로 만들며, 픽셀 추적과 전체 메시 생성을 실행하지 않습니다. 일반 ArtMesh 이미지 가져오기는 현재 픽셀로 재구성할 때와 같은 메시 생성기를 씁니다. 참조 레이어는 자체 생성 메시(`canvas_mesh_create`, 분류는 PRESET / UNKNOWN, 생성기가 다시 생성하지 않음)를 가지며, 리그 안에서 그리기 순서에 따라 다른 ArtMesh와 겹쳐 놓이고, 디포머에 바인딩하거나 변형, 편집할 수 있으며, 더 이상 생성 대기 레이어가 아닙니다. 프리뷰 모델을 빌드한 뒤 그 메시들을 참조 이미지 파츠(`PartReference`, `isSketch`), 즉 Cubism의 가이드 이미지로 모읍니다. 내보내기에서는 기본적으로 쓰지 않으며, `exportGuideImageParts`가 참일 때 씁니다. 문서 편집 후마다 한 번 검사하여(`ensure`), 새로 참조로 설정했거나 참조로 배치했거나 첫 생성 후 아직 메시가 없는 참조 레이어에 곧바로 메시를 만듭니다. 레이아웃 프로젝트가 처음 생성되기 전에는 참조 레이어도 다른 레이어처럼 대기하며 네 모서리 면으로 표시됩니다. 참조로 설정하기는 옮길 수 있는 레이어 외에 사용자가 직접 만든 메시를 가진 레이어(가져온 이미지)도 받습니다. 모델 레이어로 되돌리면, 메시가 있는 것은 메시를 유지한 채 참조 이미지 파츠를 떠나고, 없는 것은 생성 대기로 돌아갑니다.

`reference_set_mode`(`WorkspaceReferenceModes`)는 참조 하나를 세 위치 사이에서 옮깁니다. 참조 이미지를 배경 / 전경으로 바꿀 때는 `under`만 바꿉니다. 참조 이미지를 레이어 스택에 넣을 때는 그 소재와 사각형으로 참조 레이어를 배치하고(ID는 `ref_`에 참조 이미지 ID와 소재의 해시를 붙인 것), 고정은 `referencePins`로 옮기며, 숨긴 것은 계속 숨기고, 회전과 잠금은 가져가지 않습니다. 참조 레이어를 스택에서 뺄 때는 그 소재(없으면 먼저 등록)와 캔버스 사각형으로 참조 이미지를 새로 하나 추가하고, 표시 여부와 고정을 가져간 뒤, 그 레이어를 삭제합니다(메시가 있으면 메시도 함께 삭제).

**고정**은 키폼 위의 점입니다. `referencePins`와 `LayoutReference.pins`는 모두 점의 목록(`PinPoint`, 파라미터 ID → 값)이며, 참조는 어느 한 점에서든 표시되고(`ReferencePins.shows`, 각 파라미터의 차이가 범위의 0.5% 이내), 점이 없으면 어떤 포즈에서도 표시됩니다. 점이 하나뿐이면 아카이브에는 여전히 원래의 단일 객체로 쓰고, 여러 개면 배열로 쓰므로 이전 프로젝트의 읽기와 쓰기는 바뀌지 않습니다. 고정은 편집기가 언제 표시할지만 정하며 내보내기에 들어가지 않습니다. 고정 패널(`ReferencePinPanel`)은 `ReferencePinRows`에 따라 리그에서 키폼을 가진 파라미터(와 점에 나타난 파라미터)를 나열합니다. 쌍을 이루는 파라미터는 2D 패드, 나머지는 트랙으로 표시하고, 키폼 점과 현재 포즈를 그리며, 키폼 점을 클릭하면 점 하나를 추가하거나 제거합니다. 어느 행에도 속하지 않는 점은 따로 나열되어 개별적으로 제거할 수 있습니다. 캔버스 컨텍스트 메뉴의 「키폼에 고정」도 같은 패널입니다(`ReferencePinsOption`).

참조 이미지는 뷰 데이터일 뿐입니다. 참조 이미지만 바꾸는 편집은 모델을 다시 빌드하지 않으며(`onlyReferenceImagesChanged`), 캔버스 핸들을 끄는 동안에는 다시 그리기만 하고 캔버스를 재구성하지 않으며, 손을 떼면 히스토리 하나를 기록합니다.

계층 트리는 참조를 구성원으로 표시합니다(참조 아이콘과 표시 방식 레이블). 전경 참조 이미지는 루트 노드 위에, 배경 참조 이미지는 맨 아래에, 참조 레이어는 스택 안 자기 위치에 있습니다. 참조 이미지를 클릭하면 캔버스 핸들이 나타나고, 참조 레이어를 클릭하면 그 레이어가 선택됩니다. 컨텍스트 메뉴는 두 참조가 같습니다. 표시 방식(각 항목에 모델에 들어가는지 표시), 표시/숨기기, 고정 패널, 제거이며, 참조 이미지에는 불투명도와 잠금이, 참조 레이어에는 모델 레이어로 되돌리기가 추가로 있습니다. 소재 컨텍스트 메뉴에는 「참고로 추가」 아래의 배경, 레이어 사이, 전경 세 항목만 남깁니다.

끌어다 놓기: 시스템에서 끌어온 파일과 소재 패널에서 끌어온 소재는 같은 라우터(`FileDropRouter`, `CarriedFiles`가 `material`을 가짐)를 거치며, 놓는 위치와 안내가 같습니다. 편집 캔버스 위에서 끌면 아래쪽에 큰 타일(`CanvasDropTiles`)이 나타납니다. 세 가지 참조(모델에 들어가는지 명시), 선택한 레이어의 이미지 교체, 소재 라이브러리에만 가져오기(파일만)이며, 캔버스의 나머지 위치에 놓으면 레이어로 배치합니다.

### 참조 이미지에서 파츠 분리

`WorkspaceLayout.references`(`LayoutReference` 목록, 그리기 순서대로)는 배치와 비교를 위해 소재 항목을 캔버스 위에 겹치거나 모델 아래에 깝니다. ID, 소재 ID, 캔버스 사각형, 중심 기준 시계 방향 회전, 불투명도, 표시 여부, 잠금, 모델 아래에 있는지 여부를 가집니다. 이들은 문서 데이터(프로젝트와 함께 저장되고 실행 취소 가능)이지만 레이어는 아니며, 생성 뷰, 리그, 내보내기 모두 이들을 포함하지 않습니다. 참조 이미지가 쓰는 소재는 삭제할 수 없습니다. `layout_set_reference`는 `id`가 가리키는 한 장을 설정, 수정, 제거하고(생략하면 첫 번째, 없으면 새로 만듦), `layout_add_reference`는 한 장을 더 추가하며, `layout_order_reference`는 순서를 조정합니다. 새로 설정하면 기본적으로 캔버스 안에 맞게 비례 조정해 가운데에 놓습니다. 참조 조회(색 추출, 윤곽, 스냅), `material_crop`의 `canvas_rect`, `view_render_model`의 `reference`는 첫 번째를 씁니다. 한 장뿐이면 아카이브에는 여전히 원래의 단일 `reference` 객체로 쓰고, 새 필드가 기본값이면 쓰지 않으므로 이전 프로젝트의 읽기와 쓰기는 바뀌지 않습니다. 한 장보다 많으면 `references` 배열로 씁니다.

`material_crop`은 항목에서 새 항목을 무손실로 잘라냅니다. `rect`는 항목 픽셀이고, `canvas_rect`는 캔버스 단위입니다(참조 이미지 사각형, 또는 항목의 이 캔버스 기준 기본 배치를 통해 환산). 새 항목의 기본 배치는 바로 이 픽셀들의 캔버스 위 위치이므로, 배치하면 원래 자리에 놓입니다. `material_export_png`는 항목을 그대로 PNG로 씁니다. 전형적인 용도는 참조 이미지에서 머리, 눈 등의 확대 이미지를 잘라 외부에 넘겨 확대하거나 더 선명한 레이어별 파츠로 다시 그리게 한 뒤, 가져와서 확대 이미지의 위치에 배치하는 것입니다. 파츠의 픽셀이 참조 이미지보다 많고 레이어는 같은 크기의 사각형에 놓이므로 텍스처가 더 촘촘해집니다. 가져온 이미지에는 위치가 없으므로, `material_set_placement`의 `from`으로 확대 이미지의 위치를 가져오게 합니다.

### 벗겨내기

`material_peel`(`WorkspaceMaterialPeel`)은 어떤 파츠를 제거한 생성 이미지 한 장을 써서 현재 이미지에서 그 파츠를 벗겨내고, 새 항목 두 개를 만들어 둘 다 현재 이미지의 위치에 둡니다.

- **파츠**: 현재 이미지 자체의 픽셀이며, 투명도는 두 이미지의 차이(각 채널 색 차이의 최댓값을 약간 흐리게 한 뒤 임계값 구간 안에서 선형 전환)에서 옵니다. 같은 크기의 마스크로 범위를 제한하고, 확장하고(`grow`), 축소한 마스크를 강제로 불투명하게 하고(`core`), 마지막으로 닫기 연산으로 작은 틈을 메울 수 있습니다(`close`). `keep`은 파츠 위의 점(항목 픽셀)을 주며, 이 점들과 연결된 덩어리만 남기므로 생성 모델이 덩달아 바꾼 먼 곳의 잔점은 파츠에 들어가지 않습니다.
- **그 아래의 이미지**: 현재 이미지이되, 파츠 영역만 생성 이미지로 바꿉니다. 생성 모델은 이미지 전체를 약간씩 다시 그리므로 파츠 밖은 모두 원래 픽셀을 유지하며, 파츠를 그 아래 이미지에 다시 겹치면 현재 이미지로 복원됩니다.
- **비교 크기**: 생성 모델은 흔히 더 작은 크기에서 작업하므로, 출력을 현재 이미지 크기로 확대하면 모든 선이 원본보다 약간 부드러워지고, 원래 크기로 비교하면 선이 차이로 잡힙니다. `compare_scale`이 확대 배율을 주면 두 이미지를 먼저 블록 평균으로 같은 배율만큼 축소해 비교하고, 차이를 다시 쌍선형으로 확대해 되돌리므로, 생성 모델이 실제로 바꾼 곳만 남습니다.
- **색조**: 비교 전에 먼저 이미지 전체의 색조 이동(각 채널 차이의 중앙값, 비교 크기에서 집계)을 제거합니다. 그렇지 않으면 이동 자체가 옅은 파츠 한 겹으로 잡힙니다. 드러난 영역은 합성 전에 주변의 바뀌지 않은 한 둘레 픽셀에 맞춰 Lab 공간에서 평균과 분산을 맞춥니다.

가장 앞의 파츠부터 시작해 각 단계는 이전 단계에서 남은 이미지 위에서 계속하며, 가려진 부분은 생성 모델이 채웁니다. 외부 생성 도구는 메인라인에 없으며, `comfy-tools` 브랜치를 참고하세요.

`view_render_model`은 참조 이미지를 함께 그릴 수 있습니다. `reference.mode`는 `over`(모델 위에 덮음), `under`(모델 아래에 깖), `difference`(채널별 차이값. 겹치는 곳은 검은색이며 결과에 평균 차이 0–1의 `referenceDifference`가 붙음) 중 하나이고, `opacity`는 참조 이미지 자체의 불투명도를 덮어씁니다. `density`는 레이어의 텍스처 밀도에 따라 색을 칠하며(캔버스 단위당 텍스처 픽셀 ¼ 이하는 파랑, 1은 초록, 4 이상은 주황. 텍스처 작업 공간 히트맵과 같은 색 단계), 결과에 `texelDensity`가 붙습니다. 편집 캔버스 오른쪽 아래의 표시 토글에는 「참조 이미지」(참조 이미지가 있으면 표시를 전환하며 단축키는 Alt+R, 없으면 클릭해 추가)와 「텍스처 밀도」가 있습니다. 계층 패널 맨 위의 「참조 이미지」 그룹은 각 장을 나열합니다. 표시, 불투명도(25%씩 증감), 위/아래, 잠금, 순서 조정과 제거이며, `+`로 이미지를 추가합니다. 잠기지 않은 한 장을 선택하면 편집 캔버스에 그 핸들이 나타납니다. 안쪽을 끌면 옮기고, 모서리 점을 끌면 중심 기준으로 비례 확대·축소하고, 위쪽 원형 점을 끌면 회전하며, 한 번 끌 때마다 히스토리 하나입니다. 소재 컨텍스트 메뉴에서 참조 이미지로 추가하고, 그 불투명도를 조정하고, 제거할 수 있습니다. 이미지를 편집 캔버스 위쪽의 「참조 이미지로 설정」 슬롯에 끌어다 놓아도 한 장이 새로 추가됩니다.

### 벡터 그리기

파츠는 참조 이미지를 보고 벡터로 그릴 수 있습니다(`WorkspaceDrawingEdits`, `WorkspaceVectorDrawing`).

- **그림이 곧 소재**: `material_draw`는 벡터 항목 하나를 기록합니다. SVG의 `viewBox`가 캔버스 위 그 위치(캔버스 단위), 즉 항목의 기본 배치입니다. 항목은 밀도(캔버스 단위당 텍스처 픽셀, 0.05–16)로 렌더링되므로, 작은 파츠에도 필요한 만큼 픽셀을 줄 수 있습니다. 기록할 때 루트 요소의 `width`, `height`를 제거하고 `preserveAspectRatio="none"`을 설정하여 `viewBox`가 래스터를 정확히 채우게 합니다. 다시 그리면 그것을 표시하는 레이어는 픽셀이 교체되고, 이전 위치에 있던 레이어는 새 위치로 옮겨집니다. 레이어와 소재의 연결은 유지됩니다.
- **부분 수정**: `material_draw`의 `edits`는 요소 `id`로 속성을 바꾸므로(`WorkspaceVectorDrawing.patch`) 전체를 다시 보낼 필요가 없습니다. `material_get`의 `include_svg`로 저장된 원문을 다시 읽습니다.
- **그리기 키트**: `WorkspaceLayout.drawingKit`(`DrawingKit`)는 색, class 규칙, SVG 정의를 저장하며 모든 그림이 공유하므로, 각 파츠가 같은 색과 선을 씁니다. 키트를 바꾸면 모든 벡터 항목이 원래 해상도로 다시 렌더링되고, 바뀐 것은 레이어에 동기화됩니다. 어떤 그림에 색이 빠지게 되면 거부합니다.
- **렌더링 전 해석**: Skia의 SVG 모듈은 스타일시트와 CSS 변수를 지원하지 않으므로, 렌더링 전에 키트와 그림 자체 `<style>`의 규칙(요소, `#id`, `.class` 선택자. 조합 가능, 중첩 불가)을 명시도(specificity)에 따라 각 요소의 `style`에 써 넣고, 요소 자신의 `style`은 마지막에 둡니다. `var(--name)`은 키트 색으로 바꿉니다. 키트 정의는 `<defs>`에 합칩니다(그림 자체의 같은 id가 우선). `data-taper`가 있는 경로는 폭 계수(처음부터 끝까지 고르게 분포)에 따라 획을 채운 윤곽으로 바꾸므로 선의 양 끝을 가늘게 할 수 있습니다. `<ellipse>`는 동등한 `<path>`로 바꿉니다(렌더러가 타원의 경계 상자 그라데이션을 검게 그리기 때문). 가져온 SVG도 문서 키트로 렌더링합니다. 블렌드 모드는 렌더링하지 않습니다.
- **참조 이미지 읽기**: `reference_sample`은 점의 색과 영역의 주요 색을 취하고(Lab 공간에서 5비트 히스토그램에 k-means), `reference_trace`는 색 허용 오차에 따라 시드에서 퍼져 나가 픽셀 경계를 따라 바깥 윤곽을 얻은 뒤 다각형과 매끄러운 경로로 단순화하며, `reference_snap`은 점을 근처 선의 중심에 스냅합니다. 셋 모두 캔버스 위 참조 이미지의 위치에 따라 환산해 캔버스 좌표를 반환합니다.
- **비교**: `view_render_model`의 `grid`는 좌표 레이블이 붙은 격자를 그리고, `outline_material_ids`는 항목의 불투명 가장자리를 뷰 위에 그리므로, 배치하지 않고도 참조 이미지와 비교할 수 있습니다.

### PSD로 내보내기

`material_export_psd`는 폴더를 PSD로 씁니다. 항목은 기본 배치에 따라 놓고(없는 것은 왼쪽 위부터 한 줄로 늘어놓음), 하위 폴더는 레이어 그룹이 되며, 캔버스는 프로젝트 캔버스를 취해 모든 항목을 담을 수 있도록 넓힙니다. 벡터 항목은 텍스처 해상도로 래스터화하고, 밀도가 다른 레이어는 캔버스 사각형에 맞게 리샘플링해 씁니다.

## 소재와 레이어의 연결

`layerMaterials`로 연결된 레이어는 소재 자체의 픽셀을 표시하며(래스터는 소재와 같고, 사각형은 배치 사각형), 소재가 유일한 원본이고, 소재 라이브러리는 모든 레이어의 이미지를 수록합니다(`WorkspaceMaterialLinks`). 모든 가져오기 경로가 소재를 등록합니다. PSD와 Layout 매니페스트는 레이어마다 하나씩 등록합니다. `project_import_cmo3`(새로 만들기와 교체)는 각 ArtMesh를 텍스처 아틀라스에서 복원한 이미지를 파일 이름으로 이름 붙인 폴더에 등록하며, `material_import`가 CMO3를 읽을 때도 같은 복원을 써서 두 곳의 픽셀이 일치합니다. `layer_import_images`는 `Imported images`에 등록합니다. 편집으로 새로 생긴 레이어(나누기, 메시 밖으로 칠하기 등)는 `Layers`에 등록하며, 메시 밖으로 칠해서 나뉜 레이어는 원래 레이어의 소재 바로 뒤에 둡니다. 연결은 저절로 끊어지지 않습니다.

- 다른 레이어와 소재를 공유하는 레이어에 칠하는 것은 곧 소재에 칠하는 것입니다. `source_paint_*`와 `paint_session_begin`(`layer_id`)은 일반 레이어처럼 캔버스 전체에 칠하며, 세션 스냅숏은 `material_id`를 추가로 보고합니다. 커밋할 때 레이어 메시에 따라 잘라내며(`WorkspacePaintOverflow`), 메시 위이면서 소재 사각형 안에 있는 픽셀은 소재 수정으로 기록하고 연결된 모든 레이어에 동기화하며, 나머지 새로 칠한 픽셀은 바로 위에 붙는 새 레이어로 나뉘고 연결은 유지됩니다. 나뉜 레이어는 동시에 소재가 되어(원래 레이어의 소재와 같은 폴더의 바로 뒤. 원래 레이어가 연결되지 않았으면 최상위) 그와 연결됩니다.
- 메시 재구성은 소재를 공유하는 레이어에 대해 소재 래스터 전체를 유지하며 가장자리를 잘라내지 않습니다. 소재를 혼자 쓰는 레이어만 일반 레이어처럼 칠하고 재구성합니다.
- `WorkspaceDocumentEdits.apply`와 래스터 커밋은 후보가 완성된 뒤 `reconcile`을 실행합니다. 레이어 픽셀이 더 이상 소재와 같지 않을 때, 그 레이어만 그 소재를 쓰고 이번에 소재를 바꾸지 않았다면 소재가 레이어를 따라가고(픽셀과 기본 배치), 그렇지 않으면 레이어에 원래 소재 바로 뒤에 놓이는 복사본을 줍니다(`mat_`에 원래 소재와 레이어의 해시를 붙인 것). 편집으로 새로 생기고 소재가 없는 레이어는 곧바로 등록합니다. `material_fork`는 소재를 공유하는 레이어 각각에 명시적으로 복사본을 주며 픽셀은 바뀌지 않습니다. `material_unlink`는 그 예전 이름입니다.

## 인터페이스

- **소재 패널**(도킹 모듈 `materials`): 왼쪽에 접을 수 있는 간결한 폴더 트리가 있고, 내용 영역과의 구분선을 끌어 폭을 조절합니다(72–360dp). 내용 영역은 경로 표시줄(↑와 각 단계) 아래에 현재 폴더의 하위 폴더와 항목을 나열하며, 격자 / 목록으로 전환할 수 있습니다. PSD / CMO3에서 온 폴더(`MaterialFolder.origin`)는 형식 색 띠가 있는 파일 아이콘과 항목 수로 표시됩니다. 검색은 이름과 태그(폴더 태그 포함)에 일치시키며 범위는 모든 폴더입니다. 항목의 배지는 몇 개의 레이어가 쓰는지 보여 주고, 참조로 표시된 항목은 왼쪽 위에 참조 아이콘이 추가로 붙습니다. 시스템에서 파일을 패널로 끌어오면 포인터 아래의 폴더(폴더 타일이나 경로 표시줄의 한 단계, 그 외에는 현재 폴더)로 가져옵니다. 항목이나 폴더를 편집 캔버스로 끌면 놓은 곳에 배치하고, 폴더 타일, 트리 행, 경로 표시줄의 한 단계로 끌면 `material_move`입니다. 컨텍스트 메뉴는 공용 `PressMenu`(캔버스 메뉴와 같은 외형과 애니메이션)입니다. 폴더를 더블클릭하면 들어가고, 항목을 더블클릭하면 소재 창이 열립니다. 컨텍스트 메뉴에는 열기, 배치, 참조 레이어로 배치(항목이 이미 참조로 표시되어 있으면 「모델 레이어로 배치」), 기본적으로 참조로 배치하는 토글, 선택한 레이어의 이미지 교체, 텍스처 해상도(SVG), 그것을 쓰는 레이어 선택, 이름 바꾸기, 새 폴더, 폴더를 PSD로 내보내기, 상위 폴더로 이동, 삭제가 있습니다. 썸네일은 필요할 때 백그라운드에서 생성되며 128 / 512 / 2048 세 단계로 메모리에 캐시됩니다. 투명한 가장자리가 면적의 약 2할을 넘으면 보이는 픽셀로 잘라낸 뒤 축소합니다.
- **소재 창**: 독립된 시스템 창(`MaterialEditorWindow`, `PSD2LiveViewModel.materialEditor`가 항목을 지정)으로, 크기와 위치를 자유롭게 바꿀 수 있습니다. 열려 있는 동안 패널에서 항목을 클릭하면 전환됩니다. 뷰는 휠로 확대·축소하고 가운데 버튼 / Space로 끌어 이동하며, 뷰 밖은 잘립니다. 칠하기는 캔버스의 페인트 모드를 그대로 재사용합니다. 창은 전용 `CanvasEditor`(페인트 모드)를 가지며, 그 페인트 세션은 소재 세션입니다(`WorkspacePaintSession.materialId`, `layerId`는 `material:<id>`). 도구 모음 `CanvasToolBar`, 옵션 표시줄 `ToolOptionsBar`, 세션 표시줄 `PaintSessionBar`, 컨텍스트 메뉴 `CanvasContextMenu`, 오버레이 `drawPaintOverlays`, 누르기 / 끌기 / 놓기 처리는 모두 캔버스와 같은 코드이며, 키 입력은 키 표에 따라 분배합니다. 색과 브러시 팁 설정은 열 때 현재 캔버스에서 가져오고 닫을 때 되돌려 씁니다. 소재 세션은 소재 자체의 픽셀이 바뀌거나 프로젝트가 바뀔 때만 무효가 되며, 다른 편집은 평소처럼 커밋됩니다. 적용은 `paint_session_commit`을 거쳐 `material_set_pixels` 한 번으로 기록되며, 소재를 떠나거나 창을 닫을 때 자동으로 적용됩니다. "조정" 메뉴는 뒤집기와 색조 / 채도 / 명도 / 대비(백그라운드 미리보기)이며, 적용하지 않은 획이 있으면 쓸 수 없습니다.
- **Layout 작업 공간 프리셋**: 소재 패널이 왼쪽, 편집 캔버스가 가운데, 계층 트리와 레이어 표가 오른쪽입니다. 시작 페이지의 「레이아웃 프로젝트」(또는 "파일 > 새로 만들기 > 새 레이아웃 프로젝트")에서 캔버스 크기를 입력하면 생성되지 않은 프로젝트를 새로 만들고 이 작업 공간으로 들어갑니다.
- **생성 표시줄**: 생성 대기 내용이 있을 때 편집 캔버스 오른쪽 위에 나타나며, "생성 전", "생성 대기 N" 또는 교체한 이미지 수를 표시합니다. 주 버튼은 "생성 / 다시 생성"이고, 드롭다운에서 교체한 이미지의 형상을 새로 고칠지 고를 수 있습니다.
- **레이어 표**: 유형 / 파츠 / 좌우 세 열을 태그 셀(생성 대기 중인 분류는 강조 색 테두리), 차분, 차분 파라미터 두 열로 바꿨습니다. 레이어는 쌓임 순서에 따라 뒤에서 앞으로 나열됩니다(소스 이미지 순서, Cubism 그리기 순서가 증가하는 방향과 일치하며, 나중에 배치한 레이어도 실제 위치에 나타남). 도구 모음의 「앞으로」「뒤로」는 선택한, 옮길 수 있는 레이어를 조정하며, 캔버스에는 단축키 Ctrl+] / Ctrl+[(한 단계 앞으로 / 뒤로)와 Ctrl+Shift+] / Ctrl+Shift+[(맨 앞으로 / 맨 뒤로)도 있고, 모두 `ShortcutRegistry`에 등록되어 있습니다. 캔버스 오른쪽 아래의 표시 토글에는 참조 레이어가 있을 때 「참조 레이어를 위에 표시」가 추가됩니다. 도구 모음의 「참고 이미지로 변환」은 선택한 옮길 수 있는 레이어를 참조와 모델 사이에서 전환하며(모두 이미 참조이면 되돌리고, 그렇지 않으면 모두 참조로 설정), 캔버스 단축키는 Ctrl+Alt+R입니다. 참조 레이어는 이름 뒤에 참조 아이콘이 붙고, 클릭하면 되돌립니다. 오브젝트 모드의 캔버스 컨텍스트 메뉴에서는 생성기가 읽지 않은 레이어에 「참고 이미지로 변환」 토글이 추가로 있습니다.
- **튜토리얼**: "선택 모드" 강의를 "오브젝트 모드"로 바꾸고, "소재와 배치" 강의를 새로 추가했습니다.

## 작업(GUI와 MCP 공용)

모든 문서 작업은 순수 후보이며, GUI는 `WorkspaceDocumentPort.applyDocumentEdits`로 호출하고, MCP는 구성원 하나짜리 문서 일괄 처리의 프로세스 작업(job)으로 실행합니다. 둘 다 `workspace_apply_edits`의 구성원이 될 수 있습니다.

| 작업 | 종류 | 설명 |
| --- | --- | --- |
| `layer_tag` | 문서 | 1–128개 레이어의 태그 `set` / `add` / `remove` |
| `layer_set_variant` | 문서 | 차분: `none` / `toggle` / `switch` |
| `layer_classify` | 문서(기존) | 이미 생성된 레이어의 결과에 `pending: true`가 붙음 |
| `layer_reorder` | 문서 | 생성 전, 생성 대기, 참조 레이어의 쌓임 순서 조정 |
| `layer_mark_reference` | 문서 | 생성기가 읽지 않은 레이어를 참조 레이어로 설정하거나 모델 레이어로 되돌림 |
| `layer_pin_reference` | 문서 | 참조 레이어를 키폼에 고정하거나 고정 해제 |
| `reference_place_grid` | 문서 | 키폼 격자 참조 이미지를 칸으로 잘라 각각 고정된 참조 레이어로 배치 |
| `rig_generate` | 문서 | 생성 또는 다시 생성. `refresh_geometry` |
| `material_import` | 문서, job | 파일을 읽고 `material_add`를 커밋 |
| `material_add` | 문서 | `material_import`가 임시 저장한 내용을 추가 |
| `material_folder_create` / `material_move` / `material_rename` / `material_delete` / `material_tag` | 문서 | 정리 |
| `material_set_resolution` | 문서 | SVG 텍스처 해상도. 그것을 표시하는 레이어의 픽셀도 교체됨 |
| `material_fork` | 문서 | 소재를 공유하는 레이어 각각에 자신만의 복사본을 줌. 픽셀은 바뀌지 않음(`material_unlink`는 예전 이름) |
| `material_adopt_layers` | 문서 | 아직 소재가 없는 레이어마다 소재를 하나씩 등록 |
| `material_set_pixels` | 문서 | 소재 페인트 세션이 임시 저장한 픽셀(`staging`)을 기록. `paint_session_commit`이 발행. 크기는 바뀌지 않으며, 그것을 표시하는 레이어의 픽셀도 교체됨 |
| `material_paint` / `material_adjust` | 문서 | 항목 픽셀에 획 하나를 칠하거나 한 묶음의 획(`gestures`)을 순서대로 칠함 / 뒤집기와 색 조정. 크기는 바뀌지 않으며, 그것을 표시하는 레이어의 픽셀도 교체되고, SVG는 비트맵이 됨 |
| `layer_place` | 문서 | 항목이나 폴더를 배치. `reference`로 참조 레이어 여부를 지정 |
| `material_mark_reference` | 문서 | 항목(또는 폴더 안의 모든 항목)을 기본으로 참조 레이어로 배치할지 여부 |
| `material_list` / `material_get` / `material_preview` | 조회 | 목록(페이지 나눔, 필터), 상세(참조하는 레이어 포함), PNG 미리보기 |
| `material_export_psd` | 출력, job | 폴더를 PSD로 내보냄 |
| `material_export_png` | 출력, job | 항목을 그대로 PNG로 씀 |
| `layout_set_reference` | 문서 | 참조 이미지 한 장을 설정, 수정, 제거(회전, 잠금, 위/아래) |
| `layout_add_reference` | 문서 | 참조 이미지 한 장을 추가 |
| `layout_order_reference` | 문서 | 참조 이미지의 그리기 순서 조정 |
| `reference_set_mode` | 문서 | 참조를 배경, 레이어 사이, 전경으로 옮김 |
| `material_crop` | 문서 | 새 항목을 무손실로 잘라내고 캔버스 위치를 기억 |
| `material_set_placement` | 문서 | 항목의 기본 위치 설정(사각형, 또는 다른 항목의 위치를 취함) |
| `material_peel` | 문서 | 파츠를 제거한 생성 이미지로 파츠를 벗겨내고, 파츠와 그 아래 이미지 두 항목을 새로 만듦 |
| `material_draw` | 문서 | 캔버스 좌표의 SVG로 벡터 항목을 그리거나 다시 그리고, 밀도로 렌더링하며, 레이어도 업데이트 |
| `layout_set_drawing_kit` | 문서 | 그림이 공유하는 색, class 규칙, 정의. 바꾸면 모든 벡터 항목을 다시 렌더링 |
| `reference_sample` / `reference_trace` / `reference_snap` | 조회 | 참조 이미지의 색과 주요 색, 마술봉 윤곽, 선에 스냅 |
| `project_create` | 프로젝트, job | 생성되지 않은 빈 프로젝트를 새로 만듦 |
| `project_import_layout` | 프로젝트, job | Layout 매니페스트(또는 매니페스트가 든 zip)로 생성되지 않은 프로젝트를 새로 만듦 |
| `workspace_inspect scope=generation` | 조회 | 생성 여부, 생성 대기 레이어, 대기 중인 분류, 형상을 새로 고칠 수 있는 레이어, 참조 레이어(`reference_layers`) |

`workspace_inspect scope=layers`의 각 레이어에 `tags`가 추가되고, 생성 대기 중인 것에는 `pending: true`, 소재에서 온 것에는 `material_id`가 붙습니다. 생성 상태는 더 이상 편집이나 내보내기를 막지 않습니다.

## 검증

시나리오 테스트가 다루는 범위는 다음과 같습니다.

- 태그와 이전 분류가 같은 리그와 메시 ID를 얻고, 사용자 태그는 리그를 바꾸지 않으며, 저장 후 다시 열어도 유지됨(`LayerTagScenario`).
- 생성되지 않은 프로젝트와 빈 캔버스에서 파라미터, 계층, 메시를 편집할 수 있고, 저장 후 다시 열기와 내보내기 후 다시 읽기가 일치함; 생성은 기존 메시 토폴로지를 고정함; 생성 후 배치한 레이어도 즉시 편집할 수 있고, 다시 생성하면 작성자 계층이 유지되며, 사용자의 디포머와 키폼이 유지되고, 메시 ID가 바뀌지 않음; 분류는 다음 생성을 기다리며, "분류 + 생성"을 같은 일괄 처리로 했을 때와 같은 리그를 얻음(`LayoutGenerationScenario`).
- 참조 이미지는 레이어가 되지 않고, 사용 중인 소재는 삭제할 수 없으며, 캔버스 사각형으로 잘라낸 확대 이미지의 픽셀이 참조 이미지와 일치하고 배치하면 원래 자리에 놓임; 차이, 겹치기, 밀도 뷰, 수정, 저장 후 다시 열기와 지우기(`ReferenceLayoutScenario`).
- PSD, PNG, SVG를 소재로 가져오기; 폴더, 이동, 태그; 배치 후 태그가 분류가 됨; 참조된 소재는 삭제를 거부함; SVG 해상도를 바꾸면 레이어 픽셀은 바뀌지만 캔버스 사각형은 바뀌지 않음; 소재로 이미지 교체; 소재에 칠하거나 조정하면 그것을 표시하는 레이어가 동기화되고 캔버스 사각형은 바뀌지 않으며, 한 묶음의 획은 순서대로 한 번의 수정으로 적용됨; 소재 페인트 세션의 획과 실행 취소는 세션 안에 머물고, 그동안 다른 편집은 평소처럼 커밋되며, 커밋 후 소재와 레이어가 일치하고, 소재 픽셀이 다른 곳에서 수정되면 세션이 더 칠하는 것을 거부함; 연결된 레이어에 칠하기(단일 획과 세션)는 곧 소재에 칠하기이며 다른 연결된 레이어가 동기화되고, 레이어 메시 밖으로 칠한 부분은 새 레이어로 나뉘되 연결은 유지되며, 메시 재구성은 연결을 유지하고, 독립 소재로 분리한 뒤에는 칠하기가 그 레이어와 그 소재만 바꾸며, 연결은 저장 후 다시 열어도 유지됨(`aLinkedLayerShowsItsMaterial`); 빈 조정, 그리고 단일 획과 획 목록을 동시에 준 경우는 거부되며, 칠한 뒤 SVG는 비트맵이 됨; 생성, 저장 후 다시 열기; 폴더를 PSD로 내보내고 다시 읽으면 레이어와 위치가 일치함; 빈 프로젝트에 PSD 폴더 전체를 배치한 뒤 생성(`MaterialLibraryScenario`).

- Layout 매니페스트를 생성되지 않은 프로젝트로 열기(픽셀, 사각형, 쌓임 순서, 그룹, 태그, 차분, 소재); 쌓임 순서 조정, 생성 후 이미 생성된 레이어의 이동 거부, 저장 후 다시 열기; zip과 소재 가져오기; 잘못된 매니페스트는 거부; PSD나 매니페스트 폴더 전체를 배치하면 쌓임 순서 유지; 매니페스트의 참조 레이어는 리그와 어떤 텍스처 아틀라스에도 들어가지 않고, 함께 움직이는 네 모서리 사각형으로 표시되며, 되돌리면 다음 생성 때 들어감; 이미 생성된 레이어는 참조로 설정할 수 없음; 참조 소재는 표시나 지정에 따라 배치됨; 참조 레이어만 있어도 생성할 수 있음(`LayoutManifestScenario`, 형식 자체는 [Layout 매니페스트](LAYOUT_MANIFEST.md#검증) 참고).

## 아직 포함하지 않은 것

- 소재를 계층 트리의 지정한 위치 아래로 끌어다 놓기; 여러 레이어를 선택해 태그 일괄 편집(`layer_tag`는 이미 여러 레이어를 지원하지만 UI는 아직 한 행씩 편집).
- 이전 프로젝트의 "현재 소스 이미지에서 소재 생성".
- 새 소재 라이브러리와 `asset_*` 소재, `assetCatalog`의 통합.
- 생성 대기 레이어가 미리보기 애니메이션에 참여(지금은 정적 메시만 표시).
