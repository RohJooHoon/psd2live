# 레이아웃 매니페스트

[문서 목록](../../README.md) · [中文](../../zh/spec/LAYOUT_MANIFEST.md) · [English](../../en/spec/LAYOUT_MANIFEST.md) · [소재와 레이아웃 구현](MATERIAL_LAYOUT_WORKSPACE.md) · [사용자 가이드](../guide/LAYOUT.md) · [PSD 소재와 명명 규칙](PSD_LAYER_SPEC.md)

레이아웃 매니페스트는 PSD2Live가 레이어로 나뉜 소재를 읽어 들이는 교환 형식입니다. 캔버스를 이루는 이미지가 무엇인지를 적은 JSON 파일로, 각 이미지의 경로와 픽셀 크기, 캔버스 위의 사각형, 겹침 순서, 그룹, 의미 태그, 차분, 표시 여부, 불투명도, 참조용인지 여부를 담습니다. 어떤 도구든 이 페이지를 따라 매니페스트를 쓸 수 있으며, PSD2Live는 이를 사용해 아직 생성되지 않은 레이아웃 프로젝트를 만들거나 소재로 가져옵니다.

PSD와 달리 이미지의 픽셀 수가 캔버스 위의 크기와 같을 필요가 없습니다. 작은 파츠는 캔버스가 주는 것보다 많은 픽셀을 가질 수 있으며, PSD2Live는 이를 [레이어별 크기](DOCUMENT_LAYER.md#레이어별-크기)로 유지하므로 텍스처가 더 촘촘해집니다.

## 파일과 아카이브

- 매니페스트는 확장자가 `.json`인 UTF-8 JSON 객체이며, 크기는 16 MiB 이하입니다. 이미지 경로는 매니페스트가 있는 폴더를 기준으로 한 상대 경로입니다.
- 매니페스트와 이미지를 `.zip` 하나로 묶을 수도 있습니다. 매니페스트는 아카이브 루트나 아카이브의 유일한 최상위 폴더(폴더를 바로 압축했을 때 흔함)에 둡니다. PSD2Live는 그 수준에서 `format`을 선언한 JSON을 찾으며, 이미지 경로는 그것을 기준으로 합니다. 같은 수준에 매니페스트가 두 개 있으면 거부합니다. macOS가 추가하는 `__MACOSX/`와 `._*` 항목은 내용으로 치지 않습니다.
- 이미지는 PSD2Live가 디코딩할 수 있는 어떤 형식이든 됩니다(PNG, WebP, JPEG, BMP, TIFF). 프리멀티플라이되지 않은 알파의 PNG를 권장합니다. 이미지 하나는 최대 16 MP, 이미지 파일 하나는 최대 1 GiB입니다. 이미지 전체에는 별도의 한도가 없으며, PSD와 마찬가지로 디코딩된 레이어가 차지하는 메모리로만 제한됩니다(이미지는 하나씩 읽고 디코딩하므로 원시 바이트를 한꺼번에 들고 있지 않음). 레이어는 최대 4096개입니다. 같은 이미지를 여러 레이어가 참조할 수 있습니다.

## 구조

```json
{
  "format": "psd2live-layout",
  "version": 1,
  "name": "character",
  "canvas": { "width": 3258, "height": 4344 },
  "groups": [
    { "path": "head", "visible": true, "opacity": 1 }
  ],
  "layers": [
    {
      "name": "source",
      "image": { "path": "source.png", "width": 3258, "height": 4344 },
      "rect": { "left": 0, "top": 0, "width": 3258, "height": 4344 },
      "reference": true,
      "opacity": 0.5
    },
    {
      "name": "back hair",
      "image": { "path": "parts/back_hair.png", "width": 484, "height": 601 },
      "rect": { "left": 804.3, "top": 207.0, "width": 1642.6, "height": 2039.6 },
      "tags": ["hair", "back"]
    },
    {
      "id": "iris_l",
      "name": "iris L",
      "image": { "path": "parts/iris_l.png", "width": 126, "height": 147 },
      "rect": { "left": 1724.24, "top": 745.36, "width": 101.65, "height": 118.63 },
      "group": "head/eyes",
      "tags": ["eye", "iris", "left"]
    },
    {
      "name": "mouth open",
      "image": { "path": "parts/mouth_open.png", "width": 183, "height": 78 },
      "rect": { "left": 1555.6, "top": 935.8, "width": 147.6, "height": 62.9 },
      "group": "head",
      "tags": ["mouth", "open"],
      "variant": { "type": "toggle", "parameter": "ParamMouthOpen" },
      "opacity": 1,
      "visible": true
    }
  ]
}
```

### 최상위

| 필드 | 필수 | 설명 |
| --- | --- | --- |
| `format` | 예 | 항상 `psd2live-layout` |
| `version` | 예 | 정수, 현재 `1`. PSD2Live는 자신보다 새로운 버전을 거부 |
| `canvas` | 예 | `{width, height}`: 정수 캔버스 단위의 캔버스 크기. 변마다 1–8192, 전체 최대 16 MP. 캔버스 단위는 Cubism으로 내보낸 뒤 모델 캔버스의 픽셀 |
| `layers` | 예 | 레이어 배열, 1–4096개 항목. 순서는 [겹침 순서](#겹침-순서)를 따름 |
| `groups` | 아니요 | 그룹 속성: `path`(필수), `visible`(기본 `true`), `opacity`(0–1, 기본 `1`). 경로는 중복되면 안 됨 |
| `name` | 아니요 | 매니페스트의 이름으로, 소재 폴더 이름으로 사용. 생략하면 파일 이름 |

### 레이어

| 필드 | 필수 | 설명 |
| --- | --- | --- |
| `name` | 예 | 레이어 이름, 출력 가능한 문자 최대 128자 |
| `image` | 예 | `{path, width, height}`: 이미지 경로(상대 경로, `/`로 구분, `..`나 `.` 구간, 백슬래시, 드라이브 문자 없이, 매니페스트 폴더나 아카이브의 해당 수준을 벗어나지 않음)와 이미지의 픽셀 크기. 크기는 이미지와 일치해야 함 |
| `rect` | 예 | `{left, top, width, height}`: 이미지가 채우는 캔버스 사각형. 부동소수점 캔버스 단위이며 너비와 높이는 양수. 캔버스 밖으로 나가도 됨. 픽셀 크기와 사각형의 비율이 텍스처 밀도: `126 × 147` 이미지가 `101.65 × 118.63` 사각형을 채우면 캔버스 단위당 약 1.24 텍스처 픽셀 |
| `id` | 아니요 | 레이어 ID, `[A-Za-z0-9_.:#-]{1,96}`, 매니페스트 안에서 고유. 이후 편집과 MCP는 이것으로 레이어를 가리킴. 생략하면 인덱스와 이름에서 유도하며, 같은 매니페스트는 항상 같은 ID를 만듦 |
| `group` | 아니요 | 그룹 경로. 이름을 `/`로 이음(예: `head/eyes`). 모든 단계가 원본 그룹이 됨 |
| `tags` | 아니요 | 문자열 배열: 의미 태그와 사용자 태그. [태그](#태그) 참고 |
| `variant` | 아니요 | 차분. [차분](#차분) 참고 |
| `visible` | 아니요 | 기본 `true` |
| `opacity` | 아니요 | 0–1, 기본 `1` |
| `reference` | 아니요 | 기본 `false`. `true`이면 [참조 레이어](#참조-레이어)가 됨 |

알 수 없는 필드는 무시합니다. 한 버전 안에서 추가되는 필드는 모두 선택 사항이며, 기존 필드의 의미를 바꾸면 버전을 올립니다.

### 겹침 순서

`layers`는 뒤에서 앞으로 진행합니다. 나중 레이어가 앞선 레이어 위에 그려집니다. 이는 PSD2Live 원본의 레이어 순서(화가 순서, PSD2Live가 PSD를 읽을 때 얻는 순서이기도 함)와 같고, Cubism 그리기 순서가 증가하는 방향과도 같습니다. 레이어 i의 그리기 순서는 레이어 i−1의 그리기 순서보다 낮지 않습니다.

PSD2Live의 레이어 표는 이 순서로 레이어를 나열하며, 생성은 이를 기본 그리기 순서로 사용합니다. 입 같은 생성기에는 자체 규칙이 있으며, 그리기 순서 눈금자의 설정이 우선합니다.

### 태그

- `tags`의 파츠 단어와 `left` / `right`가 파츠와 좌우를 정합니다. 예를 들어 `["eye", "iris", "left"]`는 왼쪽 홍채이고 `["hair", "front"]`는 앞머리입니다. 어휘와 조합은 [의미 태그](PSD_LAYER_SPEC.md#의미-태그)를 참고하세요. 그 밖의 단어는 사용자 태그로, 정리와 검색에만 쓰이며 생성에 영향을 주지 않습니다.
- 파츠 단어가 있으면 파츠와 좌우 모두 `tags`에서 가져옵니다(좌우 단어가 없으면 좌우 없음). 파츠 단어가 없거나 `tags`를 생략하면 PSD 레이어와 같은 규칙으로 레이어 이름에서 파츠와 좌우를 인식하며([이름 참조](PSD_LAYER_SPEC.md#이름-참조) 참고), `tags`의 좌우 단어가 있으면 여전히 그것이 좌우를 정합니다.
- 좌우는 캐릭터 자신을 기준으로 합니다. 캐릭터의 왼쪽은 보통 이미지의 오른쪽에 있습니다.
- 한 레이어가 `left`와 `right`를 둘 다 가질 수는 없습니다.

### 참조 레이어

`reference`가 `true`인 레이어는 참조용일 뿐입니다. 예를 들어 파츠를 나누기 전의 그림으로, 배치하고 따라 그릴 때 기준으로 씁니다. 다른 레이어와 마찬가지로 겹침 순서, 그룹, 불투명도를 가지며 캔버스에 표시되지만, 생성기는 이를 읽지 않고, 리그와 모든 내보내기에서 빠지며, 태그도 필요 없습니다. 열고 나면 언제든 모델 레이어로 바꿀 수 있고, 아직 생성되지 않은 다른 레이어를 참조 레이어로 바꿀 수도 있습니다([소재와 레이아웃 구현](MATERIAL_LAYOUT_WORKSPACE.md#참조-레이어) 참고).

### 차분

`variant`는 `{type, parameter, switch_id}`이며, MCP `layer_set_variant`와 같습니다.

| `type` | 의미 | `parameter` | `switch_id` |
| --- | --- | --- | --- |
| `none` | 차분 없음(기본값) | 생략 | 생략 또는 `0` |
| `toggle` | 파라미터로 표시하거나 숨김 | 필수 | 생략 또는 `0` |
| `switch` | 파라미터의 `switch_id`번 선택지 | 필수 | 음이 아닌 정수 |

## PSD2Live가 읽는 방식

- **프로젝트로 열기**: **시작** 페이지나 열기 대화 상자에서 매니페스트나 zip을 고르거나, 창에 끌어다 놓거나, MCP `project_import_layout`을 사용합니다. 그러면 아직 생성되지 않은 레이아웃 프로젝트가 만들어지고 레이아웃 작업 공간으로 들어갑니다. 캔버스는 `canvas`이고, 레이어는 매니페스트대로 배치되며, 이미지는 원래 픽셀을 유지한 채 사각형을 채웁니다. 태그와 차분은 레이어 분류가 되고, 사용자 태그는 레이어 태그가 되며, `reference` 레이어는 참조 레이어가 됩니다. 각 레이어는 소재로도 등록되어(`name` 이름의 폴더에) 서로 연결됩니다. 그 뒤 생성하기 전에 평소처럼 배치와 겹침 순서를 조정할 수 있습니다. 프로젝트는 매니페스트나 이미지 파일을 보관하지 않으며, 픽셀은 프로젝트 히스토리에 저장됩니다.
- **소재로 가져오기**: **소재** 패널에서 가져오거나 MCP `material_import`를 사용합니다. 그러면 `name` 이름의 폴더가 생기고 그룹은 하위 폴더가 됩니다. 각 항목의 기본 위치는 `rect`이고, 픽셀은 원래 해상도를 유지하며, `tags`도 함께 옵니다. `reference` 레이어의 항목은 참조로 배치하도록 표시됩니다. 차분은 레이어에 속하므로 소재와 함께 옮겨지지 않습니다. 폴더 전체를 배치하면 매니페스트의 겹침 순서가 유지됩니다. 폴더를 스캔할 때는 그 안의 JSON과 zip 파일을 건너뛰므로, 매니페스트의 이미지는 일반 이미지로서 한 번만 가져옵니다.
- 읽다가 오류가 나면 바로 멈추고 위치를 알려 줍니다(예: `layers[3]: parts/face.png is 808x935 pixels, the manifest says 800x935`). 일부만 가져오는 일은 없습니다.

## 검증

`LayoutManifestScenario`는 다음을 다룹니다. 매니페스트를 아직 생성되지 않은 프로젝트로 열 때 이미지가 매니페스트의 픽셀과 사각형을 유지하는지(3배 픽셀의 파츠가 밀도를 유지, 소수 사각형), 겹침 순서, 그룹과 그룹 불투명도, 태그 분류와 사용자 태그, 차분, 불투명도, 소재 등록과 연결, 그리고 참조 레이어가 생성 전후 모두 리그에서 빠지고 되돌리면 다음 생성에 참여하는지. 순서를 바꾼 뒤의 생성, 생성된 레이어의 순서 변경 거부, 저장 후 다시 열기. 매니페스트가 루트에 있는 zip과 최상위 폴더에 있는 zip이 같은 내용을 읽는지, 기본 위치와 태그를 유지한 소재 가져오기, 폴더 스캔이 매니페스트를 건너뛰는지. 밖으로 벗어나는 경로, 크기 불일치, 더 새로운 버전, 다른 형식, 한 아카이브 안의 매니페스트 두 개에 대한 거부. PSD나 매니페스트에서 온 소재 폴더 전체를 배치할 때 원래 겹침 순서가 유지되는지. 그리고 참조 소재가 배치에서 달리 지정하지 않는 한 표시대로 배치되는지.
